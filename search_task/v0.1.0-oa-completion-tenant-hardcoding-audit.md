# P60 流程租户与关键硬编码审计探索任务

> 本会话角色：规划  
> 委派角色：执行  
> 日期：2026-09-13  
> 任务性质：只读探索，不授权修复  
> 前置裁决：`product/v0.1.0-oa-completion/receipts/planning-scope-update-stage-i5-freeze-miniprogram-01.md`

## 1. 任务目标

核实 Owner 指出的“流程发起租户写死 `0L`”事实、完整调用链与真实影响面，并扫描生产路径中其他会覆盖真实请求身份、租户、权限、业务对象或环境配置的硬编码值，为 Planner 确定同步修复范围提供可验证事实。

## 2. 需要回答的问题

1. 精确定位流程发起链中所有 `0L`、`tenantId=0`、默认租户常量或等价写法，逐处说明调用入口、值来源、持久化去向及是否覆盖已认证用户的真实租户。
2. 用至少默认租户与非零租户两个身份/上下文说明当前行为：流程定义查询、发起、实例、任务、表单记录、事件/消息与审计对象最终分别归属哪个租户；若无法运行，明确缺少条件，不以静态推断冒充行为结果。
3. 判断每处命中属于合法平台常量、测试/种子数据、兼容默认值、受控系统身份，还是生产业务硬编码缺陷；测试夹具、迁移 seed、枚举值和协议常量不得仅因字面固定而误报。
4. 扫描 Server 与 Web 生产路径中的关键硬编码，至少覆盖：tenant/user/role/dept/process/form/task 等业务 ID，超级管理员或默认账号，固定权限/菜单判断，固定 Provider/渠道分支，生产 URL/域名/端口，密钥/口令/token 默认值，以及会绕过配置、租户上下文或服务端权限解析的固定值。
5. 对每个真实问题给出严重度、可触发入口、影响对象、跨租户/越权/数据污染风险、是否已有测试覆盖、最小可复现方式及建议归属：本轮流程租户修复、I5 必要前置、独立安全任务或仅登记风险。
6. 核对是否存在多处分别推导租户或业务身份的权威；列出应由执行方案统一消费的现有身份/租户上下文入口，但不得在探索回执中制定具体实现步骤。
7. 给出受影响的最小回归边界，至少覆盖流程发起、实例/任务归属、跨租户拒绝、表单与流程对象勾稽、第一方登录及 I5 SSO 未来身份装载；已经锁定且不受影响的能力不得重新展开。
8. 报告候选 HEAD、相关工作树差异和已有测试资产；用户未提交的工作树内容只报告，不覆盖、不清理、不吸收为本任务成果。

## 3. 搜索范围

- Server：流程发起、流程定义/实例/任务、表单发起关联、认证身份、租户上下文、权限装载、事件/通知、OpenAPI/IoT 发起入口、生产配置与 Flyway 迁移。
- Web：流程发起请求、会话/租户对象、路由与权限判断、生产环境配置。
- 关键词与等价形态：`0L`、`tenantId`、`tenant_id`、默认/超级租户常量、固定业务 ID、固定账号/角色/权限、`localhost`、域名/端口、secret/password/token 默认值；允许结合类型和调用关系排除误报。
- 可读取 `project.md`、两仓工程宪法、相关 `knowledge/` 状态与既有测试证据，以确认工程边界和已登记风险。

## 4. 禁止范围

- 不修改代码、配置、迁移、测试、数据、knowledge、memory、todo 或 product 状态。
- 不执行迁移、构建、服务启动或会改变数据库/仓库状态的命令；如确需行为验证，只能使用现有可安全运行且不写持久状态的测试，无法满足则在回执中说明。
- 不读取或回传真实 secret、密码、token、票据或 Provider 敏感响应；只报告键名、是否存在默认值及风险类型。
- 不开始 I5 Provider 接入，不重验 I1— I4，不处理已冻结的小程序范围。

## 5. 预期证据与完成标准

- 每个结论绑定仓库、文件/符号/配置键、调用入口和证据层级。
- 输出一份“命中项 → 分类 → 影响 → 是否必须修复 → 建议归属”的去重矩阵，并明确 Owner 指出的流程租户问题是否成立。
- 区分已确认、推测、未确认和需要外部条件；结构证据不得冒充运行证据。
- 当上述 8 组问题均有可判定答案且扫描范围、排除规则和残余盲区明确时，探索完成。
