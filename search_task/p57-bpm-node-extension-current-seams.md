# P57 BPM Engine 统一流程节点扩展能力现状探索

> 本会话角色：规划，委派角色：执行
> 任务等级：XL 前置只读探索
> 日期：2026-09-02

## 任务目标

为 P57 正式需求方向提供可验证的现状边界：完整识别当前流程节点种类、设计态到运行态的链路、分散硬编码入口、后端扩展契约与前端消费契约，并判断“统一发现、注册、校验和运行来源”需要覆盖的真实范围。

本次只返回现状事实、差异和风险，不实施 P57，不生成正式需求方向。

## 需要回答的问题

1. 当前系统实际支持哪些流程节点？按稳定类型标识列出完整清单，并分别说明每种节点是否可被设计器创建、保存、发布校验和运行；若四个阶段的清单不一致，逐项列出差异。
2. 从前端节点面板/画布开始，到流程模型保存、后端解析与发布校验，再到运行期分派/执行，节点类型和配置经过哪些关键入口？给出最小调用链及权威文件位置。
3. 当前有哪些固定枚举、`switch`/条件分支、静态 Map/列表、重复类型定义或平行注册表控制节点能力？按“设计、传输/持久化、校验、运行、前端展示”分类，说明新增一种节点目前必须修改哪些中心位置。
4. 后端是否已有可复用的扩展接缝或启动发现机制（例如统一接口、策略集合、容器发现、注册表、处理器映射）？它们目前覆盖哪些阶段、缺少哪些阶段，是否存在重复类型覆盖、顺序不确定、非法实现继续启动等行为。
5. 当前节点元数据和配置模型由谁定义？核实稳定类型标识、显示信息、可配置能力、配置校验、模型序列化/反序列化及运行处理之间的契约关系；明确哪些事实尚无统一表达。
6. 前端当前从静态定义还是后端接口获得可用节点与配置能力？列出相关 API、类型、Mock、设计器消费入口及其一致性风险；判断建立通用消费接缝的最小影响面，但不要设计具体 UI 改版。
7. 是否存在已保存流程定义、版本兼容、BPMN/内部模型映射、未知节点降级或迁移约束？只报告已验证事实；无法从当前仓库证明实际存量时明确标记，不作推断。
8. 依据现状，给出 P57 应锁定的统一能力边界、必须保留的兼容语义、主要风险和分阶段验收建议；同时明确哪些内容属于后续 P58，不得并入 P57。
9. 评估“新增一个仅用于行为验证的节点实现，且不修改中心化节点类型分支”是否能覆盖设计发现、保存、发布校验和运行全链；若不能，指出缺失接缝和需要 Planner 裁决的问题。

- 前端：流程设计器节点面板/画布、节点类型与配置模型、流程定义 API、相关 Mock 和测试；只追踪 P57 通用接缝。
- 根目录只读资料：`todo/requirement-pool.md` 的 P57/P58 定义，以及与当前 BPM 节点现状直接有关的 `knowledge/` 状态或历史索引。

## 预期证据

- 当前节点清单矩阵：节点类型 × 设计/保存/发布校验/运行，附权威文件路径与关键位置。
- 分层链路图或等价的顺序清单：前端发现 → 模型传输/持久化 → 后端校验 → 运行分派。
- 硬编码与注册来源矩阵：位置、用途、当前新增节点是否必须修改、统一后可否消除。
- 后端现有扩展接缝与前端消费契约清单，区分已验证事实、风险和待 Planner 裁决项。
- P57/P58 边界、兼容性风险及验证节点可行性结论。

所有结论必须指向具体路径和位置；代码结构证据用于现状规划，不得表述为功能行为已通过。

## 完成标准

完整回答九个问题，结论优先，回执目标小于 5KB；节点清单、全链入口和硬编码来源能够互相勾稽。无法确认的事项必须说明已查范围、缺失证据及其对正式方向的影响。
