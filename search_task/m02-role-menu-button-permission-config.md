# M02 角色菜单/按钮权限配置闭环探索

**角色确认**：本会话角色为 `规划`，委派角色为 `执行`。本任务仅做现状探索，不生成需求方向，不实施功能。

## 任务目标

确认当前代码在 `M02-F02-01 菜单权限` 与 `M02-F03-01 按钮权限` 上的最新实现边界，为规划层形成“角色菜单/按钮权限配置闭环”的单功能需求方向提供可靠依据。

## 需要回答的问题

1. 当前 `sys_role_menu` 的读取、写入、删除、事务与租户隔离链路分别在哪里；除 Flyway seed 外，是否已经存在可供角色管理复用的绑定写入口。
2. 角色新增、修改、删除时，菜单/按钮权限关系目前如何处理；是否存在孤儿关系、内置角色误改、跨租户绑定或越权配置风险。
3. 菜单与按钮在数据模型中如何区分，权限标识如何从后端加载并贯通到后端 `@PreAuthorize`、前端菜单过滤和按钮级权限控制；哪些现有契约必须保持不变。
4. 前端角色管理页、相关 API/types/Mock 当前具备哪些配置能力；实现“按角色勾选菜单和按钮权限”最小闭环时应复用哪些现有组件或模式。
5. `admin-role-governance`、`user-group-membership` 等近期功能是否改变了旧审计结论；旧结论中哪些仍成立，哪些已经失效。
6. 建议的模块级影响范围、必要的双方言 Flyway 变更判断、关键安全边界与最小验收场景是什么。
7. `M02-F02-01` 与 `M02-F03-01` 是否适合合并为一个功能方向；若不适合，给出必须拆分的直接证据。
