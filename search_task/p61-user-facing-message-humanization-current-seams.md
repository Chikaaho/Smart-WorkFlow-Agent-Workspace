## 1. 目标

系统性盘点Server与Web所有用户可达错误码描述、接口消息、页面提示、状态文案和恢复指引，找出不符合真实软件行业表达习惯、过度技术化、语义不清、直译生硬、缺少行动指引或不适合目标受众的内容。不得只搜索“挑战”或Owner举例；“登录挑战”等仅作为已知症状。

探索只产出现状、触发路径、治理分类和实施接缝，不修改代码、迁移、测试、文案资源或远端状态。

## 2. 全量扫描范围

### Server

- 错误码/异常枚举、统一响应、参数校验注解、认证与授权过滤器、Controller/Service抛错文本；
- 登录、验证码、会话、SSO、租户、组织权限、表单、流程、审批、工作台、通知、文件、任务调度与开放接口；
- 数据库种子或迁移中可呈现给用户的菜单说明、状态说明和错误提示；
- 第三方SDK/基础设施异常向用户层映射的位置，区分内部诊断与外显消息。

### Web

- i18n资源、API错误映射、toast/message/notification/dialog、表单校验、空状态、权限/路由拦截、登录与恢复流程；
- 所有模块页面中的直接中文/英文提示、状态标签、按钮反馈、批量操作结果和移动端提示；
- 后端`code/msg/detail`到最终页面的透传、覆盖、拼接与兜底路径。

测试与文档只用于证明触发行为和既有契约，不把测试专用文本误列为用户文案。日志文本只有在会透传到用户界面或接口消费者时纳入。

## 3. 必须识别的问题类型

1. 非行业惯用或明显AI化措辞，例如把登录校验过程称为“登录挑战”。
2. 内部实现术语直接暴露：Provider、principal、subject、tenant line、engine command、workflow token、栈/SQL/类名等。
3. 用户无法判断“发生了什么、是否需要处理、下一步怎么做”的空泛提示。
4. 中文生硬直译、英文语法/术语不自然、中英文风格或标点不一致。
5. 同一错误在不同入口文案漂移，或机器错误码与页面语义错配。
6. 把成功、处理中、可重试、不可重试、权限不足、对象不存在和系统故障混成同一提示。
7. 泄露账号存在性、租户信息、凭据细节或其他安全敏感状态；认证文案必须继续满足防账号枚举要求。
8. 仅改表层字符串会破坏调用方兼容、自动化断言、国际化键或错误码稳定性的接缝。

## 4. 回传格式

回传写入：

`search_fallback/p61-user-facing-message-humanization-current-seams.md`

至少包含：

- 覆盖方法、扫描入口、文件/资源/错误码数量及无法覆盖边界；
- 按模块列出稳定问题ID、源码路径/符号、当前原文、真实触发条件、最终展示位置、目标受众、严重度及问题分类；
- 区分“机器码保持兼容，仅改用户文案”“需要新增用户/诊断双层消息”“需要前后端共同改契约”；
- 给出统一写作原则与代表性改写建议，但不要在探索阶段批量改代码；
- 标出认证安全、防枚举、多语言、第三方原文、批量结果与恢复指引的特殊处理；
- 提议可分批实施的原子范围、回归测试接缝、可见浏览器验收页面与预计文件集；
- 明确禁止用少量关键词命中数冒充全系统覆盖。

## 5. 执行纪律

- 只读探索，不执行commit、push、merge、tag、Release、迁移或工程实现。
- 如需核对真实页面，只能使用可见浏览器；正式流程证据禁止无头浏览器。
- 固定测试输入和可继续动作不得请求用户二次确认；真实凭据、MFA或人机验证除外。
- 不把内部诊断信息简单删除；应识别其正确承载层，并保留可运维性与可审计性。
