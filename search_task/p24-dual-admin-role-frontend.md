# P24 扩展：双层管理员角色模型前端探索

> **角色确认**：本会话角色：规划；委派角色：前端执行。

## 任务目标

核实前端用户/角色管理是否能表达“不可变超管账号 + 可配置 admin 管理员角色”，以及 job/storage 菜单授权是否需要前端改动。

## 需要回答的问题

1. 用户管理页面是否允许对 userId=1 执行编辑、删除、启停、重置密码、改变角色等操作；分别有哪些前端保护或禁用状态？
2. 角色管理页面是否允许对 `superadmin` 执行编辑、删除、启停、权限/菜单重配；是否依据 ID、code、builtIn 或其他字段判断？
3. 现有角色页面是否存在菜单树/权限绑定配置入口，能否配置一个 seed 的 `admin` 角色；若缺失，缺口具体在 UI、contracts 还是后端 API？
4. job/storage 菜单一旦由后端菜单树返回，现有路由和侧边栏是否可直接显示并进入；是否需要任何前端代码修改？
5. 为清晰表达“superadmin 不可变、admin 可配置”，前端最小影响范围与测试范围是什么？只返回模块级结论，不设计具体实现。

## 搜索范围

- 前端用户、角色、菜单、路由、侧边栏及 job/storage 模块的直接相关源码与测试。
- 前端 contracts 中用户/角色/menu 字段定义。
- `product/` 中 sys-mgmt-crud、checklist-gap-hardening 的直接相关方向与回执。

## 禁止范围

- 不读取或修改后端仓库及 `knowledge/`。
- 不修改任何源码、测试、产品、记忆或探索回执以外文件。
- 不运行 typecheck、lint、test、build、dev server 或依赖安装；只做静态读取与检索。
- 不扩大为菜单系统、权限系统或页面整体重构。
