# P58 流程节点能力完善现状探索

> 本会话角色：规划（Planner）  
> 委派角色：执行（Executor）  
> 任务等级：XL 前置探索  
> 权威需求：`todo/requirement-pool.md` 中“P58 Owner 补充需求定义”

## 任务目标

核清 P57 完成后的真实扩展接缝，以及通用选人、审批、会签、分支、抄送、站内信和第三方通知的现有能力与缺口，为 P58 正式方向提供可验证事实；本任务只探索，不实施、不生成产品方向。

## 需要回答的问题

1. P57 统一节点契约当前对节点类型、配置字段、发布校验、翻译、运行分派和前端渲染分别提供哪些接缝？新增节点的最小接入面是什么？
2. 当前审批人选择已支持哪些策略、配置结构、候选解析与权限校验？固定用户、角色、流程表达式、后端 Bean 适配器各自已有多少基础；旧 `DESIGNATED` / skeleton 兼容路径如何处理？
3. 前端是否已有可复用的用户/角色选择器、表达式编辑器或扩展注册机制？“可扩展 JavaScript 选择器”若接入现有前端，最小安全边界和加载方式是什么，是否存在执行任意脚本的风险？
4. 当前审批任务是单候选、候选组还是多人任务？任一人审批即结束节点所需的任务认领、并发提交、重复请求和审计语义目前如何；数据模型能否记录实际处理人和其他候选人的失效结果？
5. 当前引擎是否已有会签/多实例基础？所有人、任一人、比例结算分别可落在哪些 Flowable 或领域接缝；当前是否具备通过/拒绝计数、提前结束、并发幂等和历史审计字段？
6. CONDITION / EXCLUSIVE_GATEWAY 的稳定标识、图结构、连线配置和翻译接缝现状如何？普通分支要形成可发布、可运行闭环，仍缺哪些配置、校验和前端交互？
7. 当前是否已有抄送领域对象、接口、页面或审计记录？若没有，最小持久化与“命中全部用户”去重/快照/权限语义的落点是什么？
8. 当前通知模块已具备哪些触发事件、模板、发送记录、站内信和第三方通道 SPI？审批拒绝事件是否已产生、为何没有通知；短信、飞书、钉钉、企业微信、公众号、小程序应复用或新增哪些统一接缝？
9. 上述能力分别会影响哪些后端模块、前端模块、数据库表/迁移、公共 API 与 Mock；哪些组合会形成循环依赖或双权威？
10. 是否存在真实存量流程、历史 `graph_json`、已发布 BPMN 或通知记录的兼容风险？无法从仓库证明的外部存量必须明确标为未验证，不能推断不存在。
11. 给出建议的 XL 分阶段依赖顺序，但不得替 Planner 作范围取舍；指出每阶段可形成的真实浏览器、请求/响应、运行轨迹、持久化与零残留行为证据入口。

- 禁止修改任何文件、数据库、依赖、配置或运行状态。
- 禁止编译、测试、启动、迁移、部署及浏览器写操作。
- 禁止生成 P58 正式方向、拆分实施 Step 或代替 Planner 作产品裁决。
- 禁止扫描与 P58 无关的模块；禁止把测试名、类名或注释当作已实现行为。

## 预期证据

- 每条结论给出完整文件路径与关键位置；用“已实现 / 部分实现 / 仅预留 / 未发现”区分成熟度。
- 给出一张能力矩阵：通用选人、审批、会签、分支、抄送、站内信、第三方通知 × 设计/保存/校验/运行/持久化/查询。
- 给出已验证事实、推断和未验证外部条件的明确分栏。
- 输出控制在 5KB 左右，结论优先，不粘贴大段源码或原始搜索日志。

## 完成标准

上述 11 个问题均有明确答案或“未发现/无法验证”结论，且足以让 Planner 锁定配置模型、节点语义、阶段顺序、兼容边界与行为验收标准。
