# P60 I4「编排、流程运营与工作台」现状接缝探索

> 本会话角色：规划（Planner）  
> 委派角色：执行（Executor）  
> 任务性质：只读探索，不实施 I4

## 任务目标

为 Planner 形成 P60 I4 正式阶段方向提供一份可在一次阅读中完成决策的现状回执：明确既有能力、可锁定证据、真实缺口、权威接缝、风险和可验证环境。不得在本探索中生成产品方向、实施 I4 或改变任何功能状态。

## 需要回答的问题

1. 逐域给出当前实现与缺口矩阵：静态条件分支、动态并行分支与汇聚、抄送、模板中心、流程监控与受控干预、基础分析、外部发起/状态查询/嵌入式办理/签名回调、批量审批、流程交接、完整工作台、PC/移动端同对象追踪。
2. 对每个已存在能力标明唯一权威对象及调用链：后端模块/服务/数据模型/API，前端路由/页面/状态/API 消费，迁移与既有测试；指出是否存在第二套节点、参与人、任务、图、流程定义或状态权威。
3. 核对 I1— I3、P4、P54/P55、P57/P58 已交付能力中哪些可直接复用并锁定，哪些会因 I4 改动而失效或必须做受影响回归。特别核对 I3 回执中“Quartz/多实例调度集成属 I4 邻接范围”的实际接缝。
4. 核对动态并行“参与部门”场景所需对象是否齐备：表单/流程变量集合、部门与负责人解析、租户与有效性校验、去重与上限、进入节点时快照、分支来源审计、汇聚策略、零命中/负责人缺失策略、并发与重复触发。
5. 核对批量审批和流程交接的权限与一致性边界：允许动作、逐项结果、意见表单限制、任务归属、代理规则、历史不改写、跨租户/跨用户拒绝、并发幂等和通知关联。
6. 核对模板、监控、分析与干预的现状数据基础：模板版本/复制/授权，实例检索与瓶颈/超时/失败，挂起/恢复/终止/迁移办理人审计，发起量/完成量/耗时分位/节点停留/超时/退回驳回/办理人工作量及有权穿透。
7. 核对流程专用跨系统接入现状：认证授权、租户边界、幂等键、表单校验、状态查询、嵌入式任务权限、出站签名、重试、去重、失败可查、敏感字段过滤；说明可否在本地或受控测试环境完成真实 HTTP 回调闭环。
8. 核对完整工作台现状与缺口：我发起的、草稿、流程分类/常用事项、待办、已办、抄送、消息入口，筛选/分页/稳定排序/详情，取消任务排除、无审批权抄送、权限变化回落，以及 PC/移动端是否使用同一对象、权限和状态语义。
9. 给出建议的 I4 行为验收场景清单，但不得编写实现 Step 或替 Planner 改变 P60 总方向；每个场景说明真实身份、对象、入口、预期行为、持久化/轨迹/审计勾稽点及负向边界。
10. 列出必须由 Owner 或外部环境提供的条件；区分真实外部依赖、当前工具可完成项和可用等强度替代，不得把尚未尝试或可本地闭环的事项声明为阻塞。

## 搜索范围

- 工作区权威状态与既有 P60/I1— I3/P4/P54/P55/P57/P58 方向、回执和证据索引。
- `project.md` 声明的 Server/Web coding 仓库中与 BPM、组织、表单、通知、工作台、移动端、开放接口、Webhook、调度、审计、权限和租户相关的源码、迁移、路由及测试。
- 仅为回答上述问题所需的 Git 当前分支/提交身份与只读差异信息。

## 禁止范围

- 不修改业务代码、测试、配置、迁移、知识状态、product 方向或既有回执；唯一允许新增/写入的是本任务指定的 `search_fallback` 回执。
- 不运行编译、测试、构建、迁移、服务启动、数据库写入、浏览器写操作、部署、提交或推送。
- 不实施 I4，不拆解 Executor 实施 Step，不核销 P 编号，不改 I1— I3 锁定基线，不创建标签或 Release。
- 不读取、记录或回传密钥、Token、密码、真实个人数据；凭据存在性只报告安全配置入口与可用性结论。

## 预期证据

- 每项结论至少给出精确文件路径与符号/行号；涉及调用链时同时覆盖入口、服务/状态机、持久化或审计、前端消费。
- 已交付或可锁定结论必须指向既有行为回执/原始证据位置及其候选身份；只有结构存在时明确标为结构证据。
- 缺口必须绑定 P60 总方向的具体条款，并说明是产品缺失、证据缺失、环境缺失、契约冲突还是仅需受影响复核。
- 回执附一张“能力域 → 现状 → 缺口 → 权威接缝 → 风险 → 建议验收场景 → 证据指针”压缩矩阵。

## 完成标准

- 十个问题均有明确答案；I4 全部范围无遗漏，且已交付、部分交付、未实现、待行为核实四种状态可区分。
- 回执结论优先、目标小于 5KB；不复制长代码、原始日志或大段历史。
- Planner 能据此直接形成 I4 的目标、非目标、影响范围、风险和验收边界，不需要自行读取代码或 knowledge。

## 失败处理

若信息不足、路径不存在或只读工具失败，仍须写回执：逐项记录已尝试范围、真实工具结果、剩余未知、可替代探索路径和解除条件；不得以猜测填空或改为实施任务。
