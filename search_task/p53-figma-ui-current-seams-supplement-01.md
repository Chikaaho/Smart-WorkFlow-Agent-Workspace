## 2. 需要回答的问题

### G1：32 组设计文件逐项身份

对 01—32 每一项分别列出：序号、nodeId、页面名、精确 SVG 相对路径、精确 PNG 相对路径、两者尺寸、各自 SHA-256、配对结论、是否存在实质差异。不得使用通配符、合并行或“同上”。哈希必须由工具生成并在回执中回读；若文件在探索期间变化，明确记录变化前后身份并停止沿用旧结论。

### G2：真实路由与 32 节点映射

给出当前真实路由的紧凑完整清单，至少包含：路由 path/name、静态或动态来源、页面组件、壳外/用户端/管理端/移动 H5 归属、主要权限门禁，以及与 32 节点的对应编号。动态菜单无法穷举实际 path 时，列出生成规则、当前种子/服务端来源与能够确认的实际入口；无法确认的项标记 `UNKNOWN`，不得推测。

### G3：节点 22—26 分别核对

把流程中心五个分类节点 22、23、24、25、26 拆成五行，分别给出 nodeId、精确设计文件、现有分类键/路由参数、当前真实卡片来源、权限过滤、设计示例与真实数据的差异。不得用“与 21 同构”代替逐项结论。

### G4：可判定的视觉回归输入

基于当前 Web 工具链和可实际运行的能力，给出一套可执行建议，必须包含：

1. 建议采用的截图/像素比较工具及其当前可用性；
2. 桌面与移动的精确视口集合，以及每个视口覆盖的页面族；
3. 基准状态集合（至少默认、加载、空态、错误、禁用、弹窗/浮层中实际适用者）；
4. 数值化像素差异阈值或区域阈值，并说明如何单独阻断裁切、遮挡、错位、错误断点和关键状态缺失，不能仅以整页差异百分比放行；
5. 需要人工复核的页面与判断点；
6. 若现有工具无法完成某项，给出真实工具结果与等强度替代，不把“尚未安装”直接写成外部阻塞。
