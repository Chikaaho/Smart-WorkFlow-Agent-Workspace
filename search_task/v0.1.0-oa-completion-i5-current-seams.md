## 1. 探索目标

## 2. 必须回答的问题

1. 四个 Provider 各自是否已有配置模型、启停入口、授权发起、回调/换票、身份绑定、已绑定登录、解绑/失效、错误恢复与审计；逐项给出权威定位和生产调用链，区分正式实现、Mock、占位与缺失。
2. 外部稳定身份如何映射本地 user、tenant、role 与 data scope；重复绑定、冲突绑定、跨租户绑定、本地账号停用、角色撤销、租户禁用分别在哪一层拒绝，是否存在绕过本地权限链的路径。
3. Web Provider 是否落实 state、nonce、回调白名单及官方支持的安全机制；小程序一次性 code 换票、会话建立、重放防护与敏感字段处理现状如何。
4. 前端登录/绑定/解绑/错误恢复页面与后端契约是否同源；移动端与 PC 是否使用同一身份对象和权限结果。
5. 当前数据库迁移、密钥配置方式、日志脱敏、审计字段与历史兼容边界；不得读取或回传真实 secret、票据、code、access token 或 Provider 敏感响应。
6. 现有自动化测试、受控测试应用、官方沙箱/开发者应用、可用回调域与网络条件分别是什么；哪些真实端到端证据可立即获取，哪些需要 Owner 提供外部配置。
7. I1— I4 已锁定的用户、租户、权限、工作台、移动端和流程对象中，I5 会直接影响哪些入口；列出必须回归的最小集合，不把已锁定能力重新包装为 I5 缺口。
8. 给出四 Provider × 核心能力矩阵、共享能力与 Provider 特有差异、建议的原子验收对象、风险与停止条件；不得制定实现方案或开始开发。
