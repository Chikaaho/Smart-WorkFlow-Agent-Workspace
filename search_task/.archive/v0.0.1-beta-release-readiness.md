# v0.0.1-beta 发布候选就绪核验任务

> 本会话角色：规划，委派角色：执行

## 任务目标

在当前实际 checkout 上独立判断项目是否已具备 `v0.0.1-beta` 发布条件。发布候选的必须业务链为：

**授权管理者配置用户、组织与角色 → 创建并发布可填写表单 → 创建并发布绑定该表单的单节点审批流程 → 业务用户提交表单并生成流程实例 → 审批人处理待办 → 发起人刷新后查看最终结果与最小流转记录。**

本任务只产出发布就绪结论和阻断清单，不创建 tag，不提交、不推送、不修复发现的问题。

## 需要回答的问题

1. 根知识仓、后端仓、前端仓当前分别处于哪个分支与 HEAD？远程是什么？工作区有哪些已跟踪修改和未跟踪文件？是否存在尚未纳入发布候选的必要改动？
2. `v0.0.1-beta` 在三个仓库本地及远程是否已存在？若发布物由三个独立 Git 仓库组成，单一 tag 应落在哪个仓库、如何唯一指向另外两个仓库的候选提交？只报告事实和风险，不创建 tag。
3. 当前 checkout 是否仍通过正式质量门：后端根全量测试、H2/PostgreSQL 永久迁移链、前端 typecheck、lint、test、build？必须遵守两端工程宪法、2G 上限和前后端编译互斥，报告原始命令、退出码、可复算计数与失败/跳过数。
4. 使用本轮唯一数据，从真实前端页面和真实后端完成上述完整业务链。逐项记录账号身份、组织、角色、表单、流程定义、业务数据、流程实例和任务标识，并证明保存、重新登录或刷新后仍可勾稽。
5. 发布候选的关键页面是否可达、无白屏/404/死按钮/持续加载，成功与失败提示是否与真实后端结果一致，浏览器控制台是否存在主链未处理错误？
6. 按 README 的最小启动路径，在干净的新进程和新库条件下能否启动后端与前端并进入登录页？默认配置、数据库迁移、端口、必要环境变量或缺失说明是否会阻断首次体验？
7. 是否存在会阻断 beta 的敏感信息、硬编码凭证、无法复现的本地依赖、未提交的必要迁移、质量门失败、主链缺陷或发布物无法唯一定位的问题？
8. 最终给出唯一结论：`READY`、`CONDITIONALLY_READY` 或 `NOT_READY`。若不是 `READY`，列出最小阻断项；非阻断观察项必须单独列出，不得混入阻断项。

## 搜索与验证范围

- 根知识仓：Git 状态、tag/remote/分支事实、README 与发布入口；
- 后端 `Smart-WorkFlow/`：工程宪法、Git/质量门/启动与业务链所需实现；
- 前端 `Smart-WorkFlow-Web/`：工程宪法、Git/质量门/启动、真实页面与浏览器行为；
- `knowledge/current-status.md`、正式功能清单和已知问题仅用于核对当前权威状态；
- `product/minimal-closure-first-acceptance/` 仅用于理解已锁定标准，不能替代本轮当前 checkout 行为证据。

## 禁止范围

- 禁止修改业务代码、测试、迁移、依赖、工程配置、治理文件、README、产品状态或需求池；
- 禁止创建、删除或推送 tag，禁止 commit、push、pull、merge、rebase、reset、checkout 或清理工作区；
- 禁止使用 Mock 页面、固定演示返回、源码片段、测试名称或历史截图替代真实行为；
- 禁止把未授权扩大、接口绕过页面、仅隐藏按钮或提示成功但未创建实例判为通过；
- 禁止对发现的问题现场修复；只记录精确复现事实和影响。

## 预期证据

- 三仓分支、HEAD、remote、工作区状态及 tag 查询原始输出摘要；
- 前后端正式质量门与双迁移链的原始日志路径、退出码和可复算计数；
- 启动命令、运行 profile、端口、健康检查和登录页行为；
- 完整业务链的页面截图/DOM、关键请求响应、持久化回查和跨对象标识矩阵；
- 未授权身份的真实页面与后端拒绝证据；
- 发布阻断项与非阻断观察项分表；
- `READY` / `CONDITIONALLY_READY` / `NOT_READY` 唯一结论及事实依据。

## 完成标准

只有同时获得当前 checkout 的三仓可追溯性、全量质量门、干净启动和完整真实页面业务链证据，且能够区分阻断项与观察项，才算探索完成。任一关键证据无法取得时如实给出 `CONDITIONALLY_READY` 或 `NOT_READY`，不得沿用历史绿灯补齐结论。

## 失败处理

环境、账号、数据库或外部依赖导致无法验证时，说明已完成范围、唯一阻塞点、解除条件和未验证风险；产品缺陷本身不得包装为环境阻塞。

## 回执位置

将压缩结论写入 `search_fallback/v0.0.1-beta-release-readiness.md`，目标小于 5KB；大体量原始日志和截图放入执行角色获准写入的证据目录，并在回执中提供路径。
