## 任务目标

在后端固定提交 `ba59539` 的 clean 隔离 checkout 上，查明 `ApprovalProcessIntegrationTest` 启动阶段 `Abort trap: 6` / exit 134 的直接原因，并用受控、可复算的行为证据判断该提交是否满足后端发布门禁。

## 需要回答的问题

1. abort 由哪个进程、线程或原生组件发出；对应 JVM fatal log、macOS crash report、Surefire dump、标准错误或系统资源记录中的第一条确定性故障是什么？
2. 失败前后的 Java/Maven 版本、架构、内存、磁盘、文件描述符、进程数、临时目录和并发编译状态是否满足项目约束？是否存在可复现的环境冲突或资源耗尽？
3. `ApprovalProcessIntegrationTest` 在不修改代码、测试参数和断言的前提下能否稳定运行？
4. 后端根全量测试能否在同一固定提交、同一受控环境下完整达到 955/0/0/0？
5. 根因属于候选实现/测试缺陷，还是候选之外的 JVM、原生库、运行器或资源异常？结论分别由哪些原始证据支持？

## 验证范围与顺序

1. 建立新的隔离 checkout 和隔离 Maven 本地仓，确认 HEAD=`ba59539`、工作树 clean；记录前后端编译互斥快照及运行环境基线。
2. 优先收集上轮或本轮生成的 JVM fatal log、Surefire dump、macOS crash report与完整 stderr；不得只截取 `Process Exit Code: 134` 一行。
3. 在保持原测试配置和断言不变的条件下运行 `ApprovalProcessIntegrationTest`。若找到明确环境原因，修正仅限临时运行环境后复验；不得修改仓库文件。
4. 定向测试连续通过 3 次后，再运行后端根全量测试。若根因已有唯一、直接的崩溃证据且已消除，全量完整通过 1 次即可提交；若根因仍不能唯一确认，则必须全量连续通过 2 次才可作为稳定性补证。
5. 任一次复验再次 exit 134、出现测试失败/跳过、改变测试配置才能通过，或无法取得规定计数，立即按未核销报告，不得继续堆叠无解释重跑。

## 唯一可接受证据

- 固定提交、clean 工作树、互斥检测和环境基线的原始输出；
- 能直接定位 abort 的 fatal/crash/dump/stderr 证据，或明确说明已检索的标准位置及不存在结果；
- 三次定向测试各自的命令、退出码、测试计数和日志路径；
- 一次有明确根因或两次无明确根因情况下的根全量测试命令、退出码及逐模块可复算汇总，目标均为 955/0/0/0；
- “根因事实 → 环境处置或候选缺陷 → 复验结果”的一一对应矩阵。

## 已锁定项与禁止事项

- F1～F3、F5～F8 全部锁定，不重验前端、业务链、启动、Redis 三态或 tag 事实。
- 不修改业务代码、测试代码、POM、Surefire 参数、JVM 参数基线、README、需求或治理文件；不跳过、隔离、删除或弱化测试。
- 不 commit、不 push、不创建 tag；不把其他提交或当前开发分支替代 `ba59539`。
- 编译测试使用 `MAVEN_OPTS="-Xmx2g"`，并遵守前后端编译互斥约束。
- 不泄露密钥、密码、token 或与根因无关的本机隐私信息。

## 完成标准

- **可核销**：固定提交不变；定向测试连续 3 次通过；后端全量按根因确定程度完成 1 次或 2 次完整通过，每次均为 955/0/0/0；所有证据可复算且未改变测试语义。
- **候选失效**：证据指向候选代码/测试的确定性缺陷，或完成受控诊断后仍复现 exit 134/其他失败。
- **BLOCKED**：仅限无法访问必要系统崩溃证据或真实外部资源阻断；须列出已检索位置、已完成证据和唯一解除条件。
