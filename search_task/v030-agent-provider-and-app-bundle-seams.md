# 探索：AI 供应商管理与应用导入导出的现状接缝

本会话角色：规划，委派角色：执行。日期：2026-11-03。

## 任务目标

为下一版本两个 L 级功能写方向前，核实现有实现：
1. Agent 的 AI API 管理：现有"大模型管理"和 LangChain4j 接入方式，判断能否演进为"一张供应商表、三种 API 格式、任意兼容供应商、后台单例＋模板装配"。
2. 应用导入导出：一个应用包含哪些定义对象、它们之间怎样引用，判断整包导出导入的边界和难点。

只回答事实，不出方案、不写方向。

## 需要回答的问题

### A. AI API 管理（优先）

1. 现有模型配置的数据模型：表名、关键字段（供应商、base URL、模型名、密钥存放与加密方式、参数、启停、租户归属），迁移在哪个版本/文件。
2. LangChain4j 的版本和已引入的模块（如 open-ai、anthropic、google-ai-gemini、ollama 等）；当前用哪些 builder 构造 ChatModel/StreamingChatModel。
3. 模型实例怎样创建和复用：每次调用新建，还是有缓存/单例；配置修改后怎样生效（"动态装载"的实际机制）。
4. 目前实际支持哪些 API 协议格式（OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 等），哪些只是字段预留。
5. 谁在调用模型：智能体运行、流程节点、单步调试、Token 统计、会话等调用点，以及它们怎样选定用哪个模型配置。
6. 前端 `/agent/model` 页面和"新建大模型配置"弹窗现有字段与操作（含连通性测试）。
7. 已知问题、TODO 或硬编码（例如写死的供应商名、写死的 URL、只认 OpenAI 的分支）。

### B. 应用导入导出

8. "应用"的数据模型，以及应用下挂哪些对象：目录/分类、表单定义（含版本、快照、列表配置、字段权限）、流程定义（含版本、节点配置、审批意见表单引用）、工作台卡片、菜单、数据源、字典、图表等。列出表名和外键/引用字段。
9. 流程怎样引用审批意见表单，审批意见表单是否属于应用、能否被多个流程或应用共享。
10. 对象标识：主键类型，是否有稳定 key/code，跨租户、跨环境是否唯一；有没有同名或同 key 约束。
11. 已有的任何导入导出能力：表单数据 Excel（P32）、流程 BPMN/JSON 导入导出、`P15 跨环境导入导出`（I16）相关代码或残留。
12. 引用到应用外部的东西：用户/角色/部门（审批人）、数据源连接、字典、附件、IoT 设备、Agent 模型。哪些是按 ID 引用的。
13. 应用相关的权限点和租户隔离方式（tenant_id 列、拦截器）。
