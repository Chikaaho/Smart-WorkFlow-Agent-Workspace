## 1. 探索目标

为 P53“全局 UI 与组件布局优化”建立可实施、可验收的现状底图。Owner 已将完整 UI 以 SVG、PNG 两套版本导出到工作区 `docs/ui/`；本探索需要把 32 个设计页面/浮层与现有 Web 路由、页面、布局壳、组件、设计令牌、权限入口和真实业务能力逐项映射，识别可直接实现、需复用改造、设计稿有但产品尚无对应能力、现有页面有但设计稿未覆盖的差异。

本任务只做事实探索与回执，不修改业务代码、测试、配置、资产或 Git 状态，不启动 P61 提示语治理的剩余执行包。

## 3. 必答问题

### A. 工程与页面底图

1. Web 当前框架、构建工具、UI 组件库、路由、状态管理、样式组织、主题/令牌入口分别是什么；给出精确文件与行号。
2. 用户端、管理端、登录态外页面当前分别使用哪些布局壳、顶栏、侧栏、菜单与权限门禁；是否存在平行壳或重复组件。
3. 当前所有真实路由与主要页面清单；标注桌面、移动/H5、响应式或固定宽度现状。

### B. 32 节点逐项映射

每个设计页面必须给出：`docs/ui/` 中对应的 SVG/PNG 文件、上游 nodeId、对应路由、现有页面/组件、状态（`EXACT` / `PARTIAL` / `MISSING` / `PROTOTYPE_ONLY`）、主要差异、依赖的真实接口/权限、建议复用的组件。不得用“其余类似”省略。

对于设计中的按钮、菜单、筛选、卡片、指标、列表操作、弹窗和状态，区分：

- 已有真实行为；
- 已有能力但入口/布局不同；
- 仅视觉示例，当前没有对应业务能力；
- 可能改变业务规则、权限或数据契约，必须另行产品裁决。

### C. 设计系统与资产

1. 从代表页及重复结构中提取颜色、字体、字号/行高、间距、圆角、阴影、边框、层级、表单控件、表格、按钮、状态标签、卡片、弹窗和导航的候选令牌。
2. 核对项目已有令牌、组件和 Element Plus 覆盖方式，列出可复用、需收敛、需新增的唯一入口；不得建议逐页复制绝对定位代码。
3. 盘点 `docs/ui/` 与项目现有 Logo、图标、插画、渐变和其他资源，识别可直接复用、需从页面SVG拆分、需优化压缩或缺失的资产；说明格式、来源、命名和落库建议。
4. 核对 Inter 与中文字体的实际可用性和回退链，避免设计工具字体在目标环境失真。

### D. 响应式、国际化与可访问性

1. 设计稿顶层均为 1440px；核对现有 PC、移动/H5 断点与页面，列出缺失的移动设计决策，不能把桌面缩放截图当移动实现。
2. 说明 zh-CN/en-US 长文本、数字、表格列、导航和表单标签对布局的影响；P61 已建立的机器语义与双语能力不得被 UI 改造破坏。
3. 盘点键盘焦点、对比度、语义标签、错误提示关联、弹窗焦点管理、触控尺寸和缩放风险。

### E. 实施与回归边界

1. 给出按共享基础优先的实施切片建议：设计令牌/资产 → 全局壳与导航 → 通用组件 → 登录/工作台 → 数据页 → 设计器 → 流程与审批 → 浮层/响应式收口。建议可以根据现状证据调整，但必须说明依赖关系和回滚点。
2. 标出 UI 改造会触碰的 P60/P61 已锁定行为与测试；行为、权限、接口和数据语义原则上保持不变。
3. 标出 P61 哪些 Web 视觉证据会因 P53 实施自然失效，哪些 Server/机器契约证据可继续保留；不得提前重跑或伪造新基线。
4. 建议可自动化的视觉回归方案、目标视口、基准截图、差异阈值和人工复核点。阈值必须能发现裁切、遮挡、错位、错误断点和状态缺失，不能仅比较“页面可打开”。
