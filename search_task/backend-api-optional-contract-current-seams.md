# 后端跨模块 API `Optional` 契约现状探索

> 本会话角色：规划（Planner）  
> 委派角色：执行（Executor）  
> 目标任务：`backend-api-optional-contract`（XL，当前 `PLANNING / EXPLORING`）

## 任务目标

在不修改任何文件、不运行编译或测试的前提下，完整盘点后端所有 API 模块中对其他模块开放的可调用方法，为 Owner 硬约束“开放方法的返回值必须使用 `Optional` 包装”形成可执行、可验收且不漏项的事实基线。

## 需要回答的问题

1. 列出全部后端 API 模块（包括但不限于目录或 artifact 名称为 `*-api` 的模块），并说明哪些包/类是真正的跨模块调用面，哪些只是 DTO、事件、枚举、常量或模块内部实现。
2. 对每个跨模块可调用方法给出：完整签名、当前返回类型、实现位置、所有生产调用方模块、相关测试，以及“已为 `Optional`”/“未包装”的精确分类与计数。
3. 按查询单值、集合/分页、布尔/状态、数值/原始类型、命令结果、`void`、异步/回调/事件发布等方法类别分组；特别标出 Java 中不能直接形成 `Optional<void>` 的签名，以及 `Optional<List<T>>` / `Optional<Page<T>>` 可能引入的“无结果 vs 空集合”双重语义。
4. 查明当前缺失语义：哪些方法会返回 `null`，哪些使用空集合/布尔值/异常表达缺失、拒绝或失败；不得只根据方法名推测。
5. 标出全部兼容影响：接口实现、生产调用方、Mock/桩、测试夹具、反射/序列化/框架绑定、对外 HTTP 边界、循环依赖或模块依赖红线。
6. 查找现有工程守门或可复用模式（例如 ArchUnit/自定义静态检查/既有 `Optional` Facade），判断如何以可机械验证的方式覆盖“全部 API 模块 + 全部跨模块开放方法”。
7. 给出可复算汇总：API 模块数、开放类/接口数、方法总数、已合规数、待改造数、按方法类别的分组计数，并说明排除规则。

## 搜索范围

- 必须先完整读取 `Smart-WorkFlow-aPaaS-server/docs/governance/engineering-constitution.md`。
- 只读 `Smart-WorkFlow-aPaaS-server/` 中的 Maven 模块声明、全部 API 模块源码、其实现与生产调用方、相关测试、模块依赖规则。
- 允许使用 `rg`、`find`、Maven 模块列表的静态读取和只读脚本统计；统计脚本不得写入仓库。

## 禁止范围

- 禁止修改任何业务、测试、配置、文档、依赖或状态文件。
- 禁止运行编译、测试、构建、启动、迁移或部署命令。
- 禁止只抽样部分 API 模块，禁止把 Controller 的 HTTP 返回契约与模块间 Java API 方法混为同一边界。
- 禁止在探索回执中代替 Planner 制定最终方向或开始实现。

## 预期证据

- 每个 API 模块的相对路径与识别依据。
- 方法级清单：相对文件路径 + 行号 + 完整签名 + 实现/调用方/测试指针。
- 可复算的搜索规则、排除规则和分类计数；如自动统计无法精确识别“跨模块开放”，必须列出人工复核差异。
- 只保留支撑规划决策的结论与索引，不粘贴大段源码或原始命令输出。

## 完成标准

上述 7 个问题全部有明确结论；清单可以从汇总计数反向复算；不确定项按精确签名单独列出，不用猜测填补。

## 失败处理

如发现定义边界无法从代码事实唯一识别，仍要回传已完成的全量清单、冲突候选和唯一待 Owner/Planner 裁决问题，不得扩大为实现任务。
