## 0. 结论摘要

**四个 Provider（企业微信、飞书、钉钉、微信小程序）的 SSO 接入在代码、配置、页面、数据库、测试五层均为「缺失」；仓库只存在一个共享、无实现、无调用的预留 SPI，以及一批仅用于出站通知的渠道枚举。**

- 唯一身份接入接缝：`sw-framework/sw-security/src/main/java/com/sw/ck/security/spi/SocialAuthenticationProvider.java:4-15`（`type()` + `authenticate(String code)`），类注释自述「本模块不内置任何渠道实现、不在任何地方调用，仅预留接口」。全仓 `grep -rn SocialAuthenticationProvider` 仅命中该定义行，**无 implements、无注入、无调用方**。
- 关键词易混项：`NotifyChannel`（`sw-basic-notify-api/.../api/NotifyChannel.java:4-12`）含 `FEISHU/DINGTALK/WECHAT_WORK/WECHAT_OFFICIAL/WECHAT_MINI_PROGRAM`，但这是**出站通知渠道枚举**，与登录身份无关；对应通知渠道本身亦无适配器（属 I6 范围，本次不计入 SSO 缺口，但需与 I6 划清边界避免重复建设）。
- 前端零痕迹：`src/` 全仓检索 `wechat|weixin|openid|unionid|oauth|sso|dingtalk|feishu|qrconnect|callback|state` 无任何真实或占位命中（7 个历史命中经逐条核验均为「第三方库边界」「岗位 association」等无关语义）。
- 数据库零痕迹：全部 Flyway 迁移中不存在任何第三方身份表或列（`openid/unionid/provider/social/external_id/bind/login_type/sso` 全部零命中），`LoginUser` 也无第三方身份字段。
- 因此 §1—§3 中「配置模型、启停入口、授权发起、回调/换票、身份绑定、已绑定登录、解绑/失效、错误恢复、审计」**九项对四个 Provider 一律为「缺失」**，差异只在未来所需的外部条件，不在现有代码。

现有可复用的**第一方**认证与权限底座是完整且已有行为证据的（P45 已 COMPLETED）：`/auth/challenge`（RSA 公钥+图形验证码）→ `/auth/login`（RSA-OAEP 解密+验证码+时间戳）→ JWT access（900s，仅内存）+ refresh httpOnly cookie（7d，轮换+重放全量撤销）。I5 的真实工作量落在「在这条链上新增身份来源」，而该链的租户、权限、审计、密钥现状存在下述需先由规划层裁决的硬边界（见 §9 红线）。

## 2. 外部身份 → 本地 user / tenant / role / data scope 映射与拒绝层（Q2）

**现状：映射不存在。** 无绑定载体表，无 `(provider, tenant, external_id)` 唯一约束，无映射服务；`LoginUser` 字段仅 `userId/username/tenantId/deptId/roles/permissions/dataScope/customDeptIds/superAdmin`（`sw-framework/sw-security/.../holder/LoginUser.java:12-37`）。

可作为 I5 继承的**现有拒绝/收敛层**（每条均为「已实现且有行为证据」）：

| 风险 | 现有拒绝层 | 权威定位 | 结论 |
|---|---|---|---|
| 本地账号停用 | 登录期状态校验（`status != 0` → 401）+ 装载期 `isActive` + 每请求按 Redis 缓存装载 | `AuthController.java:166-171`、`:291-296`；`UserDetailsProviderImpl.java:106-109`；`JwtAuthenticationFilter.java:74-106` | 已实现；缓存 TTL = access 900s，驱逐后下次请求立即回查 |
| 角色撤销 / 授权变更 | 角色 `status=1` 过滤 + 变更即 `kickOut` 清 Redis 缓存（fail-secure，驱逐失败抛错回滚） | `UserDetailsProviderImpl.java:130-142`；`SysRoleServiceImpl.java:103,120,191,228-251`；`SysUserServiceImpl.java:197,219,277,287-299` | 已实现；撤权后**立即**收敛 |
| 重复绑定 / 冲突绑定 / 跨租户绑定 | **无任何层**（无载体、无唯一约束、无服务校验） | — | **缺失** |

**租户上下文的真实来源与边界**（与 I5 强相关）：
- 租户**取自本地 `sys_user.tenant_id` 行**（`UserDetailsProviderImpl.java:158`），**不接受客户端租户头**；前端亦不发送租户头（Web 工程宪法 §111）。
- 登录装载时以线程级全表挂起 `TenantLineSuspension` 绕过租户行过滤（`UserDetailsProviderImpl.java:82-91,96-104`），使**用户名全局唯一**的账号可跨租户装载；业务请求一律按 `LoginUser.tenantId` 正常过滤（`CommonTenantLineHandler.java:25-35,44-56`）。未登录上下文回落 `SUPER_TENANT_ID`（`CommonTenantLineHandler.java:26-30`）。
- `sys_tenant.domain_name` 列存在（`V1__init_schema.sql:23`）但**全仓无 Java 引用**——按域名解析租户的能力是**休眠字段，无实现**。
- 「非零租户用户当前没有受支持登录入口」是**已登记的认证产品边界**（`knowledge/known-issues.md:14,16,20`、`knowledge/features/p45-login-security.md:14`），不登记为 I 编号。多租户 SSO 必须自己解决「外部身份 → 哪个租户」这一未解问题。

**是否存在绕过本地权限链的路径**：不存在客户端可注入角色/租户/权限的入口。现存两处「旁路」均为设计内且受控：`superAdmin` 短路（`UserDetailsProviderImpl.java:162-166`）与 `TenantLineSuspension`（仅认证装载期、线程内 try-with-resources、注释明确「不得用于任何业务读写」）。**风险提示**：SSO 回调属「认证前」路径，若在回调内复用该挂起开关做业务态读写，将直接绕过租户隔离（详见 §9 R2）。

## 8. 共享能力与 Provider 特有差异、建议的原子验收对象、风险与停止条件（Q8）

**共享能力（仓库内已存在，I5 应复用而非重建）**：统一登录链（challenge/RSA/验证码/时间戳）、JWT + refresh cookie 轮换与重放撤销、`LoginUser` 装载与 Redis 缓存、`kickOut` 权限即时收敛、租户行过滤与认证期挂起、服务端数据范围过滤、AES-GCM 凭据加密 + `mask`、DB 唯一约束 + 时间窗 nonce 防重放（openapi 先例）、`permit-urls` 放行机制、`NotifyTargetResolver`（userId → 手机/邮箱，已实现，可供 I6 复用）。
**Provider 特有差异**：仓库内无代码体现（§1）；差异仅在外部协议与所需凭据（§6），需官方文档确认后才可固化为验收对象。

**建议的原子验收对象（验收粒度建议，非实现方案）**——每个 Provider 各自独立、可判定、绑定真实外部证据：
1. 配置与启停：配置项存在、缺失/非法时**明确失败**（不静默降级），启停后行为可观测。
2. 授权发起：跳转参数完整（含 `state` 等 Provider 支持的安全参数）、白名单外回调被拒。
3. 回调与换票：一次性凭证**只可消费一次**，重放被拒且有可复核证据；换票失败返回可判定错误。
4. 身份绑定：`(provider, tenant, external_id)` 唯一；重复绑定与冲突绑定被拒；跨租户绑定被拒（**依赖 §2 租户边界裁决**）。
5. 已绑定登录：外部登录成功即建立本地会话，`LoginUser` 由服务端装载，与第一方登录产出**同一身份对象**。
6. 解绑与失效：解绑后该外部身份不能再次登录；Provider 侧凭证失效/login 被撤销时本地可判定。
7. 错误恢复：Provider 错误 → 明确本地错误码与可重试语义，不泄漏敏感字段。
8. 审计：绑定、解绑、登录成功/失败、越权拒绝**落库可查**（**依赖 §5 审计载体缺失**）。
9. 越权负向：本地停用、角色撤销、租户禁用、跨租户在 SSO 登录后**同样生效**（租户禁用项**依赖 §2 缺口裁决**）。
10. 敏感字段：票据/密钥/Provider 响应敏感字段**不进入前端、普通日志与回执**（受 CSP 与 MyBatis 全量 SQL 日志现状约束，§3/§5）。

**风险与停止条件（沿用方向 §8 并落到现状）**
- **租户止点**：无「外部身份 → 租户」解析机制且租户禁用无生效路径时，租户维度验收项不得判通过；跨租户绑定未证明拒绝前不得进入下一 Provider。
- **第三方真实性止点**：无真实 Provider 应用/回调域/小程序工程时，只报告「已实现与未验证边界」，**不得以 SPI/SDK/配置页存在宣称接入完成**（方向 §6 明确）。
- **双权威止点**：若为 SSO 另建身份/权限体系（自有角色、自有会话、自有参与人解析），必须先收敛为单一权威再继续。
- **历史兼容止点**：若新增绑定语义需重新解释历史 `sys_user`/`sys_user_role` 或运行中实例身份，停止并提交兼容方案。
- **CSP 与依赖止点**：`script-src 'self'`/`connect-src 'self'` 与「HTTP 一律走单一请求层、危险第三方须套防腐层」为工程宪法不变量，B 端 SDK 直引或跨域调用不可行，需先取得规划层对引入方式的裁决。
- **容量止点**：I5 需覆盖 4 Provider × 10 项原子对象且外部条件未就绪，不得自行缩减 P0 范围或静默降级。

## 10. 已确定事实 / 推测 / 未确认 / 冲突

- **已确定（有文件与行为证据）**：四 Provider SSO 九项能力全缺失；唯一接缝为无实现无调用的 `SocialAuthenticationProvider` SPI；无绑定表/列/唯一约束；无回调路由与 CORS；前端零第三方痕迹；小程序无工程载体；第一方认证链、权限收敛、租户行过滤、数据范围过滤、refresh 轮换+重放撤销均已实现且有测试；无登录审计表；无统一脱敏；RSA/摘要密钥 fail-fast，JWT 密钥有明文默认且 prod 未覆盖；`sys_tenant.domain_name` 为无实现休眠字段；出站网络对四家厂商域可达。
- **推测（低置信）**：企业微信/飞书/钉钉在 Web 侧可用「服务端重定向授权」绕过 CSP 的 SDK 限制，而小程序侧必须新增独立工程载体；`NotifyChannel` 中的小程序/企微枚举可能在 I6 与 I5 被同时复用为「渠道」和「身份」，存在语义混淆风险。
- **未确认**：官方沙箱与开发者应用的可得性、注册周期与审核要求；可用于回调白名单的 HTTPS 回调域与路径（生产域名以服务器本地记录为准）；Provider 侧稳定标识的具体字段与版本差异（需官方文档）；多实例部署实例数（影响登录挑战/绑定并发，仓内配置齐备但无法断定）。
- **冲突（需规划层裁决，不在执行层自行决定）**：① 租户维度 —— 方向 §3.8 要求「租户禁用 SSO 后同样生效」，但租户禁用无生效路径且非零租户登录为已登记产品边界，I5 是否含「租户解析/租户禁用生效」子范围？② C1 安全机制实现方式 —— CSP/CORS 现状下 B 端 SDK 与回调形态需裁决；③ C2 审计与脱敏载体 —— 无 `sys_login_log`、无统一脱敏，是否随 I5 新建或先补通用能力？④ C3 小程序交付边界 —— 仓库无小程序工程，是否需新增第三个 coding 仓，属 `project.md` / Owner 范围决策。
- **需要外部真实条件**：四家 Provider 测试应用与凭据、回调白名单域名、微信小程序 AppID 与合法请求域名、可用测试身份（§6 已列清单）。
- **是否需要继续探索**：就现状事实而言**不需要**；上述冲突属规划层范围裁决，执行层不自行决定。
