# P62 探索附件 C：首阶段范围约束与预算输入（2026-09-30，仅事实与选项，不含产品方向）

> 主回执：`search_fallback/p62-current-seams-and-information-audit-20260930.md`。本附件只回报约束和选项事实，不代写产品方向、不设定新 SLA。

## C1. 可作为首个事务阶段有限范围的能力候选（现状事实）

已有且可直接作为事务阶段基座（证据见附件 B）：
1. **共享提交边界**：引擎与业务同 DataSource/事务管理器，G3a/G3b 真实 PG 快照在仓（当时行为证据，改动事务管理器即失效需重验）。
2. **统一命令身份/幂等/回查**：sw_bpm_command + 6 组唯一索引 + 保存点 + 双通道共享身份 + 回查接口；P4 兼容=现网行为本身。
3. **动态宽表受控入口**：DynamicTableSql 统一动态 SQL（标识符校验+强制 tenant_id/deleted+参数绑定+父行锁；详见主回执 Q3 与附件 B 补充）。
4. **租户/权限强制体系**：TenantLineInnerInterceptor fail-closed + DataScope + 调度线程还原租户模式。
5. **版本快照**：流程 PUBLISHED 版本行不可变 + 实例绑定 published_version + 表单 snapshot。

真实缺失（首阶段若纳入即为新建设，非复用）：受控动作原语（原子条件更新/增减/预占/确认/释放/台账）、C1 关键数据分类与全写入入口强制、EXPIRED/外部待核实命令态、IoT UNKNOWN 对账、发布校验的事务/等级项、性能测量基线。

## C2. 首阶段前必须先确定的决策清单（依正式需求 R01—R10 与主方向 §4，均待 ADR）

1. **兼容性**：命令状态机扩展（加 EXPIRED/外部待核实态）与既有 P4 语义、在途 sw_bpm_command 行的兼容窗口；种子基线（0.1.3 起仅全新建库）下迁移/回滚形态。
2. **事务参与者**：哪些写入口（表单保存/导入/批处理/脚本/API/流程节点）进入统一事务管理，C1 分类由谁声明、以什么形态声明（模型注解/发布配置）。
3. **在途对象**：PENDING/PROCESSING 命令、SENT 未回执设备命令、发布版本切换时在途实例的语义固定策略。
4. **迁移/回滚窗口**：五套同构租约恢复实现是收敛为统一框架还是各自扩展（影响回滚面）；Outbox 等效路线 vs 意图表路线的取舍边界。
5. **受控动作与发布体系关联**：动作版本是否复用 BpmProcessDefVersion/FormSnapshot 机制或新增动作注册表。

## C3. 现有性能证据充分性（Q6）

**结论：不充分——全仓无任何性能/负载/延迟测量资产。**
- 检索（2026-09-30 实测）：无 JMeter/Gatling/压测脚本/性能基线文档；`docs/` 无性能专题。
- 在仓并发类测试（`Phase3ReferenceConcurrencyPostgresTest`、`CommandOverlapRealEngineTest`、`CommandLeaseHandoverOverlapTest`、`ConsensusVoteConcurrencyTest`、Phase4 故障注入组）证明的是**并发正确性/故障恢复语义**，不构成吞吐/尾延迟/热点证据。
- P62 两份原稿均自述无实测：01 评审稿"未核查当前工程实现、部署容量或性能数据"、"目前缺少上述业务输入与实测数据"；CTO 稿"时效数值为行业常见参考量级，作为设计预算使用；平台实际能力以实测为准"。
- 初始预算（P99≤300ms 实时动作、生产命令受理 1—3s 等）的硬件/负载/时点：**无**——从未在任何环境测量过。
- 现网唯一运行参照：UAT 单机（chikaho.cn，PostgreSQL，0.1.3）承载 OA 演示负载，无生产量级数据。

## C4. 缺失的预算输入清单（验收前须固定，方向 §4 已列框架，此处为执行侧确认）

1. 硬件/拓扑/网络范围（单机 vs 多节点；DB 版本与参数——现网 PG 14/16 @5433 单实例）。
2. 并发吞吐目标、数据规模与热点分布（库存热点维度：物料/库位/租户）。
3. 测量窗口、失败/拒绝比例口径、普通 OA 最低保障、恢复目标。
4. 每类命令的唯一完成点与超时语义（BPM 命令现无 EXPIRED 态，设备命令 EXPIRED=24h 入参）。
5. T1 不走持久队列的路径定义（现 P0 仍走 DB 队列+有界等待，若 T1 要求旁路队列需新执行形态）。

## C5. 选项事实（供 ADR，不替选）

- 持久投递：维持意图表+恢复调度（五处）vs 收敛统一框架 vs 引入 Outbox 表——三者均无现成实现障碍，收敛影响面见附件 B B1.3。
- 实时动作执行：复用 Flowable（实例写放大）vs 轻量执行能力（新事务通道）——现网两种都无；正式需求 R01 明确不预设。
- 设备命令节点化（IOT_COMMAND translator）vs 维持事件监听器——机制就绪度见附件 B B2.3。
