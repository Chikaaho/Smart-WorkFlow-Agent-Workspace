# 授权集成（#调用集成）现有能力边界核实

结论：当前缺口是**表单宿主到受控执行端口之间的授权映射与桥接缺失**，不是凭据缺失，也不必新增 Provider 类型。平台已有一份真实的受控 HTTP 执行能力（Agent 外部工具白名单表 + RestClient 执行器），但只服务 Agent 编排，没有对表单/脚本暴露执行端口；表单侧宿主把授权标识集合写死为空且未注入执行器，因此 `#调用集成` 在到达网络前即被“未授权/执行器不可用”拒绝。

## 可复用性判断

- **执行层可复用**：把稳定集成标识映射到已启用的外部工具配置，由服务端代理发起 HTTP；Web 保持单一请求层与 CSP，不直连外部。RestClient、超时、租户过滤、调用留痕均可沿用。
- **不能原样复用**：Agent 模块未拆 api/biz，form-biz 当前不依赖 agent；直接依赖会把编排内部实现引入表单。需要最小端口（facade/端口接口）或落在中立基础模块，属于跨模块契约选择。
- **正向环境**：平台没有通用本地 HTTP 对端；dev 仅有 IoT `LoopbackPeerProvider`（专用 peerUrl），不能充当表单集成对端。可用本机受控端点（如 actuator health）做无秘密正向，仅证明执行与边界，不证明第三方 Provider；真实外部调用须另行授权且不回显秘密。

## 若继续的最小产品边界

1. 租户内集成登记/映射：稳定 key、目标 URL/方法、超时、启用、可调用表单/角色范围；可复用 `sw_agent_tool_external` 作为执行目标（只读映射），或新建独立登记表。
2. 服务端执行端点：按当前登录租户、表单与身份校验 key 授权；只允许已登记目标，不接收客户端 URL/秘密；限制方法、超时与输入输出大小；加载/提交前仅查询，写副作用仅提交后或明确业务入口，按提交/动作 ID 幂等并留痕。
