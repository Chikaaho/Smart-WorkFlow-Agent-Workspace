## 8. 系统边界与兼容风险

1. **表单脚本权威**：字段脚本在浏览器执行，公式/外部数据在服务端。新增提交前/后事件若允许改数据，必须明确服务端是否重算/拒绝，避免客户端结果成为正式事实。
2. **CSP 与执行模型**：前端禁 `eval/new Function`，现有字段脚本是自定义解释器子集；要求任意 JS 语义或异步 await 时，需决定扩解释器、改 CSP 或迁服务端，三者不能同时保持现状。
3. **租户生命周期**：停用已在登录/刷新/会话/SSO/OpenAPI 生效，但流程与定时任务未校验。若租户管理提供停用按钮，必须同时定义在途实例、待办、预约任务、通知的处理，否则会出现“已停用但业务继续跑”。
4. **超管写入归属**：当前新建对象落登录租户（超管为 0），且无租户选择器。租户管理上线后若直接沿用，会把新用户/部门写进租户 0；需先定创建语义。
5. **既有菜单种子**：`system/tenant/index` 已存在但无组件/接口，动态路由跳过。新增页面时必须同时处理菜单 id 16、权限码 `system:tenant:list` 和角色授权，避免出现两个入口或孤儿菜单。
6. **P4 入口复用**：版本挂起/激活、代理规则、废弃均已有服务端契约与前端 API 封装，新稿应接线到既有接口，不另建第二套动作或状态。
7. **全局 UI 共用组件**：P53/0.1.10 已把列表、分页、详情、侧栏、操作列收敛为共用件；新稿改动会波及多模块，需按受影响入口做回归，而不是逐页改样式。
8. **版本与快照**：表单脚本、公式、数据源、列表配置均随发布版本冻结；新事件脚本若存入 definition 之外，会破坏历史解释一致性。
9. **文案来源分层**：前端 locale、后端消息、DB 菜单/种子、租户自定义文案来源不同。全量审计若只改 locale，会漏掉后端与种子文案；若前端硬替换，又会掩盖来源问题。
10. **监听器与触发器**：设计稿的事件监听是“名称/时机/状态/脚本”列表，现有触发器是“事件/判断脚本/结果分支/动作”。另建页面会得到两个脚本入口和两套执行语义。
11. **租户管理员列**：`sys_tenant` 没有管理员字段，`superadmin` 只属于租户 0，非零租户的管理员身份尚无契约；新增租户时同时建管理员会跨越用户、角色、租户三块写入。
