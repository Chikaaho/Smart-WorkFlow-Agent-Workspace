## 0. 结论摘要

**六个渠道中只有一个（站内信）具备真实行为；短信仅有一个 dev-profile 伪造适配器；飞书、钉钉、企业微信、邮件在生产代码、配置、出站调用、回执四层全部为缺失，邮件连渠道枚举值都不存在。通知的模板版本、渠道规则、接收人/订阅规则、超时重试语义、投递回执、深链保护六项均为缺失。**

既有底座（可复用，A 级）：站内信收件箱持久化 + 越权校验 + 租户隔离；模板 CRUD/渲染/预览；批量发送（含服务端解析收件人）；发送记录分页 + 尝试流水 + 真重投重发；12 类流程事件 → 统一通知门面的 AFTER_COMMIT 链路；幂等键 + DB 唯一索引。

关键结论摘要：
- 唯一 `NotifyChannelAdapter` 实现是 `P58DebugNotifyChannelAdapter`，且 `@Profile("dev")`；生产任何非 IN_APP 渠道稳定落 `FAILED / 未配置生产渠道适配器`。
- notify 模块**无任何渠道配置键、无 `@ConfigurationProperties`、无启动期 fail-fast**；渠道未配置时不阻断启动，只静默落失败。
- 站内信**无分页、无全部已读、无未读数、无深链字段**；前端用 `pageSize=9999` + 隐藏分页规避。
- 流程事件链已与审批事务解耦（`@TransactionalEventListener(AFTER_COMMIT)`），**但引擎抄送/通知节点在引擎事务内同步投递且 `failureStrategy` 默认 `BLOCK`**，投递失败会抛 `NODE_DELIVERY_FAILED` 回滚该节点步骤——与方向 §3.9「通知结果不回滚已提交的审批动作」存在边界需裁决。
- 事件链走旧入口 `send(SendNotifyCommand)`，**不设幂等键、无 `(tenant,biz_type,biz_id,recipient)` 唯一约束**，重复发布会重复投递。
- 方向 §7 非目标中「微信小程序客户端、SSO 与通知为 Owner 冻结的后续候选，不属于当前 P60 或 0.1.0 验收范围」与 §3.9「完成…六类渠道」表面冲突，需 Planner 裁决（见 §11 冲突）。

## 2. 真实/占位/缺失、fail-fast 与硬编码（Q2）

**是否真实 Adapter**：唯一 Adapter 实现为 C 级 dev 调试桩（渠道=SMS，命中 `TIMEOUT`/`FAILURE` 关键字返回对应状态，否则伪造 `SUCCESS` + 伪造 `externalMessageId = "p58_ext_"+hash`，不访问网络）。**无生产适配器**。

**是否真实出站 HTTP**：notify 模块主代码 `RestTemplate|WebClient|HttpClient|OkHttp|FeignClient|HttpURLConnection|HttpRequest` **0 命中**；无 URL 构造、无签名/HMAC、无 access_token 缓存。（对照：`sw-biz-system` 下 SSO Provider 客户端有真实 HTTP，属 I5 已交付能力，**不是通知渠道**。）

**配置**：`sw-bootstrap/src/main/resources/application*.yml` 中通知相关键**只有** `sw.notify.enabled`（`application.yml:151-152`，默认 `true`）；sms/mail/feishu/dingtalk/wechat/smtp/webhook/app-secret/token/sign/endpoint **全部零命中**；无 `@ConfigurationProperties` 类。

**fail-fast**：**无**。无 `@PostConstruct`/`InitializingBean`/`@Validated` 配置断言；`NotifyAutoConfiguration.java:13-16` 仅 `@ConditionalOnProperty(sw.notify.enabled=true)` + MapperScan。渠道启用但配置缺失/非法时**不阻断启动**，运行期静默落 `FAILED`。→ 与方向「Provider 生产密钥无默认值且启用时 fail-fast」要求不符，属 I6 必补项。

**硬编码风险（notify 范围内）**：
- 固定租户：`db/migration/notify/{h2,postgresql}/V9__init_notify_message.sql` 与 `V57__v002_oa_notify_send_attempt.sql` 的 `tenant_id bigint not null default 0`。
- 默认成功语义：`V48__p58_notify_channels.sql:1-2` `channel default 'IN_APP'`、`delivery_status default 'SUCCESS'`。
- 伪造外部 ID：`P58DebugNotifyChannelAdapter.java:39`。
- **无**硬编码密钥、默认凭据、固定 URL、测试收件人、固定模板 ID、真实手机号/邮箱（收件人解析为 null 空实现，见 §5）。
- 相关但非 notify 新引入：`application.yml:42` 数据源有默认明文口令占位、`:216` JWT 有明文默认占位且 prod 未覆盖（即 I5 R1 / 已知问题 N6；值不回传）。**I6 新增渠道密钥不得沿用此模式。**

## 3. 站内信收件箱能力与行为证据（Q3）

**持久化（A）**：实体 `NotifyMessage.java:18-60`（`@TableName("sw_notify_message")`）；DDL `notify/{h2,postgresql}/V9__init_notify_message.sql` + `V48` 增列（`channel`/`delivery_status`/`external_message_id`/`failure_reason`/`idempotency_key`）。**每接收人一行**：`NotifyMessageServiceImpl.java:126-136` + `saveBatch :159-161`。

**未读/已读（A，部分）**：`is_read` 位于每接收人行（`:42-43`）；单条标记已读 `NotifyController.java:95-118`；已读过滤 `NotifyMessageServiceImpl.java:62-76`。**缺失**：无「全部已读」端点、无未读数端点（全仓 grep 无命中）。

**分页（B/缺失）**：`GET /notify/messages` 返回 `R<List<NotifyMessage>>`，**无分页参数**（`NotifyController.java:68-82`）；过滤仅 `read` + `keyword`（无 `bizType`、无时间窗）。前端 `pageSize=9999` 并隐藏分页控件（`NotifyHome.vue:28-29,269-271`），未绑定分页事件。对照：`/notify/records` 有真分页（`NotifyRecordController.java:38-47`）。

**权限（A）**：收件箱端点**无 `@PreAuthorize`**，仅需登录；越权由「消息 `recipient_id` 必须等于当前用户」+ 租户 SQL 隔离拒绝（`NotifyController.java:35-42,107-111,144-148`）。`notify:view` 仅为菜单权限（种子 `V38__notify_template_and_menu.sql:55`），**服务端不校验**。可确认的「调用方可传任意 userId」面只有：`/notify/records` 的 `recipientId` 过滤（需 `notify:record:view`）与 `/notify/messages/batch-send`（需 `notify:batch:send`）。

**租户隔离（A）**：`NotifyMessage extends BaseEntity` → `tenant_id`；`CommonTenantLineHandler.java:24-37` 注入并 fail closed；ignore 列表仅 `sys_menu`（`application.yml:155-157`），notify 表全部受隔离。写入侧 `NotifyFacadeImpl.persistDelivery :135-136` 显式 `setTenantId(request.getTenantId())`（引擎线程无 `LoginUserHolder`），见 §8 R-C。

**深链保护（D）**：实体/请求/DDL **均无 link/url/route 字段**（仅 `biz_id varchar(64)`，`V9:28`）；前端契约有 `bizId` 但 `NotifyHome.vue` **从不读取**，无点击跳转、无目标权限重校验。→ 既不存在受保护深链，也不存在未校验跳转漏洞；方向 §3.9「通知链接不能成为绕过对象权限的深链」当前**无载体可验**。

## 5. 流程事件 → 统一发送入口的实际链路（Q5）

**触发器覆盖（A）**：`BpmNotifyTrigger.java:16-54` 共 12 个常量，**全部同时有生产者与消费者**（无纯枚举死值）。

| 事件 | 生产者 | 消费者 |
|---|---|---|
| `TODO_CREATED` | `ProcessStartService.java:289-294` | `BpmNotifyListener.java:60` |
| `PROCESS_APPROVED/REJECTED/DISAPPROVED/RETURNED` | `TaskActionService.java:178,281-283`；会签负向结算 `ApprovalLifecycleServiceImpl.java:757` | listener `:65-79` |
| `TASK_TRANSFERRED/DELEGATED/COMMUNICATED` | `ApprovalLifecycleServiceImpl.java:167,183,216` | listener `:80-94` |
| `PROCESS_WITHDRAWN/DISCARDED` | `ApprovalLifecycleServiceImpl.java:296,320` | listener `:95-109` |
| `TASK_SIGN_REQUESTED`（加签） | `ApprovalLifecycleServiceImpl.java:261` | listener `:110` |
| `TASK_DEADLINE_ALERT`（时限催办） | `TaskDeadlineScheduler.java:225` | listener `:115` |

**缺失的事件语义**：节点终态无独立事件；会签无逐票通知（仅负向终态触发 `PROCESS_REJECTED`）。**抄送**不走事件，走引擎节点 `CopyNodeDelegate.java:48-53`（`IN_APP` + 幂等键 + `recordCopy` 审计）；**催办**走直连门面 `BpmUrgeServiceImpl.java:159-164`（旧入口，渠道固定 IN_APP），另有 10 分钟冷却唯一索引 `uk_sw_bpm_urge_cooldown`（`V56:45`）。

**传输与事务解耦（A）**：`DomainEventPublisher.java:34-36`（进程内 Spring 事件）→ 消费者 `@Async` + `@TransactionalEventListener(phase = AFTER_COMMIT)`（`BpmNotifyListener.java:46-47`）。审批事务已提交，**通知异常不回滚已提交的审批**；`ApprovalLifecycleServiceImpl.java:967-979`、`TaskDeadlineScheduler.java:212-231` 另有 try/catch 显式吞掉并记日志。**无 outbox/队列表**。

**重要例外（可能导致回滚，A）**：引擎侧抄送/通知节点在引擎事务内**同步**投递，`NodeDelegateSupport.java:89-91` `shouldBlock = !"CONTINUE".equals(failureStrategy)`，`NotificationNodeTranslator.java:49-50` 默认 `"BLOCK"`；投递失败即抛 `NODE_DELIVERY_FAILED`（`CopyNodeDelegate.java:57-68`、`NotificationNodeDelegate.java:52-56`）→ **回滚该节点步骤**。生产环境若流程定义配置了外部渠道节点，将必然失败并阻断办理。需 Planner 裁决策略语义。

`@Async` 生效性（B）：`@EnableAsync` 仅在 `FormAutoConfiguration.java:20`（`sw.form.enabled=true`），无自定义 executor。全 profile 均为 true，故实际生效；若 form 关闭则退化为同步（仍 AFTER_COMMIT）。

**重复投递（A/D）**：事件链走旧入口 `send(SendNotifyCommand)` → `NotifyFacadeImpl.java:60-72` 仅映射落库，**无幂等键、无 dedup、无唯一约束**；`uk_sw_notify_msg_idempotency` 因 `idempotency_key` 为 NULL 不生效，且全仓无 `(tenant_id,biz_type,biz_id,recipient_id)` 唯一键（`V13` h2:83 明确「sw_notify_message — 无唯一约束」）。→ 重复发布/重试会产生重复站内信。引擎节点路径**有**去重（`processInstanceId:activityId:recipient` + 唯一索引）；批量渠道路径按 `"batch:"+UUID+":"+recipient` 生成键，**跨请求不去重**（`NotifyController.java:190`）。

**收件人来源（A）**：主链服务端派生（引擎在办人/候选人、发起人、参与人配置）。转办/委托/沟通/加签由调用方传 `userId`，经 `requireActiveUser` 同租户校验（`ApprovalLifecycleServiceImpl.java:891-901`）。**无任意手机号/邮箱地址注入面**（`NotifySendRequest`/`SendNotifyCommand` 只承载 `recipientId`）；但审批人可向同租户任意用户推送（站内信范围内）。

**收件人解析（D）**：`NotifyTargetResolverImpl.java:16-25` 的 `resolveEmail/resolvePhone` 直接 `return null`（`// TODO`，自述骨架占位），且**无任何生产调用方**（grep 仅命中接口与实现）。→ 外部渠道所需的手机号/邮箱/openid 解析链路**未接线**。

## 6. 数据模型、迁移与 H2/PostgreSQL 兼容（Q6）

**表（3 张，A）**
- `sw_notify_message`（收件箱 + 发送记录）：`V9`（h2:17-35 / pg:15-41）+ `V48` 增列。关键列：`recipient_id`、`title(200)`、`content TEXT`、`biz_type(30)`、`biz_id(64)`、`is_read`、`channel(40)`、`delivery_status(20)`、`external_message_id(200)`、`failure_reason(500)`、`idempotency_key(200)` + 租户/审计/deleted/version。索引 `(tenant_id,recipient_id)`、`(tenant_id,delivery_status)`；唯一 `(tenant_id,idempotency_key)`。
- `sw_notify_template`：`sw-bootstrap/.../V38__notify_template_and_menu.sql`（h2:9-27 / pg:23-48）。`template_code`、`name`、`title_template(200)`、`content_template TEXT`、`enabled smallint`、`remark`；唯一 `(tenant_id,template_code,deleted)`。注意 `create_by/update_by` 为 `varchar(64)`，与 message/attempt 的 `bigint` 不一致（B）。
- `sw_notify_send_attempt`：`V57`（h2/pg 各一份）。`message_id`、`attempt_no`、`channel`、`status`、`failure_reason`、`external_message_id`；仅 `idx(message_id)`，无状态索引。

**模板版本（D）**：实体/DTO/DDL **无版本号、无渠道/类型字段**（`NotifyTemplate.java:25-50`；`sw_notify_template` 的 `version` 是 MyBatis-Plus 乐观锁基列，非内容版本）。`updateTemplate` 为**原地覆盖**（`NotifyTemplateServiceImpl.java:76-87`，禁止改 `template_code`），无历史表、无追加版本。→ 方向 §3.9「模板支持按事件与渠道配置…」与 §5-9「模板版本可追踪」当前**无载体**。

**白名单变量（D）**：无白名单存储。`TemplateRenderService.java:32-35` 只校验占位符**语法**（`[A-Za-z_][A-Za-z0-9_]*`），值域由调用方 `Map<String,String>` 决定；缺失变量在渲染时抛 `TemplateRenderException`（`:58-70`）。替换为纯字面 `appendReplacement + Matcher.quoteReplacement`（`:61-64`），**无 SpEL/OGNL/模板引擎依赖**（pom 无模板引擎），表达式注入风险低。**但无任何 HTML 转义**（`escapeHtml|HtmlUtils|StringEscape` 零命中）→ 未来卡片/邮件按 HTML 渲染时是 XSS 敞口（当前无渲染器，未触发）。

**接收人规则/订阅边界/渠道规则（D）**：无实体、无表、无服务。仅存在 `NotifyBizType`（WF_TODO/WF_APPROVED/WF_REJECTED/WF_RETURNED/SYSTEM）与 `NotifyChannel` 两个枚举；收件人解析是**每次请求即时 SQL**（`NotifyMessageServiceImpl.java:163-177` + `NotifyMessageMapper.java:41-119`，批量上限 500 `:33`），不落规则。

**记录字段（A）**：`失败原因`=`failure_reason(500)`；`外部标识`=`external_message_id(200)`（message 与 attempt 均有）；`尝试次数`**无计数列**，由 `max(attempt_no)+1` 派生（`NotifyRecordServiceImpl.java:188-191`）；`状态`为字符串字面量：`SUCCESS/FAILED/TIMEOUT/PENDING` + 重发中间态 `RESENDING` 与在途 `DELIVERING`（`NotifyRecordServiceImpl.java:37-40`），**无状态枚举类**。重试扫描索引存在：`idx_sw_notify_msg_delivery (tenant_id,delivery_status)`。

**重发语义（A）**：仅从 `FAILED` 可重发，条件更新转 `RESENDING`（`:126-134`）→ 真调 `attemptDelivery` → 真调适配器（`NotifyFacadeImpl.java:143-172`）→ 回写终态。测试证明真重投与异常终态化（`NotifyRecordServiceTest`）。**但对五个外部渠道因无生产适配器，重发稳定返回 FAILED，不会向厂商发出任何请求。**

**迁移体系（A）**：Flyway `locations` 共 10 条 `db/migration/{vendor}/...`（`application.yml:61-79`），`baseline-on-migrate: true`、`validate-on-migrate: true`、`out-of-order: false`；另有生产专用 `prod-update/{vendor}` 链与独立历史表 `flyway_schema_history_prod`（`FlywayConfiguration.java:35-57`，目录暂空）。dev 专用夹具 `devseed/{vendor}` 仅在 `application-dev.yml:73` 装载（`V900—V903`，生产不含）。全局单序列：H2 终点 `V88`、PG 终点 `V87`（`V88__i5_drop_form_key_global_unique.sql` 为 H2-only，PG 由 V13 等价完成）；notify 占用 `V9/V48/V57`，**I6 新迁移应取 V89 起（避开 devseed 的 V900+）**。

**已知迁移不对称（A，I6 须避让）**：`V63__p21_iot_device_action.sql` 在 `bpm` 与 `bootstrap` 两处 h2/pg 共 4 份同名同内容（真实重复，当前被 Flyway 容忍，`FlywayFullChainH2Test` 断言 88 执行）；`V41`（form JSON→CLOB）H2-only；`V88` H2-only。

## 8. 跨租户 fail-closed 与敏感暴露（Q8）

**跨租户（整体 A，fail closed）**：`sw_notify_message`/`sw_notify_template`/`sw_notify_send_attempt` 均含 `tenant_id` 且未被加入 ignore 列表，查询自动注入租户条件并 fail closed。收件箱另有 `recipient_id = 当前用户` 校验；记录/重发受 `notify:record:*` 权限约束。**深链维度无法判定**（无深链载体）。

需 D/裁决的缺口：
- **R-C（推断，未运行验证）**：`NotifyFacadeImpl.persistDelivery :135-136` 显式 `setTenantId(request.getTenantId())`，落库租户取自调用方请求值而非登录上下文（引擎线程确无 `LoginUserHolder`）。读侧仍受拦截器约束，但写入租户权威来源需 I6 明确并加负向验证。
- **R-F（A）**：`/notify/records` 允许传任意 `recipientId` 并返回**完整 `NotifyMessage`（含 content）**（`NotifyRecordController.java:19-26,38-47`；`NotifyRecordServiceImpl.pageRecords :57-71`）。租户内「有权管理者可见」是注释声明的设计口径，但属敏感面，需与方向「接收人只看到其有权访问的业务摘要」对齐。
- **R-E（A）**：MyBatis `log-impl: StdOutImpl`（`application.yml:227`）**全量打印 SQL 与参数**且无脱敏过滤器 → 通知正文、收件人 ID、未来外部消息标识可能进入普通日志。
- 正文当前按原样返回与展示，无统一脱敏注解（与 I5 现状一致）。
