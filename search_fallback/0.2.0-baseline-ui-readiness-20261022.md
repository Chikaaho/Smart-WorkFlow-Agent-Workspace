## 结论

1. **0.1.10 已发布，工作区未同步**。远端 main/develop 同点（Server `85e1ab784`、Web `2df670b50`），tag `0.1.10` 指向 `8a2aa56`/`e03a886`；本地两仓停在 0.1.9；knowledge、根 `version.json`、`CHANGELOG.md` 仍 0.1.9；Release 引用的 `product/0.1.10-bugfix/receipts/` 不存在。UAT 部署仅见 Release 正文。
2. **五项目标都有基础，缺口多为“服务端已有、前端无入口”**。P2 子表/关联、公式、受控数据源、三层权限、列表配置、删除/停启、版本快照已实现；权限/列表/数据源无配置 UI；TEXT length 未校验，新稿另有最小长度/正则/提示，属新契约。P4 六类动作与实例干预已有页面；版本挂起/激活、代理规则、废弃只有接口；审批暂存已有接口无按钮。
3. **P29 确需新增，且有菜单冲突**。后端无租户 CRUD、前端无页面；用户/部门含 `tenantId` 但不展示、不筛选；新建对象落登录租户，超管会写入租户 0。种子已有“租户管理”菜单（id 16，`system:tenant:list`），组件与接口缺失，路由被跳过。启停已在登录/刷新/会话/SSO/OpenAPI 生效；流程与定时任务未校验。新稿把管理员账号/初始密码放进新增租户，超管只读，用户/部门增加租户列与筛选；新建用户/部门弹窗没有租户字段。
4. **P65 只有字段级能力**。`onLoad` 与值变更脚本是字段级；无提交前/后事件，无主表、明细行、控件、流程上下文 API。脚本面板与函数目录已共用；流程脚本走服务端 GraalJS，表单脚本走浏览器解释器。新稿的事件监听只覆盖流程发起/结束，现有触发器已能配这两类事件，但模型是“判断脚本+结果分支”，没有启用状态。
5. **UI 与文案只完成一部分**。P53 与 0.1.10 统一了大量组件；全量文案审计未交付，操作手册不存在，`HintTip` 仅 3 个文件。来源分散在前端 locale、后端消息、DB 种子。
6. **Figma 已实读**。文件 `mbEKPcZv9pcchmElQanR5E`，核心页 258 个顶层画框、规范页 25 个组件族；读取 31 个节点，覆盖租户、超管用户/部门、子表/校验、流程动作、事件监听与脚本面板、设计器、数据详情，并导出 5 张临时截图核对。结构对应与设计差异见附件第 7 节。
