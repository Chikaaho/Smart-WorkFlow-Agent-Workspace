## 0. 结论摘要

1. **Owner 指出的「流程发起租户写死 `0L`」部分成立，但定位需修正。** 流程**发起命令链本身没有写死 `0L`**：`FormSubmitService` 从 `LoginUserHolder` 取真实租户 → `FormSubmittedEvent.tenantId` → `CommandEnvelope.tenantId` → `StartCommand.tenantId` → `startProcessInstanceByKeyAndTenantId(key, …, tenantId)`，且 `tenantId == null` 时显式抛错（`ProcessStartService.java:150-152`）。真正写死 `0L` 的是**流程发起入口对象的归属租户**：
   - **表单定义/配置/快照/列表配置**：`FormDefServiceImpl` 7 处 `setTenantId(0L)`，且因 MyBatis-Plus `strictInsertFill` 仅在字段为 null 时填充，该显式值必然压过真实租户自动填充；
   - **启动期骨架流程部署与表单绑定**：`BpmDeployRunner` 以 `SUPER_TENANT_ID="0"` 身份部署 BPMN 并插入 `sw_bpm_form_binding`。
2. **现状不产生真实跨租户事件，但构成 I5 与多租户流程发起的硬前置。** 非零租户用户无受支持登录入口（既有登记的产品边界，`knowledge/known-issues.md:14/16/20`），且不存在租户开通服务（全仓无 `SysTenant` 实体/Service/Controller，`sys_tenant.status/expire_time` 零消费方）。当前唯一可运行身份是 tenant 0，故 `0L` 与真实上下文恰好相同，缺陷被掩盖。
3. **一旦装载非零租户身份（I5 SSO，或 `tenant_id≠0` 的 OpenAPI 应用 / IoT 设备），流程发起会在三个独立环节失败**：表单定义解析（`FORM_NOT_FOUND`）→ 表单绑定查询（静默 no-op）→ Flowable 定义租户不匹配。**此为结构证据＋静态推断，未取得运行证据**（运行非零租户身份所需条件当前不具备，见 §9）。
4. **另有 6 类与流程租户无关的生产硬编码/默认值**（prod 固定验证码、JWT/Druid/MinIO 默认凭据、`/actuator/**` permit-all、前端 `v-perm` fail-open 等）。不得并入本轮流程租户修复，按 §5 矩阵分别归属。
5. **Web 生产路径未发现固定租户、固定账号/角色/权限码、固定业务对象 ID 或密钥默认值**；前端身份与租户全部来自后端 `/system/auth/me`。唯一真实前端风险是 `isSessionPlaceholder()` 的 `v-perm` fail-open（仅 UX 显隐，服务端仍拦截）。
