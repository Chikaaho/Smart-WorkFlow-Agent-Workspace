# 模型注册表

> 工作区统一知识库 — 模型注册分册。
> 记录规划层所有可用模型的完整信息。
>
> **用途**：
> 1. 说明模型能力和成本等级。
> 2. 说明模型适用的逻辑角色。
> 3. 说明各模型族的权限边界和上下文策略。
> 4. 为 Sub Agent 调度提供选择依据（v4-pro vs v4-flash）。
> 5. 为未来启动配置提供参考。
>
> **不负责**：切换当前主会话模型。当前主模型由用户启动 Claude Code 时的配置决定。注册表中的「推荐角色」是能力适配性描述，不是运行时切换指令。
>
> **关键定位**：DeepSeek（v4-pro）是默认完整工作引擎，可独立完成从需求到归档的完整生命周期。Anthropic 高能力模型（opus-4.8、sonnet-5）是用户手动引入的高能力规划增强与纠偏补丁，不是默认生命周期必经节点。
>
> 维护者：上下文 Agent（通过委派 DeepSeek 写入 knowledge/）
> 读取者：Anthropic（参考）、DeepSeek（维护）
> 最后验证时间：2026-07-30

## 1. 字段说明

| 字段 | 说明 |
|------|------|
| **OpenRouter Model ID** | 完整模型 ID，作为唯一标识 |
| **提供商** | 模型提供商 |
| **当前状态** | `启用` / `候选` / `禁用` / `待验证` |
| **推荐角色** | 入口 / 规划 / 上下文 / 探索 / 编码 / 验证 |
| **核心能力** | 模型最适合的任务类型 |
| **能力等级** | 对当前 Agent 架构的能力评价（A=最强 / B=强 / C=中等 / D=基础） |
| **输入成本等级** | 相对成本等级（$$$$=最高 / $$$=高 / $$=中 / $=低） |
| **输出成本等级** | 相对成本等级（同上） |
| **上下文能力** | 可处理上下文规模（如 200K / 128K / 32K tokens） |
| **工具兼容性** | 是否兼容当前 Claude Code 工具调用 |
| **协议兼容性** | `anthropic-messages` / `responses` / 其他 |
| **当前折扣** | 是否存在临时折扣（无 / 有：具体折扣说明） |
| **适用场景** | 推荐使用场景 |
| **禁止场景** | 不应使用的场景 |
| **上下文策略** | `完整上下文` 或 `最小上下文` |
| **升级模型** | 当前模型不足时使用哪个模型 |
| **降级模型** | 成本优化或故障时使用哪个模型 |
| **最后验证时间** | 最近一次验证日期 |

## 4. 模型升级/降级关系图

```
能力递增 →

  anthropic/claude-opus-4.8  ←── 升级（高复杂度决策）
           ↑                       
  anthropic/claude-sonnet-5  ←── 日常默认（入口/规划/上下文）
           ↓                       
  （候选）anthropic/claude-haiku-4-5  ←── 降级（机械任务，待验证）

  deepseek/deepseek-v4-pro   ←── 升级（复杂探索、信息不足、连续失败）
           ↑                       
  deepseek/deepseek-v4-flash ←── 默认探索/编码
```

**降级触发条件**：
- 默认模型不可用（API 错误、配额耗尽）
- 成本优化（当前任务对能力要求低，且降级模型通过硬性门槛）
- 用户明确指定

## 6. 维护规则

1. **新增模型**：通过 search_task 委派 DeepSeek 验证 OpenRouter Model ID 是否存在、确认工具和协议兼容性，验证通过后从「待验证」移至「启用」或「候选」。
2. **状态变更**：模型不可用时标记为「禁用」并记录原因；恢复后重新验证。
3. **折扣更新**：临时折扣只记录在「当前折扣」字段，不作为模型选择的硬性依据。
4. **最后验证时间**：每次验证（含重新验证）后更新对应模型的该字段。
5. **不编造 ID**：所有新增模型 ID 必须来自 OpenRouter API 实际返回值或官方文档，不凭记忆填写。
