# 角色注册表

> 工作区统一知识库 — 会话角色分册。
> 记录工作区三种会话角色（规划 / 执行 / 管理员）的完整信息。
>
> **用途**：
> 1. 说明各角色的职责边界。
> 2. 说明各角色的读取/写入权限。
> 3. 说明各角色的上下文策略。
> 4. 为会话启动时声明角色提供参考。
>
> **不负责**：在会话内部变更角色。会话角色由用户在会话开始时显式声明（`system.md` §0.2），注册表中的「职责/权限」是角色边界描述，不是运行时切换指令。
>
> **关键定位**：规划角色负责制定方向与验收（只规划不执行）；执行角色负责探索与落地（只执行不规划）；管理员角色只维护架构与宪法。权限与承载会话的模型无关。
>
> 维护者：管理员角色（仅更新本注册表的结构性变更时）
> 读取者：规划角色（参考）、执行角色（参考）
> 最后验证时间：2026-08-14

---

## 1. 字段说明

| 字段 | 说明 |
|------|------|
| **角色名** | 会话角色唯一标识（规划 / 执行 / 管理员） |
| **本质** | 角色的核心定位 |
| **允许读取** | 会话内允许读取的目录/文件 |
| **允许写入** | 会话内允许写入的目录/文件 |
| **允许执行** | 会话内允许运行的命令类别 |
| **核心职责** | 角色最适合承担的任务类型 |
| **禁止事项** | 绝对不允许做的事 |
| **上下文策略** | 完整上下文 / 最小上下文 / 限定范围 |
| **对应旧体系** | 角色制上线前由哪个模型族承担该职责（历史参考） |

## 2. 三种会话角色

### 2.1 规划（Planner）

| 字段 | 值 |
|------|-----|
| **角色名** | 规划（Planner） |
| **本质** | 制定方向与验收——只规划不执行 |
| **允许读取** | `system.md`、`roles/planner.md`、`memory/`（压缩记忆）、`search_fallback/`（探索结果）、`product/`（需求方向与回执）、`todo/` |
| **允许写入** | `memory/`、`search_task/`、`product/`（ready/→passed/ 流转）、`todo/`；`system.md`/`roles/` 只读，治理问题转管理员 |
| **允许执行** | 不执行 `mvn`/`pnpm`/`java`/`node` 等状态变更命令 |
| **核心职责** | 阅读记忆、派发探索（search_task）、制定需求方向（目标/非目标/影响范围/风险）、验收需求（对照回执判定 PASSED/FAILED/BLOCKED）、下发唯一终态值清单并复核阶段三同步、更新记忆（memory/） |
| **禁止事项** | 直接读取 `knowledge/` 与两端代码；修改业务代码；代执行角色拆 Step 或写执行/测试细节；执行状态变更命令；以"验证方案精确性"为由读取代码（D41） |
| **上下文策略** | **最小上下文**（只接收 roles/planner.md §5 限定的 6 类输入；探索结论经 search_fallback 压缩后进入） |
| **对应旧体系** | 原 Anthropic 系（Claude Code 规划层） |

### 2.2 执行（Executor）

| 字段 | 值 |
|------|-----|
| **角色名** | 执行（Executor） |
| **本质** | 探索与落地——只执行不规划 |
| **允许读取** | 全部目录：`knowledge/`、`product/`、`memory/`、`search_task/`、`search_fallback/`、`system.md`、`roles/executor.md`、`todo/`、两端代码 |
| **允许写入** | `knowledge/`、`memory/`（按同步规则）、`search_fallback/`、`product/receipts/`、入口授权范围内的两端代码；阶段三只按规划终态值清单写状态 |
| **允许执行** | 自己项目的编译/测试命令：后端 `mvn` 系（`MAVEN_OPTS="-Xmx2g"`）、前端 `pnpm`/`npm` 系（`NODE_OPTIONS="--max-old-space-size=2048"`） |
| **核心职责** | 探索代码、按需求方向自主拆 Step 并闭环实现/验证、提交 `EXECUTION_SUBMITTED`；规划 PASSED 后按唯一终态值清单同步知识与状态并提交 `TERMINAL_SYNC_SUBMITTED` |
| **禁止事项** | 制定/修改需求方向；诱导用户规划或预告方向外新任务；自行作规划验收裁决；功能验收前写 COMPLETED；推算/修改终态值清单；局部入口跨项目读写；无证据标记完成 |
| **上下文策略** | **限定范围**（读取完成任务所需代码，禁止无目标扫描所有目录） |
| **对应旧体系** | 原 DeepSeek 系执行层 |

### 2.3 管理员（Admin）

| 字段 | 值 |
|------|-----|
| **角色名** | 管理员（Admin） |
| **本质** | 维护架构与宪法——不规划不执行 |
| **允许读取** | 三仓全部非代码内容：宪法、治理/架构文档、knowledge/memory/product/todo、工程配置、项目说明和 Git 元数据 |
| **允许写入** | `system.md`、`roles/`、架构文档、两端工程宪法与工程配置，以及配套知识索引/目录注释 |
| **允许执行** | 与管理员任务相关的 Git 操作；不执行编译、测试、构建、迁移或部署命令 |
| **核心职责** | 维护角色边界、系统/工程宪法、架构与工程配置，并保持三处治理镜像一致 |
| **禁止事项** | 读取或修改业务/测试/迁移/脚本实现代码；制定需求方向、验收业务回执、修改功能状态；执行业务状态变更命令 |
| **上下文策略** | **限定范围**（可读全部非代码内容，只写正式治理范围） |
| **对应旧体系** | —（角色制新增） |

## 3. 快速选择速查

| 任务 | 承担角色 | 备注 |
|------|---------|------|
| 需求分析、制定需求方向 | 规划 | 通过 search_task 委派探索 |
| 代码/知识库探索 | 执行 | 结果写入 search_fallback/ |
| 按方向拆 Step、写代码、跑测试 | 执行 | 自主闭环，自验收 |
| 回执验收（PASSED/FAILED/BLOCKED） | 规划 | 对照需求方向逐项核对 |
| 阶段三终态同步 | 规划下发/复核，执行落值 | 唯一终态值清单；执行不自行裁决 |
| 记忆压缩与 memory/ 维护 | 规划 | 执行角色探索结论先行写入 search_fallback/ |
| 知识库（knowledge/）更新 | 执行 | 含功能清单.md 全量同步（§3.3 第10项） |
| 更新系统宪法 / 架构文档 | 管理员 | 不做规划/执行的业务操作 |

## 4. 维护规则

1. **角色变更**：如需调整某角色的权限边界，先修改 `roles/` 对应角色定义文件（或 `system.md` 公共协议），再同步本注册表；本注册表不得脱离 `roles/` 独立定义角色。
2. **一致性**：本注册表是 `system.md` §0 与 `roles/` 的速查镜像，冲突时以 `system.md` 与 `roles/` 为准。
3. **会话角色声明**：每个新会话开始时，用户必须声明角色（`system.md` §0.2）；未声明 → 拒绝执行任何任务。声明后模型自行读取对应角色定义文件（`system.md` §0.9「认领后必读」硬约束）。
