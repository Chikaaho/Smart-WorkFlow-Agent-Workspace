## 1. 功能概述

打通 README 示例二「校园出入口流量异常」与示例三「MES 温度智能判断」的端到端链路，并把示例中缺失的能力做成通用配置：

- **IoT 规则 → Agent 图执行桥接**：事件规则可声明 `agentEnabled/agentGraphKey/agentInputMappingJson`；触发记录以 `AGENT` 动作落库，提交已发布图执行并回写 `agentExecutionId`；执行输入支持 `RECENT_SERIES`（设备属性时间窗序列）。
- **研判失败即升级**：执行 FAILED 时按 `agent_failure_config_json`（升级模板、`formDataExtra` 级别字段、负责人 `IN_APP`/`EMAIL` 双渠道通知）在同一事务生成 FLOW 升级触发；`CANCELLED/INTERRUPTED` 不自动升级。
- **Agent 内部工具**：`发起工单流程`、`查询近期流程记录`、`发送通知告警` 三个白名单工具（beanName/methodName，单字符串入参）。
- **渠道凭据密文配置**：`sw_notify_channel_config.config_cipher`（AES-256-GCM，与模型 Key 同口径），Email 适配器优先使用租户密文凭据、缺省回落 yml/env；接口只写不回显。
- **IoT 规则页编辑**：新增编辑动作；研判参数以键值维护并合并为 `fixed` 映射条目，阈值/窗口/斜率改后下一次触发即生效；失败升级配置 JSON 页面维护。
- **真实链路**：OpenRouter 联网搜索（低价 `:online` 模型）、真实 LLM 研判、真实 163 SMTP 邮件均已实测。

## 4. 失败升级与幂等

- 同一次执行（executionId）的升级触发与各渠道通知均使用稳定幂等键：`iot-esc-<executionId>`、`iot-fail-<executionId>-<channel>`；单次失败只产生一次升级和每条渠道一次投递。
- 修复：恢复调度不再把 AGENT 的 FAILED 终态按流程模板重投；PENDING 重投保留 `actionType/agentGraphKey/agentInput`。
- 修复：通知工具接受数字字符串形式的接收人 ID（页面 `fixed` 参数与模型工具参数常以字符串传 64 位 ID）。
- 修复：外部工具 GET 把入参 URL 编码进查询串（JDK 客户端忽略 GET body，曾导致搜索工具空查询）。
