# 0.1.0 回滚 / 恢复说明

## 原则

- 回滚不重写数据库历史；I6 迁移（V89/V90/V91/V92）只追加列/表或做兼容性类型转换，旧版本代码在 0.1.0 库上可运行（增量列不干扰既有字段读写）。
- 禁止删除 `flyway_schema_history` 行来“还原”迁移记录。

## 应用回滚

1. 停止 0.1.0 应用进程。
2. 部署上一受支持基线（0.0.2 → Server `20fffc1d…` / Web `0bf6e892…`；或 P60 对应阶段基线）。
3. 启动并确认健康；旧代码读到 I6 新增列时按其原始 schema 视图（Flyway validate 不会因我新增列失败：0.1.0 库包含旧基线全部对象与数据）。
   - 若旧基线 Flyway `validate` 因 schema 漂移（我方新增列）报错：将 `spring.flyway.validate-on-migrate=false` 仅作为回滚窗口内的应急开关，恢复升级后立即改回。

## 数据库恢复（破坏性故障）

1. 从备份恢复数据库到升级前时点（备份策略见 `docs/ops/production-ops.md` §9）。
2. 上基线应用后重启；Flyway 将看待库为既有状态，不重放已执行迁移。
3. 升级窗口内产生的通知/审批增量不做合并补发；如需业务回放，走业务侧导出的riage 凭证由 Owner 裁决。

## 渠道回滚

- 任一外部渠道异常：在「渠道配置」页停用租户级渠道即可（站内信保底不受影响）；无需回滚整个版本。
- 渠道凭据泄漏：立即轮换 Provider 侧凭据并同步轮换秘密注入，不动数据库。

## 验证回滚成功

- 登录管理员进入收件箱，列表/已读/未读数可用。
- 发起/办理一个简单流程确认核心链路完好。
