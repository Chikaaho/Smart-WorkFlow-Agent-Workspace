# 0.1.0 升级步骤（从受支持旧基线升级）

> 覆盖 0.0.2 基线（Flyway V58 以内，v0.0.2-oa）与 P60 各阶段基线（V82—V88）→ 0.1.0（V93）。
> 不支持跨过 0.0.2 之前的更旧版本直接升级。

## 1. 前置条件

- 数据库：PostgreSQL（生产）或 H2（单机/开发），Flyway `baseline-on-migrate=true`、`validate-on-migrate=true`、`out-of-order=false`。
- 备份：升级前执行完整数据库备份（见 `docs/ops/production-ops.md` §9）。
- 秘密注入：`JWT_SECRET`、`SW_SSO_CIPHER_KEY`、`SW_CIPHER_KEY`、SMTP/Provider 渠道凭据等仅经环境变量/秘密管理注入，不落配置文件；0.1.0 起生产缺 `JWT_SECRET`（或为占位值）或缺 `SW_SSO_CIPHER_KEY` 将启动期 fail-fast。

## 2. 升级步骤

1. **停机边界**：停应用进程；数据库保持在线（迁移在启动期执行）。
2. **发布 Server**：部署 0.1.0 jar；启动时 Flyway 自动补齐 V89（通知域数据模型）、V90（通知菜单/权限种子）、V91（通知 Provider 主体绑定）、V92/V93（布尔标志收口）；迁移终点断言 V93。
3. **发布 Web**：部署 0.1.0 前端静态资源；无独立数据库动作。
4. **验证最小集**：
   - 登录任意租户管理员，确认「通知 / 收件箱 / 通知规则 / 渠道配置 / 订阅偏好」页面可达；
   - 发起一次含审批的流程，确认收件箱收到待办通知、未读数减少；
   - 单击通知深链跳转正常且无权用户访问被拒绝（401/403）。
5. **渠道启用（可选）**：为已装配并配置完整的渠道（邮件 等）在「渠道配置」页启用租户级渠道；未配置渠道保持禁用。

## 3. 兼容边界

- 既有 `sw_notify_*` 数据全部保留；迁移只追加列/表，不重写历史消息、模板、流程实例与版本。
- 旧模板仍在「模板管理」可见并有初始版本快照；编辑后才追加新版本。
- 生产运行中实例：滚动升级窗口内允许在线（AFTER_COMMIT 事件链不依赖新表存在，旧事件在旧代码下行为不变）。

## 4. 升级失败处理

- Flyway 校验失败：不要改历史迁移；修复环境后重试。
- V89/V90/V91/V92/V93 执行中失败回滚：Flyway 事务内自动回滚该迁移；排查后重启继续。
- 详细回滚见 `ROLLBACK.md`。
