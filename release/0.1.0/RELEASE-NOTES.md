# 0.1.0 发布说明（面向用户）

**CH-aPaaS 0.1.0 正式发布版**（P60 路线 `v0.1.0-oa-completion`，当前迭代 0.0.3；2026-09-14 登记候选，2026-09-15 发布）。

## 这一版带来什么

**统一通知**：过去的 OA 通知只有站内信可用；本版完成六类渠道同一权威——站内信收件箱、短信、飞书卡片、钉钉通知、企业微信卡片与邮件。所有流程事件（待办、转办、委托、沟通、加签、退回/驳回/通过、抄送、催办、时限提醒）都经同一通知引擎派发；管理员可为每类事件配置接收人与渠道顺序，用户可为自己选择可选订阅。

**可靠投递**：每一次通知都有唯一的业务身份，并发、重复触发、服务重启都不重复打扰；发送失败自动按退避重试并记录每一次尝试；通知结果绝不回滚已经提交的审批动作。

**更好用的收件箱**：收件箱支持真分页、未读小红点计数、一键全部已读、稳定排序；PC 与手机浏览器（移动 H5 `/m/notify`）看到同一份收件箱与已读状态；需要处理的事务点「查看详情」直达，权限不足时服务端会再次拒绝。短信、邮件等产品配置须管理员在「渠道配置」里完成并启用。

**模板与订阅**：模板按事件与渠道版本化发布，历史通知始终按发出当刻的模板版本展示；变量按白名单校验，内容按目标渠道转义渲染，收件箱内容不支持任意脚本或外链。管理端新增「通知规则」「渠道配置」「订阅偏好」页面；发送记录默认脱敏展示，完整详情需要独立权限并留审计。

**0.1.0 发布材料**：机器可读版本权威 `version.json`；CHANGELOG（`CHANGELOG.md`）；升级 / 回滚 / 配置变化 / 迁移清单（本目录各文档）。

## 使用须知

- 未配置生产凭据的渠道在「渠道配置」中显示「未装配」，且不能被启用；这是有意的 fail-fast 设计。
- "必须送达"的待办与安全/状态通知至少保留站内信，普通用户不能关闭。
- 所有 Provider 凭据只存放于环境变量/秘密管理，不进配置文件与日志。
- 短信、飞书、钉钉、企业微信、邮件五类外部渠道与三方 SSO 的真实凭据链验证为 Owner 延期 / 未验证，尚未取得真实 Provider 上的成功/失败/恢复行为证据。
