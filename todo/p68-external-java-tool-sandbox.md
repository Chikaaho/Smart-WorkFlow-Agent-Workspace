# P68 · 外部开发的 Java 工具：模板、上传审核、Agent 动态编译与沙箱运行

日期：2026-11-10｜来源：Owner 补充需求｜状态：未排期｜预估等级：XL（运行外部代码，涉及安全边界）

## Owner 原话

> graph 等工具需要做成可在外部单独开发的 java class，开发下载模板编写完成后上传、审核、保存，类似 mcp 作为入口给 agent 使用，agent 动态编译，运行时用沙箱（可选，或者进主 jvm）运行执行工具，执行结束后销毁沙箱/进程，保留快照和日志 7 天

## 需求理解

1. **开发**：平台提供工具模板下载（Java 工程骨架、接口定义、入参/出参声明方式、本地调试说明），开发者在平台外独立编写。
2. **上架**：上传源码 → 审核 → 保存。审核通过前不能被 Agent 使用；保留版本。
3. **入口**：工具以类似 MCP 的方式登记（名称、说明、入参/出参结构），Agent 能发现并调用，与现有智能体工具配置统一。
4. **运行**：Agent 调用时动态编译；运行方式可选：
   - 沙箱：独立进程/隔离环境，执行结束后销毁；
   - 主 JVM：直接在服务进程内运行。
5. **留存**：每次运行的快照和日志保留 7 天，到期自动清理。

## 评估时需要定的事项

1. 「主 JVM」模式的准入：哪些工具允许进主 JVM、谁来批准；进主 JVM 后无法真正隔离，审核要更严格。
2. 沙箱的隔离边界：CPU/内存/时长上限，网络与文件访问策略，能调用哪些平台接口；可参考 IoT 受控脚本的子进程执行器（P21，`todo/iot-subprocess-output-race.md`）。
3. 审核内容：谁审、审什么（依赖白名单、危险 API 扫描、人工审阅），审核记录如何留痕。
4. 编译时机：上传时编译校验 + 运行时按需编译，还是审核通过后缓存编译产物；依赖 jar 如何引入。
5. 「快照」指什么：入参、出参、编译产物、运行环境信息中保留哪些；7 天清理是否可按租户配置。
6. 与 P67 的关系：Graph 本身作为工具被外部化，还是 Graph 调用外部工具，或两者都要。

## 验收方向（排期时细化）

- 下载模板 → 本地写一个工具 → 上传 → 审核通过 → Agent 调用成功，返回出参。
- 未审核或被驳回的工具 Agent 不可见、不可调用。
- 沙箱模式下工具运行结束后进程已退出；越权访问（文件、网络、超时、超内存）被拦截并记录。
- 运行快照和日志 7 天内可查，超过 7 天自动清理。
