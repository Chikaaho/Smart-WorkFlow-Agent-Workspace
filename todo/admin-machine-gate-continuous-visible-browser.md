> 优先级：P0治理插单  
> 状态：COMPLETED（规划确认，2026-09-15）

## 目标

让已授权的本地验收链连续完成，并把正式流程的浏览器证据限定为用户可见、可交互且可复核的会话。

## 机器门禁行为

1. 当动作已属于当前授权工作项，输入值由dev/test配置或既有测试契约确定、不是秘密，且动作不会触发破坏性、远程发布或未授权外部状态变化时，Supervisor/Stop Gate将其判定为可继续动作并要求Executor直接完成。
2. 只有真实凭据、MFA、真实人机验证、破坏性操作、远程发布或授权外动作才允许进入用户确认/输入路径。
3. 正式流程浏览器验收必须声明并校验`headless=false`，保存可回读视觉制品、URL、视口、身份、对象和网络索引。后台浏览器结果不能作为正式流程通过依据。
4. Headless模式可保留给不承担正式流程通过结论的隔离回归或组件测试，但必须明确证据层级，不能升级为正式浏览器证据。

## 影响范围

- `system.md`、`roles/executor.md`中与连续执行、浏览器证据和确认边界有关的规则。
- `.codex/governance/terminal-contract.json`、Validator、Stop Gate、Supervisor回注及对应治理测试。
- 不改变业务代码、产品权限、安全确认或远程发布授权。

## 验收标准

- 已授权的确定性本地测试输入场景从页面操作连续推进，不产生新的用户确认节点。
- 真实秘密/MFA/人机验证与破坏性、远程动作仍会进入既有门禁。
- 正式流程证据声明headless或缺视觉制品时，Validator拒绝通过。
- 可见交互式浏览器并包含完整视觉/对象证据时，Validator接受该证据层级。
- 治理测试覆盖上述正反场景，终态契约、文档和实现保持单一语义。
