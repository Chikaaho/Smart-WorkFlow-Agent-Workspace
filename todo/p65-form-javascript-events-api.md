## 产品目标

在表单设计器中增加“高定 JS / 自定义 JavaScript”能力。设计人员可以给表单配置事件脚本，通过平台提供的统一函数 API 操作主表、明细表的数据与控件属性，获取流程及组织数据，实现初始化、计算、联动、提交前处理和提交后处理。

## 事件与编辑入口

在动作设置中添加动作并选择触发时机，进入 JavaScript 片段编辑器编写和保存脚本。提供三个事件：

| 触发时机 | 处理函数 | 功能意图 |
|---|---|---|
| 页面加载完成 | `onLoad` | 表单页面及所需数据就绪后，初始化数据、回填默认值和调整组件属性 |
| 表单提交前 | `beforeSubmitHandler` | 提交事件中执行数据整理、计算、联动和提交前检查 |
| 表单提交后 | `afterSubmitHandler` | 提交事件后执行后续处理，可读取提交结果及相关上下文 |

开发面板以现有流程中的 JS 面板为基础，表单与流程共用一套 UI（Owner 2026-10-18 补充）。统一编辑器布局、代码编辑、格式化、保存/取消及函数帮助交互；按表单或流程场景加载相应的事件、变量、函数目录和调用上下文。现有面板的具体复用能力由执行方在立项探索时核实。

函数目录参照截图提供分类与搜索，函数帮助展示用途、参数、返回值及调用示例，便于插入调用。截图中的第三方函数名、实现代码和注释仅作为能力参考，实际 API 命名与契约在正式设计时确定。

## 开放 API 能力范围

这里的开放 API 指供表单脚本调用的平台函数接口；对外 HTTP OpenAPI 的发布与授权另有 P22 跟踪。

1. **数据模型、常用变量与通用函数**：查看可用字段/模型标识，获取当前表单、当前用户及页面上下文；提供常用数据转换、日期、计算等辅助能力，具体目录在设计时收敛。
2. **主表数据与控件**：读取/设置单字段及主表数据，处理默认值、清空值、派生值和字段联动；读取/调整控件的显示隐藏、只读/可编辑、必填、选项等受支持属性，并即时反映到页面与表单数据模型。
3. **明细表数据与控件**：读取明细集合、指定行及单元格，新增/删除/更新行，批量赋值、计算和汇总回主表；按表、行和字段定位控件，处理列或单元格的显示、编辑、必填及选项等属性。截图中的子明细表函数作为关联候选，是否支持嵌套层级在立项时结合现有表单能力确定。
4. **流程数据**：读取当前可用的流程定义/实例、当前节点、任务、发起人、办理人、流程变量或状态等上下文，用于表单联动；尚未发起流程的页面须明确哪些信息可用。
5. **组织数据**：查询有权访问的用户、部门、角色、岗位及其关联关系，获取当前用户所属组织等信息，用于回填、筛选选项和业务计算。
6. **其他函数与集成调用**：提供消息提示、确认弹窗等交互辅助函数；通过平台封装的函数入口调用已授权的平台/集成能力，具有明确的参数、返回值、异步结果和错误反馈。具体开放清单待设计，不把任意接口访问默认纳入范围。

## 使用效果举例

- 页面加载后，读取当前用户及所属部门，回填申请人和申请部门，按业务条件设置字段只读或显隐。
- 提交前，遍历明细行计算金额，将合计写回主表，并检查业务条件。
- 根据当前流程节点和办理上下文，调整主表或明细表控件属性。
- 提交后，读取本次提交结果并执行配置的提示或后续联动。

## 正式设计需明确的行为边界

以下为原始需求关注点；正式行为已由 0.2.0 决策记录 DR05—DR07 确定，实施以该记录为准：

- 页面加载完成与数据加载、明细渲染的先后关系，重复进入或重新加载时的触发次数。
- 提交前脚本与表单校验的顺序，是否可阻止提交，如何返回校验信息，以及异步函数的等待与超时语义。
- 提交后事件是在提交成功时执行还是在请求结束时执行，失败时如何获取结果；保存草稿与审批动作是否触发这两个提交事件。
- 同一事件多个动作的执行顺序、错误处理；提交后修改数据的持久化语义；重复点击与重试的副作用控制。
- 脚本随表单版本保存、发布和回滚的规则，以及已有实例采用的脚本版本。
- 函数目录覆盖范围、参数/返回值、错误码及兼容规则；子明细表支持范围。

## 权限及可靠性边界

脚本与平台 API 沿用当前用户、租户、表单及字段的数据权限。调整页面控件属性不能提升服务端写入权限；组织和流程查询只能返回已授权数据。需要明确脚本配置权限、执行隔离、超时及异常提示，避免脚本错误导致表单无法恢复或重复提交。
