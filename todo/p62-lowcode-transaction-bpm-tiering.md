## 1. 产品目标与 Owner 已确认条件

在同一个低代码平台上构建 OA、MES、WMS 与 IoT 联动业务，通过 BPM 分级提供不同的执行与等待策略，通过事务型数据能力保护业务约束。

1. 普通 OA 默认可靠异步，受理、执行与结果可追踪、可恢复。
2. MES 等生产场景及时送达，具有明确完成点、时效预算、资源保障与超时语义。
3. WMS 等数据密集业务在竞争、重复提交和故障恢复下仍保持库存及台账一致性。
4. 业务由低代码配置构建；平台提供受控的数据动作、编排、发布校验与运维能力。
5. 按常见交互和生产命令时效建立初始设计预算；不预设项目一定断网或一定在线。
6. BPM 分级与数据一致性分别定义，任何等级均不得绕过数据保护、租户或权限。

## 2. 正式范围

### R01 BPM 分级与执行语义

建立实时动作、生产轻流程、标准流程和后台批量四类平台执行形态。现场硬实时控制作为接入边界，由适合的现场控制系统负责，不列为通用 BPM 的时限保证。

- 实时动作：面向过站、扫码、库存预占等短操作；目标是低开销、受控事务与确定业务结果。
- 生产轻流程：面向派工、设备命令等自动流程；具有持久恢复、截止时间和目标业务回执。
- 标准流程：覆盖人工审批及长生命周期编排，默认可靠异步。
- 后台批量：允许限流和排队，不挤占关键生产资源。

等级决定默认策略，但优先级、等待方式、业务完成点和事务边界仍分别建模。等级不能被当作权限或一致性级别。

实时动作以避免不必要的完整 BPM 实例和逐节点历史写放大为方向；必须保留业务结果、幂等依据、版本身份与必要审计。是否复用引擎或采用轻量执行能力，后续依据现状确定，不直接要求重建第二套业务规则。

### R02 低代码事务型数据动作

提供可声明配置的原子条件更新、数量增减、唯一性与业务约束、版本冲突处理、台账模板、动作级幂等、预占凭据及释放规则。实施人员可配置业务行为，不必编写任意 SQL 才能保证一致性。

C1 类关键数据只能通过受控动作写入，表单保存、导入、批处理、脚本、API 和流程节点必须遵守同一约束。不得存在绕过路径。

余额、预占、流水及必要的流程/表单状态能够在已验证的本地事务边界内组合提交。具体库存维度由模型声明，保护范围包含租户、货主及实际库存对象。

### R03 一致性与可靠传播

- 同库只是实现本地事务的条件；只有参与同一事务管理与提交边界的写入才能承诺原子性。
- 同步短动作能够原子完成的部分不无故拆成异步步骤。
- 内部异步订阅、查询投影、跨进程和外部通知，只要存在提交与投递间隙，都需要持久事件或等效可靠机制；Outbox 的适用性由事务边界决定，不按“内部/外部”标签排除。
- 对跨事务长流程，定义预占、确认、释放、冲正和结果对账，明确竞争裁决与不可撤销副作用的处理。
- 库存查询投影不能替代执行时的权威校验。

### R04 统一命令与双通道兼容

同步和异步入口共享命令身份、业务规则、幂等记录及结果查询语义；等待超时不创建新命令，断连不丢失已可靠受理的命令。

区分可靠受理、执行中、成功、明确失败、过期和外部结果待核实。过期仅能表示相应业务动作确实未继续生效；不能因本地等待超时掩盖已发出的设备动作。

继承 P4 的普通异步/P0 同步优先、专用授权和回查边界。现有运行实例、受理命令及历史结果需要兼容，迁移不产生重复执行或不可查询对象。

### R05 调度与消息扩展

以持久命令/队列与可替换投递边界为基础，数据库持久队列为评审建议的默认方案，外部 MQ 作为按需适配能力。具体可用性、吞吐与恢复需有证据。

内存通知仅可作为已持久化命令的快速唤醒，不成为唯一受理事实或独立副作用执行权威。消息和恢复路径共享竞争领取、防重与状态裁决。

恢复租约不能单独证明旧执行者已经停止；必要时结合执行版本与目标端校验。设备侧缺去重能力时，应提供结果待核实与对账，不能承诺物理动作恰好一次。

### R06 资源保障与多租户

按业务等级和租户设置准入、并发、队列公平性及下游资源预算。保护关键生产通道，并保证普通 OA 不永久饥饿。

隔离验收覆盖数据库连接、锁竞争、CPU、持久化及外部依赖；仅拆线程池或队列不能宣称其他通道完全无影响。

过载时有明确的排队、拒绝和降级规则。高等级权限由服务端确定，客户端不能自报提权。

### R07 IoT 与响应式边界

遥测接入、流处理、长连接和实时推送与生产控制负载分别治理；关键命令、告警及回执不可套用遥测抽样丢弃策略。

控制命令区分目标受理与设备完成，关联命令、设备和实际结果。响应式与虚拟线程是待兼容性及收益验证的执行选项，不自动授权升级 JDK、替换持久化技术或全面重写。

### R08 低代码配置与发布校验

发布时检查等级授权、节点兼容性、事务边界、外部调用超时和失败规则、脚本权限、数据保护及资源约束。实时本地事务块不能容纳人工等待或不可控远程副作用。

规则、数据模型、流程与动作版本具有可追溯快照；发布新版本不能静默改变已受理命令的语义。用户可理解校验失败原因并修正配置。

### R09 部署适配

平台能力不绑定单一云服务、Broker 或网络假设。云端、现场、云边协同作为部署适配方向；本次登记不默认承诺完整离线自治已立项实施。

如后续项目启用现场自治，必须明确数据权威范围、断网准入、预占与全局库存分配、身份授权时效、同步冲突和权威迁移边界。单一权威范围需防止故障恢复后出现两个写入者。

服务端预算与网络耗时分别度量，同时保留用户/设备端到端时效指标，不能以服务端达标替代实际送达。

### R10 运行治理与演进

提供分段延迟、队列等待、截止时间违约、拒绝率、恢复耗时、台账差异与外部结果待核实指标。支持按租户、等级、动作版本和部署节点定位。

演进遵循度量基线、事务能力、分级执行、隔离恢复、按需部署适配及证据驱动优化的依赖关系。各阶段需明确兼容、回滚边界与独立验收；具体实施拆解由执行角色在后续授权方向内制定。

## 3. 初始时效预算

以下值采纳 CTO 稿作为平台内部初始设计目标，不宣称行业统一标准或既有实测 SLA。

| 类别 | 初始预算 / 完成点 |
|---|---|
| 实时动作 | 服务端 P99 ≤ 300 ms，本次业务事务提交；端到端交互以约 1 s 为参考目标 |
| 生产命令 | 目标业务受理 P99 ≤ 1–3 s；正式阶段方向按操作固定单值，设备执行另定完成预算 |
| 普通 OA | 可靠受理 ≤ 1 s 为参考目标，流程推进延迟及最大排队另行界定 |
| 批处理 | 按批量、完成窗口和资源额度定义 |
| 硬实时控制 | 由现场控制契约定义，平台不作通用毫秒级保证 |

验收前固定硬件、部署、网络范围、并发/吞吐、数据规模、热点分布、测量窗口、错误率与拒绝率；不能通过排除失败请求或持续拒绝请求制造 P99 达标。T1 通常不走持久队列，不以队列长度衡量其全部时效。
