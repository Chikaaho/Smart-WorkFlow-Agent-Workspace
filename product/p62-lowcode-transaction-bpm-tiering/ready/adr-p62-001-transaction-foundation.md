# ADR-P62-001：事务能力首阶段边界

日期：2026-09-30；Planner决策；适用P62首个事务阶段。事实输入为本次探索附件B/C，证据层级以审查01为准。产品方向已确定，工程细节由Executor设计；实施授权以阶段状态为准。

| 决策 | 选择与理由 | 兼容/回滚边界 |
|---|---|---|
| 本地动作执行 | 以可独立调用的受控本地事务动作服务承接短动作；复用现有DynamicTableSql、租户/权限和共享提交边界。动作无需人为制造完整审批实例；在已存在流程内调用仍遵守其合法事务边界 | 原P4受理/双通道/回查保持；不把原P0等待链冒称新实时动作；不另造第二套校验规则 |
| C1分类 | 由具模型发布权限的设计者显式声明关键数据、约束及允许动作，随模型/动作发布冻结；普通表单不得直接写C1受保护值 | 既有未声明模型保持原语义；已有数据启用C1须先校验约束，失败拒绝发布；新旧入口统一保护 |
| 动作版本 | 动作拥有可查询的独立版本身份，遵循既有不可变发布快照机制并绑定模型/表单版本；不强制将动作伪装成流程定义 | 已受理调用/预占凭据固定原版本；新发布不改变原对象；停用只能阻止新调用，既有确认/释放仍可完成 |
| 可靠传播 | 首阶段复用持久意图+恢复作为首选路线；所有跨事务传播均须证明与业务提交的原子受理及后续恢复 | 不以新Outbox表存在性验收；不开展五套恢复实现的整体重构；若既有接缝不能覆盖实际新增事件，提交等效可靠设计差异 |
| 命令演进 | 首阶段保留P4状态和身份语义，动作请求有稳定幂等身份与结果回查；租户+动作版本+调用身份建立关联 | EXPIRED/外部待核实及IoT对账留分级执行阶段；本地等待超时不等同业务失败，不重放副作用 |
| 数据演进 | 以0.1.3新基线为前提规划可追加、非破坏的后续迁移，分别验证新建及0.1.3已有数据路径 | 不把0.1.3曾获删库授权沿用到P62；保留发布基线校验和；回滚不得丢弃动作流水/预占，新数据或在途对象不兼容旧版本时以停用新入口并向前修复为边界 |

后续另行决策：四类执行的统一等级契约、旧执行者防护、未知设备结果对账、调度收敛、隔离配额及性能合同。现场自治、MQ、JDK/响应式演进均不由本ADR自动立项。
