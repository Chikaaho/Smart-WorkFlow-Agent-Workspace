## 一次交付的验收集合

下表是同一个最终交付的并列标准，不是分批下发的步骤。Executor须提供 R01—R10 → A01—A12 → 实现/证据/边界映射；每项区分既有锁定、新增验证、批准延期或不适用，不以阶段名称替代覆盖证明。未延期的可执行缺口均在本次修复授权内。

| 标准 | 本次必须兑现的结果 |
|---|---|
| A01 四类业务 | 四类形态均有可配置、可发布、可运行、可查询的真实入口。至少形成一条关联业务链：表单申请/库存预占 → 标准人工审批 → 批准后的受控确认或设备命令 → 用户查询最终业务结果；拒绝/取消后已产生效果与待释放凭据可定位并受控处理。实时、生产轻流程与批量的独立代表场景沿用有效证据；不得为凑一条链把人工等待塞入轻流程。 |
| A02 事务约束 | 模型声明的租户、货主/业务维度、库存对象、数量精度与唯一约束在竞争、重复、失败时成立；余额、预占、确认/释放及台账可勾稽。已提交事实不可由查询投影替代。 |
| A03 全入口保护 | 配置/UI、API、导入、脚本、批量、节点和恢复路径的实际可写入口服从同一 C1、租户及权限保护；无写能力的路径记录能力边界，不虚构绕过缺陷。新增连接路径重点证明没有权限与事务旁路。 |
| A04 原子与传播 | 声明需要同成同败的本地写入共享已验证事务；跨事务节点、审批后动作和设备意图具有持久关联与可靠恢复。中断不丢失已受理效果、不重复业务效果；部分成功明确展示。失败处置复用预占/确认/释放、受控冲正或核实边界，追加事实与审计，不删除原台账；不可撤销副作用不得伪装自动回滚。 |
| A05 命令恢复 | 同步/异步、等待超时、响应丢失、重试、重复消费和重启保持稳定命令与业务身份；异载荷拒绝，旧执行者重叠不能重复落效果。新增受理来源须复核生产标准业务键，不能套用任意跨键安全结论。 |
| A06 时效 | 仅引用已验收限定样本与原边界；目标环境容量、拒绝时效及持续负载均按 Owner 决定延期、未验证，本次不增加性能达标条件。截止/超时状态的功能正确性必须成立。 |
| A07 资源与租户 | 准入、额度、保留/借用、跨策略总账、有限调度行为、租户隔离与拒绝无副作用沿用资源功能裁决；新增路径须受相同机制约束。全负载公平、等待上界与持续保障延期，不声称共享硬件完全隔离。 |
| A08 竞争与设备结果 | 确认/释放/过期竞争只有合法结算；命令受理与设备完成分开。已发出但结果不明进入待核实，禁止盲重发；迟到/重复/冲突回执和授权人工核实能按关联对象收敛或保留冲突审计。受控真实传输对端可证明平台合同，证据不得升级为厂商实网或物理效果证明。 |
| A09 发布与冻结 | 等级权限、节点/事务/等待、外部超时及资源配置非法组合在发布时可理解地拒绝；合法配置运行，命令、动作、模型、流程及资源策略版本可追溯，在途语义不随新发布改变。 |
| A10 兼容与回退 | P4普通异步/P0专用授权及既有查询保持；旧在途对象、非空迁移与历史结果仍可处理/查询。维持协调升级、关新受理、保留结果和向前修复边界，不授权旧新消费者混跑新语义。新增迁移只追加、非破坏。 |
