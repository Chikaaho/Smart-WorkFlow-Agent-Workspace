# ADR-P62-002：分级执行与统一命令

日期：2026-09-30；Planner决策；状态：已采纳。该阶段业务与同步均COMPLETED并归档passed/；实施合同见 `../passed/direction-p62-tiered-execution-unified-command.md`。当前产品合同为同目录 `direction-p62-final-delivery.md`，执行账本为 `../receipts/planning-execution-prompt-final-delivery-01.md`；资源完整性能合同延期。
事实输入：限定探索主回执及A/B/C附表；Server ca8cb87、Web19e1c47结构快照，非本阶段行为验证。首阶段已交付动作能力，BPM动作调用节点/命令fence/未知结果接线及性能资产仍缺。

| 决策 | 选定方向与理由 | 兼容/后果 |
|---|---|---|
| 四类形态 | 形态、优先级、等待、完成点、事务边界独立；OA默认异步 | NORMAL/P0旧语义保持；服务端授权，不把形态当提权 |
| 生产轻流程 | 新增事务动作NodeTypeTranslator及delegate，通过form-api受控port复用事务内核；START/END/CONDITION/动作，无环≤16动作 | 现有NodeFunction仅人工任务触发，不挪用通知/抄送节点承载动作；必要契约/迁移授权，最小实现结构由Executor定 |
| 轻流程提交 | 各节点短事务；效果、节点进度/结果原子，整流程允许部分已完成 | 失败须明确已完成效果与预占；不作自动跨节点回滚承诺 |
| 命令身份 | 统一逻辑身份/载荷指纹/查询，允许既有物理记录映射；实时动作不强制排队 | 同入口重放和跨通道复用同一操作身份；旧幂等与冻结版本不丢失 |
| 批量 | 复用持久命令队列，新增必要批次/逐项持久化和幂等，1—500项逐项事务 | 既有导入整批原子及审批/通知接口不改变；成功项不重放 |
| 恢复 | 业务同事务权威结果与执行权防护结合；效果可确定回查，旧执行者不能重复提交效果 | 修正当前业务提交/complete分离窗口及仅回写token保护的不足；不重构其他四套恢复框架 |
| 截止 | 新命令准入截止30s默认、1—300s可配置冻结；执行中超时不证明未生效 | 不给人工实例增加EXPIRED；部分提交不可伪报整命令无效果过期 |
| 未知结果 | 既有设备意图关联生产路径接线、合法迟到回执和独立授权人工核实；禁止未知自动重发 | 厂商无查询接口，不虚构自动对账；受控真实对端验平台机制，腾讯实网仍延期；必要最小权限可新增 |
| 升级窗口 | 新能力关闭时升级；新类型产生前旧消费者退出，全部消费者与Web协调切换 | 不支持旧消费者处理新类型；保留旧行，非空升级验证；停新入口/保留结果/向前修复为回退界限，不授权本轮上线 |
| 时效合同 | 按方向固定M1/8GiB/PG17.5环境、16并发5min负载，300ms/2s及120s恢复目标 | 数字为限定验收预算，当前未实测；64并发仅压力画像，完整多租户保障及生产SLA后续验收 |

不引入新Broker、JDK/响应式升级或现场自治。共同事务不能靠同库推断；REQUIRES_NEW仅可承载独立拒绝审计，不承载成功结果。修改方向或降低预算须由Planner依据新事实裁决，Executor不得自行扩大范围或减少验收。
