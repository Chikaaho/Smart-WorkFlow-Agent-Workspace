## 1. 结论

探索回执覆盖了版本登记、组件、TABLE/REFERENCE、公式、外部数据源、定义生命周期、列表配置、三层权限、移动端、版本链和影响范围，能够支撑 I2 产品方向。该结论只确认规划信息充分，不是 I2 功能验收，也不证明静态实现已经可运行。

当前存在一个执行前必须消除的权威冲突：Planner 当前材料已经使用 `0.1.0` 且 I1 已由最终裁决确认 `COMPLETED`，执行侧当前权威材料仍保留旧登记与“待规划确认”口径。I2 方向将授权 Executor 先做最小登记同步并回读，正式功能数、90 项清单、P 编号和 I1 行为证据均不得变化。

## 2. 证据等级纠正

| 探索结论 | Planner 纠正后口径 |
|---|---|
| 多类 `FieldType` 与 v0.0.2 A5 合并标为“已验收” | 只有 v0.0.2 A5 明确锁定的多选、附件、图片、说明文字、默认值和显隐规则可直接按行为通过项沿用；其他类型的注册或实现存在属于结构证据，仍需在 I2 同一真实表单中完成行为验收 |
| TABLE/REFERENCE 已存在或已通过 | P32 只锁定导入导出范围内 TABLE/REFERENCE 往返；I2 的设计配置、发布校验、填报、草稿、审批回显、对象权限和历史解释仍是待验范围 |
| 附件已有通过证据但当前静态接缝显示仅存 storageKey | v0.0.2 的对象权限行为继续锁定；当前静态发现作为受影响风险，不自动推翻旧结论。I2 若改变附件或权限链，必须用同一候选的正反行为重新证明受影响部分 |
| schema 单一权威成立 | 组件定义的主 schema 可作为现有基础；前后端各自解释显隐、校验、公式或权限时仍须证明契约一致。生产安全与最终提交以服务端判定为权威 |
| 移动端零实现 | 采信为当前静态缺口；I2 必须提供移动 Web 表单使用入口，但不扩张为原生 App 或移动端表单设计器 |

## 3. 已锁定且禁止无条件重验

- P52：表单工作台、保存发布状态、历史只读、表单—流程稳定关联、深链与多标签隔离；
- P56：24 列布局、拖放、宽度、换行、持久化与设计/预览/填报一致性；
- P32：`.xlsx` 导入导出及其 TABLE/REFERENCE 数据往返边界；
- v0.0.2 A5：多选、附件、图片、说明文字、默认值、显隐、草稿/提交和附件对象权限；
- I1：用户、角色、部门、岗位、负责人、租户和权限收敛基础。

只有 I2 实现实际影响、候选身份无法对应或出现新增反证时，才重验受影响原子；不得把全部历史功能重新当作待实现范围。

## 4. 规划裁决

1. I2 使用一个真实表单贯穿组件、规则、权限、PC/移动和版本链，不用多个近似对象拼接完成。
2. 公式、外部数据源、字段/记录/动作权限以服务端为最终权威；前端体验不能成为安全边界。
3. 移动端范围限定为响应式移动 Web 的表单填报、草稿、提交和只读回看；管理设计仍以 PC 为主，I3 审批动作不提前纳入。
4. 发布版本冻结 schema、公式/数据源配置和列表解释；外部查询结果与公式结果在业务提交时形成可追溯值，历史查看不得重新调用外部源改变原结果。
5. I2 不创建补充执行提示。补充提示只在后续同类验收缺口连续失败时按 Planner 规则生成；本轮正式阶段方向本身就是唯一执行入口。
