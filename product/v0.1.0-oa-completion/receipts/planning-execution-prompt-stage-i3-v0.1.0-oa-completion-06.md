## 3. R8c 零裁量行为链

使用唯一 marker 创建一个最小两个人工审批节点定义，节点 A 与节点 B 的办理人必须明确且可登录/可调用；意见表单沿用已锁定的有效 TEXT 组件。按以下顺序执行，任何一步失败即停止生成终态包：

1. 发起实例，回读实例 ID、首轮 A 任务 ID、节点 key、assignee、状态；任务 ID 必须为非空真实值。
2. 以 A 办理人完成首轮 A，返回 HTTP/业务 code 0，提交非空意见 `A-R1`；回读该任务关闭。
3. 从待办/实例运行态重新取得首轮 B 的真实任务 ID，不允许从错误字段猜测或拼接。
4. 以 B 办理人调用 `/workflow/tasks/{真实B任务ID}/return`，返回 HTTP/业务 code 0，提交非空退回意见 `B-RETURN-R1` 和明确目标节点 A；回读 B 旧任务关闭。
5. 回读新建二轮 A 任务：ID 非空、与首轮 A 不同、节点为 A、轮次/创建时间可证明发生在 RETURN 后。
6. 完成二轮 A，code 0，提交非空意见 `A-R2`；回读关闭并取得二轮 B 的真实任务 ID。
7. 完成二轮 B，code 0，提交非空意见 `B-R2`；实例最终完成且不存在残留 PENDING 任务。
8. 从权威实例详情/历史端点回读按时间排序的四步动作：`APPROVE(A-R1) → RETURN(B-RETURN-R1) → APPROVE(A-R2) → APPROVE(B-R2)`。四条均须包含非空 `opinionData`、意见表单 ID/版本、节点、任务/办理人、动作和可区分轮次的事实。
9. 证明意见快照不可变、主业务表单零反写，且一次 RETURN 只创建一组二轮任务；不得出现重复实例、重复动作或第二副作用。

必要反向断言：任何 `/undefined/`、HTTP/业务非零、404、空 task ID、空历史、缺 RETURN、缺二轮、只有首轮意见，均必须使 R8c 自动判定失败。
