## 4. 剩余缺口矩阵

### G1：审批不回滚与持久恢复未形成行为闭环（A3）

- **失败事实**：回执只给出 `AFTER_COMMIT`、默认 `CONTINUE`、调度器及退避结构，并明确没有人工重启恢复演练。仍支持显式 `BLOCK`，但未证明任何运行时 Provider 失败都不会回滚已经合法提交的审批动作。
- **完成条件**：以同一流程/任务/通知对象证明发送失败或超时后审批动作与流程状态保持已提交；通知进入失败/待重试；服务停止并重新启动后从持久状态恢复，追加尝试而非新增业务通知，最终进入明确终态。
- **必要负向**：不得用调用调度方法、Bean 存在或单测 mock 发送代替真实持久状态与重启前后回读。显式失败策略若仍可回滚已合法审批，必须收敛到方向 §3.2 的产品语义。

### G2：模板、规则与渲染安全只有部分证据（B5/B6）

- **失败事实**：回执承认 HTML 安全专项负向未单独落盘；模板不可变版本、白名单变量、规则 CRUD、事件开关、接收人规则与渠道组合主要是结构声明。
- **完成条件**：用真实 API/持久化证明发布新模板版本后历史通知仍引用旧版本；未知、缺失、类型/长度非法变量在发送前失败；危险 HTML/URL 被拒绝或安全处理；规则启停、接收人和订阅变化对后续投递真实生效且不改写历史。
- **必要负向**：强制通知不能关闭，普通用户不能修改他人订阅或管理规则，非法内容不能以前端隐藏或 Adapter 自行处理作为防线。

### G3：租户、权限、目标解析与最小暴露矩阵不完整（B7/B8/D14）

- **失败事实**：只存在“跨租户未读=0”一项新行为证据；模板、规则、订阅、消息、尝试、回执、重试、详情权限、深链和 tenantId/recipientId 伪造未逐项验证。EMAIL/PHONE 解析和记录脱敏只有实现声明；Provider 主体解析仍明确缺失。
- **完成条件**：固定两个租户、多个用户和同一业务对象，对上述每类资源的读、写、启停、重试、详情与跳转逐项证明 fail closed；服务端权威解析有效联系方式，失效、缺失、跨租户和客户端伪造均明确失败；管理员摘要与受权详情返回符合最小暴露边界。
- **零残留**：以实际响应、前端状态和日志/回执扫描证明正文、联系方式、密钥、Token、SQL 参数、内部异常及 Provider 原始响应没有越界暴露。

### G4：PC、移动 H5、菜单与深链缺少真实浏览器链（C10/C11）

- **失败事实**：回执明确未运行浏览器验证；页面、路由、V90 菜单及权限种子存在只能算结构。Web 新增页面与契约没有新增专项测试，总测试计数与 I5 基线相同。
- **完成条件**：在真实后端模式使用有权用户与无权用户完成 PC/H5 收件箱分页、详情、未读数、单条/全部已读、删除边界、偏好和受保护跳转；证明动态菜单可达、刷新/深层路由可恢复、PC/H5 操作同一消息且状态一致。
- **必要负向**：跨用户、跨租户、撤权后深链和构造请求均被服务端拒绝；Mock 不得参与证据链。新增页面与关键交互需有与风险相称的前端聚焦测试。

### G5：五类外部渠道未验收（D12/D13/D14）

- **失败事实**：短信 Provider 尚未选定；短信、飞书、钉钉、企业微信、邮件均无真实成功、失败、恢复及 Provider 侧勾稽。D13 只能记为“本地契约已实现”，不能标记验收完成；Provider 明文主体映射源仍未确定。
- **完成条件**：五渠道分别使用真实测试应用、沙箱或可控账号完成成功、可控失败与恢复/重试；逐一勾稽本地业务通知、尝试、外部标识、脱敏回执和 Provider 结果。启用、缺失/占位配置、超时/限流和目标失效均有真实行为。
- **外部条件**：Owner 仍需提供短信选型、五渠道凭据/账号、可控收件人及必要域名。在条件到位前 G5 保持 `VERIFYING`，但不阻止 G1—G4、G6—G9 的独立工作继续。

### G6：流程事件与多身份全场景未完成（A2/E16）

- **失败事实**：`bpm 205` 回归和路由测试没有逐项展示方向要求的流程事件产生同一真实通知对象；管理员、发起人、多个审批人、代理/受托人、抄送人和无权用户的同对象全链尚未提交。
- **完成条件**：固定一个真实流程对象与身份集合，逐项证明待审批、加签、退回、驳回、节点通过/不通过、流程通过/不通过、抄送和催办的通知身份、接收人、模板版本、审批轨迹与投递记录互相勾稽；重复与并发只有一次合法副作用。

### G7：真实旧库升级与历史解释未验证（E17）

- **失败事实**：H2/PG Flyway 全链证明新建/测试链能到 V90，但回执明确没有带既有通知、模板、流程实例和历史记录的旧库升级演练。“增量列语义保障”是声明证据。
- **完成条件**：从受支持的旧基线数据库保留代表性既有消息、模板、投递尝试、流程实例与历史记录升级到 V90，升级前后按同一 ID 回读且语义可解释；失败恢复和回滚边界按版本材料实际演练或给出可判定结果。

### G8：版本材料仍是候选骨架（E15）

- **完成条件**：固定实际候选后，由工具生成并回读 Workspace/Server/Web SHA、版本、迁移终点、测试计数与材料清单；CHANGELOG、发布说明、升级、回滚、配置变化、DB 迁移和 manifest 相互一致。标签、Release 和远端推送仍需 Owner 单独授权。

### G9：工程门禁证据与新增前端范围需补齐（E18）

- **失败事实**：Server 回执只列出 `mvn test`，未列出工程宪法要求的独立 compile 门；新增多页面和契约却没有新增专项前端测试。当前全量通过只锁定已有命令的结果。
