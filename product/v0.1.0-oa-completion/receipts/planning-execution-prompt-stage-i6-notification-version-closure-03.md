## 2. 零裁量剩余账本

每项必须独立形成`product/v0.1.0-oa-completion/receipts/evidence/i6-05/<原子ID>/`。R1—R7全部为`YES`前不得提交；R8只能为`YES`或满足§5的唯一`EXTERNAL_BLOCKED`。

### R1-RULE-VIEW

- 正向目标：具有规则查看/管理权限的租户管理员在真实菜单进入规则页，GET列表成功，并完成创建、编辑、启停、删除和回读。
- 反向目标：无权用户菜单不可见，直接页面/API请求403/404且零写入。
- 固定对象：T100租户管理员A、无权用户B、规则RV1。
- 证据包：浏览器截图索引、网络请求原始流、删除前后SQL/API回读、权限/菜单响应、命令/exit code。
- 全部为是：权限码已登记；前后端同源；A全链成功；B全链拒绝；RV1删除后不可读取且历史消息不改写。

### R2-PHONE

- 正向目标：服务端权威解析有效PHONE；该验证停在resolver/身份层，不经过SMS Adapter，不需要Provider选型。
- 反向目标：失效用户、缺失号码、跨租户用户、重复号码歧义和客户端原始号码旁路均明确失败且不产生通知/尝试。
- 固定对象：T100/T200各两用户，登记脱敏摘要，不记录号码明文。
- 证据包：聚焦集成/API原始流、身份来源回读、消息/尝试前后计数。
- 全部为是：六格矩阵逐格有结果；有效值只由服务端权威得到；所有负向零副作用。

### R3-ADMIN-UI

- 正向目标：真实后端管理页面依次访问模板版本、渠道配置、通知规则、发送记录、尝试详情和授权重试；每页至少完成一次与权限相称的读取或动作。
- 反向目标：无权用户菜单不可见且构造请求拒绝；敏感值不出现在页面状态、网络响应和截图。
- 固定对象：复用T100管理员A/无权B、模板TV、规则RV1、失败消息MF及其尝试AF。
- 证据包：PC浏览器截图/录像索引、URL、网络请求、动作前后状态、Mock检查。
- 全部为是：六个管理面均真实可达；授权重试新增一次尝试但不新建业务消息；无权链拒绝；零敏感暴露。

### R4-CROSS-CLIENT

- 正向目标：选择一个固定消息MC和流程实例PC；PC标记已读后H5立即读到同一状态，H5跳转后刷新仍打开PC，随后PC回读一致。
- 反向目标：撤销对象权限或使用跨租户/无权用户打开同一MC/PC，PC与H5均重新鉴权拒绝。
- 证据包：对象账本、PC/H5截图索引、消息ID/实例ID可见的网络流、操作前后回读。
- 全部为是：两端所有证据中的MC/PC逐字一致；无Mock；正向一致；撤权后两端均拒绝。

### R5-ROLE-CHAIN

- 正向目标：一个固定流程实例PR包含发起人、至少两个可区分审批人、代理/受托人、抄送人；管理员对同一PR有授权监控视图，各身份完成与角色相符的页面/HTTP行为并收到对应通知。
- 反向目标：另一个与PR无关系的用户U0对同一PR页面、深链、详情和办理全部拒绝，零流程/通知副作用。
- 固定对象：PR及其任务轮次、上述全部用户、消息集合；不得用不同实例拼接。
- 证据包：角色—动作—任务—消息矩阵、浏览器/HTTP原始流、流程轨迹与通知回读、U0前后计数。
- 全部为是：每个身份在同一PR出现；两个审批人可区分；代理/受托人真实办理；抄送人只读；U0全拒绝。

### R6-COPY-TEMPLATE

- 正向目标：抄送通知使用明确事件类型、规则、已发布模板版本和统一通知身份；至少回读事件、业务对象、接收人、渠道、模板ID/版本、幂等身份。
- 反向目标：不再以`SYSTEM`+空模板版本产生新抄送；重复抄送事件不产生第二业务效果；历史旧通知不改写。
- 固定对象：新抄送实例CP、模板版本V1/V2、接收人C。
- 证据包：实际流程触发、通知/模板/尝试SQL或API回读、重复触发结果、历史行前后对比。
- 全部为是：新通知模板版本非空且固定；V2发布后旧通知仍引用V1；重复单效果；旧SYSTEM历史不修改。

### R7-CANDIDATE

- 正向目标：R1—R6完成、受影响回归和最终门禁通过后，生成唯一候选记录。
- 反向目标：不再出现多个“当前”MANIFEST哈希，不声称写入manifest后Workspace仍保持生成前clean；不遗漏证据文件。
- 固定语义：`workspaceSourceHead`表示生成manifest前的源码/治理候选提交；`manifestArtifactSha256`表示manifest制品本身。二者不同对象，不互相冒充。生成后Workspace状态如为dirty必须如实记录；若再提交manifest/回执，新增`evidenceCommit`而不改写`workspaceSourceHead`。
- 证据包必须包含：`command.txt`、`stdout.log`、`stderr.log`、`exit-code.txt`、`objects.md`、`actual.md`、最终manifest快照、SHA256校验文件和回读输出。
- 全部为是：回执、actual、command、snapshot只有一组当前hash；本包六文件全在；Server/Web HEAD及状态、Workspace source head/evidence commit语义明确；V92、门禁计数和R8边界一致；无标签/Release/推送。

### R8-EXTERNAL

- 正向目标：短信、邮件、飞书、钉钉、企微逐一真实成功、可控失败、恢复并与本地记录勾稽。
- 外部阻塞替代：仅Owner未提供所需选型/凭据/账号时允许；不能把生产SMS Adapter尚未实现或PHONE未验证包装成外部阻塞。
- 证据包：逐渠道列出非秘密配置键名、Adapter状态、测试账号/收件人是否可用、实际工具结果类型和解除条件；值只写`PRESENT/ABSENT`，不得记录秘密。不得再用MINIO/COS行替代通知配置。
- 全部为是：五渠道全部真实通过；或R1—R7全YES后，五渠道逐一`ABSENT`工具结果齐全、独立工作穷尽、解除条件明确，机器终态如实为`BLOCKED`。
