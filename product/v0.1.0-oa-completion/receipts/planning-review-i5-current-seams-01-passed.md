## 2. 已锁定的现状事实

1. 企业微信、飞书、钉钉、微信小程序的第三方 SSO 在代码、配置、页面、数据库和测试五层均未实现；唯一现存身份接缝是无实现、无调用的 `SocialAuthenticationProvider` 预留 SPI。
2. `NotifyChannel` 中的 Provider 枚举属于 I6 出站通知，不构成 I5 身份接入能力；I5 与 I6 必须保持身份渠道、通知渠道两个语义域分离。
3. 第一方认证、JWT/refresh、`LoginUser` 装载、权限收敛、租户行过滤和数据范围底座可以复用，但第三方身份映射、绑定唯一性、租户禁用校验、SSO 防重放、错误恢复和审计均缺失。
4. Web 前端没有第三方入口或回调页；PC 与响应式移动端当前共享同一会话、权限对象和路由守卫。
5. 仓库中没有微信小程序工程载体；四个 Provider 的测试应用、凭据和可用回调白名单均不在仓库内，因此当前不能取得真实 Provider 端到端证据。
6. 五个相关 Provider 域名的 DNS 与 TCP 443 在探索时可达；这只证明出站网络条件，不证明任何 Provider 接入完成。

## 3. 规划裁决

以下三项不再向执行层开放自由解释：

- **租户边界**：I5 必须把租户有效性纳入统一认证与会话收敛门，第一方与第三方登录使用同一判定；不得仅为 SSO 建立旁路。范围只覆盖认证所需的租户状态/有效期判定和第三方身份到租户的唯一映射，不扩展为完整租户管理功能。
- **Web 接入形态**：企业微信、飞书、钉钉采用服务端发起、服务端回调/换票、同源前端承接结果的模式；不引入浏览器端 Provider SDK，不放宽既有 CSP，不增加跨域前端直连。Provider 支持的 `state`、`nonce`、回调白名单和一次性消费必须在服务端闭环。
- **审计与脱敏**：I5 内补齐身份接入所需的最小持久审计与敏感字段保护，覆盖配置变更、绑定、解绑、登录成功/失败、重放与越权拒绝；不扩展为全系统通用操作审计平台。secret、code、token、`session_key` 和 Provider 敏感响应不得进入前端、普通日志、审计正文或回执。

既有 JWT 默认密钥风险是 P45 已登记风险，不作为 I5 新缺口重开；I5 只禁止复制该默认值模式，Provider 生产密钥必须无默认值并在启用时 fail-fast。
