## 3. 直接反证与未满足项

### 3.1 最终候选身份未绑定（影响 G1—G16、G17）

- 回执声明最终运行 JAR SHA256 为 `b3ec7b14...`，`g0-authority-reread-final.txt` 也只在 11:39 对磁盘文件给出该值。
- 实际运行环境记录先后出现 `b7c5496a...` 和 `52cf4ded...`；没有一份启动记录把 `b3ec7b14...` 与双进程 PID、端口、数据库及 G1—G16 行为采集时间绑定。
- 因此无法确认回执中真实 API/SQL 行为属于最后修复后的候选。最终代码修复会使旧运行快照失效；全量单测通过不能自动替代已要求的真实运行行为。

### 3.2 设计器与查看器证据不完整（G1、G2、G4）

- `browser/designer-dom.txt` 只显示按钮和节点面板，未记录拖入、移动、选中、属性修改、连线建立/调整、删除、撤销、缩放/平移、保存后刷新恢复及错误对象聚焦的前后状态。
- 浏览器 DOM 中“撤销”“删除所选”均为 disabled，且没有画布节点/连线状态或“校验通过”结果；API 脚本预置 graph 不能替代真实设计器交互。
- 实例查看只证明当前样例的“已完成/未经过”图例，未证明当前、取消、失败节点/连线与真实轨迹一致；历史缺坐标兼容仅有单测自述，没有方向允许的前向兼容夹具或降级行为附件。

### 3.3 审批动作存在真实语义冲突（G6—G11）

- `DISAPPROVE` 请求落库行为为 `REJECT|REJECTED`，与方向要求“不得与流程级 REJECT 使用同一枚举或混称”直接冲突；页面也只显示“驳回”，未提供两种语义的可辨识行为。
- 多个动作的 `trace` 为空，未形成页面、HTTP、任务、意见、Flowable 轨迹、通知和终态的统一链。
- RETURN 未证明表单可修改范围、路径重走依据与取消原因回看。
- ADD_SIGN 只有并行链，缺串行、取消及失效人员；SUPPLEMENT_SIGN 未证明取消、越权、失效人员、重复请求。
- DELEGATE 只证明 owner/assignee 字段，未执行受托人完成后回归原责任人确认或受控完成。
- AUTHORIZE 的正向字段 `proxy_task_assignee`、`proxy_audit_row` 均为空；时段、流程/节点范围、过期、人员停用、跨租户及撤销后的既有/新任务行为未闭合。

### 3.4 会签结果暴露产品缺陷（G8）

- ANY 负向和 RATIO 50% 负向场景中，第一张 `DISAPPROVE` 票后实例已 `REJECTED`，第二位投票人得到 404；这不能证明“两名参与人全部不通过后才负向结算”，反而证明分母/负向阈值仍可能提前结算。
- 双进程 A 场景原始摘要显示两个请求均成功且 `collision_retry={}`，但 verdict 写“败者 2305 后重试”，结果与结论互相矛盾。
- 回执另承认竞争后立即重试可能出现 FK 500。方向要求冲突返回既有结果或明确状态，500 不能作为已满足边界保留。

### 3.5 时限与节点函数仅覆盖子集（G12、G13）

- G12 只证明一类 `AUTO_APPROVE` 到期和一次重启后的 DONE 门；没有提醒、催办、升级、通知失败解耦，以及实际启用的其他自动动作或多实例调度竞争。
- G13 只证明 `resolveParticipants` 的一个内建正向和未知版本发布拒绝；`handleResult`、超时、异常、非法用户/输出、跨租户、变量越权、输出超限、重复调用、失败策略、审计及生产任意脚本零入口均未提交。

### 3.6 意见与身份矩阵不满足方向（G14、G15）

- 组件矩阵只有 9 种类型，未证明其等于 I2 全部组件目录，也未给出每个不可用组件的原因与设计端/构造请求双拒绝。
- 未证明主表单到意见表单的只读初始化映射，也未在普通审批、会签、加签、补签和退回新轮次逐类证明默认备注/绑定意见表单、服务端校验、提交和历史回显。
- 身份矩阵中 admin、user2、user3、user4 都显示 `superadmin`，userId/tenantId/realName 全为空；不能证明管理员、发起人、多个审批人、转入人、受托人、代理人、沟通人和无权用户之间的差异权限。真实登录成功不等于角色身份满足。

### 3.7 封装、清理和秘密残留（G16、G17）

- `runtime-down.txt` 的最终可见回读仍为 `PORT_50886=2 rows`、`RESIDUAL_PROC_ROWS=1`，追加 kill 后没有再次回读端口/进程为零；与回执“0 残留”冲突。
- `env/token-admin-a.txt` 和 `g0/tokens.out` 是非空凭证形态文件，证据包不得保留可重放会话凭证；应安全移除或不可逆脱敏后重新生成清单。
- 全量 Server/Web 门禁原始流和 exit 0 可读取，但没有工具生成的“最终源码/产物指纹 → 门禁 → 运行行为”同一快照链；目前不能晋级正式基线。
- `g16_ledger/ledger.json` 只导出十张表，通知为独立 148 行汇总；在 G6—G15 未闭合前，无法证明每类动作的 requestId、取消原因、意见、轨迹和通知逐对象勾稽。
