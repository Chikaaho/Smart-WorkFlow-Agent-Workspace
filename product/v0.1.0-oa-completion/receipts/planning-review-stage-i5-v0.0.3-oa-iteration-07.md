## 1. 总结论

token 摘要维度撤销修复了验收 06 指出的 userId 共享缓存复活问题；跨秒 A/B 序列中，B 的 access/refresh 与缓存重载成功，A 在三个检查点均拒绝，相关回归为 `22/22`、`295/0/0/0`、BootTest `3/3`，这些子断言可锁定。

但回执与原始包明确记录了真实反证：JWT 无 `jti` 且 `iat` 只有秒级，同一秒内同一用户两次登录会生成逐字节相同的 access token；解绑撤销 A 后，立即建立的合法 B 会与 A 共用同一摘要并被拒绝直到撤销 TTL 过期。执行层通过等待 1.1 秒获得不同 token 后才使用例通过。

这不是可延期的普通边界：它直接违反 G6c1“解绑后第一方新会话 B 可建立且不被 A 的撤销误伤”，也影响方向验收标准 #10 的既有第一方登录契约。人为等待不能作为登录协议前置条件。因此 G6c1 未通过，I5 不能进入 PASSED。

G8 仍为合法外部依赖，继续 PENDING。
