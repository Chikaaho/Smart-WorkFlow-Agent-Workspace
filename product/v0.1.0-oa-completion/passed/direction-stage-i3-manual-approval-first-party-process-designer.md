## 4. 产品契约

### 4.1 自研流程设计与查看单一图契约

- 自研设计器直接使用 P57 统一节点能力和 `ProcessGraph`，不得另建平行节点目录、边模型或仅供前端解释的私有流程格式。
- 节点面板只展示统一能力端点声明为可设计的节点；节点名称、类别、拓扑、配置字段、枚举、必填和校验约束由同一服务端契约提供。前端不得继续手抄参与人策略或节点配置目录作为正常权威。
- 设计页覆盖节点拖入、节点移动、连线建立/调整、选择、删除、属性配置、画布平移/缩放/适配、撤销必要的未保存编辑、保存、校验、发布和错误定位。系统节点及不可删除、不可连线等约束必须与服务端一致。
- 节点和连线使用稳定 ID；坐标、折点及画布信息进入版本化 `ProcessGraph` 契约。页面刷新、重新编辑和只读查看必须保持同一图形身份，不因数组顺序或渲染时机漂移。
- 草稿允许暂时不完整，但只允许有权用户修改 DRAFT；保存执行基本对象、权限和格式检查。独立校验返回全部可判定错误及 `nodeKey`/`edgeKey`，页面能够定位并聚焦问题对象。发布必须执行服务端完整校验，任何错误均零部署。
- 流程定义列表和实例详情使用同一自研渲染内核。定义查看保持图结构；实例查看能够区分当前、已完成、未经过、取消和失败节点/连线，且与真实任务及轨迹一致。
- 历史 `graph_json` 缺少坐标时采用确定性兼容布局并标明兼容来源；若历史数据不足以可靠还原图形，则展示真实可解释的节点/轨迹降级视图，不得生成错误连线或空白成功态。

### 4.2 第三方图形依赖退出

- 从生产依赖、包清单、锁文件、共享 adapter、业务页面、样式、测试夹具和构建产物中完整移除 `bpmn-js` 及仅为其存在的直接资源。
- 不以 CSS 隐藏品牌链接、删除依赖内部水印代码、改写依赖源码或保留不可达 import 作为替代方案。
- 现有定义查看和实例轨迹查看两个消费点必须迁移后再删除旧 adapter；移除不得牺牲缩放适配、状态高亮、错误显示、资源清理或历史回看。
- 最终生产源码、依赖图、锁文件、静态产物和运行 DOM 均不得包含该库、其 adapter 或 `bjs-powered-by` 注入结果。历史回执中的既有文字不属于生产残留，不改写历史。

### 4.3 流程定义版本与发布冻结

- DRAFT 可以保存和反复编辑；PUBLISHED、SUSPENDED、DISABLED 或已有运行/历史引用的版本不得被原地覆盖 `graph_json`。
- 已发布定义再次编辑必须形成新的草稿版本；版本号单调递增，发布时冻结图、节点配置、表单版本、意见表单版本和函数版本。运行实例绑定明确的发布版本与图快照。
- 挂起只禁止新实例并保持既有实例可解释；激活恢复同一版本。安全删除仅适用于无发布、运行、历史和业务引用的草稿。
- 旧定义、新草稿、运行实例和历史记录的对象身份清晰；不得通过就地改行、重建数据库或替换对象制造兼容完成。

### 4.4 审批动作统一语义

- `APPROVE`：当前参与人的通过动作，进入节点结算规则；普通单人节点满足规则时推进。
- `DISAPPROVE`：当前参与人的不通过意见，交由当前节点的明确结算规则处理；不得与流程级 `REJECT` 使用同一枚举或在页面、轨迹、通知中混称。
- `RETURN`：退回到本实例已经经过且设计允许的目标人工节点；生成新的办理轮次，关闭或取消原轮次剩余任务，记录表单可修改范围和后续路径重走依据。
- `REJECT`：形成流程级驳回终态，关闭所有仍可办理任务并保留驳回人、意见、节点、轮次和原因。
- 每个动作在页面按钮、权限资源、请求契约、任务状态、业务持久化、Flowable 轨迹、意见记录和通知事件中使用同一稳定语义。

### 4.5 会签、加签与补签

- 会签继续支持 ALL、ANY、RATIO，并补齐一票否决等 P34 剩余规则。进入节点时冻结参与人和分母；达到通过或不通过条件后原子结算，其余任务具有明确取消原因。
- 会签重复与并发操作在多实例部署下只能形成一次合法计数、一次节点推进和一个终态；不得只依赖单 JVM `synchronized`。
- 加签由当前有权办理主体在有效人工节点追加一个或多个有效人员，并明确串行或并行。原任务、加签任务、发起人、参与人、意见、顺序、结算与取消原因全部可追溯。
- 补签用于已经越过但仍需补充确认的责任，不重开或改写原流程终态；补签记录必须关联原实例、原节点、原终态及补充确认结果，并明确是否只作审计补充或触发受控后续业务动作。
- 加签与补签拥有不同动作、权限、状态和历史展示，不得共用一个含糊的“新增审批人”语义。

### 4.6 转办、委托与授权代理

- `TRANSFER` 将当前任务责任转移给另一有效办理人；转出人失去当前办理权，转入人获得同一任务的受控办理权，任务对象不被复制成双活。
- `DELEGATE` 保留原责任人，受托人完成后按节点配置回到原责任人确认或受控完成；委托链、受托动作、回归状态和最终责任清晰。
- `AUTHORIZE` 是带开始/结束时间、流程范围、节点/业务条件和授权主体的代理规则；只对生效期间新进入或明确允许接管的任务生效。冲突、循环代理、自我代理、跨租户和失效用户必须拒绝。
- 三者均不得静默改写历史办理人、候选快照或原审批意见；撤销、到期、人员停用及组织变更具有确定行为。

### 4.7 撤回、沟通与废弃

- `WITHDRAW` 只允许发起人在设计允许、尚未越过不可撤回边界且没有冲突终态时撤回；撤回关闭当前任务并形成明确实例状态，重复请求不产生第二次效果。
- `COMMUNICATE` 向指定有效人员征询意见，不转移任务责任、不授予审批结算权。沟通回复独立于审批意见保存，并关联发起人、接收人、任务、轮次和时间。
- `DISCARD` 仅允许明确授权的主体终止无效实例；必须记录前后状态、理由、操作者、被关闭任务与通知结果，不能作为普通驳回或数据清理捷径。
- 三类动作的可用状态、按钮、深链、服务端权限和负向结果一致；越权或过期请求零副作用。

### 4.8 办理时限与受控自动动作

- 人工节点可配置办理时限、到期提醒、升级/催办和有限自动动作；配置在发布时校验并随版本冻结。
- 自动动作只允许本方向明确登记的通过、不通过或转交策略，使用与人工动作相同的状态机、幂等、权限边界和审计模型，不开放任意脚本。
- 调度重复、服务重启和多实例竞争只触发一次合法效果；通知失败不回滚已经合法完成的审批动作，也不把未完成动作伪装成成功。
- 手动催办继续保持不改变审批结论的语义；提醒、催办、升级和自动处置在轨迹中可区分。

### 4.9 受控节点函数

- 提供可注册、可版本化的审批人解析函数 `resolveParticipants(context)` 与结果处理函数 `handleResult(context, nodeResult)` 产品契约；具体内部接口结构由 Executor 决定。
- 函数以稳定标识和版本进入统一注册表，发布时验证存在、启用、输入输出 schema、允许节点、超时和失败策略；运行实例冻结实际版本。
- 上下文限于租户、发起人、流程/实例/节点、表单版本快照、白名单变量、既往节点结果和幂等标识。输出只允许有效用户标识、解释摘要及白名单流程结果变量。
- 未知版本、超时、异常、非法用户、跨租户对象、越权变量、输出超限和重复调用具有确定失败或已配置降级结果，并完整审计。
- 生产路径禁止管理员上传或执行任意 Java、JavaScript、远程脚本及浏览器对象；函数输出不能绕过节点状态机、表单校验或审批权限。

### 4.10 审批意见表单与历史快照

- 普通审批、会签、加签、补签和退回新轮次均可使用默认备注或绑定一份已发布的审批意见表单版本。
- 意见表单复用 I2 组件与服务端校验，但必须先形成组件适用矩阵；无法满足不可变快照、对象权限或历史回显的组件不得在审批场景中伪装可用。
- 主表单和流程变量只能向意见表单执行声明式只读初始化映射；意见提交不得反向修改主表单。映射字段、来源版本、初始值摘要和用户最终值可追溯。
- 每份意见保存实际定义快照或等价不可变引用，绑定实例、节点、任务、轮次、办理人、动作和时间。后续修改/停用意见表单不得改变历史解释。
- 前端使用统一意见渲染能力，不继续把不同控件硬编码在任务详情页形成第二套组件解释。

### 4.11 权限、幂等、审计与通知一致性

- 至少区分流程设计/发布、普通办理、加签、补签、转办、委托、授权代理、撤回、沟通、废弃及超时管理权限；页面隐藏不替代服务端授权。
- 所有写动作携带稳定请求标识并绑定当前任务/实例状态；重复、并发、超时后重查只产生一次合法业务效果。冲突响应返回既有结果或明确状态，不盲目重放。
- 审计至少记录租户、定义版本、实例、节点、任务、轮次、原责任人/实际办理人、代理关系、动作、意见快照、请求标识、前后状态、取消原因和时间。
- 通知由统一入口触发并关联实际动作结果；通知失败单独可查，不反转审批状态。I3 只要求既有站内信和事件契约覆盖新增动作，不提前验收 I6 外部渠道。
- 所有列表、详情、深链和接口执行租户、用户、任务归属与对象权限；取消、失效、转出或过期任务零串读、零串办。

7. APPROVE、DISAPPROVE、RETURN、REJECT 在普通审批和会签中具有不同稳定语义；页面、HTTP、任务、意见、轨迹、通知和实例终态逐项一致。
8. RETURN 只能选择合法历史人工节点并生成新轮次；旧轮次无双活任务，表单可改范围、重走路径、意见和取消原因可回看。
