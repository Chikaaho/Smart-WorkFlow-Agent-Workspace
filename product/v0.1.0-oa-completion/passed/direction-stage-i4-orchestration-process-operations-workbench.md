## 3. 产品范围

### 3.1 动态并行编排

- 动态并行节点从主表单或流程变量中的受控集合取值，进入节点时冻结来源对象、解析结果和汇聚策略。
- `参与部门` 是本阶段强制主场景：服务端校验租户、部门有效性与负责人，按稳定部门标识解析有效负责人；重复部门和同一负责人按可解释规则去重。
- 空集合、负责人缺失、失效对象、跨租户对象和超过安全上限必须在设计/发布或运行入口得到确定结果。允许管理员选择“阻止运行”或明确配置的受控策略，不得静默跳过。
- 每条分支记录来源部门、负责人、任务、动作、意见、取消原因和汇聚结果；运行中表单或组织变化不改写已冻结分支。
- 汇聚复用统一共识规则并保证并发、重复请求和恢复后只结算一次、只形成一个流程终态。

### 3.2 流程模板中心

- 模板按分类、状态、版本和管理范围集中维护，支持分级授权、查看、复制、停用及“复制后编辑并发布”。
- 模板是创建流程定义的受控来源，不直接改写已发布定义、运行实例或历史记录；模板版本和派生定义保持可追溯关系。
- 无权管理员不可见、不可复制或修改超出管理范围的模板。

### 3.3 监控、干预与基础分析

- 有权管理员可按流程定义、实例、发起人、状态、节点、办理人和时间检索实例，并查看当前节点、瓶颈、超时和失败原因。
- 实例挂起、恢复、终止和迁移办理人逐项授权；每次干预记录操作者、原因、对象、前后状态、受影响任务和时间。定义级挂起/激活与实例级干预不得混为一条状态。
- 分析至少覆盖发起量、完成量、平均与分位耗时、节点停留、超时、退回/驳回和办理人工作量；指标口径固定并可从汇总穿透到当前身份有权查看的真实实例。
- 数据范围同时作用于汇总和明细，不得用“明细拒绝”掩盖汇总已泄漏。

### 3.4 流程专用跨系统接入

- 外部应用使用稳定应用身份绑定租户和授权范围，可发起流程、查询状态、办理被授权的嵌入式任务并接收状态回调。
- 外部发起必须复用正式表单校验、版本解析、流程权限和状态机，不得直接绕过表单提交链调用底层启动能力。
- 入站请求具备鉴权、时间窗口、防重放、幂等键、租户边界和审计；出站回调具备签名、重试、去重、失败可查及敏感字段过滤。
- 同一业务键和幂等键的重复请求只能产生一次合法业务效果；回调失败不回滚已经合法完成的流程动作。

### 3.5 批量审批

- 审批人可对其当前有权办理且允许批处理的任务提交批量动作，服务端逐项校验归属、状态、版本、意见要求和业务权限。
- 返回逐项成功/失败与稳定任务标识；单项失败不把其他项伪装为失败或成功，也不允许整批响应掩盖实际部分执行结果。
- 绑定强制意见表单、必须逐项阅读或不允许批处理的节点不得通过批量入口绕过；跨用户、跨租户、已取消、已完成和重复任务必须拒绝且零额外副作用。

### 3.6 流程交接

- 有权管理员按同一租户内的来源用户、目标有效用户、流程范围和生效时间发起离岗/调岗交接。
- 默认只迁移选定范围内尚未完成的可办理任务；有效期内的未来代理规则只有明确勾选并通过双方、时间和流程范围校验时才随迁。抄送记录、已办任务、历史意见和已过期规则不自动迁移。
- 每次交接生成可复核清单，逐项记录迁移前后责任人、结果和失败原因；历史办理人与意见不可改写，失败项可安全重试且不重复迁移成功项。

### 3.7 完整工作台与移动端

- 统一工作台包含我发起的、草稿、流程分类/常用事项、待办、已办、抄送和消息入口，并保留用户个性化布局、默认布局与权限变化回落。
- 各列表使用服务端当前身份，提供必要筛选、分页和稳定排序；取消且未办理的任务不进入已办，抄送不授予审批权，消息摘要和深链再次执行对象权限。
- 流程分类或常用事项直接打开当前用户可见的已发布表单/流程版本，不让用户选择底层引擎定义。
- 同一实例在草稿、发起、运行、待办、已办、退回、加签、抄送和终态入口保持同一对象身份与可解释状态。
- 本阶段移动端采用响应式 Web/H5 作为正式形态，至少覆盖发起、草稿、待办办理、意见表单、附件/外键授权回显和结果查询；可打开桌面页面但无法完成可用交互不算移动交付。

## 4. 架构与权限边界

- 流程图、定义版本、实例、任务、节点能力和状态继续使用 I3 锁定的单一权威，不建立运营专用第二套流程状态或任务表。
- 动态并行、普通审批、会签和抄送统一消费 P58 参与人注册表；现存审批旧解析路径必须在受影响范围内收敛，不能长期保留两套生产参与人语义。
- 所有管理、运营、分析、批量、交接和开放接口同时执行租户、菜单/动作、数据范围与对象权限；前端隐藏不替代服务端拒绝。
- 历史定义、运行实例、任务、意见、分支快照和审计记录不可被模板、组织变化、交接或运营干预静默重写。

## 5. 本阶段产品裁决

1. **移动端形态**：`0.0.3` 采用响应式 Web/H5，不要求原生 App 或小程序真机；PC 与移动仍必须使用同一业务对象、权限和流程语义。
2. **外部联调对象**：I4 验收使用本机或受控环境中的真实 HTTP 对端即可证明签名、重试、去重和失败恢复；不绑定特定第三方厂商。若后续声明某第三方正式兼容，需另交该系统真实行为证据。
3. **交接口径**：默认迁移未完成任务；代理规则为显式可选项，不默认随迁。历史、抄送和已完成对象永不因交接改变归属。

## 6. 验收边界

1. 同一真实表单选择多个有效部门，运行时冻结负责人分支并正确汇聚；重复、空集合、缺负责人、失效、跨租户、超上限和中途改表单均有确定行为。
2. 静态条件分支的两个条件出口、默认出口和类型错误在 I4 候选上保持既有正确行为；只有受影响时重采。
3. 模板分级授权、复制后编辑和发布使用真实定义，且不改变来源模板、已发布版本或运行实例；无权身份零可见、零写入。
4. 有权管理员以七类条件检索实例，完成挂起/恢复/终止/迁移中的适用动作并回读前后状态与审计；无权身份拒绝且无状态变化。
5. 基础分析各指标使用真实实例计算，平均/分位口径可复算，汇总与有权明细一致，越权汇总和穿透均被拒绝。
6. 批量审批包含同批成功、业务失败、无权、已取消和强制意见表单任务，逐项结果与最终任务/实例/动作记录一致，无重复推进。
7. 流程交接在选定范围内迁移未完成任务并按显式选项处理有效代理规则；历史零改写，失败重试零重复，越权和跨租户零迁移。
8. 外部应用经授权发起同一真实表单流程、查询状态并收到真实签名 HTTP 回调；覆盖重复请求、防重放、回调失败重试、去重、敏感字段和越权拒绝。
9. 管理员、发起人、多个审批人、代理/受托人、抄送人和无权用户从工作台访问同一实例；页面、HTTP、持久化、轨迹、审计与消息使用同一对象身份，跨用户/租户零串读串办。
10. 同一用户在 PC 与响应式移动端完成发起、草稿、待办、意见表单、附件/外键回显和结果查询，权限与状态一致，不以静态页面代替交互。
11. 模板、监控、分析、批量、交接和开放接口的数据库升级在 H2/PostgreSQL 使用同一迁移身份，已有定义、运行实例和历史记录保持兼容。
12. Server/Web 运行受影响验证和工程宪法要求的正式门禁；行为证据绑定候选 SHA、身份、租户、定义/实例/任务、请求、持久化、页面/HTTP、清理和原始结果。结构、Mock、自述或接口存在不替代真实行为。

- 不建设原生 App、小程序客户端、通用 API 管理平台、企业集成总线、独立流程大数据平台、AI 流程优化、自由流程或流程仿真。
- 不重做 I1— I3 已锁定能力，不因 I4 扩展表单设计器、人工审批动作或通知渠道范围。
- 不核销 P60 或开放 P 编号，不创建 `0.1.0` 标签、Release 或对外发布声明。

## 8. 风险与停止条件

- 动态分支若无法证明冻结快照、来源审计、单次汇聚和单一终态，停止扩大场景并先收敛一致性。
- 参与人双路径、图/定义/任务双权威或运营侧派生状态成为生产事实时，不得进入阶段验收。
- 监控、分析、工作台、消息深链或开放接口出现跨租户/跨用户泄漏时立即停止后续扩展并修复权限边界。
- 模板、干预或交接若改写历史，必须停止自动迁移并提交兼容与恢复边界。
- 本机真实 HTTP 对端可用，不得把未实现的开放接口包装成外部阻塞；真实工具限制出现时按终态契约记录实际结果和替代路径。
