## 3. 规划裁决

### 3.1 范围冲突裁决

P60 总方向 §3.9 的六类通知渠道全部属于 I6 和 `0.1.0` 验收范围。总方向 §7 的冻结对象仅指“微信小程序客户端及其 SSO、通知”，不冻结响应式 Web/H5，也不冻结短信、飞书、钉钉、企业微信、邮件和站内信。不得以 I5 的 Provider 免验裁决推导 I6 通知免验。

### 3.2 通知可靠性与审批事务

- 已合法提交的审批动作、任务结算和流程推进不得因通知发送、Provider 超时或回执失败而回滚。
- 流程事件、抄送、催办、显式通知节点和批量发送必须汇入一套持久化投递意图与投递记录权威；不得保留“事件走旧入口、节点同步直发、批量另行生成”的三套不可勾稽副作用。
- 流程定义发布时发现必需模板、接收人规则或已启用渠道配置不合法，应明确拒绝发布；运行时 Provider 故障只形成可重试的失败投递，不回滚审批业务。纯通知节点完成业务入队后即可推进，最终送达状态由通知域追踪。
- 进程内 `AFTER_COMMIT` 事件可作为唤醒手段，但不能是唯一可靠事实；服务重启或瞬时故障后必须能从持久状态恢复未完成投递。

### 3.3 单一通知对象与幂等

- 一次业务通知由租户、事件类型、业务对象、事件发生次序、接收人、渠道和模板版本形成稳定身份；同一身份的并发或重复请求只产生一次业务投递效果。
- 合法的再次催办、下一办理轮次或新的业务事件必须具有新的稳定发生标识，不能被过宽唯一键误杀。
- 业务通知、每次投递尝试和 Provider 回执分层记录；重试追加尝试，不覆盖历史，也不新建第二条业务通知。

### 3.4 模板、规则、接收人与订阅

- 模板按事件和渠道定义主题、正文或卡片、变量白名单与受控跳转目标；发布后版本追加且不可被后续编辑静默改写，历史投递固定引用实际模板版本。
- 变量只允许服务端登记的白名单键，缺失、未知、类型不符或超过长度限制在发送前明确失败；HTML/卡片渲染按目标格式转义，禁止脚本、任意表达式和任意外链。
- 通知规则定义事件开关、适用流程/对象、接收人规则、渠道顺序或组合和失败策略。接收人由服务端按当前租户、流程快照和组织权威解析，不接受客户端直接指定手机号、邮箱或 Provider 外部主体来绕过用户身份。
- 必须送达的待办和安全/状态通知至少保留站内信，不允许普通用户完全关闭；用户只能在管理员允许范围内选择可选外部渠道或非强制事件。订阅变化不改写已产生的通知。

### 3.5 六渠道边界

- 站内信是本地持久收件箱，不伪装为外部 Adapter；支持服务端真分页、稳定排序、未读数、单条/全部已读、删除边界和受保护的业务跳转。
- 短信以 Owner 选定并可控验证的一家 Provider 作为 `0.1.0` 实际交付对象；Provider 未选定前完成通用契约与安全配置边界，但不得声称短信完成。
- 邮件以受控 SMTP 或邮件服务完成 TLS、发件身份、成功/失败与可控收件箱验证；SPF/DKIM 等域名条件如由 Owner 提供，证据只记录结果，不记录秘密。
- 飞书、钉钉、企业微信分别建立独立生产 Adapter 和租户级配置，不复用 I5 SSO 凭据语义冒充通知配置；三者逐一验证成功与失败，不相互替代。
- 系统级启用的 Adapter 缺少必需非秘密配置或仍为占位值时启动 fail-fast；租户级渠道只有在配置完整性验证通过后才允许启用。默认禁用不算已交付。

### 3.6 权限、租户与敏感信息

- 通知写入租户由服务端认证上下文或已验证的异步业务信封确定；请求字段不能覆盖权威租户。模板、规则、订阅、消息、尝试、回执和重试全部跨租户 fail closed。
- 收件人查看正文前同时校验当前用户、租户和业务对象权限；深链只保存受控对象类型与稳定 ID，由服务端生成同源目标并在打开时重新鉴权，不保存或执行任意 URL。
- 有权管理员的发送记录默认展示必要摘要和脱敏接收人，不默认返回完整正文、联系方式或 Provider 原始响应；查看必要详情须独立权限并保留审计。
- 密钥、票据、联系方式、完整正文和 Provider 原始响应不得进入前端状态、普通日志、SQL 参数日志、截图或回执。现有全量 SQL 参数输出若会暴露上述内容，必须在 I6 受影响范围内收敛。

### 3.7 PC、移动 H5 与管理闭环

- 管理端完成模板版本、渠道配置、通知规则、投递记录、尝试明细和授权重试；按钮显隐与服务端权限同源，构造请求仍须拒绝。
- 用户端完成 PC 与移动 H5 的同一收件箱、未读状态、分页、全部已读、删除、订阅偏好和受保护跳转；两端读取同一消息 ID、已读状态和对象权限。
- 默认真实后端模式下路由可达；Mock 只用于开发隔离，不得遮蔽错误路由、契约漂移、权限缺口或不存在的 Provider 行为。

### 3.8 0.1.0 版本收口

- 建立单一机器可读产品版本权威，并将 Server、Web 和交付材料投影为 `0.1.0`；不得继续以互不一致的 `1.0.0-SNAPSHOT`、`0.0.0` 或文档文字作为候选版本。
- 形成用户可读 `CHANGELOG`/发布说明、从现有受支持基线升级到 `0.1.0` 的步骤与兼容边界、可执行或可判定的回滚/恢复说明、数据库迁移清单、配置变化清单和发布 manifest。
- manifest 固定 Workspace、Server、Web 候选 SHA，迁移终点、测试原始结果、文档和已批准例外；候选固定后只允许通过新回执审查的变更进入，任何代码或迁移漂移使受影响证据失效。
- 标签、Release、远端合并或推送不由本方向自动授权；到达对应动作前必须向 Owner 说明远端、分支、精确范围与风险并取得明确授权。

## 4. 验收标准

### A. 统一通知底座

1. 六类渠道契约完整且只有一套生产分派权威；生产运行中不存在 dev 调试桩返回成功、不可达旧 Hook 或缺 Adapter 静默冒充成功。
2. 同一真实流程对象的待审批、加签、退回、驳回、节点通过/不通过、流程通过/不通过、抄送和催办逐项产生可勾稽的业务通知；重复事件和并发请求只产生一次合法效果，新的轮次或催办仍可生成新通知。
3. 审批动作先形成合法业务终态，再产生持久投递意图；Provider 失败、超时、服务重启及重试均不回滚审批，未完成投递能够恢复并最终进入明确终态。
4. 每条业务通知可回读租户、事件、业务对象、接收人、渠道、模板版本和幂等身份；每次尝试追加记录开始/结束时间、状态、失败分类、外部消息标识与脱敏回执摘要。

### B. 模板、规则与安全

5. 模板按事件与渠道版本化发布；修改后历史通知仍按旧版本解释。未知/缺失变量、非法格式、脚本内容和任意跳转目标在发送前被拒绝，合法内容按目标格式安全渲染。
6. 管理员配置事件、接收人和渠道规则后真实生效；普通用户只能在允许范围调整可选订阅，强制站内待办与安全/状态通知不可被关闭。
7. 跨租户模板、规则、订阅、消息、尝试、回执和重试全部被拒绝；调用方伪造 tenantId、recipientId、外部联系方式或业务对象不能产生投递或读取。
8. 普通用户只能读取自己的有权消息；管理员记录默认最小暴露；正文、联系方式、凭据和 Provider 原始响应在前端、普通日志、SQL 参数输出和回执中零残留。

### C. 站内信与多端

9. 真实站内信收件箱完成服务端分页、筛选、稳定排序、未读数、单条/全部已读和删除边界；刷新、并发已读和重复请求结果一致。
10. PC 与移动 H5 使用同一消息和已读状态完成列表、详情、偏好和跳转；无权用户、跨租户用户或对象权限被撤销的用户通过页面、深链和构造请求均不能访问目标对象。
11. 管理端完成模板、渠道、规则、记录、尝试与授权重试；用户端与管理端在真实后端菜单下可达，前后端契约包含一致的事件、渠道与状态集合，不依赖 Mock 补齐。

### D. 五类外部渠道

12. 短信、飞书、钉钉、企业微信、邮件分别以真实测试应用、沙箱或实际可控账号完成一次成功、一次可控失败和一次恢复/重试；五者逐一提供 Provider 侧结果与本地记录勾稽，不能相互替代。
13. 每个外部渠道的启停、缺失/占位配置拒绝、超时、限流或 Provider 错误、外部标识和回执语义可判定；启用时无默认秘密，秘密不进入仓库或证据。
14. 服务端从同租户有效用户解析手机、邮箱或 Provider 稳定主体；失效用户、缺少联系方式、跨租户主体、重复绑定或未授权目标明确失败，不接受客户端原始地址旁路。

### E. 版本候选与回归

15. 单一机器版本权威及 Server/Web 投影均为 `0.1.0`；发布说明、升级、数据库兼容、运行中实例边界、回滚/恢复、配置清单和 manifest 内容一致且可回读。
16. 使用至少管理员、发起人、多个审批人、代理/受托人、抄送人和无权用户，在 PC 与移动 H5 对同一流程对象完成从发起、办理到终态及通知送达；页面、HTTP、流程轨迹、持久化、Provider 结果和清理互相勾稽。
17. H2 与 PostgreSQL 从受支持旧基线升级到 I6 终点，既有通知、模板、流程实例和历史记录保持可解释；不得通过重建数据库、删除失败数据或替换对象证明升级。
18. Server/Web 受影响聚焦验证和正式全量工程门禁通过；I1— I5 只有受 I6 改动影响的身份、权限、流程事件、工作台、移动、迁移与日志集合重验。最终命令、计数、候选 SHA、迁移版本和原始结果均可回读。

## 7. 风险与停止条件

- 任一通知入口继续同步回滚审批、存在多套投递权威或无法证明幂等恢复时，停止扩大渠道并先收敛通知底座。
- 任一跨租户/跨用户读取、重试、深链访问或外部联系方式旁路成立时，不得进入候选收口。
- 新迁移会重新解释或丢失既有消息、模板、流程实例和历史版本时，停止自动迁移并回传兼容方案。
- Provider 无真实结果时只报告实现与未验证边界；不得用调试桩、模拟回执或另一渠道结果替代。
- 候选固定后出现代码、迁移、依赖或配置漂移，受影响证据失效并重新固定候选；不得在 manifest 中手抄不一致 SHA 或计数。
- 若 P0 范围与外部可用窗口无法同时满足，返回剩余验收原子、已完成独立工作和外部解除条件，由 Owner 裁决范围或时间，不静默降级。
