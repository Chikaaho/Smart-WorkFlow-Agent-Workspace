## 1. 阶段目标

先收口会阻断非零租户身份进入 OA 主链的租户归属、生产认证安全和权限 fail-open，再完成企业微信、飞书、钉钉三种 SSO。三个 Provider 必须统一映射到本地用户、租户、角色、权限和数据范围，不建立第二套身份、会话或授权体系。

I5 完成后，默认租户与非零租户均能以服务端认可的身份创建并使用本租户表单/流程对象；第三方登录与第一方登录生成相同 `LoginUser`/会话结果，本地账号、角色、租户状态变化能够一致收敛。

## 3. 产品与架构边界

### 3.1 租户所有权与流程主链

- 表单定义、表单配置、发布快照、列表配置、流程定义、表单绑定、工作台布局、流程实例与任务均归属明确租户；用户动作从服务端认证上下文取得租户，不接受客户端覆盖。
- 相同业务 `formKey` 允许不同租户独立使用，同一租户内保持唯一。动态物理表名属于数据库全局命名空间，必须以租户感知方式生成并保持全局无碰撞；不得直接把物理表名唯一约束改成租户级而制造两个配置争用同一物理表。迁移必须兼容现有租户 0 数据，不通过重建数据库、改写历史实例或删除冲突数据完成升级。
- 流程定义按租户发布和查找，表单绑定只能关联同租户的表单与流程定义。生产启动不得隐式创建租户 0 的业务定义或绑定；dev/test 骨架与正式发布链物理或配置隔离。
- 草稿提交、同步/异步命令、OpenAPI 和 IoT 发起均使用同一租户归属规则。非浏览器调用必须由已登记应用、设备或事件载荷提供经过校验的租户与代理身份；缺失、冲突或失效时明确拒绝。
- 清除生产业务路径中以 `0L` 或等价兜底替代真实租户的行为。默认租户常量、系统操作人、迁移 seed 和测试夹具只有在其边界真实成立时保留，不以全局替换制造新语义。

### 3.2 租户有效性与权限收敛

- 第一方与第三方登录、refresh、缓存重载及关键异步身份恢复统一校验租户存在、启用状态与有效期；租户失效后不得建立新会话，并使既有会话在下一次权威装载时收敛。
- 本地账号停用、角色撤销、密码处置、租户禁用和第三方解绑分别触发与风险相称的会话撤销；Provider 登录成功本身不授予菜单、接口、审批或数据权限。
- 没有有效角色的用户采用最小权限/无数据范围，不得回落 `DataScope.ALL`。前端权限显隐在真实会话为空权限时默认隐藏，服务端拒绝仍是最终权威。

### 3.3 生产认证与运维暴露

- 固定验证码只存在于受控 dev/test 条件，生产配置或非 dev/test profile 即使误开开关也不得返回固定答案。
- JWT、Druid 和 Provider 凭据无可工作的仓库默认值；生产缺失或仍为占位值时启动/启用明确失败。秘密不进入源码、普通日志、前端、截图或回执。
- 生产 Actuator/监控入口按最小集合暴露；健康详情、指标和管理入口不能匿名泄漏运行信息。开发文档与调试入口不得随生产 profile 自动开放。

### 3.4 三 Provider SSO

- 企业微信、飞书、钉钉分别具备租户级配置、启停、授权发起、回调/换票、身份绑定、已绑定登录、解绑/失效、错误恢复和持久审计。
- Web 采用服务端授权发起与服务端回调/换票，完成后只向同源前端返回受控结果；不引入浏览器端 Provider SDK，不放宽既有 CSP，不增加前端跨域直连。
- 每次授权使用不可预测、限时、与租户/Provider/发起会话绑定且一次性消费的 `state`；Provider 支持的 `nonce` 和回调白名单同时生效。回调 code、token、secret 与原始敏感响应不得进入 URL 残留、前端状态、普通日志或审计正文。
- 外部身份以 Provider 官方稳定主体标识绑定本地账号。绑定键至少包含 Provider、租户和外部稳定标识；同一外部身份重复绑定、冲突绑定、跨租户绑定以及失效本地账号绑定必须明确拒绝。
- 已绑定登录只负责定位本地账号，最终 `LoginUser`、角色、权限、数据范围和 refresh/access 会话均由现有服务端权威装载。绑定不得写入 `sys_user_role` 或直接授予权限。
- 配置变更、授权发起、绑定、解绑、登录成功/失败、重放、冲突和越权拒绝形成最小持久审计；审计只保存必要标识、结果、时间、操作者和脱敏原因，不保存秘密或票据。

## 4. 验收标准

### A. 租户与流程前置收口

1. 默认租户与至少一个非零租户分别创建、保存、发布并读回同键表单定义/配置/快照/列表配置，双方零串读；持久化租户与操作者真实租户一致。
2. 两个租户可以使用相同业务 `formKey` 而互不冲突；其动态物理表名全局无碰撞，同租户重复 `formKey` 仍被数据库约束拒绝，H2 与 PostgreSQL 迁移链均证明升级与唯一性语义。
3. 非零租户发布本租户流程定义并建立同租户表单绑定后，真实完成表单提交、命令受理/消费、Flowable 启动、业务实例、任务、轨迹和通知事件；各层 tenantId 使用同一对象链勾稽。
4. 跨租户表单、流程定义、绑定、实例、任务或工作台布局的读取、更新、发起和办理均被拒绝；不得静默 no-op、回退租户 0 或启动另一租户定义。
5. 工作台布局按租户与用户保存，同一 userId 在不同租户的布局互不覆盖。
6. 缺失租户、信封/身份租户冲突、租户停用或过期时，浏览器、异步、OpenAPI 与 IoT 发起均 fail closed，并返回可判定结果。

### B. 认证与权限安全

7. 生产 profile 无法启用固定验证码；缺失/占位 JWT、Druid 或 Provider 凭据时明确失败，实际日志和配置回读不泄漏秘密。
8. 生产匿名请求不能取得 Actuator 详细健康、指标、环境或管理信息；允许的最小健康探针只返回规划允许的非敏感结果。
9. 无有效角色用户不取得全量数据范围；真实空权限会话的前端管理入口默认不可见，构造请求仍由后端拒绝。
10. 第一方登录、refresh、登出、改密、停用与撤权行为保持既有契约；租户禁用/过期在第一方和第三方登录后产生相同拒绝与会话收敛结果。

### C. 三 Provider 独立闭环

11. 企业微信、飞书、钉钉分别以真实官方测试应用或可控应用完成授权发起、回调换票、绑定、已绑定登录、解绑后拒绝和 Provider 失败恢复；三者逐一提供真实结果，不相互替代。
12. 每个 Provider 的 `state` 重放、过期、篡改、Provider/租户错配和白名单外回调均被拒绝；同一授权 code 不产生第二次绑定或会话效果。
13. 重复绑定、同租户冲突绑定、跨租户绑定、本地账号停用、角色撤销、租户禁用及无权限用户均有真实负向行为；外部登录不绕过本地权限链。
14. PC 与响应式移动 H5 使用同一会话对象、守卫和权限结果；登录、绑定、解绑、错误恢复页面与后端错误码/状态同源，不以 Mock 页面作为完成证据。
15. 三 Provider 的配置、绑定、登录和拒绝审计可按租户、Provider、本地用户、外部主体摘要和结果查询；原始 code/token/secret/敏感响应在前端、普通日志、SQL 参数输出、审计和回执中均为零残留。

### D. 回归与候选

16. 受影响的 Server/Web 聚焦验证、H2/PostgreSQL 迁移全链及两仓正式工程门禁通过；测试计数、命令、候选 SHA、迁移终点和原始结果可回读。
17. I1— I4 受影响最小集合通过：第一方认证、`/system/auth/me`/menus、表单版本链、流程发起与任务归属、跨租户数据隔离、工作台、OpenAPI 签名链和 PC/移动同会话。未受影响的锁定项不重验。

## 7. 风险与停止条件

- 若迁移会改写历史租户 0 表单、流程定义、运行实例或物理表含义，停止自动迁移并提交兼容边界。
- 若租户身份需要由客户端、回调参数或 Provider 自述直接决定，停止接入并收敛为服务端配置/绑定权威。
- 任一跨租户读取、绑定、登录、发起或任务办理成立时，不得继续下一个 Provider，也不得提交阶段完成。
- 若为 SSO 新建角色、权限、会话或参与人权威，必须先删除双权威路径。
- 缺少真实 Provider 条件不允许虚构完成；只冻结对应外部验收项，不停止授权内的其他独立工作。
