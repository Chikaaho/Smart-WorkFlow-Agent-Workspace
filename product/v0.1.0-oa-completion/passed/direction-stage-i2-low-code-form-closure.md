## 4. I2 产品契约

### 4.1 统一组件契约

- 基础组件至少覆盖：单行文本、多行文本、数字、单选、多选、下拉、日期、时间、人员选择、部门选择、字典、附件、图片和说明文字。
- 高级组件覆盖可增删行、逐行校验的 TABLE/子表，以及以稳定业务 ID 保存、按授权业务值回显的 REFERENCE/外键。
- 组件的设计配置、服务端 schema、发布校验、PC/移动渲染、草稿、正式提交、审批查看和历史解释保持同一字段身份、类型和版本语义。不得出现只在设计器、Mock 或某一个渲染入口可用的“孤岛组件”。
- 人员和部门选择消费 I1 的有效租户组织对象；失效、越权、跨租户和不存在对象在服务端拒绝。附件、图片与外键均校验当前表单记录及目标对象授权。

### 4.2 公式字段

- 公式只使用已登记字段、受控运算符和白名单函数，具有明确输入类型、输出类型、空值、精度、日期时间和错误语义；禁止任意 JavaScript、Java、脚本或动态代码执行。
- 字段依赖必须可判定，循环依赖和未知字段在保存或发布前被拒绝；客户端可提供即时预览，但正式提交和持久化结果由服务端按同一契约重算。
- 正式提交保存公式定义版本、输入依据与计算结果；历史查看使用当时结果，不因后来修改公式或运行环境而漂移。

### 4.3 受控外部数据源

- 表单只能引用管理员已登记、已启用且当前租户有权使用的数据源能力，以稳定标识和版本化查询契约绑定；表单定义不得保存原始密钥、任意连接串、任意 SQL、任意 URL 或可执行脚本。
- 输入映射、输出 schema、允许字段、超时、行数/响应大小、失败策略、审计和敏感字段处理必须明确；跨租户、越权对象、未知字段、超限与不可用源得到可判定失败，不静默返回伪空值。
- 设计预览与运行读取使用同一服务端安全入口。业务提交保存实际选用的稳定对象/值及必要来源摘要；历史回看不重新请求外部源改变已提交业务含义。

### 4.4 表单定义生命周期

- 未发布且无有效引用的草稿可以按可追溯软删除语义处置；已发布、已绑定流程、已有草稿数据、运行实例或历史数据的表单不得硬删除。
- 已发布表单使用停用语义：停用后禁止新的绑定、填报、正式提交和流程发起；既有运行实例、审批查看和历史记录继续按冻结快照可读。停用前已有但未提交的业务草稿可查看和导出，但正式提交需在表单重新启用后进行。
- 删除、停用、启用及拒绝原因可审计；前端隐藏入口不能替代服务端引用和状态检查。

### 4.5 列表展示配置

- 管理员可为表单的发布版本配置默认显示字段、字段顺序、可用筛选、默认排序和允许动作；配置持久化并在刷新、重登、PC/移动与不同用户之间按授权稳定生效。
- 本阶段交付表单级默认业务列表，不扩张为个人任意视图、看板、日历、图表或完整视图设计器。
- 列表查询由服务端执行字段、记录和动作权限；无权字段不能通过筛选、排序、导出、接口响应或错误信息侧漏。

### 4.6 字段、记录和动作权限

- 字段权限至少区分查看与编辑，并可按创建、编辑、只读/审批查看场景作用于 I1 的角色、用户或组织主体。无查看权字段不返回敏感值；无编辑权字段即使构造请求也不能被修改。
- 记录权限复用 I1 的租户、用户与组织数据范围，至少能表达本人、部门/部门树和明确授权范围；列表、详情、更新、删除、导入导出和流程关联使用同一服务端范围，不允许调用方选择是否启用安全过滤。
- 动作权限覆盖创建、查看、编辑、删除/停用、导入、导出和发起流程等本阶段实际动作；页面按钮、深链与真实接口结果必须一致。
- 权限撤销后新请求立即按当前身份收敛；已发布 schema 和历史数据解释保持稳定，但历史快照不赋予已撤销主体继续访问数据的权利。

### 4.7 PC、移动与全链版本一致性

- PC 管理端承担设计、配置、保存、发布和历史管理；移动 Web 不承担表单设计。
- PC 与移动 Web 均支持有权用户填报、字段交互、校验、附件/图片、人员/部门、TABLE/REFERENCE、公式/外部数据回显、草稿保存恢复、正式提交和只读回看；移动布局可响应式重排，但不得删字段、放宽校验或绕过权限。
- 发布版本冻结组件 schema、公式/数据源配置、列表解释和与业务数据相关的版本标识。后续编辑、停用或新版本不得静默改写既有草稿、实例、审批查看和历史记录。
- I2 只保证审批侧正确查看主表单；审批动作、会签、加签、意见表单等由 I3 处理。

## 6. 影响范围与关键风险

预期影响表单定义、动态数据、组织选择、附件/外键、列表查询、权限、安全外部数据接缝、PC/移动渲染和必要的前向兼容迁移；具体文件、接口、数据结构和实现步骤由 Executor 在工程宪法范围内决定。

关键风险：组件解释双权威、公式客户端可信、外部源突破出站与密钥边界、可选数据范围导致漏过滤、停用/删除破坏历史引用、列表字段侧漏、移动端另建简化 schema、发布后配置漂移。出现跨租户/跨用户读取、任意执行、不可逆历史重写、需要破坏既有发布快照或无法形成单一服务端权威时，停止扩张并提交方向冲突。

## 7. 阶段验收边界

1. G0 当前登记在执行侧权威材料中完成一致回读；I1、功能数、清单与 P 编号零漂移。
2. 同一真实表单包含全部规定基础组件及 TABLE/REFERENCE；完成设计、保存、发布、PC/移动填报、草稿恢复、提交、审批只读回显和历史回看，字段身份、值与版本一致。
3. TABLE 支持多行增删和逐行正反校验；REFERENCE、人员、部门、附件和图片使用真实对象，越权、失效、伪造和跨租户对象均被服务端拒绝且零副作用。
4. 公式覆盖多字段依赖、类型/精度/空值和日期时间等代表性行为；循环、未知字段、非法表达式和客户端篡改不能成为正式结果，历史公式值不漂移。
5. 受控外部数据源完成有权成功、无权、停用、超时、超限、输出不匹配和敏感信息不泄漏等真实服务端行为；不得用 BPM 既有表、SPI、Mock 或接口存在替代表单链路完成。
6. 表单草稿删除、发布后停用/启用、流程/数据引用拒绝和历史可读语义符合 §4.4；停用后无新提交或新发起，既有实例与历史不损坏。
7. 列表配置持久化字段、顺序、筛选、排序和动作；刷新、重登、PC/移动以及不同权限身份回读一致，无权字段和记录零侧漏。
8. 至少使用管理员、有权填报者、受限查看/编辑者、无权用户和跨租户用户，证明字段/记录/动作权限在页面、深链、请求和持久化结果中一致；构造请求不能绕过服务端。
9. 权限撤销、表单停用和定义后续变化后，新请求安全收敛，既有草稿、提交记录、流程实例、审批查看和历史快照仍由原版本正确解释。
10. 移动 Web 在实际移动视口完成同一表单的填报、校验、草稿、提交与只读回看；复杂组件无关键字段缺失、遮挡、横向不可达、假成功或仅打开桌面空壳页面。
