## 1. 目标（一句话）

让有权用户能够在图设计器中为 LLM 节点配置系统 Prompt 与用户 Prompt 模板，并使配置在保存、发布、重载和真实执行中保持一致、可预测且向后兼容。

## 2. 产品语义

- LLM 节点配置增加两个彼此独立的语义：
  - **系统 Prompt**：定义模型在该节点的角色、规则或背景；空白时不额外注入系统消息。
  - **用户 Prompt 模板**：定义本次节点调用的用户消息；未配置或空白时，保持既有行为，直接使用 `inputVar` 指向变量的原始值。
- MVP 模板仅支持命名变量的纯字符串插值，统一采用 `{{variableName}}` 占位符；变量来源是既有图执行上下文，不引入表达式、函数、条件、循环、脚本或第三方模板语言。
- 模板中同一变量可重复引用；变量值按普通文本替换，不作为模板再次解析，避免二次展开。
- 模板引用未定义变量时，必须在模型调用前确定性失败，并沿用图执行既有“未定义变量”错误语义；不得把未替换占位符发给模型，也不得静默替换为空串。
- 系统 Prompt 与用户 Prompt 模板均随图定义的既有 `GraphElement.config` 保存、回显、发布和版本化，不新增独立 Prompt 表或绕开图版本的数据源。
- 未包含新配置键的历史图必须保持原执行结果语义；既有 `modelId`、`inputVar`、`outputVar`、变量表、分支及执行历史语义不变。
- 所有实际消费图定义 LLM 节点的生产执行路径必须采用同一 Prompt 契约，避免设计器预览、图解释执行或其他既有执行入口产生不同消息结构；与图定义无关的 F01 模型管理能力不得被本轮扩展。
- 前端属性面板需清楚区分系统 Prompt、用户 Prompt 模板和输入变量名，并提示占位符语法、空白回退语义及未定义变量会导致执行失败。
- Mock 模式须与真实契约保持一致，至少覆盖保存回显、插值、默认回退和未定义变量失败，不得只保存字段而不体现执行语义。

## 3. 非目标

- 不做助手级角色 Prompt、全局 Prompt 库、Prompt 版本中心、Prompt 市场、预设模板或跨图复用。
- 不做 RAG 上下文注入、SSE 对话窗口、多轮对话编排、Token 统计、运行日志扩展或单步调试。
- 不支持表达式求值、条件模板、循环模板、函数调用、脚本、自定义过滤器或 `eval` / `new Function`。
- 不新增数据库迁移，不改变图定义表、执行历史表、节点轨迹表或模型配置表结构。
- 不改变 LLM 节点输出变量规则、LOOP/FORK/JOIN 调度、步数预算、错误分类体系或模型多 Key 轮询策略。
- 不扩展 `flow-graph` adapter 公共导出面，不顺带解决 I48 的边点击或命令式更新限制。
- 不新增默认用户、默认角色授权或新的权限码；沿用现有 Agent 图管理/执行权限边界。

## 5. 风险方向

1. **历史图回归**：缺少新配置键必须严格退化为当前 `inputVar` 原文调用，不能因默认空字符串或消息角色变化改变旧图结果。
2. **双重解析与注入**：变量值只能作为普通文本一次替换；禁止再次解析变量值中的 `{{...}}`，更不能演变为表达式执行。
3. **执行路径漂移**：若多个既有入口消费图定义，必须共享同一契约或证明语义一致，不能出现一个入口支持模板、另一个忽略配置。
4. **空值语义混乱**：缺键、空字符串和纯空白的回退行为必须一致；未定义变量必须失败，不能与空值变量混为一谈。
5. **敏感信息暴露**：Prompt 可能含业务数据，不得写入 URL、浏览器持久化、控制台日志或无必要的错误详情；测试不得固化真实密钥或敏感样例。
6. **Mock 假闭环**：仅证明字段能保存不足以验收；必须证明真实执行消息的角色、插值、回退和失败语义，Mock 与真实契约对齐。
7. **范围膨胀**：Prompt 配置容易被扩展为助手、RAG 或模板中心；这些能力全部留待独立方向。

## 6. 验收标准

1. 有权用户可在图设计器 LLM 节点中分别配置系统 Prompt 和用户 Prompt 模板；节点切换、保存、重新打开、发布及重新加载后内容保持一致。
2. 用户 Prompt 模板按 `{{variableName}}` 从既有命名变量表完成纯字符串插值；自动化证据至少覆盖单变量、多变量、重复变量、非 ASCII 文本及变量值自身含占位符样式但不二次展开。
3. 模板未配置、空字符串或纯空白时，真实执行保持历史行为：以 `inputVar` 指向变量的原始值作为用户消息；历史图无需迁移即可继续执行。
4. 系统 Prompt 非空时以系统消息语义参与模型调用，空白时不注入；用户消息与系统消息不得角色互换或简单拼成无法区分的单一字符串。
5. 模板引用未定义变量时，在模型调用前按既有未定义变量错误语义失败；不调用模型、不发送原始占位符、不静默置空，并进入既有失败执行与历史记录链路。
6. 所有实际消费图定义 LLM 节点的生产执行入口对新配置键、插值、回退和失败规则保持一致；若某既有 F01 路径与图定义无关，回执须提供不纳入的代码事实，而非为了形式一致擅自扩展。
7. `modelId`、`inputVar`、`outputVar`、变量写回、CONDITION/END、LOOP/FORK/JOIN、错误分类和执行历史查询均无回归；本轮不改变图调度或状态机。
8. 前端配置键与后端契约精确一致，空白配置不制造歧义数据；界面明确展示模板语法、默认回退及未定义变量失败提示，不使用 `v-html` 或动态代码执行。
9. Mock 覆盖配置保存/回显、默认回退、成功插值和未定义变量失败，并与真实接口字段及执行语义一致。
10. Flyway 与数据库结构零改动；回执须提供迁移范围核对证据。若发现零迁移无法达成目标，任务应报告方向阻塞而不是自行扩大范围。
11. 后端受影响测试与项目级回归、前端 `typecheck`、`lint`、`test`、`build` 均在 2G 上限下通过，测试数量不得低于当前基线后端 **685/0/0/0**、前端 **78 files / 760 tests**；前后端编译测试严格串行并提供同轮互斥证据。
12. 完成 §3.3 第10项知识库全量同步：M07-F02-02、current-status、功能追踪、known-issues、session-handoff、需求池与功能清单全文口径一致；无关清单行零漂移，并在回执中报告清单变更明细与知识库触碰文件清单。
