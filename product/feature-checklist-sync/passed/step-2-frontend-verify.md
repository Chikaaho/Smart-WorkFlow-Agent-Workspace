## 9. 详细执行方案

### 9.1 核实方法论（对每条明细逐条执行）

对功能清单中 M01/M02/M03/M04/M05/M06/M10 章节的每一条明细行（ID 格式 `Mxx-Fyy-zz`），按以下步骤核实：

1. 记录该行的 ID、功能、功能详情、描述（原文摘录，不改写）
2. 根据 §6 的模块映射，定位应在哪个前端模块中实现
3. 在该模块下搜索是否存在对应的视图组件（`.vue` 文件）、路由注册、API 调用函数
4. 若找到视图，进一步检查是否为真实交互界面（表单/列表/按钮绑定实际处理函数），而非仅路由占位（空白页面或"待开发"提示文案）
5. 按以下三档判定：
   - **✅ 已完成**：找到对应视图组件 + 有实际交互逻辑（调用 API / 表单校验 / 列表渲染等），与"功能详情"描述基本吻合
   - **🟦 开发中**：找到部分相关代码（如路由/菜单已注册但页面是占位提示，或只实现了描述中一部分子功能）
   - **⬜ 待开发**：未找到任何相关视图/路由代码，或仅存在菜单项无实际页面
6. 记录判定依据：具体文件路径 + 组件名（若判定为 ⬜，注明"已搜索 `<搜索关键词>`，无匹配代码"）

### 9.2 特别注意事项

- 不要仅因为"该明细所属模块整体标记为已完成"就默认判定 ✅ — 必须找到该条明细对应的具体代码证据
- 若一条明细描述横跨多个子功能，且其中只有部分子功能有前端实现，判定为 🟦 并在证据栏注明哪部分已实现、哪部分未找到
- Mock 模式（`msw` handlers）中存在对应 handler 不等同于真实页面已实现——需要同时确认存在对应的 `.vue` 视图和交互逻辑，仅有 mock handler 而无视图判定为 ⬜ 或 🟦（视具体情况）
- 权限相关明细注意区分"机制骨架已就位"（如 `v-perm` 指令存在）与"该具体明细对应的具体 UI 已实现"，这是两件不同的事，只判定前端侧
- 只判定**前端侧**实现状态。若某明细本质是纯后端功能（无用户可见界面，如某个纯后端校验规则），在证据栏注明"该明细无对应前端职责，前端侧不适用"，不要强行找前端证据
