# P45 登录安全有效挑战与行为证据补充方向

> 状态：READY（补充方向）
> 日期：2026-09-01
> 适用范围：仅补足第一次实现验收剩余安全语义与行为证据
> 主方向：`product/p45-login-security/ready/direction-p45-login-security.md`

## 1. 有效验证码挑战

- 挑战响应必须提供浏览器可渲染的验证码载荷，不得提供独立答案字段，也不得在文本节点、可访问元数据、文件名或其他结构中直接编码答案。
- 服务端仅保存答案摘要及验证所需元数据；前端只展示挑战载荷并提交用户输入。
- 验证码业务有效期固定为 300 秒。权威记录保留期必须长于业务有效期，使服务端能够在有效期结束后稳定判别“内容匹配但已过期”；记录保留期结束后按挑战不存在处理。
- 有效期、保留期、失败次数和消费状态均由服务端裁决；浏览器传值不能覆盖。

## 2. 原子消费与密钥轮换

- 同一挑战在真实 Redis 和真实认证服务链上并发提交时，最多一个请求完成原子消费并进入密码认证；其余请求不得签发 access/refresh token、写入额外登录态或改变其他用户状态。
- 密钥版本由服务端挑战绑定。新挑战使用当前版本；上一版本在既定重叠窗口内仍能解密其已签发挑战，窗口结束或版本退役后稳定拒绝。
- 密钥轮换证据必须包含当前版本、上一版本、重叠窗口内正向结果及退役后的反向结果；不得只用未知版本错误代替。

## 3. 登录态恢复行为链

- 当前正式部署使用的公开 API 前缀必须在等价浏览器环境中复现。证据覆盖登录响应 Set-Cookie、浏览器 Cookie 存储属性、刷新请求实际携带、refresh 响应、access 回填、session/menu 装配、F5、受保护深链和退出后刷新。
- 修改前与修改后使用相同公开前缀和同类环境，明确第一个失败点及修复后的对应结果。
- 两个用户、两个租户分别完成挑战、登录、恢复和退出，并进行交叉 UUID/Cookie 使用，证明挑战、Token、Redis 登录上下文、前端会话及路由身份不串用。

## 4. 原始证据包

每个剩余缺口只提交一份增量证据包，包含：

1. 输入版本：后端、前端 branch/HEAD、工作树状态和 P45 精确 diff 基线。
2. 实际修正文件及行为变化，不重复全部结构清单。
3. 脱敏请求、响应、Cookie 属性、Redis 状态和浏览器路由结果。
4. 实际命令、退出码和原始输出摘要；全量测试给出逐模块叶子计数与总计勾稽。
5. 正向目标断言与反向零残留断言。

不得把密码、验证码答案、私钥、access/refresh token 或完整 Cookie 值写入回执。敏感字段使用固定脱敏占位符，零命中检查只报告搜索范围、命令和结果计数。

## 5. 基线与迁移对账

- 后端全量计数相对当前正式 955、前端相对 110 files / 1060 tests、Flyway 相对 H2 V44 / PostgreSQL V44 逐项对账。
- V45/V46 必须披露迁移文件、提交来源、是否属于 P45 输入基线以及为何可被本轮测试采信。未经既有正式状态或当前任务授权的迁移不得借修改断言成为新基线。
- P45 未实际新增迁移时，最终回执不得把迁移版本变化归因于 P45；若 P45 必须新增迁移，应先回规划层裁决范围变化。

## 6. 终止条件

G1-G10 全部具有可复核行为证据后才能再次提交验收。任一真实环境、版本基线或密钥条件不可获得时，如实报告 `BLOCKED` 及缺失条件，不得用结构、Mock、单元断言或推算数字替代。
