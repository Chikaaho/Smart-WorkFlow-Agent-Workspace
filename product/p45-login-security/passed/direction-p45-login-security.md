# P45 登录安全与登录态恢复需求方向

> 功能编号：P45 / M02-F06-01
> 任务等级：L（认证、安全、跨前后端与正式状态跟踪）
> 状态：READY
> 日期：2026-09-01
> 权威探索：`search_fallback/p45-login-security-current-seams.md`、`search_fallback/p45-login-state-direct-cause-supplement.md`

## 1. 背景与问题

现有系统已具备 access/refresh 双 Token、refresh HttpOnly Cookie、轮换与重放撤销，但登录密码仍按普通 JSON 字段提交，验证码、客户端时间校验和一次性挑战尚未实现。生产页面刷新后存在返回登录页的问题；静态探索证明 access token 仅存内存是既定双 Token 职责，不是故障本身，真实断点需沿 Cookie 写入、携带、refresh、session/menu 和路由恢复链采集行为证据后确定。

## 2. 产品目标

1. 登录密码在浏览器离开前使用服务端公钥加密；服务端私钥、密码明文和完整解密结果不进入前端、接口响应或普通日志。
2. 密码认证前固定完成验证码正确性、验证码有效期和客户端机器时间校验，前一步失败时不得执行后续敏感校验。
3. 使用服务端一次性挑战抵御三分钟时间窗口内的重复登录请求，并保证多实例及并发条件下只有一次消费成功。
4. 保留现有 access/refresh 双 Token 体系：access token 只存前端内存并走 Bearer，refresh token 由 HttpOnly Cookie 承载。
5. 有效 refresh 凭证存在时，刷新浏览器、重载前端或直接打开受保护深层路由必须恢复登录态并回到目标页面；无效、过期、撤销或重放凭证才回登录页。
6. 使认证协议、Cookie 与密钥生命周期能够继续演进，不建立第二套认证状态源。

## 3. 产品与安全契约

### 3.1 登录前置挑战

- 登录页在提交前获取一次性登录挑战。响应至少包含验证码展示内容、验证码 UUID、可用 RSA 公钥、密钥版本标识、挑战有效期和服务器时间。
- 验证码 UUID 是本次登录挑战的唯一服务端标识，绑定验证码摘要、生成时间、密钥版本、失败次数和消费状态；不得把这些权威状态交给浏览器自行声明。
- 挑战权威状态使用现有跨实例 Redis 接缝并具有 5 分钟 TTL；禁止使用单实例本地内存作为权威状态。
- 新挑战不得复活已过期或已消费挑战。并发提交必须原子裁决，最多一个请求进入账号密码认证。

### 3.2 密码加密与密钥

- 前端使用 `RSA-OAEP`、`SHA-256` 和至少 2048 位公钥加密 UTF-8 密码；不得降级为 PKCS#1 v1.5、可逆对称共享密钥或自定义加密协议。
- TLS/HTTPS 仍是生产底线；RSA 字段加密不得被描述为 TLS 的替代。
- 私钥仅由服务端外部安全配置或密钥设施提供，不允许代码库或普通配置中的可用默认私钥。多实例必须共享同一有效版本集合。
- 密钥轮换期间，新挑战使用当前版本；旧版本至少保留到其最后一个挑战过期。服务端依据挑战绑定的密钥版本解密，不信任客户端任意指定版本。
- 密码不得截断。无法按协议编码或超出算法允许长度时必须安全拒绝，不得回退明文。

### 3.3 登录请求与固定校验顺序

登录请求提交账号、RSA 密文密码、验证码内容、客户端 Unix epoch 毫秒 `timestamp` 和验证码 UUID。后端按以下顺序处理：

1. UUID 缺失、挑战不存在或验证码内容不匹配：返回稳定错误语义“验证码错误”。
2. 内容匹配后检查挑战生成时间；超过 5 分钟：返回“验证码已过期”。
3. 校验客户端时间格式，并与服务器当前时间比较；绝对差超过 3 分钟或格式非法：返回“机器时间异常”。客户端时间只用于时钟异常提示，不单独承担防重放。
4. 前三项通过后原子消费挑战，再使用绑定私钥解密并进入账号密码认证。已消费、重复或并发落败的挑战不得再次进入密码认证。
5. 密文非法、解密失败、账号不存在或密码不匹配统一返回“密码错误”。账号状态沿用现有已接受语义；P45 不借机核销 P25/I50 或改变其独立方向。

验证码内容错误可以在同一挑战内重试，但必须具有有限且可配置的失败次数；超过上限即使挑战失效。验证码与时间均通过后，无论密码最终正确与否，该挑战均已消费，下一次登录必须取得新挑战。

所有外显提示同时具有稳定机器错误码；内部审计只记录类别、挑战标识摘要、时间和必要上下文，不记录验证码原文、密码明文、私钥或完整密文。

### 3.4 Cookie、双 Token 与页面刷新恢复

- 保留现有职责：access token 只存在前端内存，不进入 Cookie、`localStorage` 或 `sessionStorage`；refresh token 继续使用 HttpOnly Cookie，现有轮换、重放撤销和用户状态复核不得退化。
- Cookie 必须由后端设置并具有 `HttpOnly`、生产 `Secure`、适当 `SameSite`、明确 Max-Age 和能够覆盖当前公开 refresh/logout URL 的最小 Path。Path 不能继续依赖未经部署验证的内部路径假设。
- 当前受支持的同源部署及其公开 API 前缀必须明确并可配置。不得为本轮目标无边界开放跨源 CORS；若项目声明跨源为正式受支持部署，则 Cookie credentials 与服务端 CORS 必须成对收敛并提供行为证据。
- 应用启动和受保护路由守卫必须先完成 refresh 恢复，再决定放行或跳转；恢复期间不闪回登录页。refresh 成功后继续装配用户、权限、菜单和动态路由，并返回刷新前的目标路由。
- refresh 无 Cookie、Cookie 无效/过期/撤销/重放或用户状态拒绝时，统一清理 access 内存态、用户会话、权限菜单和动态路由，再进入登录页。不能把 Cookie 因 Path/来源配置不可达误判为凭证无效。
- 主动退出必须撤销 refresh、清除 Cookie 和前端全部认证态；退出后刷新不能恢复旧会话。
- Mock 必须表达相同的状态转换和错误语义，但 Mock 不能替代真实浏览器 Cookie 行为验收。

## 4. 非目标

- 不新增 SSO、MFA、无密码登录、密码复杂度/定期轮换策略或完整自适应风控。
- 不把 access token 持久化到 Cookie、Web Storage 或其他长期客户端存储。
- 不另建平行 Token 体系，不迁移现有 JWT 签名算法，不降低 refresh 轮换和重放撤销语义。
- 不默认开放跨域认证，不以宽泛 CORS 或 `SameSite=None` 作为 Cookie Path 问题的替代修复。
- 不在本轮实现完整账号自动锁定/定时解锁体系、登录审计管理页面、refresh 历史行清理任务。
- 不顺手修改 P25/I50、SSO、用户状态模型或无关安全配置；发现的独立风险按既有问题流程登记。

## 5. 影响范围

- 后端认证与安全层：登录前置挑战、登录请求契约、固定校验顺序、RSA 密钥管理、Redis 原子挑战、错误码、refresh Cookie 配置及安全日志。
- 前端认证层：登录页挑战交互、WebCrypto 加密、认证 API 契约、冷启动恢复、路由守卫、请求层、状态清理和错误展示。
- 部署配置：当前正式同源入口、公开 API 前缀、Cookie Secure/SameSite/Path 与必要的密钥配置。
- 测试与 Mock：前后端契约、认证分支、并发/重放、密钥轮换、Cookie 恢复和路由行为。
- 正式状态：P45、M02-F06-01、功能清单与知识入口只在功能验收和阶段三授权后同步，不得提前核销或晋级。

## 6. 风险与约束

- Cookie Path、代理前缀和浏览器来源判断错误会造成“有效 refresh 被当作无效”；实现前必须先观察当前部署行为链的第一个失败点。
- RSA 密钥版本与挑战未绑定会导致轮换窗口内无法解密或错误降级；必须由服务端挑战记录绑定。
- 验证码检查与消费非原子会留下并发重放窗口；多实例下不得使用本地锁替代共享原子状态。
- 将 access token 放入 Cookie 会改变 CSRF 与过滤器信任边界；本方向明确禁止。
- 详细认证失败提示可能成为旁路信息；账号不存在、解密失败和密码错误必须保持统一语义。
- 前后端 Mock 很容易绕过真实 Cookie 行为，最终验收必须包含真实浏览器和真实后端链路。

## 7. 功能验收标准

1. 真实登录前置响应包含可用公钥、密钥版本、验证码 UUID/展示内容、有效期与服务器时间；浏览器及日志中无私钥或密码明文。
2. 真实浏览器登录请求包含五项规定字段，密码字段为符合协议的 RSA 密文；服务端正确解密后仍使用既有密码哈希校验，不改变密码存储语义。
3. 验证码错误、验证码过期、机器时间异常和密码错误四类分支分别返回规定错误码/提示；每个分支均证明后续校验未提前执行。
4. 挑战在多实例共享存储中 5 分钟过期；正确前置校验后一次性原子消费。相同 UUID/密文重复提交及并发提交只有一次可进入密码认证，其余全部拒绝且无副作用。
5. 缺失/非法字段、错误密文、错误密钥版本、轮换窗口内旧挑战和轮换后过期挑战均有明确正反向结果；不存在明文或旧协议降级路径。
6. 首先记录当前真实部署的完整行为链：登录 `Set-Cookie`、浏览器存储、刷新请求 Cookie、refresh 响应、access 回填、session/menu 和路由结果；证据必须定位修改前的第一个失败点。
7. 修复后，当前正式部署公开前缀下登录响应设置安全 refresh Cookie；F5、应用重载和直接打开受保护深层路由均在有效凭证下恢复原页面，不闪回登录页。
8. refresh Cookie 无效、过期、撤销、重放或用户状态拒绝时，浏览器 Cookie、access 内存、用户/权限/菜单和动态路由均被清理并进入登录页；不存在循环 refresh 或半登录态。
9. 主动退出后 refresh 被撤销且 Cookie 清除，刷新不能恢复；不同用户和租户的 Cookie、Redis 挑战、会话与路由状态不串用。
10. access token 仍只存内存；Cookie、`localStorage`、`sessionStorage` 中均无 access token。refresh token 不暴露给 JavaScript、响应体或普通日志。
11. 既有 refresh 轮换/重放撤销、登录成功、用户状态、权限菜单和受保护 API 行为无回归；Mock 与真实契约一致但不作为 Cookie 通过依据。
12. 前后端受影响范围测试、真实浏览器行为检查及项目级回归全部通过；回执提供实际命令、退出码、测试计数、请求/响应、Cookie 属性和路由结果，并遵守工程资源与互斥约束。
13. P45 实现完成时仅提交执行回执和建议状态，不提前写功能 `PASSED/COMPLETED`、不核销 P45、不晋级 M02-F06-01、不覆盖历史回执。

## 8. 待确认问题

无。实际生产断点由执行阶段按验收标准 6 先采集行为证据后确定；这属于对既定目标的现场定位，不改变产品方向。具体类名、配置键、Redis 原子实现和内部 Step 由执行层依据工程宪法自行设计并在回执中披露。
