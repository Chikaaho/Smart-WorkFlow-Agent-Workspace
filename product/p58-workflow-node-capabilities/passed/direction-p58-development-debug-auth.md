# P58 开发环境调试认证补充方向

> 归档：2026-09-04功能级PASSED，依据规划验收08；主方向现位于同目录，下文执行期引用作为历史保留。

> 下发角色：规划（Planner）  
> 指定角色：执行（Executor）  
> 任务等级：L（认证安全自动升级门；并入 P58 XL 验证范围）  
> 功能状态：VERIFYING 期间补充  
> 日期：2026-09-03  
> 主方向：`product/p58-workflow-node-capabilities/ready/direction-p58-workflow-node-capabilities.md`

## 1. 目标

为本地开发、自动化浏览器和多身份行为验收提供受控身份入口，使 Executor 不依赖验证码或人工登录即可使用真实用户、真实角色和真实权限完成 P58 证据链；该入口不是生产认证能力。

## 2. 唯一允许语义

- 请求格式固定为 `Authorization: Bearer test_<userId>`，`userId` 只能是合法的十进制用户标识，不接受用户名、租户、角色、权限列表或其他自由载荷。
- 仅当运行 profile 属于 `dev` 或 `test`、专用配置开关显式为 `true`、请求来源为本机回环地址三项同时成立时，调试认证才可进入解析。
- `test_<userId>` 只替代“证明当前请求来自该用户”这一认证步骤；用户、租户、启停状态、角色、菜单和接口权限必须从正式存储与正式授权链加载。
- 用户不存在、已停用、已删除、格式非法或无接口权限时，分别按照正式认证/授权语义拒绝，不能自动创建用户、提升权限或回退为管理员。
- 调试 token 不写入 Cookie、不兑换 access/refresh token、不进入正式 token 存储，也不能通过登录接口获得生产会话。
- 每次接受或拒绝调试认证都记录结构化安全日志，至少包含调试标识、userId（格式合法时）、请求路径、请求标识和结果；不得记录密码、正式 token 或敏感表单数据。

## 3. 激活与生产门禁

- 调试认证实现必须同时受 profile 和属性条件约束；仅配置文件出现开关不足以构成隔离。
- 默认值必须为关闭。`prod` 及非 `dev/test` profile 下即使通过环境变量或命令行强制把开关设为 `true`，应用也必须启动失败或确定性拒绝所有 `test_` token。
- 非回环来源携带 `test_` token 必须拒绝。代理头不得未经可信代理边界直接覆盖实际来源地址。
- 普通 JWT、Cookie、未认证和无权访问的既有行为不得改变；调试解析不能抢占、降级或吞掉正式认证失败。
- 前端只允许在开发构建中通过已有 token 注入接缝使用该值；生产构建不得显示调试登录入口、默认用户或调试 token。

## 4. P58 验证使用方式

- Executor 使用正式接口创建或确认至少三个真实普通用户及所需角色/权限，再以不同 `test_<userId>` 建立独立浏览器/API 会话。
- P58 的候选审批、会签、抄送、通知和越权场景必须使用这些独立身份；不得因调试认证跳过候选归属、任务权限、租户隔离或数据权限检查。
- 调试认证只解决登录取证，不替代真实页面、请求/响应、Flowable 轨迹、业务状态和持久化证据。
- 验证结束后清理 P58 测试用户、角色、流程和业务数据；调试开关恢复关闭，并用负向请求证明 token 已失效。

## 5. 验收标准

1. `dev/test + 开关开启 + 回环请求 + 真实启用用户` 可以通过 `/auth/me` 识别为对应用户，随后权限检查使用该用户真实角色与权限。
2. 两个权限不同的普通用户使用各自 token 请求同一受保护接口时，分别得到与正式授权配置一致的允许/拒绝结果；不能都变成管理员。
3. 用户不存在、停用、删除、token 格式非法、非回环来源和开关关闭场景均被确定性拒绝，并有对应安全日志。
4. `prod` 或其他非开发 profile 在强制设置开关为 true 时仍不能接受调试 token；生产前端构建不存在调试入口和默认 token。
5. 调试认证不产生 Cookie、正式 access/refresh token 或 token 存储记录；关闭开关后原 token 立即无效。
6. 使用独立调试身份完成 P58 主方向要求的真实多用户浏览器和接口证据，且权限、业务状态及持久化链没有因调试入口被旁路。

## 6. 非目标与停止条件

- 不支持共享万能 token、用户名 token、跨租户参数、角色参数、权限参数或调试管理员默认账号。
- 不把调试认证用于演示、预发布或生产环境，不代替真实登录功能验收。
- 若无法证明非开发 profile 绝对不可接受该 token，或实现需要放宽正式授权链，本补充方向必须停止并报告，不得以“仅开发使用”的说明替代行为门禁。

## 7. 回执要求

补充回执必须附原始启动 profile/开关、HTTP 请求响应、`/auth/me` 身份、权限允许/拒绝、安全日志、Cookie/token 存储零新增、生产负向启动或拒绝、前端生产构建零入口以及关闭开关后失效证据。测试名、配置文件存在或代码扫描只能作为辅助。
