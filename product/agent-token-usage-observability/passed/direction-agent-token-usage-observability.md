## 1. 目标（一句话）

让有权用户能够从既有 Agent 执行与会话历史中看到供应商实际返回的输入、输出和总 Token 用量，并在多次模型调用场景下获得可追溯、可聚合且不伪装成计费数据的使用统计。

## 2. 产品语义

- 统一统计三个基础指标：输入 Token、输出 Token、总 Token；字段含义以模型供应商经 Spring AI 返回的 usage 为准，不自行用字符数或分词器估算。
- “未知”与数值 `0` 必须严格区分。供应商未返回 usage、返回不完整或当前协议无法取得时显示为未知，不得记为零或参与虚假精确的汇总。
- 图执行路径按一次图执行聚合其可观测的全部 LLM 节点调用；循环、并行分支及重复节点调用均不得漏算或因节点 ID 相同被去重。
- 会话路径按既有会话与消息关系保留可追溯的 Token 事实，并提供会话级汇总；同一会话的多轮调用必须累计，不能只展示最后一轮。
- 若一次业务调用发生模型候选切换、重试或工具递归，只统计当前生产调用链能够从供应商响应中可靠取得的 usage；界面和接口不得宣称这是供应商账单或所有失败尝试的完整成本。
- 成功记录必须保存可取得的 usage；失败记录仅在确有供应商 usage 证据时记录，不能通过异常类型推算。统计缺失不得改变既有 SUCCESS / FAILED、错误分类、结果文本或重试语义。
- 后端接口与前端展示使用同一字段语义。现有运行日志应展示执行级 Token 汇总；既有会话历史能力应提供最小可达的会话 Token 查看入口，不另造脱离执行/会话记录的孤立统计口径。
- Mock 模式须复现已知、未知、多调用聚合与跨会话隔离语义，不得固定返回与真实接口不一致的“漂亮数字”。
- 所有统计继续受现有租户隔离、逻辑删除、Agent 查看权限与 superadmin 语义约束；无权用户不得通过统计接口或页面侧信道获知其他租户使用量。

## 3. 非目标

- 不做金额换算、价格表、账单对账、预算、充值、成本中心、告警、配额扣减或财务报表。
- 不改变模型多 Key 轮询、额度冷却、429 识别、重试次数或候选选择策略。
- 不用本地 tokenizer、字符数或经验公式补算供应商未返回的 Token；不承诺与厂商最终账单完全一致。
- 不做按日/月趋势图、模型排行、跨租户总览、导出、复杂筛选或独立 BI 仪表盘。
- 不做 SSE 对话窗口、助手配置、RAG、Prompt 库、工具管理页、单步调试或新的图执行控制能力。
- 不改变 Prompt 插值、变量表、LOOP/FORK/JOIN 调度、节点轨迹、错误分类和执行状态机。
- 不新增权限码、默认用户或默认角色授权；沿用现有 Agent 查看/管理权限边界。
- 不以本轮自动核销 P8 或将 M07-F04-02 标为完成；只有 Token 统计与最小会话查看入口均有证据闭环，且阶段三同步确认后，才由规划层裁定对应状态。

## 4. 影响范围（模块级）

### 后端

- F01 编排/会话路径与 F02 图解释执行路径中模型响应 usage 的读取、传递、聚合和持久化。
- 既有会话、消息、图执行记录及其 DTO/API 的 Token 统计契约；具体落点由执行层基于现状决定，但不得建立无法追溯到业务执行记录的平行统计真相源。
- H2 与 PostgreSQL 双方言 Flyway 迁移。当前根路径最高为 V34，执行层须现场确认可用版本号，不得仅凭本方向硬编码占号。
- 既有租户、权限、逻辑删除、失败记录和分页查询边界的回归保障。

### 前端

- 现有 Agent 运行日志列表/详情中的执行级 Token 汇总展示。
- 既有会话历史接口的最小生产可达入口，能够查看会话级汇总及其消息/轮次 Token 事实；不要求本轮建设完整聊天窗口。
- 未知值、部分可用值和确定数值的明确展示，以及 Mock handlers/fixtures 的契约同步。

### 规划与知识状态

- 本轮唯一功能为 P8 / M07-F04-02 的 Token 使用统计可观测闭环。
- P7 单步调试、M07-F03 助手/RAG、M07-F04-01 SSE 对话窗口、IoT、OpenAPI 和其他候选不得随本轮自动变更状态。

## 5. 风险方向

1. **统计口径失真**：供应商未返回 usage 时若写零，会把“未知”伪装成“免费调用”，直接破坏统计可信度。
2. **多调用漏算或重复**：图循环、并行分支、同节点重复执行和会话多轮调用都可能导致覆盖、按节点去重或重复累计。
3. **双执行路径漂移**：F01 会话编排与 F02 图解释执行必须共享字段语义；不能一条路径持久化总量、另一条只返回瞬时值。
4. **重试与计费误解**：框架未暴露的失败尝试不能推算；产品文案必须明确“供应商响应可观测 usage”，避免被当成账单依据。
5. **失败链回归**：采集与持久化不得吞掉原异常、改变错误分类、把 FAILED 改成 SUCCESS，或因 usage 缺失导致执行失败。
6. **迁移兼容**：新增字段应兼容既有记录；历史记录必须显示未知而非零，H2/PG 新库与升级链均需保持可用。
7. **租户与权限泄露**：汇总接口、列表字段和页面聚合都必须在服务端完成授权与租户隔离，不能依赖前端过滤。
8. **范围膨胀**：Token 数据容易扩展为价格、预算、趋势和告警；这些均不属于本轮。

## 6. 验收标准

1. F01 会话编排与 F02 图解释执行均能读取供应商返回的输入、输出、总 Token，并按统一字段语义进入既有业务记录；任一路径不得仅在日志或瞬时响应中存在。
2. 图执行级汇总覆盖单节点、多 LLM 节点、LOOP 重复执行及 FORK/JOIN 分支调用；同一节点多次执行不去重，聚合结果可由调用事实复算。
3. 会话级汇总覆盖同一会话多轮调用，并能追溯到消息或轮次级 Token 事实；不同会话、不同租户之间不得串计。
4. 输入、输出、总 Token 三项保持自洽；供应商缺失或部分缺失 usage 时使用明确的未知语义，不写零、不估算，并且不会使原本成功的业务调用失败。
5. 模型候选切换、重试、工具调用和失败场景不改变既有业务语义；只记录真实可取得的 usage，接口与界面明确不将统计宣称为账单或完整失败尝试成本。
6. 既有执行历史列表/详情能够展示执行级 Token 汇总；会话历史具备最小生产可达页面，能够查看会话汇总及消息/轮次明细，未知值展示清晰。
7. 历史数据无需回填即可兼容：迁移前记录在新接口和页面中表现为未知，现有分页、详情、节点轨迹、会话消息和错误记录仍可正常读取。
8. Token 数据的查询与聚合满足现有 Agent 权限、未认证拒绝、撤权拒绝、superadmin 放行、租户隔离和逻辑删除边界；前端直达/刷新也不能绕过守卫。
9. Mock 覆盖确定 usage、未知 usage、多调用聚合、会话隔离与无权访问，并与真实 DTO、错误和展示语义一致。
10. H2 与 PostgreSQL 迁移链、校验和升级路径均闭合；迁移只承载本功能必要字段/索引，不顺带修改其他 Agent 表或历史迁移。
11. Prompt 配置、变量映射、图调度、执行历史、会话消息、模型多 Key 轮询和既有 Agent 功能无回归；不新增本方向非目标中的能力。
12. 后端受影响测试与项目级回归、前端 `typecheck`、`lint`、`test`、`build` 均在 2G 上限下通过，测试数量不得低于当前规划确认基线后端 **723/0/0/0**（Agent **234**）、前端 **79 files / 775 tests**；前后端编译测试严格串行并提供本轮时间与互斥证据。
13. 完成 §3.3 第10项知识库全量同步：P8、M07-F04-02、current-status、功能追踪、known-issues、session-handoff、需求池与功能清单全文口径一致；无关清单行零漂移，并在回执中报告清单变更明细与知识库触碰文件清单。
