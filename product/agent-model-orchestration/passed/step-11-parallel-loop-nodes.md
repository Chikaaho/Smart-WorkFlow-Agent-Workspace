## 1. 背景

M07-F02 图设计器（Step6-10）已完结，`AgentGraphInterpreter` 目前是**纯单路径顺序解释执行**：单指针推进、非条件节点出边强制唯一、CONDITION 节点单选一出边，无任何并发/扇出/join 语义。步数上限（`maxSteps = 节点数 × 2`）是死循环兜底，非循环功能。命名变量表（Step10）为单一 `HashMap`，同键后写覆盖，无并发写入语义。

前置探索（`search_fallback/m07-step11-parallel-loop-precedent.md`）已确认：
- **循环**在现有回边+CONDITION 关键词路由机制上机械可行（测试用例已验证自环可执行），主要缺口是步数预算需要重新设计。
- **并行**是真正的架构增量，需要新的多活跃执行点执行模型，现有代码/文档均无依据。
- 存储（V25 表结构）、发布校验、执行前校验、前端画布连线，全链路均**无 DAG（无环）假设**，环一直被容忍，不构成阻塞前提。

## 2. 目标（一句话）

图执行引擎（`AgentGraphInterpreter` 及配套前端图设计器）支持**循环节点**（图中允许回边，执行时按设计意图重复某段路径直至满足退出条件）和**并行节点**（图中允许从一个节点扇出到多个分支并发执行，之后可汇合），使图设计器能表达比当前纯线性/单选一分支更复杂的编排逻辑。

## 3. 非目标（明确排除）

- 不做单步调试（todo 池另一独立项，不在本轮范围）
- 不做执行历史持久化（todo 池另一独立项，不在本轮范围）
- 不做图节点级多Key轮询（todo 池另一独立项，不在本轮范围）
- 不改变 F01 编排路径（`AgentGraphFactory`/LangGraph4j）——两条执行路径继续并存互不干扰，本轮只改 F02 自建的 `AgentGraphInterpreter`
- 不要求补齐"完整数据流静态校验"（如变量引用的编译期检查）——沿用现有"运行时报错"策略；是否需要为循环/并行新增最基本的合法性检查（如"循环节点必须存在可达退出路径"）由执行层自行判断是否必要，非本轮强制目标
- 不因本轮引入环/分支而重新设计变量表结构——并行分支写同一变量名时按"最后写入覆盖"处理（用户已决策：视为流程设计或配置错误的信号，系统不承担并发合并/隔离责任，不引入分支局部变量空间或 JOIN 合并规则）
- 不得现场扩展 `flow-graph` adapter 导出面（如新增边点击事件、命令式数据更新通道）——若实现中确认必须扩展该防腐层契约，按 I31 先例暂停并回规划层单独评估，不得执行层自行决定
- 不修改 `contracts/agent.ts` 现有的开放式类型设计（`type?: string`、config/style 不透明 Map）——新节点类型通过现有开放字段表达，不引入新的强类型约束

## 4. 影响范围（模块级）

**后端**（`Smart-WorkFlow/sw-basic/sw-basic-agent/`）：
- `AgentGraphInterpreter`：执行模型扩展，需要支持循环（回边+步数预算重设计）和并行（多活跃执行点/扇出/汇合语义）

## 5. 风险方向

1. **步数预算冲突**：循环迭代和并行扇出会共同消耗当前"全图 2×节点数"的单一步数预算，现有兜底机制若不调整，循环节点可能刚执行 1-2 次就被误判为死循环。执行层需重新设计预算机制（是否给循环节点独立迭代上限、是否按执行路径分别计数等），具体方案由执行层判断。
2. **变量覆盖行为的可预期性**：按用户决策，并行分支写同一变量名按最后写入覆盖处理，不做拦截或告警。执行层实现时需确保这一行为在文档/回执中明确说明，避免被误判为缺陷。
3. **前端多出边交互**：当前 UI 无"添加出边"入口（画布拖拽连线才能生边），并行/循环若需要更复杂的分支管理交互，实现时需在不扩展 `flow-graph` adapter 契约的前提下完成（见非目标），如遇确实做不到的情况，暂停并回规划层评估，不得绕过硬约束。
4. **环检测范围的边界判断**：本轮引入的是"设计意图内的合法环"（循环节点/回边），与"意外形成的死循环图"在语义上需要区分开——执行层若认为需要在发布或执行前增加针对性校验，可自行设计，但不得以此为由否定"图允许环"这一既有既定事实（探索已确认全链路无 DAG 假设，非本轮引入的新前提）。

## 8. 执行层落地摘要（功能级完成回执要点，供最终验收）

**执行层自主设计决策**（详见 `receipts/step-11-execution-plan.md`）：

| 决策点 | 落地 |
|---|---|
| 节点契约 | `LOOP`（循环头，config.maxIterations 缺省 10，单出边）+ `FORK`（扇出 ≥2 出边）+ `JOIN`（汇合 ≥2 入边） |
| 执行模型 | 多活跃执行点**逻辑并发**（交错推进，非线程级并行）：FORK 全出边分支、JOIN 挂起聚合、任一 END 早到终止全部 |
| 步数预算 | `maxSteps = 2 × 节点数 + Σ(maxIterations of LOOP) × 节点数`；无 LOOP 退化原公式（回归安全） |
| 执行前校验 | 新增 FORK 出边≥2 / JOIN 入边≥2 / LOOP maxIterations≥1；不做"循环体可达退出路径"静态分析（运行时双层兜底已足） |
| 变量冲突 | 按用户决策：后写覆盖，不拦截不告警（用例 16 显式断言） |
| 零迁移 | 语义全走 config 不透明 Map，无 Flyway/DDL/DTO 变更；F01 路径零触碰 |
| 前端 | graphAdapter.ts 常量/显示名 + GraphDesigner.vue 色板/属性面板（LOOP maxIterations 输入）；contracts 与 flow-graph adapter **零改动** |
