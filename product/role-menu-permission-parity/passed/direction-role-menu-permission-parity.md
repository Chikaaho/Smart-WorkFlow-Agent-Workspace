## 1. 目标（一句话）

在不重复实现既有 RBAC、也不改变生产权限模型的前提下，补齐普通角色菜单/按钮权限配置在真实 API、前端 Mock、页面交互与自动化证据之间的一致性，使 `M02-F02-01` 与 `M02-F03-01` 达到可验证、可回归的完整闭环。

## 2. 需求语义

### 2.1 单一权限树

- 菜单与按钮继续使用同一棵权限树和同一套角色绑定关系；按钮是 `menu_type=2` 的权限节点，不建立第二套按钮授权模型。
- 普通角色必须支持权限树读取、保存、清空和再次打开后的准确回填。
- 目录、页面与按钮的既有权限语义保持不变：菜单可见性不能替代按钮 permission，也不能替代后端接口授权。

### 2.2 真实 API 与 Mock 等价

- Mock 环境必须支持当前生产契约中的角色菜单/按钮权限读取与替换保存，不能再因缺少 handler 返回 404。
- Mock 的路径、请求载荷、响应结构、清空语义、未知角色行为、受保护角色行为和重复保存结果必须与真实 API 保持一致。
- Mock 保存后的状态必须能被后续读取和页面回填观察到；不得只返回成功而不更新夹具状态。
- Mock 中角色、数据范围和超管/普通管理员语义须与当前后端契约一致，清除会掩盖权限缺陷的陈旧值。

### 2.3 受保护角色与授权边界

- `superadmin` 继续以角色 code 判定并保持不可修改；前端禁用不能代替后端拒绝。
- 普通 `admin` 不获得任何 code 旁路，仍依赖显式角色菜单和按钮 permission。
- 普通角色保存、清空权限后，菜单可见、按钮显隐和接口允许/拒绝结果必须与绑定关系一致。
- 租户隔离、`sys_menu` 全局表、`sys_role_menu` 租户关系表以及现有唯一约束保持不变。

### 2.4 状态结项

- 本方向通过后，`M02-F02-01` 与 `M02-F03-01` 应由长期 🟦 更新为 ✅。
- P1 中此前的 I31、I36 及 M02-F02/F03 子项均已闭合时，P1 应正式核销；不得误改 M02 其他功能或 P2 以后候选状态。

## 3. 非目标

- 不重新设计 RBAC、菜单路由、权限表达式或超管旁路。
- 不新增第二套按钮权限表、端点或独立配置页面。
- 不新增 Flyway 迁移，不为既有或未来角色追加默认授权，不改变 V31/V33 的授权决策。
- 不扩展用户组消费、用户角色绑定、数据权限、资源管理、SSO 或其他 P1/P30/P31 范围。
- 不在本轮处理角色创建与菜单保存跨请求事务合并、角色删除后的历史关系清理等尚无失败证据的独立数据治理问题；如执行层发现可复现缺陷，只在回执中报告，不自行扩项。

## 5. 风险方向

1. **假 Mock 成功**：handler 仅返回成功但未持久化内存状态，会让回填和二次编辑继续失真。
2. **树勾选语义漂移**：父子联动、半选节点和叶子节点保存方式若与真实 API 不一致，可能造成权限丢失或扩大。
3. **仅 UI 通过**：按钮显示正确不能证明后端授权正确，必须保留允许、拒绝与未认证三类证据。
4. **超管保护漂移**：Mock 或页面若允许修改 `superadmin`，会掩盖真实后端的强制保护语义。
5. **状态误核销**：P1 核销时容易误把 M02 其他 🟦/⬜ 项一并关闭，必须逐项限制状态变更。
6. **范围膨胀**：探索发现的数据卫生和跨请求事务风险不是本轮已证实缺陷，不得借收口任务进行架构重构。

## 6. 验收标准

1. 真实 API 与 Mock 均能完成普通角色菜单/按钮权限的读取、替换保存、清空和再次读取；路径、载荷、响应及错误语义逐项一致。
2. Mock 保存会真实更新当前测试会话中的角色权限状态；重复保存、空集合、未知角色和受保护角色均有明确且与真实 API 一致的结果。
3. 角色管理页对普通角色能够正确加载权限树、保存、清空并重新打开回填；目录/菜单/按钮混合树及父子/半选场景不会静默扩大或丢失权限。
4. `superadmin` 的菜单权限修改在前端无可执行入口，直接调用真实后端仍被拒绝；普通 `admin` 不触发超管旁路。
5. 非超管用户的授权链至少证明：已授权菜单可见、已授权按钮可用且对应接口允许；撤权后菜单或按钮不可达且接口拒绝；未认证请求拒绝。菜单可见与接口可调用须分别有证据。
6. 租户边界保持正确，不得读取或修改其他租户的角色权限；全局菜单与租户角色关系的既有模型不变。
7. 前端角色 API、Mock handler 和角色管理页均有针对权限树的自动化回归证据；后端既有角色权限与请求级安全测试完成回归。不得以手工点击代替核心契约测试。
8. 无 Flyway 新增、无默认授权变化、无无关业务代码变更；如现场发现必须违反该边界才能完成，功能应标记 BLOCKED 并回报规划层。
9. 后端受影响测试与项目级全量测试、前端 typecheck/lint/test/build 全部通过且不低于当前基线：后端 **647/0/0/0**，前端 **71 spec / 646 tests**；命令遵守 2G 上限和前后端编译互斥。
10. 阶段三完成全量知识同步：`M02-F02-01`、`M02-F03-01` 更新为 ✅，P1 在其全部子项已闭合后核销；功能清单计数、需求池、current-status、功能追踪、known-issues 和 handoff 相互一致，无旧当前态残留。
