# P52 表单设计器工作台与关联流程管理需求方向

> 本会话角色：规划（Planner）  
> 功能编号：P52  
> 任务等级：L（跨表单与流程模块、跨前后端、进入正式功能状态跟踪）  
> 状态：READY  
> 日期：2026-09-01  
> 立项前正式功能数：37

## 1. 背景与选择原因

当前表单设计、保存、发布、历史版本和关联流程分散在不同入口，用户需要离开当前表单上下文后重新定位对象。P52把这些高频动作收敛到同一工作台，直接改善已完成的“表单 → 流程”主链。

本轮选择 P52，原因如下：

1. 目标和对象明确，能够形成单一、可验收的用户闭环；P53尚缺视觉方向、优先页面和验收样例，不具备直接立项条件。
2. P52连接既有表单与流程能力，优先消除真实主链中的上下文跳转成本；相比独立新增模块，用户收益更直接。
3. 相比 P21剩余的通用物模型、自定义 Adapter、原生 MQTT和真实设备现场联调，P52范围更内聚，不依赖外部账号、硬件或现场环境。
4. P52为后续全局 UI 优化提供一个边界清楚的工作台样板，但本轮不以局部实现替代 P53的全局设计决策。

## 2. 产品目标

围绕当前表单建立统一工作台，使有权限用户在不丢失表单身份和编辑上下文的前提下完成：

- 查看当前表单名称、保存状态和发布状态；
- 保存当前草稿、发布已保存草稿、查看历史发布版本；
- 在“表单设计 / 关联流程”之间直接切换；
- 查看当前表单关联的全部流程，创建并绑定新流程，进入已有流程的管理或编辑入口；
- 刷新、深层链接或重新进入后仍准确恢复同一表单及所选工作区。

## 3. 产品契约

### 3.1 顶部工作台

- 顶部区域形成稳定的信息与操作层级：当前表单身份和状态可见，中部切换“表单设计 / 关联流程”，右侧提供“保存 / 发布 / 历史版本”。
- 保存状态至少区分未修改、未保存、保存中、保存成功和保存失败；失败不得显示成功或清除未保存标记。
- 发布状态至少区分草稿与已发布，并显示当前已发布版本信息；按钮禁用必须有可理解原因。
- 当前表单必须由稳定业务标识确定，不能依赖标题、列表位置或仅存内存的临时选择。

### 3.2 保存与发布

- “保存”只保存当前表单草稿，不隐式发布；重复点击、慢响应或失败重试不得产生错表单写入或虚假成功。
- “发布”只作用于最近一次成功保存的当前草稿。存在未保存修改时，必须先提示用户保存、放弃或取消；保存失败时不得继续发布。
- 发布前沿用现有表单有效性校验并完整展示阻塞原因；不得为工作台入口降低既有发布约束。
- 切换到关联流程、离开页面或返回列表时，若存在未保存内容，使用同一套保存、放弃、取消保护语义。

### 3.3 历史版本

- 历史版本列表至少展示版本号、发布时间、发布状态和可追溯的操作信息；版本顺序明确且不会把草稿误标为已发布版本。
- 用户可只读预览某一历史版本，并明确看见“历史版本”标识；关闭预览后返回当前草稿，不得把历史内容悄然覆盖当前编辑内容。
- 本轮不提供历史版本回滚、复制为新草稿、版本删除或版本差异比较。

### 3.4 关联流程

- 切换到“关联流程”后，默认只展示与当前表单稳定标识关联的流程；一个表单允许关联多个流程。
- 列表至少展示流程名称、状态、版本和最近更新时间，并提供创建关联流程、进入已有流程编辑/管理入口。
- 创建关联流程时自动带入当前表单身份，但最终关联必须由服务端持久化和校验；不得只靠前端路由参数形成伪关联。
- 复用现有流程创建、设计、发布、挂起/激活等已存在能力和权限，不在本轮另建平行流程管理体系；现有能力不存在时不得用无效按钮伪装支持。
- 从流程返回时恢复原表单及“关联流程”上下文；无权、已删除、已停用或不属于当前表单的流程必须明确拒绝，不能串入列表。

### 3.5 路由、权限与一致性

- 表单标识和工作区选择具有可恢复的路由表达；F5、复制合法深链或重新进入后，恢复同一表单及正确上下文。
- 表单不存在、已删除、无权访问或路由标识非法时，进入明确的拒绝/不存在状态，不得回退到其他表单。
- 保存、发布、历史查看、流程创建和流程管理分别沿用真实权限；前端按钮可见性不能替代后端授权。
- 多标签页或快速切换不同表单时，各自的草稿、版本、流程列表和反馈不得串位；迟到响应不能覆盖当前表单状态。

## 4. 非目标

- 不实施 P53全局主题、品牌视觉、全部页面布局或组件库重构。
- 不重写表单设计器画布、字段模型、动态表单引擎或栅格布局，不核销 P2/P46。
- 不重做流程设计器、审批能力、流程版本治理或 P4/P47范围。
- 不提供历史版本回滚、差异比较、删除、分支或合并。
- 不新增跨表单流程编排、批量绑定/解绑、流程模板市场或跨租户共享。
- 不以 Mock、静态按钮或本地临时状态替代真实持久化关联与真实权限校验。

## 5. 影响范围

- 前端表单设计器：顶部工作台、保存/发布反馈、脏状态保护、历史预览、关联流程区域和路由恢复。
- 后端表单能力：草稿、发布、版本历史及必要的并发/状态一致性契约。
- 流程模块：表单关联查询与创建绑定，复用现有流程管理入口及权限。
- 权限与审计：表单操作、版本查看、流程创建/管理的真实授权和必要操作追溯。
- Mock与测试资产：核心状态转换和错误语义需与真实接口一致，但不作为真实链路通过依据。
- 正式状态：P52及相关清单项只能在规划验收和阶段三授权后同步，不得提前核销或晋级。

## 6. 主要风险

1. **上下文串位**：依赖标题、列表位置或全局单例状态会导致切表单、迟到响应和多标签页互相覆盖。
2. **发布错版本**：把未保存内存态、旧草稿或历史预览内容当作发布对象，会破坏版本语义。
3. **伪关联**：只在前端拼接表单参数而无服务端持久化，会在刷新或其他入口中丢失关系。
4. **权限越界**：列表过滤或按钮隐藏不能替代保存、发布、版本和流程接口的对象级授权。
5. **范围膨胀**：工作台容易被扩张为全局 UI 重构、完整版本治理或流程设计器重写，必须遵守非目标。
6. **离开保护不一致**：不同切换入口采用不同脏状态策略会造成静默丢稿或重复保存。

## 7. 规划验收边界

以下标准必须由真实页面、请求/响应、持久化回查和受影响范围测试证据逐项证明：

1. 打开一个有权表单时，工作台准确显示表单身份、保存状态、发布状态和版本；打开另一表单不会串位。
2. 编辑后状态变为未保存；保存成功、失败、重试和迟到响应均得到正确反馈，失败时内容与未保存状态仍保留。
3. 有未保存修改时，发布、切到关联流程和离开页面均执行统一的保存/放弃/取消保护；取消不丢稿，保存失败不继续后续动作。
4. 发布只针对最近成功保存的当前草稿；校验失败不发布，成功后版本和状态在刷新后仍一致。
5. 历史列表与持久化版本一致；历史预览只读且有明确标识，退出后恢复当前草稿，历史内容不能覆盖草稿。
6. 关联流程区域只返回当前表单的流程；一个表单关联多个流程时列表完整，不关联流程和其他表单流程为零串入。
7. 创建关联流程后，服务端持久化关系，刷新及从独立流程入口回查仍一致；进入已有流程后返回可恢复原表单上下文。
8. F5、应用重载、合法深层链接和多标签页场景均维持正确表单与工作区；非法、无权、已删除对象得到明确拒绝且不回退到其他对象。
9. 不同权限账号对保存、发布、历史、创建流程和管理流程的页面能力、真实请求和后端结果一致；越权请求无副作用。
10. 真实后端不存在假按钮、错误成功提示、空白关键页面或仅前端临时关联；Mock核心语义一致但不替代真实行为证据。
11. 现有表单编辑/保存/发布、流程创建/管理及“表单 → 流程”主链无回归；回执给出实际命令、退出码、计数及页面行为证据。
12. 执行层只提交执行与测试回执，不提前写功能 `PASSED/COMPLETED`、不核销 P52、不自行改变正式功能数或清单状态。

文件存在、源码扫描、测试名称、截图单证或执行层自述不能单独构成通过依据；关键状态必须能由操作前后数据、请求和刷新后页面共同勾稽。

## 8. 执行边界

执行角色自行核实现有表单版本、表单—流程关系、路由和权限接缝，自主制定实施计划、拆分步骤并选择实现方式。若现有数据模型不能表达稳定关联，允许在本方向范围内补齐必要契约；若需要改变表单发布语义、重写流程设计器、加入历史回滚或扩大到全局 UI，必须停止并返回规划裁决。
