# P56 保存五态二级执行提示 02

> 功能：`p56-form-grid-layout`  
> 提示级别：二级  
> 唯一剩余缺口：G6-A保存五态与失败零写入  
> 合法终态：`EXECUTION_SUBMITTED`或如实`BLOCKED`；功能保持`VERIFYING`

## 1. 权威输入

1. `product/p56-form-grid-layout/receipts/planning-review-p56-form-grid-layout-03.md`
2. `product/p56-form-grid-layout/receipts/planning-execution-prompt-p56-form-grid-layout-01.md`
3. 当前P56实现工作树中的真实表单设计器和真实后端保存链

## 2. 相对一级提示新增与收紧

- 删除G3和G6-B，禁止再次出现其主体证据。
- 把G6-A拆为成功包S和失败包F，两包使用同一真实草稿，但使用两个不同且明确的字段值。
- 每包必须按固定顺序记录时间、页面状态、请求、响应/错误、后端回读和哈希；不得用事后总结替代。
- 失败包必须在任何重试保存之前恢复只读能力并回读后端，证明失败值从未落库。
- “保存失败后仍是未保存”必须由一次真实离开/发布动作触发未保存保护证明，不接受内部变量或源码说明。

## 3. 固定输入

- 使用一个真实后端DRAFT表单，全文记录`formId`和`formKey`，不得记录密码、Token、Cookie。
- 固定字段：选择一个可编辑TEXT字段。
- 成功值固定为：`P56_G6_SUCCESS_20260902`。
- 失败值固定为：`P56_G6_FAILURE_20260902`。
- 基线回读必须来自实际保存端点对应的后端读取接口；记录definition/config中目标字段值和完整响应体SHA-256。

## 4. 证据包S：成功五态

严格按以下顺序执行并记录，不得合并步骤：

1. `S1`：刷新草稿，记录时间、页面`未修改`、后端目标字段基线值与SHA。
2. `S2`：把目标字段改为固定成功值，记录时间和页面`未保存`。
3. `S3`：使用受控慢响应启动真实保存，记录请求method、URL、开始时间；请求仍pending时记录页面`保存中`以及保存/发布按钮禁用状态。
4. `S4`：放行同一请求，原样记录HTTP status、业务code/message、响应时间；禁止重新点击形成第二个请求。
5. `S5`：记录页面`保存成功`的时间；随后记录自动回到`未修改`的时间。
6. `S6`：调用后端读取接口，记录目标字段恰等于成功值及新SHA；刷新页面后仍回读成功值与`未修改`。

正向断言：`S3.requestId = S4.requestId`，且唯一一次保存请求完成成功，页面状态顺序与持久化结果闭合。

反向断言：保存中无第二请求；成功前后无错表单、无状态跳过、无虚假成功。

## 5. 证据包F：失败五态与零写入

在S包完成后严格按以下顺序执行：

1. `F1`：后端回读目标字段为成功值，记录失败前SHA。
2. `F2`：页面把目标字段改为固定失败值，记录`未保存`。
3. `F3`：采用明确、可恢复且能证明请求未成功提交的失败机制，发起一次真实保存；记录method、URL、开始时间和失败机制。
4. `F4`：原样记录该请求的网络错误或非2xx响应、结束时间；记录页面`保存失败`、编辑器仍为失败值。
5. `F5`：恢复后端/代理后，**禁止点击保存或重试**；先调用后端读取接口，记录目标字段仍为成功值、SHA与F1一致，且全文零命中失败值。
6. `F6`：在页面仍保留失败值时执行一次真实离开或发布动作，记录未保存保护对话框出现；选择取消，证明页面留在原处且失败值仍在。

正向断言：页面明确显示保存失败，编辑内容与未保存保护语义均保留。

反向断言：失败值在后端读取响应中零命中；F1.sha = F5.sha；F5前无第二次保存请求。

## 6. 允许读取、修改与命令顺序

### 允许读取

- P56方向、规划审查03、一级/二级提示。
- 前端表单设计器保存状态与离开保护相关文件。
- 后端表单config保存与读取相关文件。

### 允许修改

仅当固定证据流程暴露真实缺陷时，允许修改：

- `Smart-WorkFlow-Web/src/modules/form/views/FormDesigner.vue`
- 与其保存状态/离开保护直接对应的聚焦测试文件
- 当前真实保存端点的最小错误处理接缝

禁止修改权限、动态高度、布局算法、P57/P58/P53或规划状态文件。

### 命令/操作顺序

1. 启动或复用真实前后端并确认健康。
2. 创建或选定固定DRAFT表单并完成基线保存。
3. 完整执行S1—S6。
4. 完整执行F1—F6。
5. 若无代码修改，不重跑任何门禁；若修复代码，仅运行保存状态直接相关聚焦测试。
6. 追加一份新回执，禁止覆盖旧回执。

## 7. 新回执唯一格式

新回执只能包含：

1. 固定表单与字段；
2. S1—S6表格，列为`步骤/时间/requestId/页面状态/请求或响应/后端值/SHA`；
3. F1—F6同结构表格；
4. S包正向/反向断言；
5. F包正向/反向断言；
6. 如有代码修复，列出修改与聚焦测试；无修改则写“无”。

禁止加入G1/G2/G3/G4/G5/G6-B/G7、全量测试、组件清单、拖动、权限或动态高度内容。

## 8. 提交前门禁

| 检查项 | 必须为“是” |
|---|---|
| S1—S6顺序完整，保存中与成功响应属于同一requestId |  |
| S包只有一次保存请求，成功值由后端回读和刷新页面共同确认 |  |
| F1—F6顺序完整，F5发生在任何重试保存之前 |  |
| F1.sha等于F5.sha，后端响应零命中失败值 |  |
| 保存失败后编辑器保留失败值，离开/发布触发未保存保护且取消后仍保留 |  |
| 回执未重新展开任何已锁定项 |  |
| 未提前核销P56或写`PASSED/COMPLETED` |  |

任一项不是“是”时只能如实提交`BLOCKED`，不得宣称缺口闭合。
