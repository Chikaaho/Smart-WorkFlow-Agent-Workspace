# BF20261013-031 执行回执：直线可拖 / 错位双向拖动 / 端口对齐不绷直

2026-10-14｜执行者提交（fix-loop 持续修复批次）；Owner 原反馈 2026-10-14 文字三项 + 截图 3 张（含 1 张直线态、2 张节点移动后的错位态）。

## ①完全直线无法拖动 → 直线给出合成手柄，拖动生成滑移折返

- 端口对齐时整条连线只有一段、没有可拖内段，因此既无手柄也拖不动。
- 现在：2 点折线给出**合成中点手柄**（`straight:true`，垂直段→左右拖 `ew-resize`、水平段→上下拖 `ns-resize`），悬停直线本身同样显示方向光标。
- 拖动即生成**滑移折返（jog，5 段）**：两端端口腿仍垂直出入（不贴边、不穿入节点），跨度默认 40px，滑移量跟随指针且与端口直线保持 ≥20px 净空；线路过短容不下折返时原样不动（不产生退化形状）。首次拖动后拖动下标自动切到折返中段，可继续左右拖、也可用上下段手柄调整高度。
- 验证：`M 420 205 L 420 275`（直线）→ 拖到 x=500 → `M 420 205 L 420 225 L 500 225 L 500 255 L 420 255 L 420 275`；继续拖到 x=300 越到另一侧（四向）。

## ②移动节点后的「错位」只能单向拖 → 夹取改用端口几何外向

- 旧口径按**折线当前方向**判定端口腿是否合法；节点移动后折线方向可能已经反向，于是可拖区间被锁成单向（表现为「只能往一个方向拖」，拖动还会反向跳）。
- 现在：端口腿相邻段的方向取自**端口几何**（节点中心 → 端口的外向，组件 `edgeDragContext` 计算，缺省才回退折线方向）；非端口腿的相邻段只禁止塌缩（可越过固定端，按拖动前一侧推离）。节点移动造成的错位态因此可以双向拖回。
- 验证：错位态（终点端口 255、中段 350）向上拖中段 → 230（旧口径会被夹到 275 且只允许向下）；正常态下拖 250、再上拖 235 双向可用。

## ③端口对齐时拖动会绷直 → 保留用户形状

- 旧口径段数上限 3 段，折返（jog）本身即 5 段 → 一旦两端节点被移动到可直线相连，形状被压回直线（「绷直」）。
- 现在：上限放宽到 5 段；`canonicalRoutePoints` 的端口对齐分支改为**保留折返**（`alignedJogPoints`），超长历史形状在对齐时也重建为折返而不是直线。
- 验证：中段拖到 255 后把 END 移到与端口同 x → 形状保留 `M 420 205 L 420 255 L 600 255 L 600 265 L 420 265 L 420 275`（5 段、全轴对齐、无重叠），不再变直线。

## ④附带修正：自动路由不再被节点移动物化

- 重建入口统一为 `rebuildEdge`（moveNode / setEdgeWaypoints / setEdgeEndpoint / normalizeGraph 共用）：输入**无拐点**时存回无拐点——默认路由继续随节点位置重算，不会因移动节点被钉在旧几何上（否则默认路由会「越移越歪」）。
- 验证：无拐点边移动节点后 `waypoints=[]`、路径按新位置重算（用例）；实景中 END 移到端口同 x 即得到直线 `M 420 205 L 420 275`。
