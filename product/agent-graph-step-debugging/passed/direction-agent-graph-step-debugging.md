## 1. 目标（一句话）

在不改变既有图执行语义的前提下，为有权用户提供可恢复、可审计的服务端单步调试会话，使用户能从图设计上下文逐节点推进、设置断点、继续或停止，并查看每一步的分支、变量与错误状态。

## 2. 选择本需求的原因

- 它是 P7 / M07-F02-04 在“运行日志”子集完成后的唯一明确剩余边界，完成后可形成“设计—执行—观察—调试”的完整图编排闭环。
- 既有图解释器、命名变量、LOOP/FORK/JOIN 调度、节点轨迹、错误分类、执行历史、权限与前端运行日志已经提供直接基础，新增价值集中且可复用现有能力。
- 相比助手配置、RAG、SSE 对话窗口，本需求不依赖新的模型选型或知识检索地基；相比 IoT/OpenAPI 模块落地，不需要从骨架开始建立整条纵向能力。
- 相比零散安全/数据权限小项，本需求能够关闭一个已持续保留的产品缺口；零散问题继续留在候选池，若发现其阻塞本功能才纳入当前范围。

## 3. 产品语义

- 调试入口位于既有图设计/图定义上下文，沿用现有图可执行性与版本规则，不改变草稿、发布或普通执行门槛。
- 启动调试后生成独立的服务端调试会话，并绑定租户、用户、图定义与不可漂移的图版本/内容快照；普通执行与历史查询语义保持不变。
- “单步”每次只推进一个能够形成节点轨迹的节点访问；LOOP 重复访问、FORK 分支、JOIN 汇合继续遵守既有解释器调度语义，不因调试模式产生另一套业务结果。
- 用户可在节点上设置或取消断点；“继续”运行到下一断点、正常结束、失败、主动停止或既有安全预算触发为止；断点在节点执行前生效。
- 调试视图至少展示会话状态、当前/下一执行位置、已产生的节点轨迹、`branchId`、`nodeSeq`、节点类型、节点耗时、当前变量快照以及失败分类/信息。
- 页面刷新或短暂断线后，可依据服务端当前状态恢复同一会话；不得依赖浏览器内存之外的客户端持久化保存调试真相。
- 同一会话的并发或重复控制请求必须有明确、一致且可审计的结果，不能造成节点重复执行、状态倒退或多次终结。
- 调试会话具有明确终态和失效策略；完成、失败、停止或过期后不得继续推进，且不得无限占用服务端资源。
- 调试过程产生的节点轨迹和终态应进入既有可观测闭环，能够从运行日志识别其调试来源并查看结果；不得把中间敏感变量写入 URL、浏览器持久化或控制台日志。
- Mock 模式与真实接口保持相同的状态转换、断点、分支/循环和错误语义，不以纯前端模拟替代服务端控制能力。

## 4. 非目标

- 不做时间旅行、回退上一步、任意修改历史变量后重放、从任意历史节点重新执行或跨版本继续。
- 不修改 LLM、工具、CONDITION、LOOP、FORK、JOIN、步数预算、变量覆盖、错误分类等既有执行语义。
- 不把单步调试扩展为生产任务编排、分布式作业调度、多人协同调试或跨实例故障接管平台。
- 不纳入助手配置、知识库 RAG、SSE 对话窗口、Token 价格/账单、图节点级多 Key 轮询、IoT 或 OpenAPI 建设。
- 不扩展 `flow-graph` adapter 的通用导出面，除非现有契约被执行层以行为证据确认无法满足本方向；必要扩展须保持最小且不夹带 I48 的其他能力。
- 不默认扩大普通角色权限，不改变 `superadmin`、租户隔离、Token 仅内存或现有运行日志访问规则。

## 6. 风险方向

1. **执行语义分叉**：若普通执行与调试执行形成两套解释逻辑，LOOP/FORK/JOIN、错误分类和变量结果会漂移；调试必须复用同一语义核心。
2. **控制状态竞态**：重复点击、并发请求、超时重试或多标签页可能造成节点重复执行或状态倒退；控制命令需具备明确的原子性和幂等边界。
3. **外部副作用重复**：LLM、内部工具和外部 HTTP 节点可能产生费用或业务副作用；单步和恢复不得隐式重放已成功节点，UI 必须明确提示调试仍会执行真实节点行为。
4. **服务端资源泄漏**：暂停会话若无过期与终态清理会长期持有资源；会话不能依赖进程内 ThreadLocal 跨请求存活，也不能无限期占用工作线程。
5. **分支与断点歧义**：FORK/JOIN 和 LOOP 下同一 nodeId 可被多分支或多轮访问；断点、当前位置和轨迹不得按 nodeId 去重或丢失 `branchId + nodeSeq`。
6. **权限与敏感信息**：变量、输入、输出和工具结果可能含业务敏感数据；必须保证租户/用户隔离、安全文本展示和最小化暴露。
7. **历史兼容**：新增调试能力不得改变普通执行接口、既有 V27/V28 历史记录或已完成运行日志页面的语义。

## 7. 验收标准

1. 有权用户可从生产可达的图定义/设计上下文启动调试；未认证、撤权、跨租户或不归属访问均由真实后端请求拒绝，`superadmin` 保持既有语义。
2. 调试会话绑定明确的图定义和稳定版本/内容快照，沿用既有可执行性门槛；调试期间编辑或发布图不会静默改变当前会话后续节点。
3. 启动后会话处于明确的可控制状态；一次“单步”只产生一个新的节点访问轨迹，并准确更新当前位置、变量、分支与终态。
4. 自动化行为证据覆盖顺序链、CONDITION、LOOP 多轮、FORK/JOIN 多分支；同一 nodeId 的多分支或重复访问不被合并，`branchId + nodeSeq` 与普通执行语义一致。
5. 节点断点可设置和取消；“继续”在节点执行前命中断点，并在下一断点、完成、失败、停止或预算触发时准确暂停/终结；断点不会改变节点业务结果。
6. 页面刷新或短暂断线后可恢复服务端真实状态、断点和轨迹；浏览器持久化不是状态权威，控制按钮与服务端状态一致。
7. 重复或并发的单步、继续、停止请求不会造成节点重复执行、状态倒退、多次终结或轨迹序号冲突；冲突请求返回清晰、稳定的契约结果。
8. LLM/工具等有外部副作用的节点在请求重试、恢复和重复命令下不会被隐式重放；行为证据覆盖至少一种工具或可观察副作用节点。
9. 成功、失败、主动停止、预算超限与过期均形成互斥终态；终态后继续控制被拒绝，过期会话资源得到清理，且已有轨迹仍按产品约定可审计。
10. 调试视图安全展示当前位置、下一执行位置、轨迹、变量、分支、耗时和错误；长文本/非 JSON 有降级，无 `v-html`、URL 泄漏、localStorage/sessionStorage 持久化或控制台明文日志。
11. 调试终态可从既有运行日志闭环识别并查看，普通执行历史、详情、节点轨迹和图设计/发布/执行能力无回归；历史记录不会被误识别为可继续的调试会话。
12. Mock 与真实 API 在会话状态、单步、继续、断点、循环/分支、错误、过期和无权场景上一致；Mock 不以客户端自演状态替代后端行为。
13. 若新增或修改持久化结构，H2 与 PostgreSQL 双方言、新库全链、既有库升级链及校验均通过；若执行层裁定零迁移，须以行为证据证明会话恢复、过期和审计要求仍可满足。
14. 后端受影响测试和项目级回归不得低于当前 **755/0/0/0**（agent 267）；前端 `typecheck`、`lint`、`test`、`build` 在 2G 上限下全部通过且不得低于 **82 spec files / 815 tests**。回执须给出可复算计数、实际命令、退出码、精确时间及前后端编译互斥零进程快照。
