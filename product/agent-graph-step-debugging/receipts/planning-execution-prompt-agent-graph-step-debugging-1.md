# agent-graph-step-debugging 执行补充提示 1（D177）

> 适用范围：仅用于闭合 D177 剩余缺口。  
> 执行依据：D175方向 + D176/D177审查记录。  
> 执行约束：执行层仅按本提示逐项执行，不得扩展范围、改写方向、重验已锁定项或提前修改终态。

## 1. 未通过缺口及证据要求

### G2 — 标准2：同一图会话快照稳定

- 使用**同一个 graphDefId** 创建调试会话，再对该图执行方向允许的编辑/发布变化，随后继续旧会话。
- 回执必须给出会话创建时版本/图内容、同图变化后的版本/图内容、旧会话继续后的实际节点轨迹与结果，证明旧会话仍按创建时快照运行。
- 若现有发布冻结规则不允许同图变化，应以真实请求结果说明阻塞，并采用能验证“持久化快照恢复不读取当前定义”的同图行为路径；不得再用另一个graphId替代。

### G4 — 标准4：普通执行与调试执行语义对照

- 对同一图、同一输入分别执行普通模式和调试模式。
- 至少覆盖 LOOP 与 FORK/JOIN，逐项对照实际 `nodeSeq`、`branchId`、重复nodeId、最终变量/结果；说明允许的记录粒度差异，但必须证明调度与业务结果一致。
- 不得只给调试轨迹或实现说明。

### G6 — 标准6：真实路由刷新恢复

- 使用真实router创建/导航到 `agent/debug/:sessionId`，挂载目标页面并触发真实API适配层请求；模拟刷新/重新创建应用后再次直达同一路由。
- 提供刷新前后服务端会话/断点/轨迹输入，实际请求，目标DOM、轨迹数量、断点和按钮状态结果。
- 组件直接unmount/mount配合替换mock返回值不等于真实路由刷新，不得重复提交。

### G8 — 标准8：外部副作用不重放

- 使用可观察的工具或副作用节点，并以调用计数器、服务端接收记录或等价行为证据记录实际调用次数。
- 覆盖首次step、相同expectedVersion重复请求、stale version请求、会话恢复后继续；证明该节点实际副作用调用总次数仍为1。
- 仅证明节点表行数/traceCount不变不足以核销。

### G11 — 标准11：既有运行日志闭环

- 必须满足方向原文：“调试终态可从既有运行日志闭环识别并查看”。提供从既有运行日志生产入口出发，识别调试记录、进入调试终态详情的真实导航/请求/DOM行为。
- 同时证明普通执行历史不会被误判为可继续调试，既有普通列表/详情/节点轨迹无回归。
- “调试列表与执行历史分离”“调试视图不调用执行历史API”不能替代该闭环；如当前产品实现确实不满足，应修正到既定方向，不得自行把方向解释为双轨完全隔离。

### G13 — 标准13：H2/PG真实迁移链

- 提供实际H2与PG Maven命令、2G环境、精确起止时间、退出码和关键原始输出。
- PG至少覆盖新库36条migrate+validate、既有V32/V33升级至链尾、checksum哨卫、V36调试表存在性；H2覆盖对应新库/validate及既有链要求。
- 明确每个命令是否包含在项目全量计数中，禁止“独立运行”同时声称“已在较早结束的全量内”。

### G14 — 标准14：唯一计数与互斥门禁

- 前端不必重验已通过业务项，但须提交同一有效轮次的typecheck/lint/test/build四门2G结果、精确时间和退出码；若沿用D177门禁，须明确未发生文件变化且证据仍对应当前提交。
- 后端提供一个唯一、非重复、可复算的项目级测试总数。必须列17模块小计或提供Surefire XML去重聚合清单，解释基线755、本轮新增数量与终值的算术关系；不得继续只报1652总数。
- 在后端开始前、后端结束/前端开始前及必要门禁点，提供避免自匹配的ps/pgrep实际命令、时间戳、退出码与**原始零输出**，覆盖mvn/java/pnpm/npm/node/vite/vitest/tsc等双方工具族。
- 不得引用不存在的“§5快照”或仅写“空”。

### G15 — 标准15：阶段三全量同步

- 仅在G2/G4/G6/G8/G11/G13/G14全部闭合后执行。
- 同步功能清单、P7、M07-F02-04、knowledge/current-status、功能追踪、known-issues、session-handoff、memory与product当前入口，并报告清单变更明细、触碰文件清单和无关清单零漂移。
- 在规划复验前只能写“待规划验收/拟核销/拟晋级”，不得写COMPLETED、正式核销P7、正式晋级M07-F02-04或把方向移入passed。

## 2. 相关验收标准原文

- 标准2：调试会话绑定明确的图定义和稳定版本/内容快照，调试期间编辑或发布图不会静默改变当前会话后续节点。
- 标准4：覆盖顺序链、CONDITION、LOOP、FORK/JOIN；同一nodeId多访问不合并，`branchId + nodeSeq` 与普通执行语义一致。
- 标准6：刷新或短暂断线后恢复服务端真实状态、断点和轨迹，控制按钮与服务端一致。
- 标准8：LLM/工具等副作用节点在重试、恢复和重复命令下不会隐式重放，至少覆盖一种可观察副作用节点。
- 标准11：调试终态可从既有运行日志闭环识别并查看，普通执行历史不可误识别为可继续调试。
- 标准13：H2/PG双方言、新库全链、既有升级链及validate通过。
- 标准14：后端项目级回归、前端四门、2G、唯一可复算计数、精确时间及前后端互斥零进程快照。
- 标准15：完成§3.3第10项全量同步，且不得提前改终态。
