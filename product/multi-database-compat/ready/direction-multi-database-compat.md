## 1. 目标

一个全新的空库，在下表每一种数据库上都能做到：
- 应用正常启动；
- 迁移链从头到尾执行成功；
- 全部 SQL 种子（菜单、角色、权限、字典、默认管理员、示例数据等）完整写入；
- 平台主链路能用。

现有 H2、PostgreSQL 的行为保持不变。

## 2. 数据库清单

| 级别 | 数据库与版本 | 说明 |
|---|---|---|
| 必须 | H2（现有测试模式） | 保持现状，作为回归 |
| 必须 | PostgreSQL（UAT 现用版本） | 保持现状；**UAT 已执行的迁移脚本校验和不得改变** |
| 必须 | MySQL 5.7 | 注意：不支持 CTE、窗口函数、`CHECK`，JSON 函数有限，默认字符集要显式设为 utf8mb4 |
| 必须 | MySQL 8.0 | 注意保留字变化（如 `rank`、`groups`）、默认认证插件 |
| 必须 | Oracle 19c（兼容 12c 及以上） | 注意：标识符长度、空字符串等于 NULL、没有 BOOLEAN 类型、序列和自增、`CLOB` 与 `VARCHAR2(4000)` 的界限、保留字（如 `user`、`level`、`comment`、`date`） |
| 必须 | 达梦 DM8 | 注意大小写敏感的初始化参数、兼容模式，Flowable 和 Quartz 如何识别达梦方言 |
| 必须（原扩展项，Owner 定全部要做） | 人大金仓 KingbaseES V8、SQL Server 2019 及以上、MariaDB 10.6 及以上、openGauss 5 | 排在第一批六种之后实现，验收标准相同 |

Oracle 11g 不在本次范围内。如果需要支持，Owner 另行提出。

## 3. 硬约束

1. **不改变已经发布的 PostgreSQL 和 H2 迁移链**：已执行过的脚本内容、版本号和校验和一律不动。新方言用 Flyway 的按厂商分目录（如 `db/migration/{vendor}`），或者用其他不影响现有校验和的方式承载。执行方先在能力核对中给出方案，经规划确认后再实施。
2. 种子数据在各数据库上**内容等价**：同样的表、同样的行数、同样的关键值（主键、编码、菜单树、角色与菜单关联、默认管理员能登录）。以 PostgreSQL 为基准逐表比对。
3. 第三方组件的表要一起覆盖：Flowable、Quartz/任务调度、MyBatis 映射里使用了方言写法的 SQL（如 `ILIKE`、`::` 类型转换、`LIMIT/OFFSET`、`ON CONFLICT`、`RETURNING`、JSON 操作符、布尔字面量）。只修 DDL 不算完成。
4. 不连接、不改动 UAT 数据库；验证全部在本机 Docker 或 CI 的临时容器中进行。本机 Docker 可以随意使用，但只停止或删除本任务自己创建的容器、卷和网络（用统一的名称前缀，例如 `swmdb-`），不动机器上其他容器。
5. 数据库镜像涉及许可证（Oracle、达梦）时，只用官方免费版或开发版镜像，不把账号、授权码或镜像凭据写进 Git。

## 4. 分阶段与验收

### 阶段 A：能力核对与方案（只读，不改代码）

回执写入 `receipts/execution-assess-01.md`：

- 清单：全部迁移脚本、种子脚本、MyBatis XML 和注解 SQL 中的方言写法，逐条列出“文件、写法、影响哪些数据库”。
- 第三方组件：Flowable、Quartz 等对每种数据库的支持情况和配置方式（重点是达梦）。
- 方案：
  - 脚本的组织方式；
  - 方言抽象的方式（例如 MyBatis `databaseId`）；
  - 主键和自增策略、布尔和 JSON 字段的映射；
  - 如何保证 PostgreSQL 和 H2 的校验和不变。
- 验证环境：每种数据库用哪个容器镜像和版本、能否放进 CI（建议 CI 每次跑 H2、PG、MySQL 8.0，其余数据库每晚或发布前跑一次）。
- 工作量估计；每种数据库的镜像能否拉取、能否在本机启动（实测）。

**规划确认方案后才能进入阶段 B。**

### 阶段 B：实现与验证（第一批六种）

按 MySQL 5.7/8.0 → Oracle → 达梦的顺序推进，每完成一种数据库提交一次进度回执 `receipts/execution-progress-NN.md`。每种数据库的完成标准：

1. 空库启动，迁移链全部成功，启动日志无 SQL 错误。
2. 种子比对：与 PostgreSQL 基准逐表比较行数和关键值，差异为 0。比对脚本放进仓库，可以重复运行。
3. 冒烟测试，全部通过：
   - 管理员登录；
   - 菜单和权限正确加载；
   - 新建表单并发布；
   - 发起流程，审批到结束；
   - 定时任务能触发；
   - 字典查询，分页查询（包括第二页）；
   - 中文和特殊字符的写入与回读。
4. 现有自动化测试在 H2 和 PostgreSQL 上全部通过，PostgreSQL 迁移校验和与 UAT 一致（回读 UAT `flyway_schema_history` 的校验和做对比，只读）。
