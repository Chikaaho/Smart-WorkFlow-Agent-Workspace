## 2. Z9 重写规则（三份 README 都适用）

**写给谁**：第一次打开仓库、想知道“这是什么、能做什么、怎么跑起来”的人。看不懂就删，或者换成一句大白话。

1. **不出现内部用语**：Owner、Planner、Executor、UAT、MVP、回执、门禁、终态、验收、返修、补丁列车、口径、收敛、防腐层、实例编号、CI run 号。确实需要指“演示环境”时，就写“演示环境”。
2. **版本一节**只写三样：当前版本号（Server 0.4.0 / Web 0.3.6）、和另一个仓的版本搭配（一句话）、一行链接“历史版本和下载见 Releases / CHANGELOG”。删掉 tag→commit、Release id、字节数、sha256、历史版本表。Server 的“回退到 0.3.2 要先恢复数据库备份”是用户真会遇到的，保留为一句话加文档链接。
3. **标题不带状态**：“三个示例流程”，不加“（已完成）”。正文也不写“已达到 MVP”。
4. **核心特性**：每条一行，写“用户能做什么”，不写“怎么实现的”。例如“表单拖拽设计，填报后自动发起审批”“审批意见可以决定流程走向”“图形化编排智能体，可调用工具和知识库”“支持九种数据库”。技术细节（CSP、增量输出、JSON 映射、防腐层）不进特性表，需要的话放进仓库结构或文档链接。
5. **示例流程**：每个一张图加 1—2 句话，说清这个流程是干什么的。不链接 knowledge 或回执。
6. **多数据库表**：列为“数据库 / 版本 / 建库要求”；验证方式一列只写“已测试”或“未测试（欢迎反馈）”，DM8、KingbaseES 写后者。建库参数保留，那是用户要用的。
7. **快速开始**：保留 Z7 实测过的步骤和命令，文字只说做什么；括号里的过程说明（如“开发种子口径”）删掉，默认账号口令直接列出即可。
8. **架构与仓库结构**：Mermaid 节点和表格说明用普通词，比如“设计器适配层”而不是“防腐层”。
9. **工作区根 README**：同样适用。治理方式一节可以保留，但压到几句话讲清“这个仓库用来做什么、分几种角色”，不列内部流程细节；发布明细（sha256、js 文件名、回执路径）全部删掉，只留 CHANGELOG 链接。
10. **整体篇幅**：两个代码仓 README 目标是现在的一半到三分之二。写完对照 humanizer-zh 的思路自查一遍：去掉解释性括号、空泛总结和堆砌的修饰语。

不改的：徽章、截图（仍不放 `agent-graph`、`approval-detail`）、命令和配置示例、链接目标、`.github/workflows` 的 `--latest=false`。
