## 计数口径与误报

- 规划审查引用的 105 条来自 assess-01 的原始文本计数（50 个 `@Select`、2 个 `@Insert`、8 个 `@Update`、45 个 `@Delete` 类文本）：其中 38 个是 `@DeleteMapping` HTTP 端点，只有 8 个是 SQL `@Delete`；6 个 `@Select` 是 Javadoc 提及，其余差异来自注释/统计口径。B0 逐条解析后，可执行注解 SQL 为 **62 条**（main 60 + dev 2）：@Select 44（main 42 + dev 2）、@Update 8、@Delete 8、@Insert 2。
- JdbcTemplate 调用 **52 处**（main 50 + dev 2），其中参数里直接承载 SQL 的 35 处，其余 17 处为 DataSource 访问、变量 SQL 或 RowMapper lambda。
- `JSON ->` 的 6 次命中全部是 Java lambda（`ps ->`、`rs ->`），不是 SQL JSON 操作符；真实 SQL 中 `ILIKE`、`::`、`RETURNING`、`->`/`->>`/`@>`、布尔字面量、`||`、`now()`、`INTERVAL`、`date_trunc`、`string_agg`、`array_agg`、`DISTINCT ON` 均为 **0 处**。
- 注解 SQL 中另有 `CAST(#{scope.userId} AS VARCHAR)`（AgentGraphExecutionMapper:38、:40）和 **15 处三参数 `CONCAT('%', param, '%')`**（6 个注解方法：JobInfoMapper 1、SysUserMapper 2、SysUserGroupMapper 4、CopyRecordMapper 8）；前者是类型名/长度差异，后者在 Oracle/达梦会因 `CONCAT` 只接受两个参数而报错。
- JdbcTemplate 里 `current_schema()`/`information_schema`（KnowledgeVectorColumnInitializer，3 处）、`pg_extension`（1 处）、`<=>` + `CAST(? AS vector)`（PgKnowledgeVectorStore，1 处）属于 pgvector/PostgreSQL 元数据链路，非 PG 数据库不执行这条链路。
