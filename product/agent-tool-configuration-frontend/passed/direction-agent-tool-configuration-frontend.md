## 1. 目标（一句话）

为既有工具 CRUD 与 Function Calling 能力补齐可达、可授权、可验证的前端配置闭环，使有权用户能够在统一「工具管理」入口维护内部工具和外部 HTTP 工具，并让启用后的工具可被图设计器 TOOL 节点选择。

## 2. 产品语义

- 在「智能体」管理域提供单一「工具管理」入口；页面在同一管理域中明确区分内部工具与外部 HTTP 工具，避免把两类契约混为一套表单。
- 两类工具均应具备列表加载、空态、错误态、新增、查看/编辑、启停和删除确认；查询、筛选及分页能力以既有后端契约为准，不为表面交互虚构后端语义。
- 新增与编辑必须覆盖既有后端 DTO 的全部可写业务字段；运行态、审计字段或后端派生字段只能展示，不得由前端伪造写入。
- `inputSchema` 等结构化配置必须提供用户可理解的编辑与校验反馈；无效 JSON/Schema 不得静默提交，合法内容必须无损往返。
- 启停状态决定工具是否可供运行时和图设计器选择；新增或编辑启用工具后，图设计器 TOOL 节点应通过既有数据源看到最新结果，不引入第二份静态工具清单。
- 前端权限必须沿用现有工具 Controller 的真实权限契约，不自创新权限码；菜单、按钮显隐和真实请求拒绝保持一致。
- Mock 模式与真实 API 在字段、CRUD、启停、删除、错误与权限语义上保持一致。

## 3. 非目标

- 不修改工具 Entity、Mapper、Service、Controller、V20/V23 表结构、运行时 `AgentToolCallbackFactory` 或既有 Function Calling 业务语义。
- 不建设工具在线调试台、试运行、调用日志查询、调用统计、版本管理、导入导出或工具市场。
- 不纳入 P9 图节点级多 Key 轮询、助手配置、RAG、SSE 对话窗口、Token 统计或其他模块缺口。
- 不重构图设计器或 `ToolPanel`；仅允许为证明既有下拉能消费新建/启停工具而修正直接阻塞该闭环的最小兼容问题。
- 不新增默认用户、不默认扩大普通角色权限、不改变 `superadmin` 既有语义。
- 不修改业务表结构。生产菜单缺失时，只允许新增 H2/PostgreSQL 双方言的最小菜单 seed 与既有权限绑定，不得改写历史迁移。

## 4. 影响范围（模块级）

### 前端

- Agent 模块的工具管理页面、内部/外部工具表单、API 与类型契约、表单校验和交互状态。
- Agent 路由、菜单消费、权限展示及 Mock handlers/fixtures。
- 图设计器 TOOL 节点既有工具下拉的兼容性回归。

### 后端与迁移

- 既有工具 CRUD、启停、删除和运行时转换 API 预期零业务改动。
- 若生产菜单尚缺失，新增不与现有版本冲突的 H2/PostgreSQL 双方言最小菜单 seed；具体版本号由执行层现场核实，禁止预设或复用已占版本。
- 除菜单可达性 seed 外，预期零后端实体、Service、Controller、业务表和运行时变更。

## 5. 风险方向

1. **双工具契约混淆**：内部方法工具与外部 HTTP 工具字段、校验和风险不同，单表单强行共用容易丢字段或错写类型。
2. **结构化配置损坏**：`inputSchema` 若只作为无校验字符串处理，可能保存不可执行配置；格式化也不能改变原始语义。
3. **菜单可见但接口无权**：静态路由、仅 `superadmin` 可用或按钮隐藏但请求未拒绝，都不构成权限闭环。
4. **Mock 与真实契约分叉**：简单内存 CRUD 容易忽略启停、删除失败、字段回填和权限拒绝语义。
5. **设计器数据陈旧**：管理页保存成功但 TOOL 节点仍使用静态或缓存旧列表，会形成“可配置但不可使用”的假闭环。
6. **历史迁移风险**：菜单必须使用链尾后的新版本并保持双方言一致，禁止修改 V36 及更早迁移。

## 6. 验收标准

1. 有权用户可从生产菜单进入「工具管理」，刷新与直接访问路由均可达；无权用户看不到对应入口或操作，直接请求仍被后端拒绝，未认证请求与 `superadmin` 行为符合既有契约。
2. 页面明确区分内部工具和外部 HTTP 工具；两类列表均具备真实数据加载、空态、错误态及与既有查询契约一致的检索/筛选行为。
3. 内部工具新增、详情回填、编辑、启停和删除形成真实 API 闭环，所有既有可写字段无损往返，前端不提交只读或自创字段。
4. 外部 HTTP 工具新增、详情回填、编辑、启停和删除形成真实 API 闭环，所有既有可写字段无损往返，前端不提交只读或自创字段。
5. 两类表单的必填、枚举、地址/方法及结构化字段校验与后端契约一致；无效 JSON/Schema 给出明确反馈且不发起保存，合法结构保存后再次打开保持语义一致。
6. 启停和删除均有明确确认、加载、成功与失败反馈；服务端拒绝或业务错误不得被界面伪装为成功，列表最终状态与服务端一致。
7. 新增或启用工具后，图设计器 TOOL 节点通过既有数据源可选择；停用或删除后的可选状态与后端既有语义一致，且不新增静态副本或平行契约。
8. Mock 模式完整覆盖两类工具的新增、读取、编辑、启停、删除、校验失败、服务端失败与无权访问，响应结构和状态变化与真实 API 契约一致。
9. 后端工具业务代码和运行时语义保持零改动；若发现必须修改才能完成上述标准，执行层应 `BLOCKED` 并提交方向冲突，不得自行扩大范围。
10. 若新增菜单迁移，H2/PostgreSQL 脚本语义对齐、版本不冲突，并以真实新库全链、上一版本升级链及权限可达行为验证；若无需迁移，回执须提供生产菜单已存在的行为证据并证明迁移零改动。
11. 前端 `typecheck`、`lint`、`test`、`build` 在 2G 上限下全部通过，测试数量不低于当前 **86 files / 850 tests**；若有迁移则后端项目级测试不低于 **827**、Agent 模块不低于 **338**，并保持 Flyway V36 之前历史链零改写。所有门禁须提供同轮精确时间、退出码、可复算计数和前后端互斥进程证据。
12. 完成阶段二要求的当前态知识同步：回执逐项报告实际修改、行为证据、测试计数及 `knowledge/`/`memory/`/需求池/功能清单触碰情况；在规划功能验收前不得核销 P48、提升 M07-F03-02、增加功能数、晋级正式基线或写 `COMPLETED`。
