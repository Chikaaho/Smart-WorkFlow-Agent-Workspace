# OA 核心界面体验设计方向

## 1. 定位与范围

- **功能名**：`oa-ui-experience-design`
- **等级 / 状态**：L / `READY`
- **规划产物**：一个可编辑的 Figma Design 文件，包含设计基础页和六个 1440px 桌面端高保真页面。
- **设计对象**：当前系统的门户、个人工作台、后台管理、数据列表、数据详情、流程节点页面。
- **参考边界**：用户提供的蓝凌 / MK-PaaS 截图仅用于抽取企业 OA 的信息层级、工作密度和流程可视化习惯；不得复制其商标、品牌色组合、产品命名、插画、页面文案或专有布局细节。

本方向独立于正在验收的 P60 I3；不改变 P60 的验收范围、状态、功能计数或既有回执。

## 2. 目标

建立一套面向中大型组织的现代企业 OA 工作界面：用户能从门户发现信息和服务，在工作台处理待办，在后台配置业务实体，在列表中检索和批量操作，在详情中理解数据与流程上下文，并在流程图中辨识当前节点、分支与审批轨迹。

界面应保持“高信息密度但不压迫”的特征：稳定导航、清晰层级、操作聚焦、状态可扫描，适合长期办公。

## 3. 统一设计语言

### 3.1 视觉基调

- **品牌主色**：深靛蓝 `#263A8B`，用于主导航、选中态、主操作。
- **辅助强调**：青绿 `#16A394`，用于正常、完成、可用状态；琥珀 `#F59E0B`，用于待处理/提示；玫红 `#E5484D`，用于异常/驳回。
- **中性色**：近白工作区、浅冷灰分区、深灰文字与弱灰分隔线，避免大面积高饱和填充。
- **字体**：优先选择可支持中文的系统无衬线字体；标题强调层级，正文保持 14px 可读密度，辅助文字不低于 12px。
- **布局**：1440px 设计基线；顶部全局栏 64px、左侧导航 248px、内容区 24px 外边距；8px 间距体系；卡片圆角 12px，浮层/抽屉圆角 16px。
- **反馈**：所有状态不能只靠颜色区分，必须同时使用文字、图标或形状；键盘焦点、禁用、加载、空态和错误态需有明确规范。

### 3.2 全局骨架

- 顶部栏：产品标识、全局搜索、当前组织切换、消息/待办、帮助、用户菜单。
- 左侧栏：一级功能分组、二级可展开菜单、当前页面高亮；可收起为图标栏。
- 内容区：面包屑、页标题及说明、页面级操作、主体卡片与二级导航。
- 右侧上下文：仅在工作台、详情和流程页出现，用于日程、流程摘要、操作记录或关联信息；不在所有页面强制占位。

## 4. Figma 文件结构与六个页面

### 4.1 `00 · Overview & Foundations`

用途：作为文件封面与交付说明，展示产品愿景、色彩令牌、文字层级、8px 间距、阴影、状态色与基础图标规则。必须标注“规划稿，不等同于已实现界面”。

### 4.2 `01 · 门户 Portal`

- 顶部以欢迎语、全局搜索和组织选择建立入口感；首屏不放营销横幅。
- 左列：通知公告、制度/知识推荐、常用链接；中列：服务分类和常用应用九宫格；右列：待办摘要、日程、消息提醒。
- 服务卡片按“行政人事、流程协同、知识文档、设备与资产、数据分析”分组，卡片显示图标、名称、简短用途及最近使用。
- 以一个“发起事项”主按钮提供快速创建入口，避免把所有功能塞入首级导航。

### 4.3 `02 · 工作台 Workbench`

- 核心区域为“待我处理 / 我发起的 / 我关注的”分段视图；待办卡展示紧急度、流程类型、标题、发起人、时限、当前节点与快捷审批。
- 右列包含可折叠的日历、今日安排和提醒；下方为“我的常用”“最近访问”“团队动态”。
- 顶部展示可读的工作摘要：待办、即将超期、已完成和本周日程；数字卡点击后进入相应列表。
- 允许用户编辑常用应用排序，但不把个性化设置放入首屏默认操作。

### 4.4 `03 · 后台管理 Admin`

- 信息架构为“组织与人员、权限与角色、流程与表单、应用与集成、消息与审计”五组；左侧导航与全局主导航层次分明。
- 首屏为运行概览：用户/部门/角色/应用/活跃流程等指标，异常待处理、最近配置变更和系统健康摘要。
- 管理操作有明确高风险样式：删除、停用、权限变更需二次确认且展示影响范围。
- 配置卡进入二级管理列表，不在概览页堆叠复杂编辑表单。

### 4.5 `04 · 数据列表 Data List`

- 标题区：页面名称、结果总数、主要动作“新建”，以及导入/导出等次级操作。
- 筛选区：常用条件直接展示；更多筛选使用可保存的抽屉；已生效条件显示为可撤销标签。
- 表格：固定首列选择框和关键标识；列包括名称/编号、状态、负责人、所属组织、更新时间、操作；支持密度切换、列设置、排序、分页和批量操作。
- 行内状态使用彩色标签加文字；空态、无搜索结果、加载骨架与权限不足均需分别呈现。

### 4.6 `05 · 数据详情 Detail`

- 顶部使用面包屑、对象标题、状态标签、关键元数据和主操作（编辑/提交/审批）。
- 信息按“概览、业务信息、附件与关联、操作记录”分组；长内容采用两列描述区，保持字段名称与值的对齐。
- 右侧上下文栏显示负责人、当前流程节点、相关记录和最近活动；窄屏时转为可打开抽屉。
- 底部固定操作区仅在存在未完成操作时出现，避免与页头重复。

### 4.7 `06 · 流程节点 Process Flow`

- 左侧为节点工具栏 / 节点目录，中间是可缩放画布，右侧是“当前节点”检查器与审批意见；顶部提供保存、发布、版本和模拟运行入口。
- 画布使用网格背景；开始/结束、审批、抄送、条件分支、并行网关、自动处理节点必须有结构不同的组件，而非仅改颜色。
- 运行查看态需高亮当前路径、已完成节点、待处理节点和异常分支；并显示实例编号、发起人、耗时及节点日志。
- 详情页的流程摘要可深链至该页的定位节点；流程页可回到对应数据详情，形成双向可理解的上下文。

## 5. 可复用组件与状态

v1 Figma 基础组件：顶部栏、侧边导航、页标题区、按钮（主/次/危险/文字）、输入与搜索、选择器、标签、统计卡、信息卡、表格行、分页、描述列表、时间线、空态、抽屉、确认弹窗、流程节点与连接线。

每个组件至少覆盖默认、悬停、禁用、加载和错误/风险（适用时）状态。流程节点还必须覆盖草稿、运行中、已完成、异常、禁用五种实例语义。

## 6. 非目标

- 不在本轮输出前端代码、接口变更、数据库变更或工程测试。
- 不复制参考产品的商业标识、专有内容、页面截图或视觉资产。
- 不把移动端、营销官网、数据大屏、低代码表单设计器扩展为本轮页面范围。
- 不改变当前 P60 / I3 的功能状态与验收标准。

## 7. 验收边界

Figma 规划稿满足以下条件后，才可作为前端实现的视觉方向：

1. 文件包含基础页和六类桌面端页面，标题与层次清晰可导航。
2. 六页共享同一套色彩、间距、字体、状态和导航规则；不混用参考产品品牌资产。
3. 每类页面至少展示一个真实业务状态和一个关键空态/异常态说明。
4. 列表、详情、流程之间的跳转关系有可理解的入口说明。
5. 交互元素满足最小 40px 点击/触控目标，文字与背景对比符合常规企业应用可读性要求。
6. Figma 文件地址、文件结构与核心组件清单回填至本方向或随后的执行回执；在此之前，功能状态保持 `READY`，不得声称设计已交付。

## 8. 风险与待确认项

- 当前 Figma 插件未完成 OAuth 连接，尚不能创建或写入文件；连接后从 Phase 0.b 继续。
- 现有工程的最终字体、图标库、路由和实际字段不在 Planner 可读范围内；前端 Executor 实施前须对照工程事实补齐，不得把本方向中的示意文案视为接口契约。
- 用户个性化工作台、字段权限和流程节点能力须沿用既有业务裁决，本方向只规定呈现与交互层级。
