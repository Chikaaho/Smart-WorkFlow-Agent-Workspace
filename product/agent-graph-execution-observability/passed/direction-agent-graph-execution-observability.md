## 1. 目标（一句话）

把既有图执行历史、失败分类和节点轨迹查询能力转化为生产可达的前端运行日志闭环，使有权用户能够从图定义上下文定位一次执行、查看结果或失败原因，并沿节点顺序、分支和变量快照追踪执行过程。

## 2. 产品语义

- 用户可从图定义列表或图设计器进入与当前图关联的运行记录，也可查看租户内有权访问的执行历史；入口应与既有 Agent 管理信息架构一致，不新增语义重复的首页占位入口。
- 运行记录列表复用既有分页和可选 `graphDefId` 过滤契约，至少展示执行标识、图定义、版本、状态、耗时、失败分类/摘要和执行时间；输入、输出及变量快照等大字段不得塞入列表主查询展示。
- 执行详情应展示输入、最终输出或失败信息、耗时、版本和时间信息，并能继续查看按 `nodeSeq` 排序的节点轨迹。
- 节点轨迹应可识别节点、节点类型、`branchId`、顺序、节点耗时和变量快照；FORK/JOIN/LOOP 的重复节点或分支不得被前端错误合并。
- 图设计器发起一次执行并取得 `executionId` 后，应能直接进入本次执行详情；既有 `success/output/errorMessage/latencyMs` 展示语义保持兼容。
- 对加载中、空记录、执行失败、详情不存在、无权限及接口失败提供明确状态；长文本与 JSON 快照应安全、可读，不使用 `v-html`，不把执行数据写入浏览器持久化存储或控制台日志。
- Mock 模式与真实接口在分页、过滤、成功/失败详情、节点顺序、分支轨迹和错误状态上保持一致，不制造后端不存在的调试控制能力。

## 3. 非目标

- **不做单步调试**：不新增暂停、继续、下一节点、断点、状态恢复或运行中会话控制；P7 的单步调试缺口保留为后续独立方向。
- 不修改图解释器执行语义、步数预算、LOOP/FORK/JOIN 调度、错误分类、变量快照或成功/失败落库规则。
- 不新增或修改 V27/V28 表结构，不做执行记录归档、清理、保留期、导出或统计报表。
- 不纳入 P6 Prompt 配置、P8 Token 统计、图节点级多 Key 轮询、工具管理、助手配置、RAG 或 SSE 对话窗口。
- 不扩展 `flow-graph` adapter 导出面；本轮消费既有图与执行历史契约，不增加边编辑、自定义节点渲染等 I48 范围能力。
- 不新增默认用户、默认扩大普通角色权限，不改变 `superadmin` 旁路、租户隔离或既有 `agent:model:view` 权限语义。

- Mock handlers、fixtures 与专项测试；失败分类和大字段的安全展示。
- 路由与按钮权限消费。是否采用独立页面、抽屉或组合视图由执行层按现有信息架构裁定，但必须满足可达、可刷新和上下文不丢失。

## 5. 风险方向

1. **轨迹语义被 UI 压平**：`branchId + nodeSeq` 承载并行、汇合与循环访问语义；按 nodeId 去重或树形误组装会丢失真实执行过程。
2. **大字段与敏感数据暴露**：输入、输出、错误信息和变量快照可能含业务敏感信息；应按需加载、安全文本渲染，不进入 URL、浏览器持久化、前端日志或测试快照。
3. **历史与实时语义混淆**：现有数据是已持久化的执行历史，不是可暂停的实时调试会话；UI 文案和按钮不得暗示不存在的控制能力。
4. **权限闭环不完整**：仅隐藏入口不能替代后端授权；生产入口、直达路由和真实请求必须继续受既有权限与租户隔离保护。
5. **Mock 掩盖契约问题**：Mock 若省略失败分类、重复节点、分支轨迹或不存在场景，会导致页面只在理想数据下可用。
6. **后端范围反向膨胀**：已有查询端点和数据模型已具备本轮地基；任何后端改动都应以“现有契约无法完成目标”的证据为前提。

## 6. 验收标准

1. 有权用户可从生产可达的图定义上下文进入运行记录，并可查看指定图的历史；若采用独立路由，刷新和直达不丢失上下文。无权用户不能通过入口或直接请求绕过授权。
2. 运行记录列表使用真实分页和 `graphDefId` 过滤，完整处理加载、空态、错误态与翻页；列表字段足以区分成功、失败、图版本、耗时和发生时间，且不内嵌输入/输出/变量快照大字段。
3. 执行详情准确展示 `executionId`、图定义/版本、状态、输入、输出或错误分类与错误信息、耗时和时间信息；不存在或跨租户记录按真实后端契约处理，不伪造空详情。
4. 节点轨迹严格按 `nodeSeq` 呈现，并保留 `branchId`、nodeId、nodeType、节点耗时和变量快照；自动化证据覆盖顺序链、FORK/JOIN 分支、LOOP 重复访问及失败节点，不按 nodeId 错误去重。
5. 从图设计器执行成功或失败后，可利用响应中的 `executionId` 定位本次执行详情；既有执行结果展示、图定义列表/设计/发布/执行能力无回归。
6. 输入、输出、错误及变量快照均采用安全文本或安全 JSON 展示；无 `v-html`，无 URL 泄漏，无 localStorage/sessionStorage 持久化，无控制台明文记录，并对超长或非 JSON 内容有可用降级。
7. `agent:model:view` 的生产入口、按钮/路由与真实请求链语义一致；至少证明授权访问、撤权拒绝、未认证拒绝和 `superadmin` 既有行为，且不通过默认扩权达成。
8. Mock 与真实 API 在分页结构、过滤、成功/失败详情、节点顺序、分支/循环轨迹和错误场景上保持一致；Mock 不提供暂停、继续、单步等后端不存在的能力。
9. 前端 `typecheck`、`lint`、`test`、`build` 在 2G 上限下全部通过，测试数量不低于当前基线 **73 files / 681 tests**，并有列表、详情、轨迹、安全渲染、权限、导航和 Mock 专项证据。
10. 后端与 Flyway 若零改动，回执须提供文件范围和现有三类查询端点可满足目标的证据，后端基线 **674/0/0/0** 不要求无意义重跑；若发生获准的最小后端契约补充，则须完成受影响测试、项目级回归及 H2/PG 迁移边界说明，且不得降低当前基线。
11. 所有编译测试遵守 2G 内存上限和前后端编译互斥；回执提供实际命令、退出码、计数、互斥检查及偏差说明。
