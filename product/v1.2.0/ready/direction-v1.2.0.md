## 1. 功能范围与验收标准

### E1 Graph 执行器（P67，Server + Web）

| ID | 验收标准 |
|---|---|
| E1-1 流程服务节点 | 流程设计器的服务节点可以选「Graph 执行器」：选择一个已发布的 Graph 并绑定**固定版本**，把流程变量或表单字段映射到 Graph 开始节点的入参，把结束节点的出参映射回流程变量。可选项只列已发布的 Graph，入参和出参都来自 1.1.0 G1-4 的参数声明，从列表里选，不手写字符串 |
| E1-2 发布校验 | 流程发布时校验：Graph 和版本存在且已发布；必填入参都有映射；出参映射的目标变量合法。不通过时指出是哪个节点、哪个字段 |
| E1-3 运行 | 流程走到这个节点时，以**系统身份**、按当前租户同步调用 Graph，等到结束再往下走。出参写回流程变量后，后续条件分支可以用它判断 |
| E1-4 超时与失败 | 节点配置超时上限（不超过 Graph 自己的执行超时）。超时、Graph 报错、出参缺必需字段三种情况：配了异常分支就走异常分支，并把原因写进流程变量；没配就让节点失败，实例上能看到原因。**不能出现节点成功但出参为空** |
| E1-5 Graph 人工节点 | 被调用的 Graph 里有人工节点时怎么处理，执行方在第一份回执里先回答（见 §3 问题 1），规划裁定后再实施。在裁定之前，发布校验先拒绝引用含人工节点的 Graph，并写清原因 |
| E1-6 表单服务端动作 | 表单设计器可以配置「调用 Graph」动作，触发时机两种：提交前、按钮。入参来自表单字段，出参回填到字段。提交前触发失败时阻止提交并提示原因；按钮触发失败时只提示，不清空已填内容。走服务端，不在前端脚本解释器里调用 |
| E1-7 运行记录关联 | 执行请求记录增加业务关联：来源（流程 / 表单 / 直接调用）、流程实例 ID、节点 ID、表单记录 ID。流程实例详情里，这个节点能看到对应的 Graph 执行编号、耗时、结果，并能跳到 Graph 执行详情。Graph 执行列表能按来源筛选 |
| E1-8 权限与隔离 | 流程或表单只能引用本租户的 Graph。跨租户的 Graph ID 发布时拒绝，运行时也拒绝（防止改库绕过校验）。以系统身份运行时，Graph 里的工具和知识库按租户隔离，和 0.2.x 现有口径一致 |

### E2 日志等级管理（P41，Server + Web）

| ID | 验收标准 |
|---|---|
| E2-1 查看 | 系统管理里新增「日志等级」页面，列出 logger（可以按名称搜索），显示配置的等级和实际生效的等级。优先复用 Spring Boot `LoggingSystem` 或 actuator `loggers`，不换日志框架 |
| E2-2 调整 | 可以把某个 logger（包或类）的等级调成 TRACE/DEBUG/INFO/WARN/ERROR/OFF，也可以恢复默认。调整立即生效，回执用一次真实请求前后的日志输出证明 |
| E2-3 权限与审计 | 只有新增的独立权限点（超管默认有）能查看和调整，其他人前端看不到菜单，后端拒绝访问。每次调整写操作日志：谁、哪个 logger、从什么等级改成什么等级 |
| E2-4 重启语义 | 页面写明「重启后恢复配置文件中的等级」。回执给重启前后对照 |
| E2-5 防误操作 | 把根 logger 调到 DEBUG 或 TRACE 时二次确认，提示日志量会增大。演示环境复测之后要恢复默认 |
