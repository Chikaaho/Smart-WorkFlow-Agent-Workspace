## 1. 背景与等级裁决

P53 不是局部换色或单页 CSS 调整。它覆盖用户端、管理端、登录、工作台、企业门户、数据页、表单与流程设计器、审批与会签、流程中心、个人菜单及响应式收口，并会同时触碰公共布局、设计令牌、路由入口、权限可见性、双语、无障碍和 P61 后续视觉证据。

本任务维持 XL：按共享基础和业务页面族分阶段推进，每阶段都必须可回滚、可独立核对，阶段性通过不等于功能级通过。P53 只改变视觉、布局、信息架构呈现和有真实能力支撑的交互入口，不授权借 UI 改造重写业务规则、接口、权限、租户、认证或流程状态语义。

## 2. 权威输入与冲突优先级

1. `docs/ui/png/` 是 1440px 渲染效果、层级、颜色和空间关系的视觉基准；`docs/ui/svg/` 是几何、尺寸、矢量元素和资产拆分参考。32 组文件身份以补充回执 G1 的 64 个 SHA-256 为准。
2. 真实业务行为、数据、权限、路由门禁、租户与流程语义以当前运行契约为准。设计中的示例数据、原型按钮、标签和菜单不能覆盖真实契约。
3. 当设计视觉与既有视觉令牌冲突时，本方向采用设计包的新视觉基线；当设计与安全、可访问性或真实能力冲突时，安全、可访问性和真实能力优先，并在回执中记录可见差异。
4. SVG 页面不得整体嵌入，PNG 不得作为页面背景伪装实现。页面必须由真实组件、真实数据状态和真实交互构成。
5. 设计文件若在实施期间发生哈希变化，受影响节点的视觉基线立即失效；Executor 必须停止沿用旧截图并回报变化范围，等待 Planner 判断是局部重基线还是方向变更。

## 3. 产品目标

1. 形成统一、可维护的 CH-aPaaS 视觉语言：品牌、颜色、字体、间距、圆角、阴影、边框、状态、导航、表单、表格、卡片、弹窗和浮层使用同一套令牌与组件规则。
2. 用户端、管理端和登录页具有清晰一致的区域身份、主导航、侧栏、个人菜单与前后台切换体验，同时保持菜单单源、服务端权限过滤和深链门禁正确。
3. 32 个设计节点均有明确运行时处置：真实页面完成布局改造，状态变体复用同一组件，纯原型只作为组件规范，缺少业务能力的部分不生成假入口。
4. 工作台、门户、数据页、流程中心、表单/流程设计器及审批详情使用真实数据和真实操作；加载、空态、错误、禁用、无权限和处理中状态诚实可见。
5. 桌面宽屏、窄桌面和现有移动 H5 在其支持范围内可用；中英文长文本、键盘、焦点、对比度、弹窗和触控行为达到正式验收要求。
6. 建立可持续的视觉回归基线，使后续改动能够发现裁切、遮挡、错位、错误断点和关键状态缺失，而不是只验证页面能打开。

## 4. 核心规划裁决

### 4.1 品牌、令牌、字体与资产

- 品牌主色以设计包确认的 `#6F2DFF` 为 P53 新基线，取代旧视觉目标 `#7e306b`；交互色阶、禁用色和 Element Plus 派生色从同一品牌阶生成，不逐页手写。
- 深色导航以设计包的 `#17213A` / `#19233B` 色阶为基线。普通正文与交互文本必须达到 WCAG 2.1 AA；设计示例色达不到对比度时允许做最小必要调整并记录差异。
- 字体采用明确的本地安全回退链。不得从未授权 CDN 或未知来源引入 Inter；只有在仓库内存在合法、可追溯字体资产时才能把它作为实际字体文件交付。
- Logo、图标和插画必须落为稳定本地资产并具有来源、命名与复用入口；全页 SVG、内嵌 base64 页面切图和 PNG 截图均不得成为运行时组件。
- 设计令牌保持单一入口；Element Plus 覆盖、业务组件和页面样式不得形成互相竞争的品牌变量源。

### 4.2 设计稿与真实能力的边界

- 设计稿决定信息层级、布局、组件形态、状态呈现与交互反馈，不自动新增 Server 能力。
- 缺少真实接口、权限或状态契约的按钮、菜单、统计、图表和设置项不得展示为可用。可以不呈现，或在产品确有只读语义时展示诚实的空态/不可用说明；不得点击后假成功。
- 页面可以新增或重组前端入口来承载既有能力，但不得改变既有 API 语义、业务结果、权限判断、数据隔离或流程状态。
- 用户端与管理端继续共享一个布局体系和一套菜单来源；区域视觉可不同，但不得复制成两套权限、菜单或路由事实源。

### 4.3 导航与信息架构

- 顶部主导航、深色侧栏和区域切换采用设计语言，但只展示当前账号真实可达的模块。设计稿中不存在对应能力的“应用管理、门户管理、运行监控”等标签不能作为空菜单落地。
- 管理入口继续受后台准入与服务端权限控制；隐藏入口不能替代直连路由和接口拒绝。用户撤权后，菜单、深链、按钮和接口结果必须一致更新。
- 企业门户作为用户端可达视觉页面交付，但只聚合现有真实工作台、流程目录和已有统计能力。公告、知识、全局搜索、趋势或关注能力没有真实数据源时不在本轮伪造；对应设计区块可以省略或使用诚实空态。
- 流程中心分类继续由服务端运行时数据驱动。行政办公、财务管理、IT 运维、设备管理、平台权限五个设计示例不得写死为生产种子，也不得绕过服务端可见集与分类计数。

### 4.4 认证、表单与流程锁定项

- 登录页交付品牌分栏、层级、表单与 SSO 视觉改造，但保持现有验证码、RSA、会话与 SSO 契约。租户输入、记住登录、忘记密码和修改密码均不在 P53 新增。
- 表单设计器保持已交付的 24 列语义、字段 schema、草稿历史和关联流程契约。设计中的 12 栏视觉可以作为 24 列的主刻度呈现，不得把底层布局退回 12 列或双列。
- 流程设计器只呈现当前正式支持的节点类型和配置能力。IoT 指令、Agent 调用、起草节点、动态审批规则、监听器与前后置处理器没有正式契约时不得出现可用入口。
- 审批意见、会签和流程图可以基于现有真实记录形成更清晰的详情与弹窗；没有审批时表单版本快照、逐人时间或聚合字段时，不得补造数据或宣称已支持。

### 4.5 响应式边界

- `1440×1024` 是全部设计节点的主视觉基线；节点 19 使用 `1440×1512` 长页内容基线。
- `1920×1080` 验证宽屏栅格与信息密度；`1280×800` 验证窄桌面侧栏、表格滚动和主要操作可达。
- `375×812` 正式覆盖登录页及现有 `/m/form/:formKey`、`/m/workflow`、`/m/notify` 三个移动 H5 页面。不得把 1440 页面整体缩放成移动页面。
- 复杂管理页和设计器本轮不新增完整移动版；在小屏访问时必须提供明确、可返回的桌面要求提示，或路由到已有等价 H5 入口，不能留下被裁切且无法操作的画布。
- 767px 断点继续作为现状兼容点，但最终行为必须以页面可达和触控可用为准，不仅以侧栏隐藏为完成标准。

### 4.6 双语与可访问性

- 所有新增用户文案、aria 标签、空态、错误态、对话框和状态标签必须同时进入 zh-CN/en-US locale；禁止新增散落硬编码文案或以中文逐字翻译构造英文。
- P61 已建立的 `errorKey`、事件引用、语言请求和安全消息边界保持不变；P53 不得用视觉组件重新拼接内部错误、状态枚举或原始异常。
- 键盘用户必须能到达主导航、侧栏、表单、表格操作、菜单和弹窗；焦点可见，弹窗打开后获得焦点、关闭后返回触发点，Escape 与 Tab 顺序符合组件语义。
- 普通文本对比度至少 4.5:1，大字号至少 3:1；触控目标、错误提示关联、语义标题、表单 label 和禁用态不能只靠颜色区分。

### 4.7 视觉回归与正式浏览器证据

- 批准在 Web 工程内引入 `@playwright/test` 作为开发依赖，建立组件/页面截图基线和跨视口项目；不得引入第二套并行视觉工具链。
- 稳定截图夹具可以使用受控测试数据验证布局，但不能代替真实后端行为证据。动态业务页面的正式结论必须由真实身份、真实权限、真实请求和用户可见浏览器会话支撑。
- headless 或后台像素比较只标记为 `COMPONENT_TEST` / `ISOLATED_REGRESSION`；功能级正式浏览器证据必须 `headless=false`，保存可回读截图、URL、视口、身份、对象和网络索引。
- 初始区域阈值采用：顶栏≤0.5%、侧栏≤0.5%、主区≤2%、en-US 长文本区≤3%。首份合法基线建立后只能做一次有说明的校准；后续不得通过随意更新基线掩盖失败。
- 无论整页差异比例是否合格，以下任一命中均失败：关键元素越界超过 1px；关键交互遮挡面积大于 4px²；关键容器位置偏差超过 2px；断点行为错误；加载/空态/错误/无权限/禁用状态缺失；locale 键回退或硬编码绕过。

## 6. 功能范围

- 统一设计令牌、Element Plus 主题覆盖、字体回退与品牌资产入口；
- 全局布局壳、顶部主导航、深色侧栏、区域标识、个人菜单和前后台切换；
- 登录、工作台、企业门户、管理后台首页形态；
- 数据列表、数据详情、流程图、审批历史与受限详情弹窗；
- 表单设计器、关联流程、历史版本、字段属性只读视图；
- 流程设计器、真实审批人选择、流程中心、发起流程；
- 现有三类移动 H5、登录页与小屏访问边界；
- zh-CN/en-US、可访问性、加载/空态/错误/无权限/禁用状态；
- Playwright 视觉回归、现有聚焦回归、构建门禁和正式可见浏览器证据。

## 7. 非目标

- 不新增或改变 Server API、数据库结构、业务状态机、租户与数据权限模型；发现必须依赖 Server 新契约的需求，停止该原子并回报，不顺手扩张。
- 不新增租户输入、记住登录、忘记密码、修改密码、多工作空间或租户切换。
- 不新增 IoT/Agent/起草流程节点、动态审批规则、监听器、前后置处理器或审批时表单版本快照。
- 不建设公告、知识、全局搜索、关注、趋势分析或完整门户内容管理；企业门户只聚合既有真实能力。
- 不把五个设计分类写为生产种子，不更改真实分类命名或权限过滤。
- 不为复杂管理页和设计器建设完整移动版，不交付暗色主题。
- 不执行 P61 剩余提示语治理；只保护其机器语义、双语和安全消息边界。
- 不修改已发布的 P60/0.1.0 标签、Release、版本身份或历史证据。
- 不在本阶段核销 P53、增加正式功能数、改动清单计数或晋级正式验证基线。

## 8. XL 阶段边界

### 阶段 A：视觉基础与回归底座

统一令牌、品牌资产、字体、基础状态组件与视觉回归能力。该阶段只建立共享基础，不以令牌完成替代页面验收。

### 阶段 B：全局壳、导航与入口页面

收敛布局壳、区域导航、个人菜单、登录、工作台、企业门户和管理后台呈现；权限、菜单单源、登录契约和前后台准入保持锁定。

### 阶段 C：数据与流程消费页面

覆盖数据列表/详情、流程图、审批详情、流程中心和发起流程；重点证明真实数据、真实状态、分类动态性和既有操作不回退。

### 阶段 D：设计器与复杂浮层

覆盖表单/流程设计器、关联流程、历史版本、字段属性、审批人选择及受限高级配置；严格按节点处置矩阵排除无契约能力。

### 阶段 E：响应式、双语、可访问性与整体收口

完成四类视口、双语长文本、键盘与焦点、对比度、状态矩阵、视觉差异和正式用户可见浏览器流程。只有 A—E 整体通过后才能提交功能级完成回执。

## 9. 功能级验收标准
