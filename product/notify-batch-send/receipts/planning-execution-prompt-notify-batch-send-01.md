# 通知批量发送一级执行补充提示 01

> 触发原因：G1—G7 中同类行为证据缺口连续两次复验未通过
> 本提示性质：首次一级收敛提示，不改变原需求方向
> 合法完成状态：`EXECUTION_SUBMITTED`；真实无法完成时为 `BLOCKED`

## 1. 权威输入

执行角色只以以下三份文件作为本轮验收输入：

1. `product/notify-batch-send/ready/direction-notify-batch-send.md`
2. `product/notify-batch-send/receipts/planning-review-20260827.md`
3. `product/notify-batch-send/receipts/planning-rereview-20260827.md`

v1/v2 完成回执只作为历史，不得用其中的自述替代本提示要求的新行为证据。

## 2. 本轮唯一剩余缺口矩阵

| 编号 | 失败事实 | 不可接受证据 | 唯一可接受证据 |
|---|---|---|---|
| R1 | 接收人解析与有效对象行为未逐项证明 | Mapper/SQL/测试名/用例表 | 同一最终代码状态下，真实批量端点或等价集成行为的原始输出：单用户、单部门、单角色、三维重叠，以及 user/dept/role 各自的不存在、跨租户、停用/删除输入；每项给出响应、最终接收人集合、落库前后计数。 |
| R2 | 原子性场景遗漏 | `@Transactional`、异常分支、文字“落库+0” | 0、500、501、缺变量、停用模板、删除模板、批次中途失败七个独立行为包；成功项勾稽响应人数=新增数，失败项勾稽前后计数相等。中途失败必须来自可复现的失败注入，而非假设。 |
| R3 | 独立发送权限只有结构说明 | 注解、权限码、seed、角色列表、源码扫描 | 真实后端请求和真实前端路由链：发送权限成功；仅收件箱权限 403；仅模板管理权限 403；未认证 401；直接路由访问拒绝；Mock 对对应身份给出等价结果。还需证明生产权限资源可授予普通非超管角色。 |
| R4 | 服务端人数确认没有页面闭环 | watch/API 函数存在、组件测试名、前端估算 | 单一重叠输入的完整页面行为链：选择对象 → resolve-count 原始响应 → 确认框显示同值 → batch-send 原始响应 → 数据库新增同值；全部数值逐字一致。 |
| R5 | Mock/真实一致性没有同输入对照 | handler 实现说明、期望集合文字 | 至少一组含父/子部门和角色重叠的相同请求，分别给出真实后端与 Mock 的原始响应、最终接收人集合和人数，三项逐字一致；未提交的子部门不得被任一侧隐式展开。 |
| R6 | 完整质量门与互斥未满足 | `npx` 替代脚本、局部 lint/test、一次性互斥概述 | 严格串行执行项目标准命令并保留原始结尾：后端全量 `MAVEN_OPTS="-Xmx2g" mvn test`；前端 `NODE_OPTIONS="--max-old-space-size=2048" pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`。每次命令前附对方编译/测试进程快照；提交最终可复算总数与新增数。 |
| R7 | v2 没有合法机器终态 | 标题写 PASSED、自验结论、正文声称终态 | 新增回执最后一行必须是通过公共 Validator 的 `SWF_TERMINAL` JSON，state=`EXECUTION_SUBMITTED`，receipt 指向本轮新增回执，并列出 R1—R6 证据文件。 |

## 3. 已锁定通过项和禁止重验项

- 非目标范围纪律已通过：发送记录、失败重发、外部渠道、定时发送及其他 P 编号均禁止触碰。
- P36 模板规则和历史通知稳定性已通过，禁止修改其产品语义；只补批量调用证据。
- 部门语义锁定为“传入哪些 deptIds 就解析哪些部门”，禁止真实后端、前端或 Mock 隐式递归未提交的子部门。
- 历史回执必须保留，不得覆盖、重命名或删除。

## 4. 允许范围

### 允许读取

- 原方向、两次规划审查与本提示；
- 通知批量发送、消息模板、通知权限相关的后端/前端/Mock/迁移/测试文件；
- 用户、部门、角色有效关系查询所需文件；
- 两端工程宪法、公共终态契约与 Validator。

### 允许修改

- 仅限核销 R1—R7 必需的通知批量发送后端、前端、Mock、生产菜单/权限资源和测试文件；
- 仅新增 `product/notify-batch-send/receipts/` 下的本轮补证回执/证据文件；
- 不允许修改方向文档、memory、knowledge、功能清单、需求池或其他功能文件。

### 允许命令

- 定位与静态检查命令；
- 构造 R1—R5 行为证据所需的测试/本地请求命令；
- R6 指定的 2G 串行全量门禁；
- 公共终态 Validator。

## 5. 禁止事项

- 禁止再以源码、SQL、测试名、用例表、注解、文件清单或“已实现”自述替代原始行为输出；
- 禁止只补部分 R2/R3 场景后声称全部核销；
- 禁止用超管旁路证明普通发送权限可用；
- 禁止用前端估算人数替代服务端确认人数；
- 禁止用 `npx` 局部命令替代 R6 指定的 `pnpm` 完整门禁；
- 禁止写功能 `PASSED`/`COMPLETED`、核销 P3/M05-F01-01、更新正式基线或移动方向；
- 禁止扩大到发送记录、失败重发、通知渠道或其他需求。

## 6. 相对上一版新增/收紧约束

**首次提示**：相对两次普通审查，本提示首次把剩余缺口收敛为 R1—R7，并规定每个缺口唯一可接受的行为证据。特别收紧：

- R2 七个场景必须逐一出现，不接受抽样；
- R3 必须包含普通非超管角色的真实生产权限链；
- R4/R5 必须使用同一输入做端到端数值和集合对照；
- R6 只接受项目标准 `pnpm` 脚本及逐门禁互斥快照；
- R7 必须以实际 Validator 通过的结构化行收尾。

## 7. 逐缺口证据包格式

每个 R 编号单独成节，严格包含：

1. 输入数据与身份/租户；
2. 实际执行命令或页面操作；
3. 原始关键输出；
4. 落库前后计数及最终接收人集合（适用时）；
5. 正向目标断言；
6. 反向零残留/越权拒绝断言；
7. 本缺口结论。

不得把多个 R 编号合并成一段“全部通过”的总结。
