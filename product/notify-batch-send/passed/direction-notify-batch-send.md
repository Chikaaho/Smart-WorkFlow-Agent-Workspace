# M05 通知批量发送闭环需求方向

> 本会话角色：规划（Planner）
> 方向状态：PASSED（2026-08-27，规划功能级验收通过）
> 候选编号：P3 / M05-F01-01；本轮只处理批量发送子集，不核销整个 P3

## 1. 目标

在现有站内通知、消息模板和个人收件箱能力之上，补齐面向授权发送人的通知发送入口，使其能够按用户、部门和角色选择接收对象，一次形成去重、可确认、受租户与权限约束的站内通知批量投递闭环。

## 2. 选择原因

选择 P3 的批量发送子集作为下一唯一业务功能，依据是：

1. P3 仍是已开发但未满足的中优先级缺口，M05-F01-01 仍为 🟦；完成本轮可以推进真实清单项，而不是只增加已完成能力之外的低优先级增强；
2. 最近两轮已完成通知查询/删除与消息模板，站内通知落库、收件箱、模板渲染、菜单权限、双方言迁移和前端通知模块均已有可复用基础，连续建设的上下文和回归边界最清楚；
3. 相比 P9 图节点级多 Key 轮询，本轮不改造图解释器核心调用链，故障扩散面更小，同时有清单收益；
4. P19/RAG 仍受选型未收敛限制，P32/P33 仍有基础库或产品语义待决，P25/I50 又不足以单独占用一轮主功能；
5. 批量发送是通知模板、后续通知规则与发送记录之间的自然承接点，但本轮严格停在站内信批量投递，不提前实现后续状态机或多渠道能力。

## 3. 产品边界裁定

### 3.1 接收对象

- 支持按用户、部门和角色选择接收对象，并允许同一次发送组合使用；
- 部门和角色只解析当前租户内、当前有效关系下的用户，不能跨租户读取或投递；
- 同一用户被多个条件重复命中时只生成一条通知，最终接收人数以去重后的用户数为准；
- 无任何有效接收人时必须在落库前明确拒绝，不能把空发送当作成功；
- 单次发送按最终去重人数设置服务端硬上限 **500 人**；超过上限必须在落库前整体拒绝，不得静默截断或部分发送。

### 3.2 内容来源

- 发送入口同时支持直接填写标题/正文，以及选择一个已启用消息模板并提供变量；两种模式互斥，不能混合出第三套内容优先级；
- 模板模式必须复用 P36 已通过的模板渲染与发送前校验语义，不新增另一套占位符解析规则；
- 缺失变量、非法模板、停用/删除模板或直接内容不完整时，必须在任何通知落库前整体拒绝；
- 历史通知继续保存最终标题与正文，后续模板变化不得回写已投递内容。

### 3.3 发送原子性与结果

- 一次批量发送要么对全部最终接收人成功落库，要么零落库；不得返回成功但只写入部分接收人；
- 成功结果至少明确返回最终去重接收人数，使前端确认信息、接口响应和实际落库数量能够勾稽；
- 失败结果必须区分输入/权限/对象解析/模板校验等可判定原因，不得用笼统成功或静默忽略掩盖失败对象；
- 本轮仅形成站内通知，不引入异步消息队列、外部渠道或跨进程补偿语义。

### 3.4 权限与管理体验

- 查看个人收件箱不等于拥有发送权限；发送入口、路由、按钮和服务端接口必须使用独立发送权限闭环；
- 授权发送人可以在页面选择接收对象、选择内容模式、看到去重后的接收人数、确认后发送，并收到明确成功或失败反馈；
- 最终人数必须由服务端按真实权限与关系解析得出，前端估算不得作为授权或落库依据；
- Mock 模式与真实后端在对象组合、去重、人数上限、模板限制、权限拒绝和结果计数上保持一致。

## 4. 本轮必须覆盖

- 后端批量接收对象解析、租户隔离、去重、人数上限、发送权限、发送原子性与结果契约；
- 直接内容与现有模板两种互斥发送模式，并复用既有模板渲染规则；
- 前端通知发送入口、用户/部门/角色选择、服务端人数确认、发送确认和结果反馈；
- 必要的菜单/路由/按钮权限与 Mock 契约；
- 用户、部门、角色重叠命中、无有效接收人、超限、跨租户、无权限、模板不可用和中途失败时零残留的真实行为闭环；
- 现有直接单用户发送、模板单用户发送、收件箱列表、过滤、已读/未读和删除能力不得回归；
- 按工作区协议同步功能清单、P3 剩余边界、知识状态和交接材料。

执行角色负责自行确定实现结构、Step 数量、执行顺序和测试方案；本方向不预先规定类、接口、迁移版本或具体技术实现。

## 5. 非目标

- 不实现发送记录状态机、失败重发、送达回执、全局发送日志或统计报表；
- 不实现定时发送、撤回、审批、草稿或发送任务队列；
- 不接入邮件、短信、微信、企微、钉钉等外部通知渠道；
- 不修改 P36 的模板语法、模板管理边界或历史通知语义；
- 不实现基于动态组织表达式、任意 SQL 或自定义脚本的接收人规则；
- 不顺带处理 P9、P19、P25、P32/P33 或其他模块缺口；
- 不因本轮完成而直接核销整个 P3；发送记录等剩余缺口必须继续保留。

## 6. 影响范围（模块级）

- 后端通知模块：批量发送契约、接收对象解析、权限、事务和通知落库；
- 后端组织与权限查询能力：仅复用用户、部门、角色及有效关系，不改变其业务模型；
- 前端通知模块：发送页面、对象选择、模板/直接内容模式、人数确认和结果反馈；
- Mock：与真实后端一致的批量解析、去重、限制和错误行为；
- 数据与权限：如现有结构不足，只允许增加本功能必需的菜单/权限或持久化支持，不扩大为发送记录状态机；
- 回归与收尾：现有通知、模板、收件箱及 P3/M05-F01-01 的状态材料。

## 7. 风险方向

1. **跨租户或越权投递**：前端提交的对象 ID 不能被直接信任，服务端必须在当前租户和发送权限下重新解析；
2. **重复通知**：用户、部门和角色交叉命中若不统一去重，会造成同一批次多条重复消息；
3. **部分成功污染**：逐人写入时的中途异常可能留下半批数据，验收要求成功全量或失败零残留；
4. **无界扇出**：部门或角色可能展开为大量用户，必须以服务端最终去重人数执行 500 人上限；
5. **模板规则漂移**：批量发送不得复制或简化 P36 渲染逻辑，预览/单发/批量发送的最终内容语义必须一致；
6. **权限误复用**：收件箱查看权限、模板管理权限和批量发送权限是三种不同能力，不能互相替代；
7. **P3 误核销**：本轮只关闭批量发送子集；发送记录、失败重发和全局日志仍在范围外。

## 8. 规划验收边界

规划层只在完成回执提供真实行为证据后逐项验收：

1. 单个用户、单个部门、单个角色及三者组合均能解析并投递给当前租户内的有效用户；
2. 同一用户被多条选择路径命中时只落一条通知，接口返回人数与真实新增通知数一致；
3. 跨租户对象、无发送权限和不存在/无效对象不能形成越权投递；
4. 零有效接收人和最终人数超过 500 时在落库前整体拒绝，数据库零残留；
5. 直接内容模式和模板模式均可批量发送，模板模式与 P36 预览/单发的渲染结果一致；
6. 缺变量、停用/删除模板、非法输入或批次中途异常时整批零落库；
7. 页面能够完成对象组合选择、服务端人数确认、二次确认、发送及明确结果反馈；普通收件箱用户不能通过菜单、路由或直接请求获得发送能力；
8. Mock 与真实后端对组合解析、去重、上限、权限、模板失败和成功计数行为一致；
9. 现有单用户直发、模板单发、收件箱列表/过滤/已读/删除不回归，前后端质量门和编译互斥证据完整；
10. 收尾只推进 M05-F01-01 的批量发送边界，P3 仍保留发送记录等未完成项，并完整同步知识、清单、需求池和交接材料。

实现说明、文件名、测试类名、源码扫描或执行层自述不能单独构成通过依据；上述标准必须由实际请求/响应、持久化计数、权限拒绝、页面交互、命令输出或等价真实行为证据支撑。

当前没有阻塞实施的产品问题。若执行探索发现现有用户/部门/角色查询契约无法在不改变组织权限模型的前提下完成服务端有效用户解析，或现有通知落库机制无法保证 500 人以内的事务原子性，必须在回执中报告方向级冲突，由规划层裁决；执行角色不得自行改为部分成功、异步补偿或扩大组织模型。
