## 一、结论

本轮不能裁决 P21 `PASSED`。

执行回执证明已形成较大实现范围，并描述了公共 MQTT Broker、JavaScript 沙箱、Java 子进程、阈值规则和流程实例等行为；但回执没有附带可独立回读的原始行为证据，且存在已明确承认的产品缺口。当前不能把结构清单、测试名称或执行层自述替代 A1—A8 行为验收。

以下规划口径继续锁定，不要求重复争议：

1. 腾讯 IoT 实网因无账号按 Owner 本轮免验，不要求真实腾讯 RequestId 或物理设备证据；仍需证明既有腾讯通用契约未回归。
2. Owner 提供的 MQTT 连接数据允许在后台真实录入；若该 Broker 返回 `NOT_AUTHORIZED`，必须如实保留为连接测试失败，不能写成健康连接。
3. 经 Owner 授权使用公共 Broker 时，公共 Broker 可以证明自建 MQTT Provider 的真实发布/订阅能力；它不替代 Owner Broker 的认证失败事实，也不能替代凭证加密/脱敏验收。
4. P21 仍为一个统一功能，不拆分新编号；后续只补下列剩余原子。

## 四、下一轮唯一剩余缺口

### G1 收敛真实 MQTT 事实与证据

- 追加一份当前 MQTT 事实表，分别列 Owner Broker 与公共 Broker 的连接配置 ID、认证结果、健康状态、Topic、双端观察和用途。
- 若公共 Broker 已获 Owner 授权，补齐后台保存连接 → 服务端订阅/发布 → 独立 CLI 双向观察 → 重启恢复 → 去重/失败的原始附件。
- Owner Broker 继续返回认证失败时只保留为真实失败分类证据，不再把无法修复该账号写成 P21 整体阻塞。

### G2 完成 A6 产品实现

- 完成流程设计/节点配置中的三类设备来源：设计时固定、发起时有权选择、表单字段/流程变量解析。
- 设计态仅显示“已发布 + 可接入流程使用 + 有权限 + 具备目标能力”的设备；保存/发布和运行时均重新校验。
- 补齐能力参数映射、触发时机、同步/异步结果和阻断/继续/人工处理失败策略，并证明单次触发只有一条命令且全链同一关联标识。

### G3 完成表单契约校验与流程表单回查

- 规则保存/发布时按真实流程模板与表单版本校验字段存在、必填、类型、枚举、引用和租户边界；触发时用实际值再次校验。
- 补真实流程实例与表单数据回查，展示设备身份、属性/事件、阈值前后值、触发时间及脚本输出的映射结果。
- 补未发布/未开放设备、模板不可用、字段不存在、类型错误、必填缺失和无权限的明确拒绝。

### G4 完成双语言真实脚本链与隔离证明

- JavaScript 与 Java 各发布一个脚本，各自通过统一宿主函数处理真实消息；两者合计至少覆盖 `fun_publish`、属性或事件写入，以及流程发起或设备行为调用。
- 补原始脚本版本、输入、输出、运行记录和宿主函数结果；补文件、环境变量/秘密、数据库、任意网络、进程/宿主类访问被拒，以及超时/资源超限被强制终止的真实结果。
- 证明异常脚本不会中断 MQTT 消费、主业务进程或另一设备/租户的正常执行。

### G5 完成权限、审计与多租户隔离

- 以有权管理员、受限管理员/普通用户、未认证身份分别验证页面入口、按钮、真实后端请求和持久化结果。
- 固定至少两个租户/数据域，验证连接、设备、Topic、脚本、规则、消息、命令和流程映射零串读/串写。
- 回查连接凭证变更、脚本/规则发布、真实联调、命令重试和流程发起的审计记录。

### G6 补完整闭环、页面和工程证据

- 用同一组对象 ID 串联：后台配置 → 自建 MQTT 收发 → 物模型更新/事件 → JavaScript/Java 脚本 → 阈值规则 → 表单填充 → 流程实例 → 流程设备命令与结果。
- 提供七个后台入口的真实浏览器 DOM/截图和请求结果，验证无白屏、假按钮、明文凭证、错误成功提示和状态错位。
- 附受影响模块、完整后端、前端 typecheck/lint/test/build、H2/PG 全链迁移的原始命令输出、计数与退出码；测试计数按实际输出引用，不手抄推算。
- 补既有腾讯 Provider、命令队列、状态回调和审批驱动设备链的受影响回归；腾讯实网继续免验。
