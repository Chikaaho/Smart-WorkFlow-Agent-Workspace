## 一、目标

在既有腾讯 IoT 能力上形成后台可管理、供应商无关且能与流程双向联动的 IoT 平台能力：

`连接配置 → 产品/物模型 → 设备 → Topic → 脚本/事件规则 → 命令与事件 → 流程实例与表单数据`

本轮完成以下统一结果：

1. 管理后台能够维护设备、连接配置、物模型、Topic、脚本、事件规则及执行记录。
2. 设备连接类型至少支持内置腾讯 IoT 与自建 MQTT。
3. 腾讯 IoT 复用腾讯的产品、设备、规则和 Topic 语义；自建 MQTT 由本系统维护产品物模型、Topic 订阅/发布、消息映射与状态。
4. IoT 管理员可以选择 JavaScript 或 Java 语法编写受控脚本，直接调用平台封装的安全函数处理消息、属性、事件、设备动作和流程发起。
5. 流程可以选择“已发布”且“可接入流程使用”的设备；设备事件、属性变化或阈值规则满足条件时，也可选择已发布流程模板、映射表单数据并发起流程。
6. 设备、脚本、规则、命令、事件与流程使用可追溯关联标识，失败、超时、重复消息和重试均不得伪装成功。

## 二、核心领域与状态

### 2.1 连接配置

连接配置独立于设备，允许多个设备复用，至少包含：

- 稳定标识、名称、租户、连接类型、启停状态、健康状态和最后检查结果。
- 腾讯 IoT 配置：地域、endpoint、凭证引用及既有腾讯产品映射。
- 自建 MQTT 配置：主机、端口、协议/TLS、客户端标识策略、用户名、密码密文、keepalive、会话与重连策略。
- 凭证只允许写入、轮换和验证；列表、详情、接口响应、日志、脚本上下文及审计记录不返回明文。
- 连接测试必须区分 DNS/网络不可达、认证失败、TLS 失败、协议失败和成功，不以“保存成功”代替“连接成功”。

本轮自建 MQTT 的首个真实联调目标使用 Owner 提供的 Broker 主机 `8.166.112.85`。账号和口令由 Owner 在当前任务上下文提供，授权 Executor 在管理后台作为真实连接数据录入并测试；不得转录到本文件、其他仓库文件、命令行回显、截图、日志或回执。端口、TLS 与协议参数由 Executor 在实际连接检查时核实，不在规划层猜测。

### 2.2 产品、物模型与设备

- 产品承载统一物模型；物模型至少包含属性、事件、行为/动作三类能力。
- 每项能力具有稳定标识、名称、数据类型、约束、读写语义和说明；行为支持输入、输出、超时、重试与幂等要求。
- 物模型采用“草稿 → 校验 → 发布”的版本生命周期；设备与已发布流程引用稳定版本或快照。
- 设备至少具有业务标识、名称、产品、连接配置、厂商身份映射、标签/分组和必要扩展配置。
- 设备管理状态与连接状态分离：管理状态至少区分草稿、已发布、已禁用/注销；连接状态至少区分未知、离线、在线，并记录最后上线、最后上报和最后命令时间。
- 设备具有独立的“可接入流程使用”开关。流程可选设备必须同时满足：设备已发布、开关启用、连接配置启用、当前用户或流程身份具备数据权限，并且设备发布的物模型包含目标能力。
- 已发布设备的关键身份、产品和物模型版本变更必须受控；影响流程引用时要显式生成新版本或重新发布，不得静默改变历史实例语义。

## 三、两类连接模式

### 3.1 腾讯 IoT

- 继续以 `productId + deviceName` 作为腾讯设备规范身份，复用已交付的腾讯 Provider、命令队列、状态回调和结果语义。
- 腾讯设备直接采用腾讯产品物模型、规则配置及 Topic 规则；本地保存稳定映射、版本快照和流程所需的通用能力视图，不要求管理员重复维护一套冲突定义。
- 腾讯专属字段只存在于连接/Adapter 扩展区，上层设备管理、脚本与流程不得硬编码腾讯 SDK 类型。
- 未配置腾讯账号时腾讯连接明确显示“未配置/不可联调”，不能静默回退为 Mock 成功。
- 本轮腾讯实网、真实 RequestId、真实设备上下线和物理设备执行按 Owner 裁量免验，不阻塞 P21；既有腾讯契约及已锁定回归不得退化。

### 3.2 自建 MQTT

- 自建 MQTT 作为内置 Provider，与腾讯 Provider 共用设备、物模型、命令、事件、审计和流程契约。
- 管理后台能够维护发布 Topic、订阅 Topic、Topic 模板变量、方向、QoS、retain、载荷格式、编码/解码映射及启停状态。
- Topic 模板变量只能使用受控的产品、设备、租户和消息上下文；渲染后必须校验主题合法性与租户/设备边界。
- 订阅消息进入统一入口后，按配置解析为属性上报、事件、行为结果或原始消息；解析失败进入可查询失败记录，不更新错误属性、不触发流程成功。
- 发布命令必须生成本地命令记录；Broker 接收、消息发送、设备回复和设备业务执行是不同状态。
- 支持断线重连、订阅恢复、重复消息去重、QoS 对应语义、超时和死信/失败重放边界；同一消息不得重复触发不可逆设备动作或流程实例。
- Provider 必须健康检查和能力声明；不支持的能力返回 `UNSUPPORTED` 或等价失败。

## 四、受控脚本能力

### 4.1 脚本生命周期

- 脚本由具备 IoT 脚本权限的管理员在管理后台创建，选择 JavaScript 或 Java 语法。
- 脚本至少支持草稿、语法/安全校验、试运行、发布、版本留痕、停用和回滚。
- 脚本可绑定连接配置、产品、设备、Topic 或事件规则，并声明触发类型、输入结构、输出结构和所需平台能力。
- 已发布规则和流程引用脚本固定版本；修改草稿不改变历史执行。
- 后台编辑器提供宿主函数清单、参数提示、示例、语法检查和试运行结果，管理员无需自行引入 SDK 或访问底层连接对象。
- 试运行使用明确的测试上下文和可控副作用开关；默认不向真实设备发布、不发起真实流程，只有管理员明确选择真实联调且具备权限时才执行真实副作用。

### 4.2 平台封装函数

JavaScript 与 Java 使用同一语义的宿主函数，至少提供：

- `fun_publish(topic, payload, options)`：向授权连接和主题发布消息，返回可查询的发布结果/命令标识；Java 提供便捷形式 `fun_publish(String topic, Object... payloadParts)`，JavaScript 提供等价可变参数形式。
- `fun_subscribe(topicFilter, options)`：声明或启用授权主题订阅，实际消息交给当前脚本的受控处理入口。
- `fun_getProperty(deviceId, propertyId)`：读取授权设备最新属性及时间信息。
- `fun_setProperty(deviceId, propertyId, value, options)`：按物模型校验后生成属性设置命令。
- `fun_emitEvent(deviceId, eventId, payload)`：按已发布物模型写入统一设备事件。
- `fun_invokeAction(deviceId, actionId, input, options)`：校验能力与参数后调用设备行为。
- `fun_startProcess(templateKey, formData, options)`：仅允许选择已发布且允许 IoT 接入的流程模板，经表单校验、权限、幂等和审计后发起流程。
- `fun_log(level, message, fields)`：写入脱敏、限量、可关联的脚本运行日志。

具体参数对象与返回对象由 Executor 结合既有契约确定，但两种语言的能力、错误码和状态语义必须一致；不得让 JavaScript 和 Java 形成两套业务模型。

### 4.3 隔离与安全

- 脚本不直接访问操作系统命令、宿主文件、数据库、任意 JVM 类、反射/ClassLoader、进程、任意网络/Socket、环境变量或连接凭证明文；所有 I/O 只能经授权宿主函数。
- Java 语法脚本必须在与主业务 JVM 隔离且可强制终止的运行边界执行，不把管理员提交的代码动态加载到主应用 ClassLoader。
- JavaScript 运行时同样需要能力白名单、CPU/内存/执行时长/输出大小限制和强制终止。
- 每次执行绑定租户、操作者或系统触发身份、脚本版本、触发来源、关联设备/消息/规则/流程和幂等键。
- 单脚本失败不得拖垮 MQTT 消费线程、其他设备、其他租户或流程引擎；错误进入可查询记录，按策略重试或人工处理。
- 保存、发布、停用、试运行、真实发布、流程发起和人工重试全部进入审计。

## 五、事件变化、阈值与流程发起

### 5.1 规则能力

已发布且允许流程接入的设备可以配置：

- 属性变化：值发生变化、由某值变为另一值、首次上报等。
- 阈值条件：大于、大于等于、小于、小于等于、等于、区间内/外。
- 事件发生：指定物模型事件或指定受控 Topic 消息。
- 连接变化：上线、离线或持续离线达到设定时长。
- 组合约束：持续时间、连续次数、防抖、冷却期、迟滞区间和重复消息去重。

规则采用草稿、校验、发布、停用和版本留痕；规则保存与发布时验证设备、物模型、Topic、脚本、流程模板和表单映射均可用。

### 5.2 选择流程与填充表单

- 事件规则只能选择状态为已发布且显式允许 IoT 接入的流程模板，并固定流程定义/模板版本和关联表单版本。
- 管理员在规则中配置表单字段映射；来源至少支持设备身份、产品、最新属性、当前消息、事件参数、阈值前后值、发生时间、规则信息和脚本输出。
- 配置保存时完成字段存在性、必填、类型、枚举、引用和租户边界校验；触发时再次校验实际值。
- IoT 自动发起使用受控的租户系统身份，并记录规则配置人、实际触发设备和事件来源；不得伪装成任意自然人。
- 发起成功必须存在真实流程实例和表单数据；只有受理标识而没有最终实例时显示处理中或失败，不能提示“流程已发起”。
- 同一 `tenant + device + event/message + ruleVersion` 使用稳定幂等键，重复上报、Broker 重投、服务恢复或脚本重试不得生成重复流程实例。
- 发起失败、超时或表单校验失败进入可查询记录；重试沿用同一幂等键，并能从设备、规则和流程三侧互查。

## 六、流程选择设备并执行能力

- 流程设计或节点动作配置支持选择：设备来源、目标设备、已发布能力、参数映射、触发时机、调用模式和失败策略。
- 设备来源至少支持设计时固定设备、发起时由有权限用户选择、从表单字段/流程变量解析。
- 设计时下拉列表只显示“已发布 + 可接入流程使用 + 有权限 + 具备目标能力”的设备；运行时必须重新校验，不能仅信任已保存配置。
- 参数可来自表单字段、流程变量、固定值和受控脚本输出，保存、发布及运行时均按能力版本校验。
- 每次触发生成唯一命令记录，保存流程实例、节点/任务、设备、能力版本、参数快照、Provider、状态、时间和结果。
- 支持同步受理、异步回执、失败、超时与受控重试；失败策略可选择阻断、记录后继续或进入人工处理，但必须在流程记录中可见。

## 七、后台、权限与可观测性

管理后台至少形成以下可用入口：

- 连接配置：新增、编辑、测试、启停、凭证轮换、健康状态。
- 产品与物模型：属性、事件、行为和版本发布。
- 设备：新增、编辑、发布、禁用/注销、流程接入开关、状态、筛选和详情。
- Topic：订阅、发布、模板、QoS、载荷映射和运行状态。
- 脚本：编辑、校验、试运行、发布、版本、停用和执行日志。
- 事件规则：条件、阈值、防抖/冷却、脚本、流程模板和表单映射。
- 运行记录：消息、属性/事件、命令、脚本、规则触发、流程发起及关联查询。

权限至少分离连接与凭证管理、产品/物模型管理、设备管理、Topic 管理、脚本管理与发布、规则管理与发布、真实联调、命令重试和只读查看。所有查询遵守租户与数据范围；前端隐藏按钮不能替代服务端鉴权。

- 运行与安全：脚本隔离运行边界、Broker 连接生命周期、指标、限流、失败恢复和凭证管理。

Executor 自行核实现有实现位置和契约，制定实施计划并选择可逆迁移方式；本方向不预设类名、表名、页面文件或 Step 数量。

## 十、风险与固定裁决

1. **凭证泄露**：连接密码只加密存储并脱敏展示；真实联调证据不得包含明文。Owner 已授权使用，不等于授权写入仓库或日志。
2. **脚本逃逸**：Java/JavaScript 都必须在受控隔离边界运行；无法证明隔离、限额和终止能力时，脚本能力不得验收通过。
3. **重复副作用**：消息重投、脚本重试、规则重复触发、流程重试和设备命令重试共用端到端幂等关联，不能只在单层去重。
4. **状态误报**：连接、Broker 接收、设备回复、脚本完成、流程受理和流程实例创建分别记录，不合并为“成功”。
5. **版本漂移**：已发布物模型、脚本、规则、流程和表单以版本/快照关联，修改草稿不能改变历史行为。
6. **租户越界**：Topic、脚本、设备、流程模板与表单映射均在服务端校验租户和权限。
7. **腾讯免验边界**：本轮可在无腾讯账号情况下通过，但必须保留“未实网验证”的真实标记，不得把 Mock 或本地推演冒充腾讯实网。

## 十一、验收边界

以下原子全部通过，P21 本轮范围才可功能级 PASSED：

### A1 后台设备与连接管理

- 真实管理员能创建自建 MQTT 连接、录入 Owner 提供的主机和凭证、保存后看到脱敏值，并能测试连接。
- 能新增、修改、发布、筛选、查看和禁用设备；管理状态、连接状态、流程接入开关和最后时间字段行为一致。
- 普通用户或无权限管理员的真实页面和后端请求均不能读取凭证明文或执行未授权操作。

### A2 自建 MQTT 真实收发

- Executor 可按 Owner 授权在本机安装适用的 MQTT CLI，并保留安装结果、版本和退出状态；安装仅用于本任务联调。
- 使用后台保存的连接完成一次真实订阅与发布，服务端与独立 CLI 双向观察到约定消息；证据展示主题、关联标识、时间、QoS 和脱敏结果。
- 认证失败、主题不允许、载荷解析失败、断线重连和重复消息至少有对应真实结果，不能只提供类名或测试名称。
- 临时 CLI 凭证文件、环境变量和进程在证据采集后清理并回查；凭证不得出现在 shell 历史、进程参数快照或附件中。

### A3 物模型与 Topic

- 能创建包含属性、事件、带输入/输出行为的物模型并发布，设备绑定确定版本。
- 自建 MQTT 的订阅/发布 Topic 能映射到属性上报、事件和行为结果；无效类型、越界 Topic 和不匹配能力被明确拒绝。
- 腾讯设备能继续呈现既有腾讯规则/Topic 的通用映射；腾讯实网证据按 Owner 裁量免验。

### A4 JavaScript 与 Java 脚本

- 两种语法各有一份已发布脚本，通过同语义宿主函数完成真实消息处理；至少覆盖 `fun_publish`、属性或事件写入，以及一次流程发起或设备行为调用。
