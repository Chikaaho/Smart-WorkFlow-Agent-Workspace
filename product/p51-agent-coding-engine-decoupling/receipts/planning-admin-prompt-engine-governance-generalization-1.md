# Agent Coding Engine 治理资源约束补充提示 1

> 指定角色：管理员（Admin）
> 提示级别：一级收敛
> 权威输入：`planning-rereview-p51-root-runtime-20260831-01.md`、`direction-admin-engine-governance-generalization.md`

## 一、唯一剩余缺口

| 编号 | 失败事实 | 唯一可接受结果 |
|---|---|---|
| A1 | `system.md` 和 `roles/executor.md` 把每种编译工具上限 2G 固化为 Engine 级硬约束 | Engine 仅要求项目明确声明资源限制和跨仓并发规则；具体数值、环境变量和工具形式全部来自项目说明或 coding 仓工程规则 |

## 二、锁定通过项

- 三角色职责、权限和三阶段协议已保留；
- Smart-WorkFlow 品牌、固定仓名和本地绝对路径已清除；
- 终态契约、Validator 与 Hook 阻断语义未改变；
- 上述项目禁止重新改写或扩展。

## 三、允许范围

仅允许修改：

- `system.md`；
- `roles/executor.md`；
- 本功能 `receipts/` 下新增的管理员补充回执。

允许执行全文搜索、内部引用检查、`git diff --check` 和限定范围 diff。不得提交、推送或运行工程编译测试。

## 四、禁止事项

- 不修改 Planner/Admin 权限文件内容；
- 不改变角色门禁、三阶段、状态机、终态 schema 或 Validator；
- 不引入任何固定资源数值、固定工具命令或环境变量示例；
- 不修改项目状态、业务实现和执行证据；
- 不重复已锁定的品牌和路径清理。

## 五、相对上一版新增约束

这是首次一级提示。新增要求是对 Engine 治理文件执行“固定资源值与工具变量”零残留检查，至少覆盖：容量数值、`MAVEN_OPTS`、`NODE_OPTIONS`、`GOFLAGS` 及其同义硬编码。

## 六、证据与自检

管理员补充回执必须包含：

- A1 修改前事实与修改后正向规则；
- 固定容量、工具命令、环境变量零残留原始输出；
- 项目说明/工程规则仍是资源限制唯一来源的引用位置；
- 权限、三阶段和终态语义未改变的限定 diff；
- `git diff --check` 及实际修改范围。

全部成立后以管理员任务普通结论结束，不裁决 P51 功能状态。
