# P51 语言无关项目接入契约补充方向

> 下发角色：规划（Planner）
> 指定角色：执行（Executor）与管理员（Admin）
> 方向状态：READY
> 日期：2026-08-31
> 共同权威输入：P51 根级运行时方向、治理入口通用化方向及其最新一级补充提示

## 一、目标

Agent Coding Engine 面向任意 coding 项目。项目可以采用任意语言、框架、工具链和仓库组织，也可以只包含文档、脚本、配置或其他不需要编译的工程内容。Engine 通过项目说明读取当前项目实际提供的工程动作，不预设项目技术形态。

## 二、项目声明模型

项目说明以仓库为基本单元，声明：

- 仓库标识、目录和职责；
- 仓库自己的工程规则入口；
- 项目实际提供的启动、检查、验证、构建、发布或其他动作；
- 每个动作的适用条件、命令入口和资源约束；
- 项目需要记录的验证基线与生命周期字段。

除仓库标识、目录和职责外，其余工程动作均按项目实际情况可选。项目未声明的动作，Engine 不推断、不生成默认命令，也不把缺少该动作判定为缺陷。

## 三、通用治理语义

- `system.md` 和 `roles/` 使用“工程动作”“项目验证入口”“coding 仓库规则”等通用概念；
- 是否存在编译、测试、数据库迁移、服务启动、制品构建或部署，由项目说明决定；
- 资源限制由项目说明或仓库工程规则为具体工程动作声明，Engine 只要求执行角色遵守已声明限制；
- 跨仓并发规则只适用于项目声明为互斥或资源冲突的动作，不假定所有仓库都有编译过程；
- 阶段三记录项目实际声明的验证基线。未适用的基线不作为固定必填类别；不得要求所有项目填写后端、前端、迁移或其他特定技术基线；
- Harness、Hook 和终态契约只校验角色、流程、证据和终态，不识别或限制语言、文件扩展名、包管理器或框架。

## 四、运行时行为

读取项目说明后，Engine 应形成当前实例的仓库清单和工程动作清单。执行角色只能调用项目实际声明或仓库工程规则允许的动作；Planner 依据项目声明的目标与验证入口制定验收边界；Admin 只维护通用治理和项目声明的工程配置，不把某类技术栈升级为全局规则。

单仓项目、多仓同语言项目、多仓异构项目以及没有编译阶段的项目均使用同一套角色协议和根级知识结构。

## 五、非目标

- 不建立语言或框架注册白名单；
- 不为项目自动选择技术栈、包管理器、构建系统或部署平台；
- 不要求每个仓库具备相同的生命周期动作；
- 不把示例项目使用的命令、目录或基线写入 Engine 通用规则；
- 不改变三角色权限、三阶段协议、状态裁决归属和终态机器契约。

## 六、验收标准

1. `system.md`、`roles/`、项目说明模板和根 README 不把任何语言、框架、包管理器、构建系统或数据库作为必备条件。
2. 一个没有编译、数据库迁移和部署动作的项目，只声明其实际验证入口后能够正常进入完整工作流。
3. 两个使用不同语言或不同工具链的 coding 仓库可以在同一项目说明中分别声明工程动作，互不继承命令、资源限制和验证基线。
4. 项目未声明某类工程动作时，Engine 不生成该动作、不尝试执行，也不因其缺失阻断任务。
5. 阶段三终态值清单只要求项目已声明且本功能实际涉及的验证基线；未适用类别可以不存在，而不是填充伪造值。
6. 全文检查不存在被固化为全局规则的语言名、框架名、包管理器命令、文件扩展名、数据库迁移工具或固定资源数值。
7. 行为证据至少覆盖：无编译项目、异构多仓项目、未声明动作的零调用断言，以及两个仓库工程动作不串用的反向断言。

## 七、回执要求

管理员和执行角色在各自下一份补充回执中增加“语言无关契约核销”章节：

- 管理员核对通用治理语义、阶段三基线字段和全文零固化结果；
- 执行角色提供项目说明解析、无编译项目、异构多仓动作隔离及未声明动作零调用的持久行为证据；
- 所有证据继续写入 P51 `receipts/`，不得只引用临时目录；
- 本补充不解锁任何已经失败或仍在验证中的缺口。
