# P51 Agent Coding Engine 根级运行时工作区修正方向

> 下发角色：规划（Planner）
> 指定角色：执行（Executor）
> 方向状态：READY
> 日期：2026-08-31
> 前置审查：`receipts/planning-review-p51-agent-coding-engine-decoupling-20260831.md`

## 一、目标

使 `main` 根目录本身成为可直接运行的通用 Agent Coding Engine 工作区。用户取得 `main` 后，只需填写项目说明并配置一个或多个 coding 仓库目录，即可进入角色门禁、探索、规划、执行、回执、验收和交接流程。

## 二、根级标准结构

`main` 根目录必须直接提供并维护以下标准入口：

- `system.md`、`roles/`；
- `knowledge/`、`memory/`；
- `product/`、`todo/`；
- `search_task/`、`search_fallback/`；
- 治理契约、Validator、Harness 配置和 Hook；
- 根 README、AGENTS 入口和唯一项目说明入口。

这些目录应包含通用说明、必要模板和可运行的初始状态文件。新项目接入不要求复制目录、执行结构生成器或修改通用治理协议。

## 三、项目配置入口

Engine 只保留一个项目说明入口。该入口至少声明：

- 项目名称、目标和边界；
- coding 仓库目录列表；
- 每个仓库的职责及单仓/多仓关系；
- 必要工程规则入口；
- 启动方式和验证入口。

所有通用入口通过该声明解析 coding 仓库，不内置固定仓名、固定目录、技术栈、端口、测试计数或迁移版本。README 必须给出最短配置方法，并链接 `develop-sw` 作为完整 Smart-WorkFlow/OA 示例。

## 四、运行实例模型

- 一份 Engine 工作区对应一个项目实例；
- 项目状态直接写入该工作区根级标准目录；
- 不在同一工作树中切换多个项目实例；
- 不同项目通过独立 Engine 工作区隔离；
- coding 仓库可为单仓或多仓，只通过项目说明建立关系；
- 删除或替换 coding 仓库不得破坏 Engine 协议、治理契约或历史状态文件。

## 五、实例初始状态

新工作区的标准状态应满足：

- `knowledge/` 有唯一当前状态入口和必要索引，但不预置业务功能事实；
- `memory/` 有规划角色可读取的最小初始摘要和交接入口；
- `product/` 有方向、回执和归档规则说明；
- `todo/` 有通用待办与需求池入口；
- `search_task/`、`search_fallback/` 可直接承载首次探索；
- 所有模板和初始值均不依赖 Smart-WorkFlow/OA。

## 六、非目标

- 不修改 `develop-sw` 已保留的 OA 业务知识、历史回执和状态事实；
- 不新增或修改后端、前端业务功能；
- 不重新创建分支或重做已锁定的分叉与回滚工作；
- 不实现同一工作树内的多项目切换；
- 不执行远端 push、force push、删除远端分支或版本发布；
- 不修改 `system.md`、`roles/`，其通用化由管理员方向负责。

## 七、方向级验收标准

1. 在只取得 `main` 的新工作区中，根级标准目录和初始状态文件齐全，无需额外生成或复制。
2. 只填写项目说明中的 coding 仓库目录后，角色入口能够读取项目身份和仓库关系。
3. 一个非 Smart-WorkFlow 示例项目真实完成：角色声明、探索任务、探索回执、需求方向、执行回执和规划审查记录。
4. 两个独立 Engine 工作区分别接入两个无关项目后，项目名称、仓库路径、当前状态、记忆、任务、回执和待办均无交叉命中。
5. 从非默认当前目录触发 Harness 时，Hook 仍能定位工作区根、终态契约和 Validator；合法与非法终态分别产生预期结果。
6. `main` README 能让首次使用者仅凭文档完成项目配置，并能进入 `develop-sw` 示例。
7. 根级全文检查不存在 OA 业务状态、P/I 编号、固定代码仓名、固定端口、测试基线、迁移版本和本地绝对路径；README 中用于示例导航的分支名称不属于污染。
8. 修改范围不触碰业务代码、业务测试、迁移和远端发布；Git diff、工作树和回滚点可复核。

## 八、回执要求

执行角色提交一份新的补充回执，逐项核销 G1、G2、G4、G5、G6，并提供：

- 根级标准目录和初始入口清单；
- 非 Smart-WorkFlow 示例完整工作流的产物路径与行为输出；
- 两个独立工作区的正向项目断言和反向零交叉断言；
- Harness/Hook 从不同当前目录触发的原始结果；
- 通用性全文检查、Git diff 和未远端发布证据。

已锁定通过项不得重复执行或重新陈述为本轮新增成果。
