# Agent Coding Engine 治理入口通用化方向

> 下发角色：规划（Planner）
> 指定角色：管理员（Admin）
> 方向状态：READY
> 日期：2026-08-31
> 关联功能：P51 Agent Coding Engine 解耦

## 一、目标

将 `main` 的工作区宪法和角色定义调整为通用 Agent Coding Engine 治理入口，使其通过唯一项目说明识别 coding 仓库和工程规则，不依赖 Smart-WorkFlow 名称、固定仓库结构或本机绝对路径。

## 二、允许修改范围

仅允许修改：

- 根 `system.md`；
- `roles/planner.md`；
- `roles/executor.md`；
- `roles/admin.md`；
- 本任务追加的管理员回执。

不得修改业务代码、业务测试、数据库迁移、项目状态值、功能验收结论、Git 分支或远端。

## 三、治理口径

- 三角色门禁、Planner/Executor/Admin 权限分层和三阶段协议保持原语义；
- `knowledge/`、`memory/`、`product/`、`todo/`、`search_task/`、`search_fallback/` 继续作为根级标准结构；
- coding 仓库名称、数量、目录和工程宪法入口由唯一项目说明提供；
- 角色规则使用“工作区根”“coding 仓库”“项目说明”等通用概念；
- 编译工具、资源限制和工程专属约束从项目声明或各 coding 仓工程规则读取，不固化当前 OA 技术栈；
- Hook、Validator 和终态契约的权威关系保持不变。

## 四、非目标

- 不改变三种角色的职责和权限等级；
- 不调整合法终态集合、Validator schema 或 Hook 阻断语义；
- 不裁决 P51 功能状态；
- 不修改 Engine 运行时目录内容或 coding 仓实现；
- 不执行提交、推送、测试、构建或部署。

## 五、验收标准

1. `system.md` 和 `roles/` 不包含 Smart-WorkFlow 产品定位、固定前后端仓名、固定本地路径或当前 OA 工程事实。
2. 三角色门禁、允许/禁止读取范围、探索通道、回执验收、阶段三和终态约束仍完整且无权限扩大。
3. 单仓和多仓项目均可通过项目说明映射为 coding 仓库，角色文件不需要按项目改写。
4. Planner 仍不能读取 coding 仓库与 `knowledge/`；Executor 仍不能作规划裁决；Admin 仍不能读取业务实现或裁决业务状态。
5. 所有内部章节、文件路径和工程规则引用可解析，不存在指向已移除固定仓名的死引用。
6. 全文检查仅保留通用 Engine 概念，没有本地绝对路径和 OA 业务事实。
7. `git diff --check` 通过，实际修改严格限定为允许范围和一份新回执。

## 六、回执要求

管理员回执应提供：

- 实际修改文件；
- 通用项目说明如何驱动单仓/多仓映射；
- 验收标准 1～7 的逐项结果；
- 专属仓名、本地绝对路径和 OA 业务事实的全文检查；
- 权限语义未扩大、终态契约未改变的差异核对；
- 未修改其他文件、未执行提交推送和工程命令的范围声明。
