# 执行补充提示模板（唯一权威）

> 本文件是**执行补充提示**的唯一权威模板，由管理员角色维护于 `product/governance/`（Planner 宪法可读路径）。
> 配套规则：`roles/planner.md` §7.1（生成前置诊断、逐级收敛、对象与生命周期、提交与停止门禁）；本模板**不另立终态契约**，终态字段与校验以 `.codex/governance/terminal-contract.json` 为准。
> 使用者：Planner 按下发补充提示（写入 `product/<feature>/receipts/planning-execution-prompt-<功能名>-<序号>.md`）；Executor 按提示执行、建账本并提交回执。
> 模板中的占位符以 `<尖括号>` 标注；示例为去身份化的失败行为案例（通用用户 A/B、实例 X），不是针对任何执行模型或具体功能的规则。

---

## 0. 生成前先诊断（不可直接加严）

对审查记录中的**每个剩余缺口**先归类，再决定写什么。每项必须关联「最新失败事实 + 原验收标准对应条目」。

| 缺口分类 | 判定口径 | 对应处理 |
|---|---|---|
| 实际产品缺陷 | 行为与验收标准不符，且非证据问题 | 要求修复实现并只复验受影响断言 |
| 缺证据 | 行为可能正确但无真实结果 | 补最小充分证据（见 §6） |
| 证据对象不匹配 | 有结果但对象/身份/环境与主张不一致 | 拒绝近似对象替换，固定对象重取（见 §4） |
| 快照过期 | 证据早于最后实现变化 | 要求当前快照复验受影响项，说明失效依据（见 §3） |
| 工具真实限制 | 合法工具/权限约束导致无法取某类证据 | 撤回该要求，提供等强度安全替代；不是执行失败 |
| 规划口径错误 | 验收标准自身歧义/示例错误/越权要求 | **规划侧先更正**，不得计为执行失败或用作加严理由 |
| 纯报告转录错误 | 格式、路径、工作目录、合并流、0字节输出导致的核对问题 | 先修正核对方式再裁决，不是产品失败 |

禁止以「又未通过」替代失败分类；禁止把历史规划错误累积成新验收门槛；同一缺口连续两次同类失败时才升级提示（见 §7）。

## 1. 元信息与替代关系

- 提示序号、日期、功能与依据的最新审查记录（唯一权威输入）。
- **替代哪一版**：明确「本提示替代提示 <N> 作为唯一当前执行入口；<N> 及更早仅作追溯，不同时作为执行待办」。
- 输入文件清单：最新审查记录、上一版提示、被引用的旧回执（只按明确证据指针读取，不要求重读全部历史）。
- 与主方向、角色权限的关系：不改变需求方向、不代写实现代码、不改变授权边界。

## 2. 唯一剩余缺口矩阵（原子账本）

每个缺口一个**原子行**，原子 ID 跨版稳定；拆分时给出父子映射（如 `G1 → G1a/G1b`），旧 ID 只作追溯。每行必须同时包含：

| 原子ID | 失败事实 | 完成条件（正向断言） | 必要反向断言 | 对象身份 | 最小充分证据 | 允许替代 | 下一动作 | 合法停止条件 |
|---|---|---|---|---|---|---|---|---|
| <G1a> | <最新审查记录中的实际差异> | <满足什么才算完成，可判定> | <必须排除什么，如零残留/动作数不增> | <用户/实例/任务/库/快照指纹> | <工具、命令或文件的最小组合> | <已锁定证据可沿用时的引用指针> | <一条具体动作> | <外部真实阻塞或已穷尽独立工作的契约条件> |

账本口径（必守）：

- **一份当前入口**：只有本提示是执行待办；旧提示/旧回执只作证据指针。
- **风险匹配**：不是每个缺口都强制「浏览器＋SQL＋全量测试」三套重复验证；能由既有锁定证据证明的直接引用，不发生新动作。
- **强度匹配**：选用能够证明该主张的最小充分证据；实际查询与真实结果不可由自述代替。

## 3. 锁定项与禁止重验项

- 列出本轮**禁止重验项**及其已有证据指针（审查记录/回执/附件位置）。
- 已锁定标准不因补证重跑；补文案、哈希转录或清单更正**不触发完整业务回归**。
- 只有出现下列情形之一才重新验证受影响项，并**写明失效依据**：
  1. 新增反证直接指向该锁定结论；
  2. 实现代码发生变化，且该变化触及锁定结论所依赖的路径；
  3. 无法确认代码或环境与证据快照一致。
- 代码变化时必须按实际工程门禁执行受影响回归，不以「减少返工」为由跳过必需门禁。

## 4. 对象与生命周期约束

- 按缺口必要性固定：用户/租户、实例/任务、数据库/环境、源码/产物指纹。
- **禁止近似对象替换**：操作者重放替代被取消用户、另建种子库替代真实运行库、列表接口替代详情接口等一律视为该缺口未修复。
- 替换已销毁场景时**显式登记新旧 ID**（如「实例 X 已销毁，改用实例 Y，索引见 <附件>」），不要求恢复不存在的历史原件。
- 证据生命周期：在场景开始前建立采集点与只读回读方式，验证完成后再清理；清理本身保留真实结果。
- 清理路径二选一（取实际存在的一条，不另造对象）：
  - **持久隔离库**：限定本轮 ID 的实际清理 + 清理后回读 + 保留对象证据；
  - **纯内存环境**：内存属性/JDBC 标识等非秘密配置诊断 + 对应进程退出/端口无监听的实际结果。
- 历史身份错配等**无法解释的旧证据**：明确剔除并引用已验证替代即可，不无限追查不可恢复原因；若涉及真实安全缺陷，仍须验证风险，不能一律按文字问题撤销。

## 5. 读取 / 修改 / 命令范围及顺序

| 维度 | 内容 |
|---|---|
| 允许读取 | <需求方向、最新审查记录、本提示、既有证据附件、实现与工程配置> |
| 允许修改 | <确证缺陷涉及的代码、验证资产、追加回执；明确禁止修改历史审查/附件、正式状态> |
| 允许命令 | <隔离验证、实际 API/SQL 查询、归档条目检查、指纹校验、受控收尾；数据库删除/远程/秘密读取仍受既有授权约束> |
| 执行顺序 | <账本建立 → 证据采集 → 断言核对 → 收尾 → 清单回读 → 回执；明确哪一步可并行> |
| 禁止事项 | <近似证据、改方向、改终态、扩大范围、删除失败输出、伪造全通过> |

## 6. 相对上一版变化（升级必须改变方法）

- 每版必须写明四点：**删除了什么、原子化了什么、替代路径是什么、提交条件如何可判定**；首份写「首次提示」。
- 连续同法无新增证据时，要求**换路径或重新诊断**，不得复制上一版主体只换编号、重新展开已锁定项或累积全部历史说明。
- 下列均**不算升级**：增加大写警告、零裁量措辞、按模型名称改变权限/验收强度。
- 提示内容聚焦「如何满足既定验收标准」，不代写实现方案。

## 7. 逐级收敛阶梯（保留现有递进）

- ① 首次失败：精确差异表 + 锁定通过项。
- ② 同类第二次失败（一级提示）：逐项缺口编号、唯一可接受行为证据、允许范围与禁止事项。
- ③ 一级后仍失败（二级提示）：删除已通过项、原子化剩余缺口、增加「相对上一版新增/收紧约束」章节、精确输入文件、允许修改文件、允许命令、执行顺序、原始输出字段、提交前核对矩阵。
- ④ 二级后仍失败（三级提示）：每个缺口一份独立证据包、正向目标断言、反向零残留断言、「全部为是才允许提交」门禁，无法满足则如实 `BLOCKED`。
- 之后继续在**最新剩余范围**上收紧；Executor 再次提交同一份无效证据时直接计为同类失败并升级，不回到一级。

## 8. 每项证据包格式与证据封装

回执中每项缺口的证据包只保留四要素，原始流单独存附件，不复制为大量正文：

```
缺口（原子ID）→ 原始文件/位置（路径:行号）→ 实际结果（工具真实输出/查询行/响应）→ 边界（覆盖范围与未覆盖项）
```

- 哈希、计数、清单：**由工具生成并回读校验**（如 `shasum -c`），禁止手抄值替代工具结果；校验文件排除自身。
- 路径声明工作目录；合并 stdout/stderr、静默命令合法，0 字节输出如实保留。
- 证据层级必须如实标注且**不冒称**：`声明` / `单测` / `集成运行` / `真实API/SQL` / `真实浏览器或HTTP`；已有独立证据可组合，但须展示关联与层级，不得把单测改名为浏览器结果。

## 9. 提交自检与合法终态

Executor 提交前逐项核对（全部为「是」才允许提交）：

- [ ] 全部缺口按 §2 矩阵关闭，无凭描述填 DONE？
- [ ] 身份/实例/任务/数据库/产物与主张一致？
- [ ] 原始查询/输出可见，反向断言（如零残留、动作数不增）有真实结果？
- [ ] 清理/扫描针对真实环境路径，无近似对象？
- [ ] 清单由工具生成并实际回读通过？
- [ ] 如有代码修复，证据属于最后快照且受影响回归已按门禁执行？
- [ ] 剩余可执行项为 0（或真实外部阻塞已按契约登记）？

终态纪律：

- 剩余账本与 `terminal-contract.json` 的 `work_items`、`remaining_actionable_count`、`tool_results` 对齐，不另建 schema。
- 有授权内可执行项就继续执行；工具限制**有真实结果**且替代路径/独立工作**已穷尽**时才按契约报告阻塞。
- 禁止无限重试、把权限申请当作已获授权、或使用「必须一次过」诱导虚构证据；不承诺未经验证的一次必过。
- Executor 不得自行写 `PASSED/COMPLETED` 或进入阶段三；提交后状态保持 VERIFYING 等待 Planner 验收。

## 附录：去身份化失败行为案例（仅作诊断示例）

下列案例来自实际功能执行期间的反复补证复盘，**只保留必要摘要**；通用身份：用户 A/B、处理人 P、实例 X、隔离库 DB1。完整审查与回执引用见 `product/p58-workflow-node-capabilities/receipts/`（审查 05—08、执行提示 01—07、回执 05—08）。明确说明：**这是失败行为案例，不是针对任何模型的规则。**

| # | 失败行为（去身份化） | 合规诊断归类 | 新规范下的处理 |
|---|---|---|---|
| 1 | 「PASS」写作基于 UPDATE 参数与 RAW 标签，未执行最终 SELECT；把成功摘要当作数据库最终状态 | 缺证据 / 自述冒充行为证据 | §2 最小充分证据：实际查询与真实结果；§8 四要素证据包 |
| 2 | 用操作者 P 重放其任务替代被取消用户 A 重放自己的子任务（对象错位） | 证据对象不匹配 | §4 固定对象身份，禁止近似替换；拒绝直至对象一致 |
| 3 | 另建 Flyway-only 种子库 DB2 证明「清理零残留」，真实运行库 DB1 已销毁 | 证据对象不匹配 | §4 清理路径二选一：真实环境的持久清理回读或纯内存属性＋进程销毁；不造无关库 |
| 4 | 证据生成晚于环境销毁，事后重建环境补回读，历史原件不可恢复 | 快照过期 / 生命周期倒置 | §4 先建采集点、验证完成后清理；不要求恢复不存在原件 |
| 5 | 运行矩阵早于最后代码修复，修复后仅跑单测 | 快照过期 | §3 失效依据：最后修改 → 受影响断言；单测不自动替代已要求的运行结果 |
| 6 | 手抄清单与哈希计数导致不一致；对压缩 JAR 执行 rg 无匹配却解释为产物排除 | 纯报告转录错误 / 方法不支持结论 | §8 工具生成并回读；§3 扫描根与包内检查须与主张一致 |
| 7 | 缺口未关闭仍交回规划等待「验收」，反复追加材料 | 可执行缺项误报阻塞 | §9 有授权内可执行项继续执行；账本状态驱动提交 |
| 8 | 规划示例「3 人 67% 两票通过」与实际比例不符 | 规划口径错误 | §0 规划先更正（所需票数为 `ceil(N×阈值/100)`），不计执行失败 |
| 9 | 要求读取认证存储后撤回，改为隔离 spy 与非秘密诊断 | 工具真实限制 | §0 撤回限制要求并提供等强度安全替代，不等于不执行 |
| 10 | 静默构建 0 字节附件、合并终端流、工作目录导致校验找不到文件 | 纯报告转录错误 | §0 先修正核对方式再裁决，不构成产品失败 |
