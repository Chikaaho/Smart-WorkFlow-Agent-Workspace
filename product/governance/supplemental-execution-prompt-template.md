# 执行补充提示模板（唯一权威）

> 本文件是**执行补充提示**的唯一权威模板，由管理员角色维护于 `product/governance/`（Planner 宪法可读路径）。
> 配套规则：`system.md` §3.6 与 `roles/planner.md` §7.1（行为证据验收、按问题性质分流、重复失败收口、对象与生命周期）；本模板**不另立终态契约**，终态字段与校验以 `.codex/governance/terminal-contract.json` 为准。
> 使用者：Planner 按下发补充提示（写入 `product/<feature>/receipts/planning-execution-prompt-<功能名>-<序号>.md`）；Executor 按提示执行、建账本并提交回执。
> 模板中的占位符以 `<尖括号>` 标注；示例为去身份化的失败行为案例（通用用户 A/B、实例 X），不是针对任何执行模型或具体功能的规则。

---

## 0. 生成前先诊断（不可直接加严）

对审查记录中的**每个剩余缺口**先归类，再决定写什么。每项必须关联「最新失败事实 + 原验收标准对应条目」。

首轮提示一次列全必要证据清单与格式，原始结果完整留存、不截断；本模板用于验收后的必要修复，不设固定轮数上限。Planner 先读取允许路径内的测试结果、实际输出和必要变更摘要，判断行为是否符合预期，不读取代码、完整代码 diff 或 knowledge；代码和权威状态事实由 Executor 核实后提供结论。不要求重复回传已可读的证据，不做逐字文字核对；已有证据足以证明行为满足要求时直接通过，不因措辞、摘录格式或补充文字不齐打回。仅剩不能消解的证据/文字小问题时，按 §7 提交用户确认，不机械生成下一版提示。明显业务、使用或 UI 还原缺陷可继续后续修复；每次重复派发必须给出具体位置、实际/预期、差异依据、限定范围与完成条件，并实际收窄执行自由度。

| 缺口分类 | 判定口径 | 对应处理 |
|---|---|---|
| 实际产品缺陷 | 行为与验收标准不符，且非证据问题 | 在原授权内持续组织 Executor 修复实现并只复验受影响断言；重复项写明具体位置、实际/预期和收窄范围 |
| 缺证据 | 行为可能正确但无真实结果 | 先读取既有原文；仅剩此类小问题时由用户确认按现有材料接受还是补齐（见 §7） |
| 证据对象不匹配 | 有结果但对象/身份/环境与主张不一致 | 区分真实行为缺陷与证据缺口；不采信近似对象，分别按缺陷或证据路径处理（见 §4、§7） |
| 快照过期 | 证据早于最后实现变化 | 说明受影响项与失效依据；区分已知缺陷与尚未验证，按 §3、§7 处理 |
| 工具真实限制 | 合法工具/权限约束导致无法取某类证据 | 撤回该要求，提供等强度安全替代；不是执行失败 |
| 规划口径错误 | 验收标准自身歧义/示例错误/越权要求 | **规划侧先更正**，不得计为执行失败或用作加严理由 |
| 纯报告转录错误 | 格式、路径、工作目录、合并流、0字节输出导致的核对问题 | 验收方直接读原始结果消解、记录必要纠正；仅剩无法消解的小问题时提交用户确认 |

禁止以「又未通过」替代失败分类；禁止把历史规划错误累积成新验收门槛。是否修复、补证或请求用户确认取决于问题性质和授权边界，审查轮数只作追溯（见 §7）。Owner 2026-10-27 已持续授权明显业务、使用或 UI 还原缺陷继续第三轮及后续；重复派发必须实际收窄范围，只有已有证据证明三项均无影响的小异常才可登记理由后提前结束相应修复。

## 1. 元信息与替代关系

- 提示序号、日期、功能与依据的最新审查记录（唯一权威输入）。
- **替代哪一版**：明确「本提示替代提示 <N> 作为唯一当前执行入口；<N> 及更早仅作追溯，不同时作为执行待办」。
- 输入文件清单：最新审查记录、上一版提示、被引用的旧回执（只按明确证据指针读取，不要求重读全部历史）。
- 与主方向、角色权限的关系：不改变需求方向、不代写实现代码、不改变授权边界。
- 本项审查历史、轮次及已采取方法，保留编号与替代关系供追溯，不作为自动停止或通过的阈值。

## 2. 唯一剩余缺口矩阵（原子账本）

每个真实缺口一行，ID 稳定；拆分时保留父子映射和轮数。下面列用于表达必要事实，不适用列省略，不要求为了格式补写文字：

| 原子ID | 失败事实 | 完成条件（正向断言） | 必要反向断言 | 对象身份 | 最小充分证据 | 允许替代 | 下一动作 | 合法停止条件 |
|---|---|---|---|---|---|---|---|---|
| <G1a> | <最新审查记录中的实际差异> | <满足什么才算完成，可判定> | <必须排除什么，如零残留/动作数不增> | <用户/实例/任务/库/快照指纹> | <工具、命令或文件的最小组合> | <已锁定证据可沿用时的引用指针> | <一条具体动作> | <外部真实阻塞或已穷尽独立工作的契约条件> |

账本口径（必守）：

- **一份当前入口**：只有本提示是执行待办；旧提示/旧回执只作证据指针。
- **风险匹配**：不是每个缺口都强制「浏览器＋SQL＋全量测试」三套重复验证；能由既有锁定证据证明的直接引用，不发生新动作。
- **强度匹配**：选用能够证明该主张的最小充分证据；实际查询与真实结果不可由自述代替。
- **行为满足即可**：格式用于定位真实结果，附件齐全度不单独作为验收项；原始结果已可直接读取时只引用位置，不另建证据包。

## 3. 锁定项与禁止重验项

- 列出本轮**禁止重验项**及其已有证据指针（审查记录/回执/附件位置）。
- 已锁定标准不因补证重跑；补文案、哈希转录或清单更正**不触发完整业务回归**。
- 只有出现下列情形之一才重新验证受影响项，并**写明失效依据**：
  1. 新增反证直接指向该锁定结论；
  2. 实现代码发生变化，且该变化触及锁定结论所依赖的路径；
  3. 无法确认代码或环境与证据快照一致。
- 代码变化时必须按实际工程门禁执行受影响回归，不以「减少返工」为由跳过必需门禁。

## 4. 对象与生命周期约束

- 按缺口必要性固定用户/租户、实例/任务和数据库/环境；源码/产物以已有版本或路径定位，不强制哈希指纹，存疑时才按 §8 针对校验。
- **禁止近似对象替换**：操作者重放替代被取消用户、另建种子库替代真实运行库、列表接口替代详情接口等一律视为该缺口未修复。
- 替换已销毁场景时**显式登记新旧 ID**（如「实例 X 已销毁，改用实例 Y，索引见 <附件>」），不要求恢复不存在的历史原件。
- 证据生命周期：在场景开始前建立采集点与只读回读方式，验证完成后再清理；清理本身保留真实结果。
- 清理路径二选一（取实际存在的一条，不另造对象）：
  - **持久隔离库**：限定本轮 ID 的实际清理 + 清理后回读 + 保留对象证据；
  - **纯内存环境**：内存属性/JDBC 标识等非秘密配置诊断 + 对应进程退出/端口无监听的实际结果。
- 历史身份错配等**无法解释的旧证据**：明确剔除并引用已验证替代即可，不无限追查不可恢复原因；若涉及真实安全缺陷，仍须验证风险，不能一律按文字问题撤销。

## 5. 读取 / 修改 / 命令范围及顺序

下表约束执行方的补充动作；规划的读取边界以 `roles/planner.md` §3 为准。

| 维度 | 内容 |
|---|---|
| 允许读取 | <需求方向、最新审查记录、本提示、既有证据附件、实现与工程配置> |
| 允许修改 | <确证缺陷涉及的代码、验证资产、追加回执；明确禁止修改历史审查/附件、正式状态> |
| 允许命令 | <本项必要的隔离验证、实际 API/SQL 查询和受控收尾；只有具体产物身份或完整性存疑时才针对该产物校验，并写明存疑点；数据库删除/远程/秘密读取仍受既有授权约束> |
| 执行顺序 | <直接读取既有证据 → 定位真实缺口 → 必要修正/采集 → 行为判定 → 收尾 → 回执；明确哪一步可并行> |
| 禁止事项 | <近似证据、改方向、改终态、扩大范围、删除失败输出、伪造全通过> |

## 6. 相对首轮变化

- 写明本次针对的真实剩余缺口、锁定项、对验收方错误的纠正及必要替代路径，不为填满模板增加动作。
- 删除能由验收方直接读取或已有证据证明的要求；文字、摘录与清单更正不触发业务重跑，不要求补写一轮。
- 不得复制旧提示只换编号、重新展开已锁定项或累积全部历史说明；不得按模型名称改变权限或验收强度。
- 提示内容聚焦「如何满足既定验收标准」，不代写实现方案。
- 仅剩证据不足或无法消解的文字小问题时，说明事实、影响、验证边界与建议并交用户确认；用户确认补齐后再列必要动作，不反复追加报告要求。

## 7. 第一层验收、逐轮收口与提前结束

- 规划承担第一层验收，先读取已有行为证据，检查标准、读取/解析、工具限制、格式门槛及是否忽略已有证据；自方有误先纠正，证据充分时直接通过。
- 明确存在功能、交互、结构、权限或状态缺陷且仍在原授权内时，规划自行纠正本角色产物，持续组织 Executor 修复并复验受影响项，不按轮数申请继续权限。规划不代写业务代码。
- 连续两轮未过先完成规划自检；明显业务、使用或 UI 还原缺陷可进入第三轮及后续，不自动转等待用户。每项派发必须写清具体位置、实际结果、预期结果、差异依据、原因或有证据的待核假设、限定动作和可判定完成条件，并比上一轮实际缩小允许对象/动作、增加必要禁止范围或补充具体参数约束，不能只说“不通过”后让执行自由发挥。
- 仅剩证据不足、未能消解的文字不一致等小问题且没有明确功能缺陷时，列出事实、影响、已验证/未验证边界及建议，请用户确认按现有材料接受还是补齐；不把缺证据当作已证实的功能缺陷，不制造通过证据或隐去未验证风险。
- 只有已有证据证明不影响业务、实际使用和 UI 还原度的小异常，才可登记理由后提前结束相应修复；任一影响存在或影响不明时不得降格，不把未通过项标为通过，也不跳过后续合并、发布与信息同步。
- 混合问题先修明确缺陷；涉及目标/范围/标准改变、实质风险接受或真正外部阻塞时，遵守既有授权与证据边界，不能一律按文字问题撤销。
- 审查历史与轮次只作追溯，不设自动停止、通过或升级给用户的轮数阈值。同一项按原对象和原断言继承失败历史，换编号、拆分、调级或会话不得重置；已过项须有新增反证、实际改动影响或快照失效依据才重开。反复无进展时调整方法或重规划，不机械重试、逐轮加严或换编号掩盖旧问题。待用户确认项只限制对应裁决，其他独立授权工作继续，不伪造工具阻塞。
- 在同一提示追加一个 `planner-convergence` JSON 代码块，使用 `agent-coding-engine.planner-handoff.v1`。字段、最小示例和校验入口见[规划收口门禁](planner-convergence.md)。账本由 Planner 生成，业务证据直接引用原件；这是规划委派门禁，不是执行补附件任务，也不改变 Executor 终态契约。

## 8. 必要结果摘要与原文位置

回执只保留必要摘要和定位，原始流完整保存、不截断；已有文件能够直接读取时不另建证据包：

```
缺口（原子ID）→ 原始文件/位置（路径:行号）→ 实际结果（工具真实输出/查询行/响应）→ 边界（覆盖范围与未覆盖项）
```

- 不做非必要哈希或整包校验，不把 MANIFEST 作为默认提交要求。只有具体产物的身份或完整性存疑时才针对该产物校验，写明存疑点、范围及实际结果。
- 计数来自真实输出，验收核对实际含义，不要求回执文字逐字一致；需要的定位清单按实际文件形成，不增加清单齐全度门槛。
- 路径声明工作目录；合并 stdout/stderr、静默命令合法，0 字节输出如实保留。
- 证据层级必须如实标注且**不冒称**：`声明` / `单测` / `集成运行` / `真实API/SQL` / `真实浏览器或HTTP`；已有独立证据可组合，但须展示关联与层级，不得把单测改名为浏览器结果。

## 9. 提交自检与合法终态

Executor 提交前按本项实际风险自检，不适用项省略，不用文字勾选或附件齐全度代替行为判定：

- [ ] 全部缺口按 §2 矩阵关闭，无凭描述填 DONE？
- [ ] 身份/实例/任务/数据库/产物与主张一致？
- [ ] 原始查询/输出可见，反向断言（如零残留、动作数不增）有真实结果？
- [ ] 清理/扫描针对真实环境路径，无近似对象？
- [ ] 完整原文可直接读取，回执位置能定位实际结果，没有非必要哈希、整包校验或重复封装？
- [ ] 如有代码修复，证据属于最后快照且受影响回归已按门禁执行？
- [ ] 剩余可执行项为 0（或真实外部阻塞已按契约登记）？
- [ ] 已按问题性质区分继续修复与用户待确认事项，进度带总阶段数、已完成、进行中、未开始，常规决定已在交接记一行？
- [ ] 同项重复派发已给具体位置、实际/预期、差异依据和完成条件，并相对上一轮实际收窄范围？
- [ ] 本角色任务产物已按 `system.md` §0.8.1 完成适用检查、提交推送及远端回读，或如实报告无新变更/真实推送限制？

终态纪律：

- 剩余账本与 `terminal-contract.json` 的 `work_items`、`remaining_actionable_count`、`tool_results` 对齐，不另建 schema。
- 有授权内可执行项就继续执行；工具限制**有真实结果**且替代路径/独立工作**已穷尽**时才按契约报告阻塞。
- 用户中途消息默认补充要求，处理后自动继续原任务；证据/文字小问题的用户待确认状态只限制对应裁决，不中断其他独立授权工作。
- 禁止无限重试、把权限申请当作已获授权、或使用「必须一次过」诱导虚构证据；不承诺未经验证的一次必过。
- Executor 不得自行写 `PASSED/COMPLETED` 或进入阶段三；提交后状态保持 VERIFYING 等待 Planner 验收。

## 附录：去身份化失败行为案例（仅作诊断示例）

下列案例用于解释缺口分类与处理方式；通用身份：用户 A/B、处理人 P、实例 X、隔离库 DB1。

| # | 失败行为（去身份化） | 合规诊断归类 | 新规范下的处理 |
|---|---|---|---|
| 1 | 「PASS」写作基于 UPDATE 参数与 RAW 标签，未执行最终 SELECT；把成功摘要当作数据库最终状态 | 缺证据 / 自述冒充行为证据 | §2 最小充分证据：实际查询与真实结果；§8 四要素证据包 |
| 2 | 用操作者 P 重放其任务替代被取消用户 A 重放自己的子任务（对象错位） | 证据对象不匹配 | §4 固定对象身份，禁止近似替换；拒绝直至对象一致 |
| 3 | 另建 Flyway-only 种子库 DB2 证明「清理零残留」，真实运行库 DB1 已销毁 | 证据对象不匹配 | §4 清理路径二选一：真实环境的持久清理回读或纯内存属性＋进程销毁；不造无关库 |
| 4 | 证据生成晚于环境销毁，事后重建环境补回读，历史原件不可恢复 | 快照过期 / 生命周期倒置 | §4 先建采集点、验证完成后清理；不要求恢复不存在原件 |
| 5 | 运行矩阵早于最后代码修复，修复后仅跑单测 | 快照过期 | §3 失效依据：最后修改 → 受影响断言；单测不自动替代已要求的运行结果 |
