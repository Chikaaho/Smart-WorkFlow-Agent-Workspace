# P64「高级流程编排」功能说明（业务版）

> 面向业务负责人 / 配置管理员：P64 新增了什么、每个配置项是什么意思、怎么用起来。
> 本文只用业务语言，不涉及接口、表结构等技术细节。
> 功能状态：已完成并验收（正式功能第 48 个，2026-10-13）；界面文案已按本文口径做过业务化调整（BF20261013-018）。

---

## 1. 一句话说明

P64 让复杂业务可以「搭积木」式地串起来：**一张主表单 + 每个审批节点各自的表单 + 自动判断 + 自动发起后续流程 + 子流程结果自动回填**。配置人员在界面上选一选、填一填即可，不需要写代码（唯一的「判断脚本」也只做判断、不改数据）。

## 2. 能力总览

| # | 能力 | 一句话说明 |
|---|---|---|
| 1 | 节点审批表单 | 每个审批节点可以挂一张已发布表单，办理人在审批时顺手填写业务数据（如检验结果、处理意见、下一阶段审批人） |
| 2 | 流程变量 | 给判断规则准备「取数口」：从主表字段、节点表单字段或系统字段取值 |
| 3 | 触发规则 | 到指定时机自动执行判断，按判断结果自动发起后续流程 |
| 4 | 三种发起方式 | 发起一个流程 / 按集合逐条发起 / 按分组批量发起 |
| 5 | 主子流程与继续条件 | 发起一批子流程后，按「继续条件」决定主流程何时往下走 |
| 6 | 结果回填 | 子流程的办理结果自动写回主表单（支持按行精确回填） |
| 7 | 岗位委托 | 后台配置「源岗位 → 受托岗位」，实际办理人自动按组织关系解析 |
| 8 | 审批数据聚合选人 | 自动汇总上一轮各任务里填的人员，去重后作为下一轮会签人 |
| 9 | MES 生产样板 | 一条完整生产工单链路示范：领料 → 开工 → 首件检验 → 批量生产 → 报工 → 完工检验 → 入库 → 关闭 |
| 10 | 规模与安全边界 | 单次发起量、嵌套层级、自动循环次数等都有明确上限，超限会明确拒绝而不是悄悄截断 |

## 3. 它是怎么串起来的（业务视角）

1. **主表单**：承载业务单据本身（如生产工单）。
2. **节点表单**：审批/办理节点上，办理人填写的业务数据（按任务、按办理轮次各自独立保存，互不覆盖）。
3. **流程变量**：把上面这些数据「登记」成变量，供后续判断使用。
4. **触发规则**：在某个时机（如节点本轮完成时）读取变量做判断，返回一个结果值。
5. **动作**：每个结果值对应一个动作——自动发起关联流程（一个 / 逐条 / 按分组）。
6. **主子流程**：如果发起的是「子流程」，可以设置继续条件与结果回填，主流程等结果齐了再往下走。

## 4. 功能与参数逐个说明

### 4.1 节点审批表单

- **用途**：审批节点上让办理人填写业务字段；默认的「审批意见」保持原样可用。
- **适用节点**：审批、会签、动态并行三类人工节点。
- **配置项**：

| 配置项 | 含义 |
|---|---|
| 节点业务表单 | 为该节点选择一张已发布表单（选错了可更换或清除） |

- **运行表现**：每个任务、每个办理轮次的数据独立保存；只有最终提交的数据才会被后续判断读取；草稿不会参与判断。

### 4.2 流程变量（设计器「变量」入口）

- **用途**：给判断规则提供取数来源。判断规则只能读取这里登记过的变量。
- **配置项**：

| 配置项 | 含义 | 填写要点 |
|---|---|---|
| 变量标识 | 变量的唯一名字，判断脚本靠它取值 | 字母/数字/下划线，创建后不可修改；改名（变量名称）不影响已经引用它的地方 |
| 变量名称 | 给人看的中文名（如「质检结果」） | 随意取，业务人员看得懂即可 |
| 数据类型 | 数字 / 文本 / 是-否 / 人员 / 部门 / 人员集合 / 部门集合 / 表格行集合 | 按实际取值对象选 |
| 数据来源 | 主表字段 / 节点表单字段 / 系统字段 | 选「节点表单字段」时还要选来源节点与该节点表单里的字段 |
| 汇总方式 | 不汇总（单值）/ 合并去重 / 逐行拼接 | 集合类变量必须选一种汇总方式 |
| 取不到值时 | 视为必填（不触发后续动作）/ 允许为空（由判断规则自行处理） | 必填变量取不到值时不触发；允许为空时判断脚本可显式处理「没有值」的情况 |

- **系统字段**（平台提供的只读白名单，共 8 个）：流程实例编号、流程标识、业务单号、表单标识、发起人、租户、当前节点、办理轮次。
- **稳定性**：变量在流程发布时随版本「冻结」；后续修改变量名称不会影响已发布版本的引用。

### 4.3 触发规则（设计器「触发器」入口）

- **用途**：到指定时机自动判断、自动发起后续流程。
- **配置项**：

| 配置项 | 含义 | 填写要点 |
|---|---|---|
| 规则标识 | 规则的唯一名字 | 创建后不可修改 |
| 名称 | 给人看的中文名 | — |
| 触发时机 | 任务提交时 / 节点本轮完成时 / 流程完成时 | 默认「节点本轮完成时」触发一次；「任务提交时」是逐任务触发，需谨慎使用 |
| 来源节点 | 判断取数的节点 | 触发时机不是「流程完成时」时必填 |
| 可读取的变量 | 判断脚本只能用这里勾选的变量 | 没勾的变量脚本读不到 |
| 判断脚本 | 只做判断、不改数据；用 `流程变量取值('变量标识')` 读取变量，返回 数字 / 文本 / 是-否 / 空 | 脚本里写 `return` 返回结果；不能改数据、不能发流程、不能联网 |
| 结果分支 | 按返回值匹配：每个分支有「分支标识 / 结果类型 / 结果值」 | 结果类型选 数字 / 文本 / 是-否；结果类型与结果值都相同的重复分支不允许 |

- **安全说明**：判断脚本运行在受限环境里（最长 5 秒、语句数与内存有上限）；出错、超时或没有匹配到任何分支时，会进入可查看的异常/未匹配记录，**不会**自动走「成功」路径。

### 4.4 自动发起流程的三种方式（动作「发起方式」）

| 发起方式 | 什么时候用 | 说明 |
|---|---|---|
| 发起一个流程 | 一个单据对应一个后续流程 | 最简单 |
| 按集合逐条发起 | 一张表里多行、每行各发起一个流程 | 需选「集合变量」；可为每条数据带入行内字段 |
| 按分组批量发起 | 多行按某个字段（如负责人）分组，每组发起一个流程 | 需选「集合变量」并填写「分组字段」 |

- **带入目标流程的数据**：每一行对应关系可选三种来源之一——取变量值 / 取集合行字段 / 固定值。
- **单次最多发起**：默认 50，最大 200；超过会整体拒绝并说明数量，不会悄悄截断。
- **可靠性**：同一个动作重复触发时会回查原结果（不会重复发起）；发起失败会留下可恢复记录，可在实例回查里重试。

### 4.5 主子流程与继续条件

- **用途**：发起一批子流程，并决定主流程何时继续。
- **配置项**：

| 配置项 | 含义 |
|---|---|
| 按主子流程编排 | 勾选后：发起时锁定本批名单（后续改动不影响已发起职责），并可配置继续条件与结果回填 |
| 继续条件 | 见下表 |
| 完成数量（达到即继续） | 仅「完成数量达到设定值」时填写：达到这个数量就继续 |
| 结果回填 | 勾选后把子流程结果回填到本表单（见 4.6） |

- **四种继续条件（业务含义）**：

| 界面文案 | 业务含义 |
|---|---|
| 全部子流程完成 | 本批全部子流程都有效完成后，主流程才继续 |
| 任一子流程完成 | 任意一个完成后主流程继续（只推进一次），其余子流程继续独立办理 |
| 完成数量达到设定值 | 完成数量达到填写的数字后主流程继续（只推进一次） |
| 不等待（立即继续） | 发起后主流程立即继续；子流程结果仍在处理中，可另行查看 |

- **边界说明**：拒绝/取消/失败的子流程不能当作完成；子流程迟到、重复或旧轮次的结果不会覆盖已使用的结果；主流程取消或退回后，本批未完成子流程不再有资格推进主流程。
- **配置入口（2026-10-13 起）**：子流程发起直接在**审批节点**上配置——节点属性 →「发起子流程」：选择目标子流程与目标表单、用判断脚本决定是否发起（留空 = 总是发起）、选发起范围（发起一个 / 按表格行逐条发起）并填写初始值（取变量值或固定值）。保存后设计器自动生成发起与等待：本节点任务提交时按条件发起子流程；**全部子流程完成后流程才继续**；判断为「不发起」时直接继续。原独立的「子流程等待」节点已从组件栏移除（历史图中的存量节点仍正常运行）。

### 4.6 子流程结果回填（「结果回填」勾选后）

| 配置项 | 含义 |
|---|---|
| 结果节点 | 子流程中产出结果的节点（结果取该节点最新有效轮次的最终提交） |
| 子表单结果表 | 行级回填时填写：子表单里承载结果的表格字段 |
| 来源行标识列 | 行级回填时填写：记录「来源行」标识的列 |
| 本表单的来源表 | 行级回填时填写：本表单承载来源行的表格字段 |
| 行级回填对应（子表列 → 本表单列） | 一行一条：子表哪一列的值回填到本表单哪一列（没列出的列不回填） |
| 主记录回填对应（子表单字段 → 本表单字段） | 一行一条：子表单哪个字段回填到本表单哪个字段 |

- **回填规则**：按「来源行标识」精确回填到对应行；并发、重复、迟到或旧轮次的结果不会写错行、不会覆盖当前有效结果；冲突会挂起等待处理。

### 4.7 岗位委托（系统管理 → 岗位委托）

- **用途**：把某个岗位的办理职责委托给另一个岗位；流程运行时自动解析受托岗位的**实际在职人员**生成待办。
- **配置项**：

| 配置项 | 含义 |
|---|---|
| 源岗位 | 被委托的岗位 |
| 受托岗位 | 实际承接办理的岗位 |
| 适用范围 | 组织默认 / 精确部门（精确部门优先于组织默认） |
| 备注 / 启停 | 说明与生效开关 |

- **规则**：最多 4 层委托（逐层检查有效期与范围）；自己委托自己、循环委托、跨租户、越权、同优先级重叠都会被拒绝；**已经生成的待办不受委托变更影响**（按当时的名单快照执行）。

### 4.8 审批数据聚合选人（参与人策略「节点表单聚合」）

- **用途**：自动汇总上一轮指定节点的各任务里填写的人员字段，合并去重后作为下一轮会签参与人。
- **配置项**：来源节点（选择读取哪个节点）+ 人员字段（读取该节点表单里的人员字段名）。
- **运行表现**：只读取该节点**本轮全部有效且已最终提交**的数据；来源任务、字段与轮次都可追溯。

### 4.9 MES 生产样板（示范链路）

- **完整链路**：生产工单 → 领料 → 开工 → 首件生产 → 首件检验 → 批量生产 → 报工 → 完工检验 → 完工 → 成品入库 → 工单关闭。
- **异常路径**：首件检验不合格按原因（工艺/物料/设备）进入对应处理流程，整改完成后发起新一轮首件检验；完工检验不合格分别覆盖 返工 / 报废 / 让步接收。
- **数量账**（领料/入库）：逐行「预约 → 有权仓库角色确认 → 按实际数量结算」；取消或未执行按真实状态释放；重复/并发操作以余额回读证明实际变化（预约不等于已领料，审批通过不等于已入库）。
- **角色**：生产计划、车间/操作、质检、工艺/维修、仓库各角色有各自的办理与查询入口。

### 4.10 规模与安全边界（设计上限，界面可见、超限明确拒绝）

| 项目 | 默认值 | 硬上限 |
|---|---|---|
| 单次集合/分组发起数量 | 50 | 200 |
| 子流程嵌套层级 | 3 层 | 8 层 |
| 同一业务根链自动发起实例总数 | — | 1000 |
| 异常处理 → 复检自动循环轮次 | 3 轮 | 10 轮 |
| 单次判断运行时长 | — | 5 秒（另有语句数与内存上限） |

### 4.11 兼容与回退

- 升级前已发布、已启动的流程与实例**保持原语义**运行到结束，不会被自动改写。
- 新能力通过「新发布版本 + 显式配置」启用；旧流程行为不变。
- 入口关闭后停止新配置/新发起，但既有实例的办理、查询、恢复继续可用。

## 7. 三个验证场景（已验收通过）

1. **MES 生产主链**：完整正常链路 + 首检异常整改复检 + 完工检验不合格（返工/报废/让步接收）。
2. **招商案例**：表格部门集合经判断规则按优先级输出分支，再结合岗位委托与聚合选人产生下一轮会签待办。
3. **主机回收案例**：按负责人分组发起 N 个子流程，各负责人只看到并办理自己的行，全部反馈齐了主流程才生成一次复核任务，结果按行精确回填。
