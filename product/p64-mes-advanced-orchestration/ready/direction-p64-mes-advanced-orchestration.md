## 1. 产品目标

在P62可靠事务/命令能力和P63动态审批基础上，提供可配置的高级流程编排，让复杂业务通过“主业务表单＋节点审批表单＋BPM变量＋少量判断JS＋配置化动作＋动态参与者＋主子流程”组成完整业务链。

用户能配置数据从哪里来、由谁办理、触发哪条流程、结果回到哪里、何时继续；运行结果可以从业务单据追踪到各流程、任务、数据版本及动作结果。MES生产链作为交付样板，证券案例作为通用能力验证场景，使用同一套产品能力。

本轮新增范围涉及节点数据、变量契约、脚本执行边界、跨流程可靠动作、父子数据权限、组织身份及多版本兼容，按XL规划。P63已验收范围继续锁定；新增能力不以重做P63替代。

## 3. 关键产品语义

### 3.1 节点表单与变量

主业务表单承载业务单据；节点审批表单承载本次办理产生的数据。节点表单可以包含检验结果、缺陷类型、不良数量、处理建议和下一阶段审批人，审批意见保留独立含义。表单绑定覆盖APPROVAL、CONSENSUS、DYNAMIC_PARALLEL三类人工任务节点。采用任务级低代码表单实例绑定已发布表单版本，支持人员、部门和动态表格等已发布业务字段；每个任务/合法轮次有独立数据身份。草稿保存与最终提交分开，只有合法最终提交形成可供后续读取的办理结果，动作与表单提交不能留下半成功状态。

变量选择器展示业务名称、类型、源节点/源表单和字段。变量引用使用稳定身份，显示名修改不改变引用；字段删除、类型变化和不可访问来源必须在配置/发布时给出可纠正结果。不得通过变量越权读取其他实例、租户或未授权节点数据。

运行取值明确当前实例、发布版本、办理轮次、任务/分支及读取时点。同一触发判断读取一致且可追踪的数据快照，不因并发提交出现字段来自不同轮次或不一致版本。单任务数据和多实例集合不隐式互换。聚合至少支持人员/部门集合并集、表格集合拼接和按字段分组；重复来源保留追踪关系。已撤回、取消或被新轮次取代的数据不混入本轮有效集合。单值来源必须选定任务或配置唯一选择规则，多任务同字段不能任取最后一条。必填变量缺值阻止触发；显式可空变量返回null，判断脚本可以显式处理；脚本最终返回null时进入未匹配处置；类型不符、失效引用和权限不足进入可诊断失败。标量保留配置类型，不做字符串/布尔/数字隐式转换；人员/部门集合按稳定ID并集去重；表格拼接保留来源实例/节点/任务/轮次/行ID，并可按指定稳定字段分组。节点表单源只读本次指定有效轮次已最终提交的数据；系统源限平台提供的只读白名单，不接受客户端任意扩充。

### 3.2 判断与执行

Trigger绑定明确事件与生效版本，提供任务最终提交、节点本轮完成、流程合法完成三个事件；默认按节点本轮完成触发一次，指定逐任务触发须显式选择。节点完成取该轮全部要求的有效任务结果；退回/取消等生命周期动作采用各自处置，不冒充合法完成。质检NG是业务表单中的质量结果，办理可以正常完成并触发整改流程，区别于审批拒绝。Trigger可使用已配置变量。JS读取范围限定在被授权上下文，只输出有限Number、String或Boolean，匹配值与类型一起比较，同类型同值重复动作分支在发布时拒绝；脚本异常、超时、资源超限、null或未匹配结果进入可查看的异常/未匹配处置，不自动启动默认成功流程。提供类型检查、结果分支配置和受控预览。BPM判断运行上下文只开放变量读取；复用脚本运行器时也必须建立该独立权限边界，预览不产生任何业务/事件/设备副作用。已有IoT脚本的宿主副作用入口与未生效的资源声明不能作为此项通过证据。

执行动作由平台依据结果匹配和权限执行。同一事件、轮次、触发配置与目标动作有稳定执行身份；重放同一合法动作回查原结果，输入冲突明确拒绝。源业务已提交后，动作失败保留可恢复记录；未可靠记录触发意图不能冒称已完成跨流程动作。外部动作不能被包装为与源业务天然同事务。

流程启动/回写权限依据服务端受控上下文，不信任客户端自报身份。重试不重跑已成功目标；未知外部效果沿既有核实边界处理。断点恢复后可以说明哪些意图已提交、哪些子流程已启动、哪些结果已回写。

### 3.3 子流程、分组与等待

发起配置区分独立关联流程和主子流程；两者都关联业务主链，后者额外约定来源快照、输出映射和等待策略。分组使用稳定负责人/业务对象身份，不用显示名或当前行序号。

派发时冻结本批有效集合、分组、预期子流程和来源行关系。父表后续编辑不会偷偷改变已派发职责。多人同负责人的分组规则、空集合和超限在发布前可解释；派发集合必须非空，空集合阻止派发并展示无有效对象原因；超限整体拒绝并说明集合规模，不能静默截断。多人负责字段需在配置中选定唯一分组身份或显式按成员拆分，同一行的回写职责及允许字段随派发冻结。不同授权字段可合并，同字段基于来源版本检测冲突，冲突挂起等待处置；删除或改变已派发行职责不重新按行号匹配，不采用后到覆盖。

| 策略 | 主流程继续条件 | 未结束子流程与后续结果 |
|---|---|---|
| ALL | 本批全部预期子流程达到配置要求的有效完成，必需结果回写已提交。 | 拒绝/取消/失败不能直接计作成功；按已配置异常处置处理。主机回收案例使用此策略。 |
| ANY | 至少一个子流程有效完成且所需结果已提交，只推进一次。 | 默认其余子流程继续独立办理；闸口采用冻结结果，后续反馈有独立版本和展示，不覆盖已使用快照。 |
| COUNT | 达到已配置正整数K，K不得超过本批实际子流程数，所需结果已提交，只推进一次。 | 与ANY采用同样的剩余办理及迟到结果边界；不足K的失败结果不能凑数。 |
| NONE | 可靠派发意图已提交即可继续，页面明确显示子流程结果仍在处理中。 | 子流程独立追踪；后续反馈进入受控的版本化结果，不覆盖已结束父流程的完成快照。 |

转办/委托/重试不新增预期子流程数。同一子结果只结算一次。主流程取消或合法退回时，本批未完成子流程失去向当前轮次写回/推进的资格；取消必须有可追踪结果。已经产生的外部效果按真实结果处置，不能用取消抹除。规模护栏见§3.5，重试和人工转办沿原业务身份记账，不通过创建新批次重置护栏。失败、拒绝、取消或必需回写冲突时，等待批次明确展示阻断原因，可由有权用户重试可恢复项或终止业务；本轮不将这些结果折算为成功完成。

### 3.4 岗位委托与聚合会签

部门负责人、分管领导等业务职责先解析为组织上下文中的岗位，岗位再解析实际有效人员。岗位委托为后台可维护的通用关系：源岗位的办理职责委托给受托岗位，以岗位稳定身份绑定，最终办理人从受托岗位的有效任职关系取得。

配置管理员在授权组织/租户范围维护源岗位、受托岗位、适用范围及启停状态，配置和变更可审计。解析顺序为“业务部门/来源→审批规则选定源岗位→有效委托关系→受托岗位→实际办理人”；部门特殊规则决定源岗位，委托关系决定实际受托岗位，两类规则的生效顺序明确。职责到岗位的绑定及特殊部门选岗均为明确配置，不从岗位显示名推断。岗位多任职解析为全部有效人员并按用户ID去重：普通审批生成一个候选办理任务，首个合法完成者办理；会签按该节点已发布的ALL/ANY/比例规则；动态并行保留每个来源部门的职责身份。同人多职责不在选人阶段合并。受托岗位必须在源职责的授权组织范围内任职；跨部门委托须明确配置该组织范围及管理权限，跨租户拒绝。

自委托、循环委托、跨租户或越权映射在配置/生效时拒绝；受托岗位缺有效人员、关系失效或解析歧义阻止推进并可诊断。每个源岗位/适用组织范围最多一条有效委托关系；精确部门范围优先于显式组织默认范围，同优先级重叠拒绝。支持最多4跳委托，逐跳检查有效期、授权范围、循环和最终任职，超过4跳阻止解析。没有命中关系时使用源岗位有效人员；命中关系但目标失效/空缺时进入异常处置，不自动回退。委托关系变更影响尚未冻结的新任务/新轮次，已生成任务继续采用原名单及关系快照，受控转办另沿原任务动作规则处理。审计可解释源岗位、命中委托、受托岗位、实际办理人和生效时点；原岗位人员的待办与数据权限不能因委托被重复授予。

P63已发布的部门负责人语义继续原义；新岗位来源/委托规则通过明确配置及新发布版本生效。同轮办理名单冻结，合法新轮次重新解析，组织和委托变更保留历史身份与来源。

下一会签默认按用户ID并集去重：A选择甲/乙，B选择丙，C选择乙/丁，生成甲/乙/丙/丁。来源任务/字段/轮次仍可追溯。P63同负责人不同部门的独立职责任务保持原义；跨任务聚合为下一会签人员集合属于显式新配置。

### 3.5 有界规模与资源

以下为本轮产品护栏及发布校验值，属于设计限制，不代表已验证容量或吞吐指标。单次集合/分组派发默认上限50、可配置硬上限200；父子嵌套默认最大3层、硬上限8层（根为第0层）；同一业务根链最多1000个自动发起实例。异常处理→复检自动循环默认最多3轮、硬上限10轮，计数归属根业务及检验阶段，超过阈值挂起并交有权用户处理。发布时拒绝明显递归引用，运行时仍校验深度与累计数量。普通人工等待不以任意短时超时强制成功。

单次判断最长5000ms、最多500000语句；输入变量快照最多1MiB、标量输出最多4KiB，执行空间预算最多128MiB。Executor须选择能实际约束执行空间的隔离方式，不能仅声明一个常量；超限必须终止该判断并保留诊断。部署配置须给出有限全局/租户并发及有限排队数，达到限制返回明确繁忙/可恢复状态，不建立无界等待。具体部署并发值由Executor记录在架构决策及回执中，不更改本合同业务语义，也不以此开启P62延期资源策略。默认值与硬上限在UI可见并经服务端复核，禁止静默截断。

## 4. 三组验收场景

### S1 MES生产主链

通过配置形成R10完整链，生产计划、车间/操作、质检、工艺/维修、仓库角色可分别办理。首检PASS进入批量生产；NG按PROCESS/MATERIAL/EQUIPMENT进入对应处理流程，整改完成后发起新轮次首检；终检PASS入库，NG进入不合格品处理并分别覆盖返工、报废和让步接收。工单关闭依据实际业务结果和应完成关联项，页面能解释结束原因。

领料/入库采用P62数量账接缝加低代码业务单据，至少记录工单、仓库/物料对象、数量单位、来源行和业务动作身份。领料逐行预约→有权仓库角色确认→实际数量结算；取消/未执行按真实状态释放，已产生效果进入授权补偿。成品入库经仓库角色确认执行数量增加，报废记录实际数量及处置原因，让步接收保留批准记录。多行单据逐行保留账务结果，部分失败不重复结算已成功行，全部必需行确认后才推进相应业务阶段。重复/并发/恢复后以同对象数量余额和效果记录回读证明实际变化，预约不冒充已领料，审批通过不冒充入库。受控数量账是本样板内部业务结果，不外推为完整仓储管理。受控设备事件/命令关联生产对象、流程与实际反馈，保持传输受理和设备执行结果层级。

### S2 招商案例：集合条件与下一轮选人

表格部门集合经BPM变量供判断JS读取，按有优先级的规则输出分支。规则使用配置的A/B/C部门稳定ID，先取集合与{A,B,C}的交集；其他部门成员保留来源但不参与此矩阵判断。Planner确定优先级为：含A/B/C→分支1；仅A→分支1；含A/B无C→分支3；含B无A→分支2；交集为空→分支4。完整真值表如下，匹配优先级随定义版本冻结：

| A/B/C交集 | 结果 |
|---|---|
| {A} | 分支1 |
| {B} | 分支2 |
| {C} | 未匹配，阻止动作并展示诊断 |
| {A,B} | 分支3 |
| {A,C} | 未匹配，阻止动作并展示诊断 |
| {B,C} | 分支2 |

随后默认选择分管领导岗位，特殊部门可选部门负责人岗位，再应用后台源岗位→受托岗位的委托配置并生成职责审批任务。各任务填报“下一阶段审批人”；本轮有效任务汇聚后并集去重，产生下一会签实际待办。选岗、委托解析、取值、命中路径和两轮人员来源可查询。

### S3 安信案例：分组、隔离、回写与ALL

领导发起→选择运维人员→运维填主机表→按负责人分组启动N个子流程→各负责人只办理自己的行→反馈准确回写→全部有效反馈已提交→运维复核→领导查看完整汇总。

固定核心样例：host-01/03属于张三、host-02属于李四、host-04属于王五，生成3个子流程。张三只能读取/修改其2行，不能通过其他数据出口获得李四/王五数据。父表调整显示排序不改变回写对象；早完成1个/2个时父流程不提前继续，全部结果满足ALL后才生成一次复核任务。

## 6. 范围、风险与阶段边界

影响范围：Server/Web相关表单、流程定义/设计器、人工任务、变量解析、受控脚本判断、可靠触发动作、组织解析、父子关系/回写/等待、业务查询/权限、必要追加迁移和样板配置。复用既有事务、命令、IoT及动态参与者接缝；通用能力与样板配置分别登记。探索矩阵为7项缺失、5项部分具备；既有源码、历史验证资产与本轮新运行证据分别报告。

XL阶段目标按产品能力划界：先形成可用的节点数据/变量/判断动作闭环，再形成动态参与者及主子流程数据/生命周期闭环，最后形成三场景整体交付与终态同步。Executor自主安排内部实施；每阶段由Planner独立验收，阶段通过不代替P64整体完成。架构决策必须记录适用范围、兼容窗口与回退点。产品架构边界为任务级业务表单、显式类型变量模型、BPM只读判断上下文、独立已发布实例及可靠关联/等待、组织岗位委托和父子稳定行共享权限契约；Executor选择内部实现并记录六项接缝决策，不能用动态多任务冒充子流程或用用户委托冒充岗位委托。

兼容窗口：升级前已发布定义和已启动实例沿其原版本完整运行至结束，不自动迁移、重算参与者或改写旧意见表单；新能力由新发布版本和显式配置启用。P64关闭入口后停止新配置/新发起，既有P64实例的办理、回调、查询、恢复继续可用至收敛。代码回退保留新增数据；不能处理存量P64实例的旧代码须在这些实例收敛后才切换，回退不通过破坏性DDL删除事实。

升级验证在授权开发/测试PostgreSQL环境，以当前0.1.6迁移链、非空旧表单/定义/运行实例为基线验证追加迁移和运行兼容；保存旧实例与新实例实际对象结果并分列回退观察。H2仅证明测试/开发兼容，产品演示部署“全新建库”边界及运行版本不因此改变；P64不含生产环境升级授权。

主要风险：读取未完成或错误轮次数据，重复事件启动多个流程，脚本越权，子流程泄露父表全量数据，按行序号误写，结果回写和Barrier推进脱节，ANY/NONE迟到结果改写下游事实，岗位解析歧义、循环委托或委托变更污染已生成任务，递归或异常循环失控，以及新引擎语义破坏存量。

当前明确边界：建设MES业务编排样板及公共平台能力；完整生产排程/MRP、全套ERP/WMS、真实厂商网络/工厂部署、硬实时和物理恰一次不属于本轮完成口径。P62性能保持Owner延期未验证，新资源策略默认关闭。周期发起主机回收、周期预约、任意即席子流程和全部复杂组织模型继续独立候选；S3可由有权用户手工发起，周期调度另行选题。
