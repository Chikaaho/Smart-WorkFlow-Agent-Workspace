# 流程中台能力与流程中心边界

2026-09-05；Planner；P4 主方向配套契约规划。依据 Owner：未来流程中心具备管理员/普通用户双视角，本次不完善流程中心。

## 1. 业务模型与双视角

流程中心是后续消费业务能力的页面入口；本次个人 OA 与后续流程中心复用相同表单、流程关联、可见性、草稿、发起和审批服务，不分别建立业务状态。

用户看到的“流程”是可发起的业务事项（如请假），选择该事项即打开强关联表单填报。一个流程强关联一个表单，系统解析唯一合法发布绑定；用户不用再选引擎流程或版本。业务事项显示名称可面向流程中心，底层稳定标识与展示文案分开，不能靠名称或页面路由解析绑定。

- 管理员视角：在有管理权限的租户范围内管理所有表单、关联流程及发布状态，不受普通用户发起可见范围过滤；编辑等操作仍逐项检查管理权限。定义管理不自动授予查看所有填报数据、代办审批或 P0 调用的权限。
- 普通用户视角：按分类浏览本人可见且已发布可发起的业务事项，选择事项进入关联表单。分类本身不授予权限；分类聚合、数量及搜索结果不能泄漏不可见事项。
- 同一身份具有两种权限时可使用两种视角；服务端依据实际权限判断，不能相信客户端传入的管理员视角参数。

## 2. 能力与接口责任

下表是业务契约，不指定新 URL、类名或数据表。Executor 复用现有契约并报告映射；仅为本轮实际闭环补足接口。分类等未来能力在本轮明确契约，后续排期实现，不要求创建空接口。

| 能力 | 输入与输出语义 | 权限与一致性 | 本轮边界 |
|---|---|---|---|
| 可发起事项目录 | 分页/关键字查询，后续支持分类筛选；返回稳定事项标识、名称、关联表单标识、发布状态及可执行操作 | 普通查询只返回本人可见的已发布事项；管理查询独立检查权限，可查看未发布或停用定义 | 实现本轮已发布表单入口需要的查询；预留分类关联契约，分类展示与治理后续实现 |
| 分类目录 | 分类标识、名称、事项归属及可选聚合数量；与事项目录使用相同筛选语义 | 普通视角只呈现其可见事项对应的分类/聚合，管理视角可维护完整分类 | 仅规划；分类层级、排序、维护及页面在流程中心正式启动时确定 |
| 填报上下文 | 用稳定事项/表单标识获取渲染结构、当前合法绑定、发布版本及允许动作 | 服务端解析绑定与可见性；不向填报人提供任意选择流程的能力 | 本轮实际接入；返回必要版本标识供一致性检查，界面不要求理解它 |
| 表单与流程管理 | 查询/编辑表单高级属性与关联流程，维护可见范围和发布关系 | 管理权限独立于发起范围；发布后唯一绑定可解析，历史实例固定原绑定 | 本轮完善已有编辑入口和必要关联；集中管理全体验后续实现 |
| 个人草稿 | 保存/查询/恢复/删除，以本人、表单和版本快照关联 | 允许缺必填，保存不进入审批；撤权保留原内容，发起重新校验 | 本轮落地 |
| 发起与命令结果 | 提交内容与幂等意图，返回受理标识/状态/实例关联；提供结果回查 | 校验必填、可见性、发布绑定；普通异步、授权 P0 有界同步；两路同一业务语义 | 本轮落地并经过 MQ 边界 |
| 个人实例与审批 | 我发起的、待办、已办查询，任务详情与已有审批动作 | 个人记录与任务权限独立于事项目录可见范围，消费时复核实际操作权限 | 本轮落地，未来中心复用 |

共用错误语义需可区分：无权访问、未发布/停用、绑定失效或冲突、字段校验失败、版本冲突、幂等冲突、已受理、处理失败。对无权访问的对象，响应不泄漏其定义或其他用户数据。具体错误码、字段名由 Executor 对齐现有 API 并在回执附契约映射。
