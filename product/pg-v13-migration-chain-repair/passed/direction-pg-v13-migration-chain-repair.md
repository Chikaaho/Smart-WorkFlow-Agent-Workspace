# I52：PostgreSQL V13 迁移链修复

## 当前状态

**PASSED** — D110 已完成补证最终复验；等待阶段三终态同步后确认 `COMPLETED`。

## 功能目标

修复 PostgreSQL 全新数据库迁移链在 `V13__logical_delete_unique_constraints.sql` 的 `2BP01` 失败，使当前完整迁移链能够从 V1 连续执行至最新版本并通过校验，同时保持已有数据库升级路径和逻辑删除唯一性语义安全。

## 规划裁定

1. 本轮唯一主问题是 I52：PostgreSQL 全链在 V13 的索引处理处失败，导致真实 PostgreSQL 新库无法连续迁移至当前最高版本。
2. 验收对象是完整迁移链，而不是孤立 SQL 片段；修复必须同时考虑全新数据库建库、已有数据库升级、Flyway 校验和与已发布迁移兼容性。
3. 不预先强制采用“修改历史 V13”或“新增 V34”中的某一种手段。执行角色须根据现场迁移依赖和 Flyway 行为选择能真实到达链尾的安全策略，并在回执中说明为何另一类路径不会留下不可达或校验和风险。
4. PostgreSQL 与 H2 可以采用不同 SQL 实现，但逻辑删除唯一约束的业务语义不得弱化；H2 已通过的 33 条链路不得因本轮回归。

## 非目标

- 不新增业务表、接口、页面或用户可见功能。
- 不修改前端。
- 不顺带处理 I36 用户组绑定、M02 权限配置入口、M07 Prompt/日志/调试/RAG、I50 登录校验时序或其他需求池事项。
- 不重构整个 Flyway 目录或统一所有历史迁移写法。
- 不以关闭或跳过 PostgreSQL 迁移验证、删除唯一性约束、手工标记迁移成功等方式绕过问题。

## 影响范围

- **后端迁移边界**：PostgreSQL V13 及与其索引/约束依赖直接相关的迁移；如安全修复确需新增迁移，只允许使用现场确认的下一个合法版本号。
- **迁移验证边界**：PostgreSQL 全新库 V1→当前链尾、受影响的已有版本升级路径、`migrate + validate`；H2 当前全链作为回归基线。
- **业务语义边界**：受 V13 影响表的逻辑删除唯一性，包括有效记录冲突与已删除历史记录共存语义。
- **知识与状态同步**：完成后关闭 I52，并按宪法 §3.3 第10项全文同步完整知识、压缩记忆、功能追踪、迁移基线及需求池。

## 验收方向

最终完成回执必须提供足够证据证明以下条件同时成立：

1. 在真实 PostgreSQL 环境中，全新数据库可从 V1 连续迁移至当前链尾并通过 `validate`，不再于 V13 报 `2BP01`；回执报告实际迁移数量、数据库版本和验证入口。
2. 至少覆盖一个与现场修复策略匹配的已有数据库升级场景，证明不会因修改已发布迁移校验和、重复对象、缺失对象或依赖关系而破坏升级；若环境中不存在可复用旧库，必须用可重复的自动化升级夹具提供等价证据。
3. 受影响的逻辑删除唯一性语义有正反例证据：有效记录冲突被拒绝，符合现有契约的已删除历史记录能够共存；不能只证明迁移 SQL 可执行。
4. H2 全链仍可从新库执行至当前链尾并通过校验，既有双方言迁移基线不退化。
5. 后端受影响模块测试与项目级回归通过，测试总数不得低于当前 591；所有 Maven 命令使用 `MAVEN_OPTS="-Xmx2g"`，且不得与前端编译/测试并行。
6. 前端零改动、无无关业务改动；回执列明实际修改范围、迁移策略、命令与结果、偏差、遗留风险，以及功能清单变化或零变化明细和全部知识库触碰文件。

## 风险方向

- **链路不可达风险**：若失败发生在 V13，单纯新增链尾迁移可能在全新库场景中永远无法执行；回执必须证明所选策略确实能越过失败点并到达链尾。
- **已发布迁移风险**：直接改历史迁移可能触发既有环境校验和不一致；不得只验证新库而忽略升级库。
- **依赖对象风险**：索引可能由约束拥有，删除顺序或对象类型判断错误会再次触发 `2BP01`，或意外移除业务约束。
- **语义弱化风险**：通过删除唯一性约束让迁移变绿不算修复，必须验证逻辑删除条件下的唯一性契约。
- **环境证据风险**：H2 通过不能替代 PostgreSQL 运行证据；若真实 PostgreSQL 环境不可用，应如实标记阻塞，不得将静态审查写成已通过。
