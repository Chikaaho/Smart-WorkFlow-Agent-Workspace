# B021-027 执行回执（第 1 轮）

日期：2026-11-03。Owner 截图：选择审批人弹窗点组织架构部门后，右侧人员列表仍是全量。

## 1. 定位

- 弹窗（`ApproverCandidatesDialog`）点部门树只把 id 写进 `deptId`，而 `deptId` 唯一用途是
  过滤「dept- 前缀的伪候选」；人员候选来自 `/workflow/defs/approver-candidates`，
  接口只接 `keyword`，服务端 `UserQueryFacade.searchActiveUsers` 无部门维度——筛选从未发生。
- 正确口径：组织架构节点应按「部门 + 全部子孙部门」过滤（tree 语义），服务端为权威过滤。

## 2. 修改

### 2.1 Server（`6e83cd66`，5 文件，已推送）
- `UserQueryFacade`：新增 `searchActiveUsersInDept(keyword, deptId, limit)`（default 回落旧
  行为，兼容既有实现）。
- `UserFacadeImpl`：注入 `SysDeptMapper`；按 deptId + 子孙部门（单次查全量部门后层级遍历，
  环保护，与 `DeptScopeProviderImpl` 同口径）过滤正常状态用户；deptId 空走原全量搜索。
  返回 DTO 携带 deptId（候选已在部门上下文中，展示副行可用）。
- `BpmProcessDefController#approverCandidates`：接受可选 `deptId`，透传 facade。
- 两处测试装配改双参构造（OrgAuthorityFacadeIntegrationTest / I4CrossTenantServiceEntryTest）。

### 2.2 Web（`37a8dda`，3 文件，已推送）
- `queryApproverCandidates(keyword, deptId?)` 透传 deptId。
- 弹窗：组织树节点点击 → 切换/取消 `deptId` 并重新拉候选（关键字与部门叠加生效）；
  删除不再承担部门语义的本地过滤分支。
- mock handler：候选补 deptId，按部门子树过滤（同口径 helper），保持 mock 演示可用。
