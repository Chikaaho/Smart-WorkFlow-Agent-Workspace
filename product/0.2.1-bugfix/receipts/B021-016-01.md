# B021-016 执行回执（第 1 轮）

日期：2026-11-02。Owner 在登录页（localhost:5173/login，2560×1440 截图四处红框）提出四点：
①「租户编码」是什么东西，应该是手动输入租户名称；②「单点登录」未居中；③ SSO 不需要输
租户名称（没意义，后面应该需要扫码选择所属企业）；④ 补充：租户名称应显示在用户名上方、
现在要点击才展示，交互很奇怪。复核指示：提示语就用普通的「请输入企业名称」。

## 1. 定位

- **①/④ 租户编码入口**：`LoginPage.vue` 的账号标签行右侧挂了一个「租户编码」切换按钮
  （V012-BUG-019 时代产物），点击才展开一个可选编码输入，提交 `tenantCode`——语义不通俗、
  位置不对、需要点击展开。文案键 `tenantAdmin.loginCode/loginCodePlaceholder`。
- **② 分隔条未居中**：≥1280 设计块里 `.login-page__sso-title` 带 `max-width: 324px` 且无
  auto margin——分隔线块（左线+文字+右线）整体靠左贴在表单内容区（422px）左缘，文字中心
  落在块内 162px 处，比表单中心 211px 左偏约 49px；右线也短一截。DOM 实测复现。
- **③ SSO 租户输入**：`onSsoLogin` 强制要求填租户名称（空 → 前端拦截），服务端
  `authorize-login` 对空白 `tenantName` 一律 `sso_tenant_required`——企业名称只用来定位
  租户级 Provider 配置，对用户没有意义；多企业歧义场景 Owner 指明后续由「扫码选择所属
  企业」承接（本轮不实现，留 fail-closed 语义）。

## 4. 运维口径（本机重启后端，后续会话参照）

- 重建必须 `mvn -DskipTests clean package`（非 clean 增量包曾出现 bootstrap.jar 未刷新）。
- 启动（工作目录 Server 仓根）：`SPRING_PROFILES_ACTIVE=local` + `SW_CIPHER_KEY`/
  `SW_SSO_CIPHER_KEY`/`SW_LOGIN_DIGEST_SECRET`/`JWT_SECRET`/`OPENAI_API_KEY`（占位）环境变量
  + `java -Xms256m -Xmx1g -XX:MaxMetaspaceSize=256m -jar sw-bootstrap/target/bootstrap.jar`。
  密钥值存放于 gitignored `config/application-local.yml` 与 branch-init-021-01/02 回执口径，
  不入台账不入 Git。缺 profile 会落 prod（5433/smart_workflow）连库失败；缺 `SW_CIPHER_KEY`
  会在 IoT 模块 fail-fast。
