## 2. 问题事实

| 项 | 内容 |
|---|---|
| 观察结果 | 表单发布后进入 /form/designer/{id}，左侧组件库与画布呈灰置不可编辑状态。 |
| 期望结果 | 发布后的表单仍可进入编辑（按既有草稿/版本机制修改，不直接影响已发布版本）；完全锁死为缺陷。根因需先定位（前端锁或后端拒绝写入）。 |
| 影响入口/身份/对象 | 表单设计器发布后编辑链路；可能跨 Server。 |

| 风险等级 | 高（涉及发布/版本契约，命中跨仓/契约门时按 L 强度处理） |
| 受影响仓库 | Web（Server publish-version 端点为 I2 基线既有能力 `7342de3`，本轮零改动） |
| 当前结论 | 已提交候选（解锁编辑 + 发布新版本原子落库） |

## 3. 根因与修复边界

- 根因：前端将 `isPublished` 直接整体灰置（palette :disabled、canvas :readonly、面板 readonly 全量下传），且已发布表单无草稿保存通道——发布即锁死为前端契约缺陷；服务端 `POST /form/def/{id}/publish-version` 既有增量 DDL + 版本递增能力未被前端使用。
- 修复范围：仅本缺陷描述对象与入口；遵循 Owner 2026-09-22 全局基线——无特殊强调时界面必须随分辨率自适应。
- 明确不做：不顺手处理其他已编号缺陷；不改产品目标与验收边界。
- 关联/重复编号：无。

## 4. 行为证据

- 复现证据：Owner 截图 `evidence/owner-registration-20260922/image-20260922010805221.png`（归档副本）。
- 修复后验证：已发布表单设计器完全可编辑（组件库/画布/属性面板），动作组以「发布新版本」替代 保存/发布（确认框 → publishNewFormVersion 原子落库 → 版本递增），离开守卫改为「丢弃/留下」双选；headed 三比例截图 `evidence/V011-BUG-015/after-published-editable-{三比例}.png` + `after-published-editable-with-new-version-button.png` + `evidence-index.json`。
- 回归保护：FormDesigner.spec 新增 publishNewFormVersion mock 与脏态路径；属性面板 keyLocked 语义（BUG-016）钉死已发布态字段标识不可改名，避免已发布表列名数据分叉。
