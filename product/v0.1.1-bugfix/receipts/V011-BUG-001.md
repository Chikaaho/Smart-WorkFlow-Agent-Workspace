## 2. 问题事实

| 项 | 内容 |
|---|---|
| 观察结果 | 登录页在宽屏（≥1280px）下右侧留大片空白死区：品牌区锁定 840px 定宽 + 表单面板锁定 600px 定宽 = 1440px，剩余宽度不被利用；表单卡锁定 440×840 绝对定位，矮视口下底部"用户协议"行被视口下缘裁切（截图可见） |
| 期望结果 | 登录页布局自适应不同分辨率：宽屏利用全部可用宽度，矮视口内容不被裁切（可滚动），布局不破相 |
| 影响入口/身份/对象 | Web 登录页 `/login`（`src/views/LoginPage.vue`），所有身份 |
| 复现条件 | 浏览器视口宽 ≥1280px（或高 <932px）打开登录页 |
| 风险等级 | 中（登录入口可用性受损：矮视口下协议行不可见、验证码可能被裁切） |
| 受影响仓库 | Web |
| 当前结论 | 根因已定位：≥1280px media 查询块按 P53 节点06 锁定坐标实现（flex 定宽 + 绝对定位网格），仅适配 4:3 视口；基础（<1280px）样式本身已是流式布局 |

## 3. 根因与修复边界

- 根因（未取得证据时写「未确认」，不把猜测写成根因）：
  `.login-page__brand` 锁 `flex: 0 0 840px`、`.login-page__panel` 锁 `flex: 0 0 600px`（合计 1440px，宽屏余量不被利用）；`.login-page__form` 锁 `position: absolute; top: 92px; left: 80px; width: 440px; height: 840px`，内部字段全部绝对定位（top:147/245/343/480/546/595 等）；`.login-page` 基础样式 `overflow: hidden` 使矮视口（如 1366×768）卡片内容被裁切。
- 修复范围：仅 `src/views/LoginPage.vue` ≥1280px media 查询块——brand 改 `flex: 1 1 auto` 填满剩余宽度、panel 保持 600px 定宽 flex 居中、form 改 440px 定宽 + `height: auto` 流式内部布局（复用基础流式样式）、`.login-page` overflow 改可滚动；保留颜色/圆角/阴影等视觉 token。
- 明确不做（防范围蔓延）：`src/modules/form/views/FormRender.vue:921` 存在同类 `min-width: 1280px` 锁定网格，本轮不修——待 Owner 提供该页证据后另行编号。
- 关联/重复编号：无。
