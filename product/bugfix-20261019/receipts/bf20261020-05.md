## 1. Owner 要求（原文要点）

1. 去掉详情弹窗右下角「关闭」，与右上角关闭重复。
2. 待办、已办、草稿、抄送、无流程数据等全部采用抄送详情的弹窗方式；审批动作在弹窗最下方增加「审批」区，放审批意见选项，右下角放操作按钮。
3. 判断「当前账号没有 form:data:* 权限导致看不到表单数据入口」在业务上是否成立；应看到却看不到即缺陷。
4. 流转记录表格与审批详情列表样式统一，使用审批详情列表的样式；当前字体、对齐、大小不一致。
5. 审批详情的操作栏靠右固定，尺寸小一点。
6. 所有表格表头、行内数据展示居中。

## 2. 缺陷与根因

### BF20261020-05 详情入口与展示不统一

- 待办、已办（两套列表）仍跳整页 `TaskDetail`；草稿没有详情入口。
- 共享详情弹窗底部另有「关闭」按钮，与右上角 X 重复。
- 流转记录使用自绘 grid 表格（12px 表头/13px 正文），审批详情列表使用 `el-table`（13px 表头/14px 正文），两页签字体、行高、对齐不一致。
- 表格未统一居中；审批操作栏在页面底部吸底，但弹窗内没有滚动容器，无法吸底。
- 详情中的只读选择控件仍以禁用输入框/下拉呈现；多值字段落库为 JSON 数组串时未归一，导致选中项不打勾。
- 普通审批人没有组织目录权限，只读部门控件调用 `/system/dept/tree` 得到 403，暴露原始部门 ID 并弹出「加载失败」。

### BF20261020-06 表单数据入口准入错误

- `/form/form-data/:formKey` 的静态路由 `meta.authority` 被写成 `['form:data:template','form:data:import','form:data:export']`。
- 租户管理员实际持有 `form:data:query`（列表/详情查询），但不持有模板/导入/导出，因此直达表单数据列表被守卫判 403；有查询权却看不到列表，业务上不成立。
- 后端 V43/V68 只注册了 `form:data:*` 按钮权限，未向管理员角色（role_id=2）及租户管理员（code=demo_admin）授予；管理员能设计/发布表单，却看不到数据动作按钮。

## 3. 修复

### Web

- `BusinessDetailDialog`：移除 footer 关闭按钮；正文改为独立滚动（`:global` 穿透 Teleport），承载任务详情插槽；保留右上角 X。
- 新增 `TaskDetailDialog`：待办/已办列表以弹窗内嵌 `TaskDetail`（`embedded` 模式），复用表单数据、办理表单、流程详情和审批区；办理完成关闭弹窗并刷新列表。
- `TodoList`：行点击/「详情」打开弹窗；移除列表内直接通过/驳回，审批统一在弹窗底部完成；候选任务保留「领取」。
- `ProcessedList`、`MyProcessed`：详情改为弹窗，不再跳整页。
- `MyDrafts`：新增「查看」，用同一只读弹窗展示草稿 payload；编辑/提交/删除不变。
- `TaskDetail`：新增 `taskId`/`embedded` props；嵌入时补「表单数据」「审批进度」标题；审批卡片增加「审批」标题，操作栏 `sticky bottom`、右对齐、按钮高度 30px；办理表单文案去技术标识（去 v2/轮次/服务端事务说明），标题改「办理表单」、状态改「已提交/待提交」。
- `InstanceFlowPanel`：流转记录改用 `el-table`，与审批详情列表共用 `detail-flow-table` 几何（44px 表头/52px 行/同一字体与内边距）；意见弹窗去掉重复的底部关闭。
- 新增 `src/styles/tables.css`：全局 `el-table` 表头与行数据居中，覆盖 `.is-right`。
- `BusinessFormReadonly`：多值字段（MULTISELECT/ATTACHMENT/IMAGE/TABLE/USER·DEPT multiple）JSON 数组串归一为数组，只读选择项正常打勾。
- `DeptControl`/`UserControl`/`ReferenceControl`：只读改为静态业务名称展示，不再渲染禁用输入框/下拉；无目录权限时不弹错误提示，部门/人员按「已选择 N 个」兜底，不暴露内部 ID。
- `TableControl`：原生子表表头/单元格居中。
- 路由：`form-data` 的 `meta.authority` 改为 `['form:data:query']`；新增路由回归用例。
- `FormData`：编辑/删除按钮按 `form:data:edit/delete` 显隐；普通用户只有「查看」，不再看到必然被服务端拒绝的操作。

### Server

- 新增可重复迁移 `R__bf20261020_form_data_admin_grants.sql`（H2/PostgreSQL 双端）：向 `admin` 与 `demo_admin` 角色授予 `form:data:template/import/export/submit/edit/delete/query` 七项权限；普通用户角色仍需显式授权。
- 升级链测试同步：迁移总数 13→14、R__ 数 12→13；历史衔接测试允许新增 R__ 应用后再 validate。
