## 1. 缺陷 BF20261020-01：流程表达式应按「计算值脚本」求值并可模拟

**现象**：审批人表达式配置为 `variables.deptSupervisors`（我在上一轮 API 写入的变量路径），界面「模拟运行」报 `无法识别的字符「.」（位置 9）`；业务方看不懂这个写法，也无法验证脚本逻辑。

**根因（两头契约不一致）**：
- 运行期 `ExpressionParticipantResolver` 走 `RestrictedExpressionEvaluator`（**路径表达式**，只读变量），所以 `variables.deptSupervisors` 能跑；
- 设计器把审批人表达式当**脚本**（「审批人表达式脚本」弹窗 + `#` 函数目录 + 模拟运行），模拟器是浏览器内**另一套本地解释器**（不支持成员访问 `.`），因此路径写法必然模拟失败；
- 脚本执行器 `BpmScriptRunner` 只允许标量返回（Number/String/Boolean/null），**数组返回直接 TYPE_ERROR**——参与者列表无法由脚本返回。

**修复（与 Owner 口径一致：流程表达式＝计算值适配器，以 return 返回结果）**：
| 层 | 改动 |
|---|---|
| api | 新增 `ParticipantScriptResolvePort`：审批人表达式脚本解析接缝 |
| engine | `ExpressionParticipantResolver` 优先交业务侧脚本引擎执行（与触发器同一 GraalJS＋`#` 语法糖）；无装配时退回受控路径（单测/纯引擎兼容） |
| engine | `BpmScriptRunner.classify`：**支持标量数组返回**（ARRAY；Number/String/Boolean 元素；嵌套对象拒绝；仍受 4KiB 与 1000 元素上限） |
| engine | 翻译校验（Approval/ServiceTask）：EXPRESSION 由「受控路径表达式」改为**脚本语义**（`ScriptSugar` 可转译＋必须含 `return`） |
| process | 新增 `ParticipantScriptResolveService`：按图变量定义构建实例变量快照（主表单字段来源等）＋组织目录函数上下文，脚本 return 值归一为参与人列表（去空去重） |
| process | 新增 `POST /workflow/scripts/preview`：**模拟运行与运行期同一引擎**（真实组织目录＋按变量类型生成的示例值），只读无副作用 |
| web | 脚本弹窗支持 `simulate` 回调：**流程脚本**调用服务端模拟；表单脚本仍用本地解释器（表单表达式＝异步插件入口，语义不同）；新增 `previewProcessScript` API |

## 2. 缺陷 BF20261020-02：节点无法改名

**根因（浏览器实测）**：节点名称输入只绑定 `@change="applyProps"`；真实交互中输入事件与 blur 均到达，但**原生 change 未被触发**，`applyProps` 从未执行——输入框显示新值、模型/画布/保存仍是旧名（保存后重载复现旧名）。其余配置字段因同时绑定 `@blur` 而正常。

**修复**：名称输入补 `@blur` 与 `@keyup.enter` 提交（与其它字段一致）。UAT 实测：改名「分管领导终审」→保存→重载后仍为「分管领导终审」；随后恢复业务名称「分管领导审批」。

**同时清理**：v6 已把 node_2 名称从「分管领导审批（脚本解析）」改为业务名「分管领导审批」，并移除上一轮仅用于计算 `deptSupervisors` 的触发器（计算已内聚到节点脚本）。
