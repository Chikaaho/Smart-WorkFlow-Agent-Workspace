## 1. 目标（一句话）

补齐部门名称与状态的条件查询及树形结果闭环，使部门管理不再只能加载全量树，并关闭 I31、将 M01-F01-04 从部分完成提升为真实可用。

## 2. 产品语义

- 无筛选条件时保持现有部门树行为和稳定排序，不改变已有新增、编辑、删除及部门选择器调用。
- 部门管理页至少支持部门名称关键字与状态筛选；两项条件可以单独使用，也可以组合使用。
- 名称关键字按面向管理员的可理解方式匹配部门名称；空白关键字等同未填写，不能因空格导致异常或错误返回空集。
- 状态筛选必须区分全部、正常、停用，并继续遵循已确认的部门状态契约：`0=正常`、`1=停用`；非法状态不得静默退化为全量查询。
- 筛选后的结果仍以树形结构展示：直接命中节点必须可见，并保留定位该节点所需的祖先路径；未命中的无关分支不应混入结果。
- 空结果显示明确空态，不回退全量树；清除筛选后恢复完整树。
- 查询结果继续遵守租户隔离、逻辑删除和现有可见范围，祖先补全不得借机暴露另一租户、已删除或无权访问的部门。

## 3. 非目标

- 不实现 M01-F01-02 部门拖拽调整层级与排序，不改变部门树的持久化排序规则。
- 不实现 M01-F01-05 负责人/分管领导设置，不新增部门字段或数据库迁移。
- 不修改人员、岗位、角色关联与组合查询；D101 已完成的 user-org-association-query 保持零回归。
- 不新增高级查询语法、拼音检索、全文检索、导出或批量操作。
- 不重构部门 CRUD、租户体系、数据权限引擎或前端通用表格/树组件。
- 不合并 I50、I38-I42、M07 或 IoT/OpenAPI 等其他候选需求。

## 4. 影响范围（模块级）

### 后端

- System 部门查询契约：在现有部门树查询入口补齐名称、状态条件，保持无条件调用兼容。
- System 部门查询层：按条件得到直接命中集合，并在授权范围内补齐必要祖先、构造稳定树形结果。
- Security / 租户 / 逻辑删除：沿用现有约束，不新增旁路，不扩大查询可见范围。
- Flyway：预期零迁移；若执行层发现必须改表，须在回执中报告方向冲突并停止扩大范围。

### 前端

- 部门管理页：增加名称与状态筛选、查询/重置行为、加载与空态展示。
- API 与类型：显式传递筛选条件，状态值与后端 `0/1` 契约一致。
- Mock/夹具：筛选语义、祖先路径、空结果与状态映射须和真实接口一致。

### 规划与知识状态

- M01-F01-02、M01-F01-05 及其他组织管理缺口保持原状态，不得随本轮批量上调。

## 5. 风险方向

1. **树形筛选失真**：只过滤直接命中行可能丢失祖先导致树无法定位；保留整棵命中子树又可能混入无关节点，必须按本方向的“命中节点 + 必要祖先”语义验证。
2. **越权祖先补全**：为构造路径回查祖先时不得绕过租户、逻辑删除或可见范围，尤其不能通过父链泄露不可见部门信息。
3. **状态契约回退**：部门状态曾发生前后端语义反转，必须继续使用 `0=正常/1=停用`，不得套用角色/岗位的相反语义。
4. **调用方兼容**：现有用户管理等部门选择器可能复用同一树接口；新增参数不能改变其无条件调用结果、排序或返回结构。
5. **前后端半闭环**：前端出现筛选控件但后端忽略条件，正是 I31 所代表的交付断裂；验收必须以真实结果集合证明条件生效。

## 6. 验收标准

1. 无条件查询返回与当前兼容的完整部门树，既有部门新增、编辑、删除和部门选择器行为无回归。
2. 名称、状态筛选分别有效且可组合；空白名称、正常/停用、无匹配结果和非法状态均有稳定且明确的行为，非法状态不会返回全量数据。
3. 筛选结果只包含直接命中节点及必要祖先路径，不包含无关分支；父子层级和排序稳定，无重复节点。
4. 祖先补全与筛选结果遵守租户隔离、逻辑删除和现有可见范围；至少用两个租户、已删除部门及受限部门证明不会越界。
5. 前端名称输入、状态选择、查询、重置、加载和空态完整可用；状态值严格为部门契约 `0/1`，Mock 与真实接口一致。
6. 后端项目级全量测试和前端 typecheck/lint/test/build 全绿，测试数量不低于当前基线（后端 563；前端 66 spec / 577 tests），并包含名称、状态、组合条件、祖先路径、空结果、非法状态和隔离边界的专项证据。
7. 预期无 Flyway、无业务表结构变化；D101 的人员关联、组合查询、超管保护及现有数据权限回归通过。
8. 所有编译测试遵守 2G 内存上限与前后端互斥，回执提供实际进程检查、命令、退出码和测试计数证据。
9. 完成 §3.3 第10项知识库全量同步：I31、M01-F01-04、current-status、功能追踪、known-issues、session-handoff 与需求池按全文当前状态核对，并证明无关清单行零漂移。
