# M03 表单数据导入导出需求方向

> 本会话角色：规划（Planner）  
> 方向状态：PASSED（2026-08-29，规划功能级验收通过）  
> 候选编号：P32 / M03-F04-02  
> 立项前已完成功能数：35

## 1. 目标

在现有动态表单数据管理链路中提供可下载模板、可校验导入和按现有查询权限导出的 `.xlsx` 能力，使业务人员能够批量录入与提取指定表单的数据，同时保持字段语义、租户隔离、数据权限和动态宽表安全约束不变。

## 2. 选择原因

1. P32 能直接推进 M03-F04-02 的真实清单空白项，而不是完成项之外的附加增强；
2. 现有表单定义、数据新增、数据查询和文件下载模式可复用，不需要外部账号、硬件或现场环境；
3. 相比 P33 打印模板/PDF，本功能的输入、输出和失败边界更容易形成可判定闭环；
4. 相比 P9 图节点级多 Key 轮询，本功能不触及 Agent 核心执行引擎且能产生清单收益；
5. P19/RAG 仍受 I13 限制，P25/I50 范围过薄，P21 现场联调边界不适合作为当前首选。

## 3. 产品边界裁定

### 3.1 文件与模板契约

- 本轮只支持 `.xlsx`；不接受 CSV、旧版 `.xls`、PDF 或其他文件格式；
- 导入必须以系统针对指定表单生成的模板为入口，模板应同时提供用户可理解的字段名称和不会因普通改名而漂移的字段映射；
- 模板只包含当前表单可录入的有效业务字段，不暴露租户、软删除、审计、物理表名等内部字段；
- 表单定义变化后，旧模板如已不兼容必须被明确拒绝并提示重新下载，不得按相似标题猜测映射；
- Excel 单元格中的用户数据只作为数据处理，不得被执行为公式、脚本或外部链接。

### 3.2 导入语义

- 导入目标必须是用户当前选择且有权操作的单个表单；本轮采用**新增数据**语义，不提供按主键更新、覆盖、合并或 upsert；
- 每行必须经过与现有单条新增一致的必填、类型、长度、选项、关联、租户及业务校验，不得因批量入口绕过现有约束；
- REFERENCE 等关联字段继续遵守“持久化稳定 id、展示业务值”的既有语义，不能把显示文本直接当作不受校验的存储值；复杂字段的文件表达可由执行角色结合现有表单契约确定，但不得改变既有关系原语；
- 文件、模板、表单或任一行存在错误时，必须返回可定位到行和字段的错误；本轮采用**整批原子失败**，不得留下部分成功数据；
- 空文件、错误表单模板、重复或缺失字段映射、不支持的数据类型、越权关联对象以及超过系统明确限制的文件必须在写入前拒绝；
- 导入规模必须有明确、可配置或可维护的上限，超限时直接拒绝，不能依赖内存耗尽或请求超时作为限制机制。

### 3.3 导出语义

- 导出对象是指定表单在当前查询条件、租户边界和数据权限下可见的数据；不得通过导出获得列表/API 中不可见的记录或字段；
- 导出列与当前有效表单字段对应，字段标题面向业务用户；REFERENCE 等字段的业务展示和值身份不得混淆；
- 导出结果应稳定表达空值、日期时间、数值、布尔、选项及当前系统支持的其他字段类型，不得把用户文本转化为可执行公式；
- 无数据时仍应返回结构正确、可打开且只有表头的文件，而不是服务异常；
- 导出大数据量必须采用有界方式，不得无上限一次性加载全部数据导致服务不可用。

### 3.4 管理端体验与权限

- 在现有表单数据管理入口提供模板下载、导入和导出操作，不新增平行的数据管理系统；
- 页面必须清楚展示目标表单、处理状态、成功结果和逐行错误，失败后可再次选择文件重试；
- 前端按钮可见性、真实请求和后端授权必须一致；隐藏按钮不能替代服务端权限校验；
- Mock 模式与真实接口在模板、正常导入导出、格式错误、校验失败和权限拒绝等核心语义上保持一致。

## 4. 本轮必须覆盖

- 指定表单的系统模板下载；
- `.xlsx` 新增式批量导入、整批校验、原子写入与行/字段级错误反馈；
- 按现有查询条件、租户和数据权限导出；
- 现有表单字段验证、REFERENCE 身份语义、软删除和动态宽表 `tenant_id` / `deleted` 安全约束；
- 现有表单数据管理页面中的真实操作入口，以及相应 API、权限和 Mock 行为；
- 文件格式安全、公式注入防护、文件/行数上限和有界资源使用；
- 对现有表单定义、单条新增、查询、编辑、删除、流程发起及关系约束的必要回归保护。

执行角色自行确定实现结构、依赖选型、Step 数量、执行顺序和测试方案；本方向不指定类名、接口路径、库、迁移版本或内部算法。

## 5. 非目标

- 不实现 `.xls`、CSV、PDF、Word 或图片导入导出；
- 不实现数据更新、覆盖、upsert、跨表单迁移、跨租户迁移或通用 ETL；
- 不实现异步任务中心、定时导入导出、邮件发送、云盘同步或导入历史管理；
- 不实现 Excel 在线编辑器、公式计算、宏、图表、样式设计器或任意脚本；
- 不借本轮重构动态表单引擎、动态宽表模型或关系原语；
- 不处理 P33 打印模板、P9 多 Key 轮询、P19/RAG、P25/I50、P21 IoT 剩余边界或其他模块缺口。

## 6. 影响范围（模块级）

- 后端表单模块：表单定义解析、模板生成、文件解析、批量校验、原子写入、查询导出及权限边界；
- 动态数据访问：沿用既有字段白名单、参数绑定、`tenant_id`、`deleted` 与关系约束；
- 前端表单数据管理：模板下载、文件选择、导入反馈、导出触发和权限交互；
- Mock：与真实接口一致的核心成功、校验错误、格式错误和拒绝行为；
- 依赖与工程配置：允许执行角色在工程宪法范围内选择必要的 Excel 处理能力，但不得扩展为通用文档平台；
- 收尾材料：P32、M03-F04-02、正式功能状态、清单、需求池、知识状态和交接摘要。

## 7. 风险方向

1. **动态 SQL 越界**：导入导出不能绕过字段白名单、参数绑定、租户和软删除条件；
2. **部分写入**：中途失败留下部分数据会使重试产生重复或脏数据，必须保持整批原子性；
3. **字段漂移**：按标题猜字段会在表单改名后写错列，模板需要稳定映射和兼容性检查；
4. **权限泄露**：导出若绕过当前查询与数据权限，会形成批量泄露通道；
5. **资源耗尽**：无界解析或导出会放大为内存与响应时延风险，必须有明确上限和有界处理；
6. **文件内容注入**：用户数据不能在生成或打开 Excel 时成为公式、脚本或外部链接；
7. **字段语义失真**：日期、数值、选项和 REFERENCE 等字段的显示值、输入值与持久化值必须保持既有契约。

## 8. 规划验收边界

规划层只在完成回执提供真实行为证据后逐项验收：

1. 有权用户能针对指定表单下载结构正确的 `.xlsx` 模板；模板不暴露内部字段，失效模板被明确拒绝；
2. 合法文件可一次导入多行新增数据，落库结果与现有单条新增的字段校验和持久化语义一致；
3. 必填、类型、长度、选项、关联或模板错误能精确定位到行和字段，并且整批零写入、重试无脏数据；
4. 导入不能更新既有记录、跨租户写入、引用越权对象或绕过动态宽表安全约束；
5. 导出只包含当前租户、当前权限和当前查询条件可见的数据及允许字段，越权身份无法获得文件；
6. 空结果能导出合法表头文件；常见字段类型和 REFERENCE 的展示/身份语义在导入、存储、查询和导出间一致；
7. 公式式文本、异常文件、错误格式和超限文件被安全处理，不执行公式/脚本，也不以资源耗尽作为失败方式；
8. 文件与行数上限、导入原子性和大数据量有界处理有可复现行为证据；
9. 前端普通用户、获授权用户和未登录用户的按钮、请求、最终页面/反馈及后端拒绝行为一致；
10. Mock 与真实后端在模板、正常导入导出、校验失败、格式错误和权限拒绝上的核心语义一致；
11. 现有表单单条新增、查询、编辑、删除、流程发起及关系约束没有回归，前后端质量门具有可复现结果；
12. 功能收尾只核销 P32、推进 M03-F04-02；已完成功能数在功能验收前保持 35，阶段三目标值必须由规划另行下发并完整同步知识、清单、需求池和交接材料。

实现说明、文件名、测试类名、源码扫描或执行层自述不能单独构成通过依据；上述标准必须由实际命令输出、请求/响应、持久化结果、页面交互或等价真实行为证据支撑。

## 9. 待确认问题

当前没有阻塞实施的产品问题。若执行探索发现现有表单数据契约无法保证整批原子写入、复杂字段无法在 `.xlsx` 中保持既有语义，或当前权限模型无法表达导入与导出操作，必须在回执中报告方向级冲突，由规划角色裁决；执行角色不得自行降级为部分写入、绕过复杂字段、扩大权限或改造为通用 ETL。
