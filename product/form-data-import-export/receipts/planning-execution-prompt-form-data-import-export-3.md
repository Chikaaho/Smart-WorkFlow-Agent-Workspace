# P32 表单数据导入导出三级零裁量提示

> 日期：2026-08-29  
> 唯一目标：核销 S1—S4  
> 相对上一版新增/收紧约束：删除 L1—L15 全部已通过内容；剩余压缩为四个独立证据包；每包增加正向目标断言、反向零残留断言及“全部为是才允许提交”门禁

## 1. 唯一权威输入

仅使用正式方向、`planning-rereview-v3-20260829.md`、本提示、当前终态机器契约和公共 Validator。禁止引用 v1—v6 中 L1—L15 的内容作为新证据，禁止重新运行或展开这些锁定场景。

## 2. 允许范围

只允许读取/修改：P32 TABLE 导入导出实现与测试、查询筛选导出实现与测试、P32 Mock 身份/权限行为与测试、表单控制器编辑回归测试、阻塞当前后端全量门的 Flyway 全链契约/迁移前置，以及本功能新增执行/测试回执。禁止修改正式方向、memory、knowledge、需求池、清单和其他无关业务。

若后端全量门的 Flyway 阻塞无法在上述范围内安全修复，S4 必须提交 `BLOCKED`；不得把失败门禁解释为通过。

## 3. S1 独立证据包：TABLE 父子表往返

### 固定输入

- 一个已发布表单，主表至少包含 `name`，TABLE 字段至少包含两个子字段；
- `.xlsx` 主 sheet 两条父记录，TABLE 子 sheet 至少三条子记录，并通过稳定父行标识分别关联两条父记录；
- 一个非法子行文件（缺必填或类型错误）。

### 必须动作与原始输出

1. 合法文件导入；报告响应、主表两行 id、每个父 id 对应子表行数和逐字段值；
2. 查询两条父记录；报告 TABLE 字段的父子归属；
3. 导出并解析主 sheet/子 sheet；报告父行标识、子行数量和值；
4. 非法子行整批导入；报告行/字段错误和导入前后主表、子表计数。

### 正向目标断言

- 两条父记录及三条子记录正确落库，子行不串父；导出后结构和值可还原同一父子关系。

### 反向零残留断言

- 不得丢 TABLE 列、不得只导主表、不得把全部子行挂到同一父行；非法子行时主表和子表均零新增。

## 4. S2 独立证据包：查询筛选导出

### 固定输入

- 同一授权身份可见至少四条记录，其中至少两条匹配一个明确筛选条件、两条不匹配。

### 必须动作与原始输出

- 使用页面/API 当前真实查询参数执行列表查询和导出；记录完整筛选请求、列表返回 id、解析后导出文件 id/业务唯一值。

### 正向目标断言

- 列表与导出恰好包含同一组两条匹配记录。

### 反向零残留断言

- 导出文件不得出现两条不匹配记录，不得忽略筛选后退化为权限范围内全量导出。

## 5. S3 独立证据包：Mock 权限一致

### 固定输入

- Mock 环境的未登录身份、无 P32 权限普通登录身份、有 P32 权限身份；同一模板或导出请求。

### 必须动作与原始输出

- 分别执行请求，逐字段记录 HTTP 状态、业务码、响应结构和页面反馈；与已锁定真实后端 401/403/200 口径逐项对照。

### 正向目标断言

- Mock 未登录=401、普通无权限=403、授权=成功，字段和页面反馈与真实模式同义。

### 反向零残留断言

- 不得出现 Mock 无身份维度、所有身份都成功、只隐藏按钮但请求成功、或用 URL 一致代替权限行为。

## 6. S4 独立证据包：成功编辑与后端全量门

### 固定输入

- v5 已修改路由下的一条现有表单记录，包含满足必填约束的合法更新数据；
- 当前完整后端 checkout，包括实际 V42/V43 迁移链。

### 必须动作与原始输出

1. 对现有记录执行 PUT 成功编辑；报告请求、响应、更新前后逐字段值，确认 id 不变；
2. 运行编译互斥检测；
3. 后端根目录执行且只执行一次最终门：`MAVEN_OPTS="-Xmx2g" mvn test`；
4. 报告退出码、Tests/Failures/Errors/Skipped 精确总计和各模块最终状态；
5. 单独追加测试回执，包含 S1—S4 新增测试的可定位名称、实际计数与结果；
6. 回执末行使用规划验收前合法执行状态并通过 Validator。

### 正向目标断言

- PUT 返回成功且数据更新；后端根测试退出码 0、Failures=0、Errors=0；独立测试回执存在；Validator 退出码 0。

### 反向零残留断言

- 不得以“命中控制器后业务报错”代表编辑成功；不得排除失败模块、做移除迁移的对照实验后宣称全量门通过；不得把 Failures/Errors 归类为无关后提交完成态。

## 7. 固定执行顺序

1. 只实现/验证 S1；通过后锁定本地结果；
2. 只实现/验证 S2；
3. 只实现/验证 S3；
4. 修复 S4 阻塞并验证 PUT；
5. 执行互斥检测与一次后端根全量门；
6. 写一份新的执行回执和一份新的测试回执；
7. 对执行回执末行运行公共 Validator。

禁止重跑前端 typecheck/lint/test/build；这些已在 L14 锁定。除 S1—S4 外不得增加测试范围或业务范围。
