## 1. 目标

三个流程的关键流转都要由**审批意见**驱动：前一个节点审批人在意见表单里填写的结论、选人、数值，经**流程变量**（必要时经**脚本**计算）决定后续走哪条分支、由谁处理。

## 2. 每个流程的必做设计

节点名称和选项可以按业务调整，但每个流程都要满足下表的“驱动关系”。

### A 跨部门灾备演练审批

| 节点 | 审批意见表单（新增） | 驱动关系 |
|---|---|---|
| 申请单位负责人审核 | 方案完备性（完备/需补充）、**现场总指挥**（人员）、回退方案可行性说明（多行，必填） | “需补充”退回申请人；“现场总指挥”成为后续“现场指挥确认”节点的处理人 |
| 技术委员会会签 | **风险评级**（低/中/高）、影响系统清单（多选）、预计停机时长（分钟）、技术意见（多行，必填） | 任一委员评“高”时，增加“安全合规部复核”节点；脚本汇总会签人的最高风险等级和最长停机时长，写入流程变量 |
| 总公司科技部会签 | 执行决定（按计划执行/调整窗口/否决）、**调整后的演练时间**（日期时间）、附加条件（多行） | “调整窗口”时，定时 MQTT 预约使用意见中的新时间，不再使用申请表单里的时间；“否决”时直接结束并通知申请人 |
| 现场指挥确认（新增） | 演练准备就绪（是/否）、现场人员到位情况 | 处理人 = A 中的“现场总指挥”变量 |

脚本：用技术委员会的停机时长和影响系统数计算 `drillImpactLevel`。停机时长超过 240 分钟或影响系统数 ≥ 5 时，总公司会签前先增加“分管副总审批”。

### B 校园出入口流量异常处置

| 节点 | 审批意见表单（新增） | 驱动关系 |
|---|---|---|
| 安保值班负责人复核 | **事实核实结论**（属实/误报/部分属实）、**现场处置人**（人员）、到场核实时间、现场情况描述（多行，必填） | “误报”：记录原因后结束，不进入 P0/P1；“现场处置人”成为“现场处置”节点的处理人 |
| 现场处置（新增） | 处置措施（多选：疏导/封闭通道/增派安保/联系主办方）、处置完成时间、遗留风险 | — |
| P0 应急响应 | **是否上报**（无需上报/上报学校/联动属地派出所）、上报对象、处置结论 | “上报学校”“联动属地派出所”分别进入对应的上报或知会节点 |

脚本：按到场核实时间和工单 `responseDueAt` 计算是否超时，结果写入 `responseOverdue`；超时时增加“保卫处处长督办”节点。

### C MES 设备温度研判

| 节点 | 审批意见表单（新增） | 驱动关系 |
|---|---|---|
| 班组长现场确认 | **现场实测温度**（℃）、**原因分类**（设备故障/工艺参数/传感器漂移/环境因素）、是否已停机、**指派维修人**（人员） | 原因分类分别走“设备维修”“工艺调整”“仪表校准”；维修类节点的处理人 = “指派维修人” |
| 设备维修 / 仪表校准 | 处理措施、更换备件、处理后温度（℃） | — |
| 复产审批（新增） | 是否同意复产、复产条件 | 只在“已停机 = 是”时出现 |

脚本：比较现场实测温度和 Agent 研判时的读数；偏差超过 3℃ 时写入 `sensorSuspect = true`，并强制进入“仪表校准”分支（即使原因选的是其他项）。

## 3. 意见内容的质量

- 每个意见表单 3—6 个字段，结论项使用字典下拉，必填项配置校验。不能只有一个“备注”。
- 测试实例中填写的意见要像真实审批人写的：带具体事实、数值和条件，例如“同意。回退脚本已在 11 月 3 日预演通过，建议把切换窗口从 22:00 改到 23:30，避开批量结息。”不得只写“同意”“通过”“ok”。
- 详情页和流转记录中要能看到每条意见的全部字段（中文标签和字典中文值）。

## 4. 执行路线

1. **能力核对**（本地）：分别确认平台是否支持以下能力——(a) 意见表单字段写入流程变量；(b) 条件分支引用意见变量；(c) 参与人按变量或意见中的人员字段解析；(d) 脚本节点或表达式计算变量；(e) 定时预约时间取自变量。不支持的项直接在 `feature/0.3.1-approval-driven-flow` 分支上开发，补测试。
2. **本地配置并跑通**：§2 中的每一条驱动关系至少用一个实例覆盖到（包括退回、误报、否决、高风险加签、超时督办、传感器偏差强制校准）。
3. **发版 0.3.1**（仅在有代码改动时）：门禁 → develop → main → 版本 0.3.1 → tag/Release → 部署 UAT → 回读 build.version。
4. **UAT**：导入或更新配置，发布流程；每个流程至少跑两条不同的意见驱动路径，用 headed 浏览器截取意见填写页、详情页的流转记录和流程图。
5. **导出应用包**覆盖 `assets/`；包中缺少的配置（Agent 图、IoT 规则、脚本，如有）在回执中说明。
