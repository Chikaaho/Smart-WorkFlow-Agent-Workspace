# 运营与风险管理工作台配置包

文件：[operations-risk-workbench.appbundle.json](operations-risk-workbench.appbundle.json) 是平台应用整包导出（预览 → 确认导入两步），来源为本地 0.3.0 验证环境通过平台导出功能生成的包。

| 流程 | 表单字段数 | 节点数 | 配置重点 |
|---|---:|---:|---|
| 跨部门灾备演练计划审批 | 25 | 7 | 演练范围、时间窗口与恢复目标；申请单位负责人审核 → 技术委员会会签 → 参与部门分管领导动态并行（按表单多选部门解析）→ 总公司科技部会签 → 按表单知会领导；审批通过后按计划开始时间预约 MQTT 指令 |
| 校园出入口异常事件分级处置 | 20 | 7 | 入离校流量与基线、校内活动与联网检索摘要；活动关联（SPECIAL）转 P1、无法解释（NO_EXPLANATION）转 P0 并知会应急负责人 |
| MES 设备温度偏离研判与安全处置 | 23 | 6 | 75/80/85℃ 阈值、升温速率与研判窗口；停机阈值、快速升温、正常波动三条分支分别进入紧急处置、异常工单、记录复核 |

包内包含业务字典（演练类型、风险等级、校园出入口、事件处置级别）。

导入与启用说明：

- 导入后表单与流程均为草稿，需要在应用内逐项发布才会出现在流程中心；流程编号规则随包保留（`YJ-`／`XY-`／`MES-` + 日期 + 序号）。
- 流程审批人按**角色编码**解析（`drill_reviewer`、`drill_tech_committee`、`drill_hq_signoff`、`campus_duty_officer`、`campus_emergency_lead`、`mes_emergency_lead`、`mes_shift_supervisor`、`mes_process_engineer`）。导入前目标租户须存在这些角色且**已有启用成员**，否则导入会把未匹配的角色编码置空并记入导入报告。
- 灾备流程的设备动作（`deliveryMode=RESERVATION`）不随包携带目标设备：导入后需在流程定义处重新绑定本环境设备（本地验证环境设备 `drill-room-hq-a`）。
- 包内不含供应商密钥、外部搜索配置、知识库文档、IoT 产品/设备/规则与通知渠道凭据；这些按环境在页面配置。
