# P61 用户可见提示语治理范围纠偏

> 角色：规划（Planner）  
> 日期：2026-09-20  
> 状态：`IN_PROGRESS`  
> 当前等级：L  
> 权威关系：本文件是 P61 当前范围修订；与原方向冲突时以本文件为准，原方向仅保留历史与已完成事实。

## 1. 当前裁决

Owner 明确 P61 的主要目标是调整用户可见提示语。P61 从 2026-09-20 起按以下边界继续：系统性收口现有错误提示、页面提示和恢复指引，使其自然、准确、可行动，并保持必要的安全防泄漏和既有机器契约兼容。

既有执行已经完成的 `errorKey`、双语目录、诊断引用、错误分类等安全且有益的实现不回退；但不再把继续扩建这些基础设施、补齐全站双语平台或证明所有架构能力作为 P61 关闭条件。当前剩余工作跨 Server/Web，仍按 L 级跟踪，不再按核心架构演进的 XL 范围推进。

## 2. 当前目标

1. 生产可达的用户提示使用自然、简洁、符合软件产品习惯的表达。
2. 提示优先说明“发生了什么”和“下一步怎么办”；不同原因不被无条件折叠为同一句空泛失败。
3. 用户层不显示堆栈、SQL/JDBC、类名、字段内部名、租户标识、文件路径、Provider 原文或其他诊断细节。
4. 文案调整不改变业务结果、认证顺序、权限、租户隔离、流程状态和既有机器码兼容性。
5. 中文为主要治理对象；产品当前实际展示的英文一并修正自然度，但不要求借本任务建设或补齐完整国际化平台。

## 3. 当前非目标

- 不新增或重构全局错误码体系、诊断平台、事件追踪平台或客服工单能力。
- 不要求所有模块、所有页面和所有状态建立成对中英文视觉样本。
- 不因文案治理重做批量业务模型、导入事务模型、权限模型或接口数据结构。
- 不验收颜色、组件布局、响应式排版、移动端画布、页面覆盖率或像素还原；这些属于 P53。
- 不以进程 manifest、全量网络索引、全仓逐文件排除清单或穷举截图作为提示语质量的独立通过门槛。
- 不重验 Owner 已延期的真实 Provider 成功链。

## 4. 当前验收标准

1. 当前生产用户提示清单中的不自然、自造、内部实现化、无行动指引和上下文错误文案已关闭；排除项只需说明其不是用户可见提示。
2. 登录/认证、统一异常兜底、表单或流程、通知或外部集成至少各有一个代表性真实行为，最终提示与触发原因匹配且给出合理下一步。
3. 对 SQL/JDBC、堆栈、内部类/字段、租户标识、Provider 原文等高风险来源，公共响应和普通用户可见面保持零外露；既有锁定证据未被相关修改影响时可直接沿用。
4. 文案变化前后的 HTTP/机器错误契约、权限结果、认证防枚举和业务状态保持兼容；不要求为了文案新增机器字段。
5. 聚焦静态检查与代表性真实 HTTP/可见浏览器证据相互支持；不要求全站截图或 P53 视觉验收。
6. 只运行实际受影响的工程检查；既有 Server 1422/0/0/0、Web 1212 passed + 3 skipped 基线在相关路径未变化时继续锁定。

## 5. 与 P53 的并行边界

P53 继续作为 P0 主任务，负责颜色、布局、组件和响应式；P61 作为 P1 并行恢复项，只处理文案及必要的安全净化。两者不得在同一未隔离工作树并发修改同一文件。P61 若触及 P53 同期修改的页面文件，最终应基于 P53 最新集成结果复核该页面的提示语，不重做 P53 视觉验收。

## 6. 状态边界

P61 保持 `IN_PROGRESS`。Executor 完成当前六项标准后提交一次正式 completion receipt；不得自行写 `PASSED/COMPLETED`、核销 P61、晋级正式基线或移动方向文件。
