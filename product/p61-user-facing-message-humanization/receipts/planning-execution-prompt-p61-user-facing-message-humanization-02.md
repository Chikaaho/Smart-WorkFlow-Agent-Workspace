## 4. 对象、快照与生命周期

- R2b/R3/R4/R7/R8c 使用同一最终 Server/Web manifest；证据必须记录工作树指纹，不能只写当前 HEAD。
- R4b-E 固定一个失败请求和完全相同的 eventRef；旧 `req-b203...` 响应与 `req-60ee...` 日志不拼接。
- R2c 每类固定一个批次/任务集合；计数、详情、页面和持久化回读必须指向相同对象。
- R3 固定同一表单版本、label/key 和权限身份。
- R7 固定 1280×720 主视口；移动 H5另记录实际移动视口。每对证据记录 identity、tenant、object、locale、URL、network index、screenshot、probe、timestamp、headless=false。
- 已销毁的 H2 对象允许新建，必须登记新旧 ID；不要求恢复旧内存库，也不得把新对象写成旧对象。
- 场景开始前建立采集点；验证结束后执行限定本轮对象的清理并回读。纯内存环境记录 JDBC 标识、进程退出和端口无监听即可。

## 6. 相对提示 01 的新增与收紧

- **删除了什么**：删除 R1、R2a、R5、R6a、R8a、迁移分类和已锁定单测/API层的重复实现要求；不再接收对历史阶段的重复复述。
- **原子化了什么**：把批量三类、诊断来源与受众、事件引用、浏览器覆盖/配对/快照、最终盘点/身份/回执拆成独立可判定项。
- **替代路径是什么**：从“结构扫描 + 单测 + 少量 DOM 探针”改为“固定对象真实行为 + 同时点视觉/网络配对 + 工作树/产物 manifest”；通知用受控结果链，不依赖真实 Provider。
- **提交条件如何判定**：每个子项都有正反结果；视觉制品不含键名/404/空白；最终证据全部关联同一 manifest；十八项回执无部分完成且 remaining_actionable_count=0。

## 7. 原始输出字段与证据包

每个原子项在回执正文只写：

`原子ID → 原始文件/位置 → 实际结果 → 边界`

原始附件必须保留：

- HTTP：method、URL、身份代号、tenant/object/batch ID、locale、status、body、eventRef、timestamp。
- 浏览器：headless=false、session、URL、viewport、identity、tenant、object、locale、htmlLang、localStorage、DOM 关键文本、CJK/英文句/key-name 扫描、overflow、network index、screenshot、timestamp。
- 诊断：同一 eventRef、授权载体位置、A/B 结果、脱敏与零泄漏断言。
- 快照：Server/Web 工作树指纹、diff/未跟踪文件清单哈希、产物哈希、服务 PID/启动时间、证据采集时间。
- 门禁：工作目录、完整命令、stdout/stderr、退出码、报告聚合；静默输出可为 0 字节但退出码不可缺。
- 清单/哈希：工具生成后实际回读校验；校验文件排除自身。
