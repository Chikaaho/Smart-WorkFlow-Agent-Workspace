## 1. 真实响应（HTTP 层，同一批次 3 行 = 2 有效 + 1 无效）

```json
{ "code": 0, "data": { "totalRows": 3, "successCount": 0, "errorCount": 1,
  "errors": [{ "rowNum": 4, "message": "字段「月薪」需要数字，当前填写的内容不是数字" }],
  "processing": 0 } }
```

- 回读：导入前后记录总数 `0 → 0`（整批回滚，零落库）。
- 逐项失败明细**安全且可定位**：行号 + 字段显示名「月薪」（R3 修复链生效的直接受益者），
  无异常原文、无内部 key。
- `processing` 由服务端同步契约显式给出（本轮已补 `ImportResult.processing=0`，
  Web `FormData.vue` 改为消费该值，不再前端臆算）。
- 四项计数勾稽：total=3 = success 0 + failed/errorCount 1 + 连带回滚行 2（Web 面板
  `importRolledBack` 明确把「失败 1、连带回滚 2」讲清楚，不用「失败 3」冒充）。

## 2. 结构性冲突（需要规划裁决，执行侧不自作主张改产品契约）

二级执行提示 R2c-I 完成条件要求「**同一导入批次至少一项成功、一项失败**」。
服务端 `FormImportExportService.importData` 是**有意设计**的整批原子契约
（代码注释与 doc 明示：「任一行失败则全部回滚，零落库」；`status.setRollbackOnly()`）：

- 混合批次的真实结果只能是 `successCount=0 + errorCount=逐行明细`，**不可能出现 1 成 1 败**；
- 该契约与表单数据「导入=新增」语义、防半批脏数据的产品决策一致；
- 二者只能取其一：改产品契约（分批提交/部分落库）或改完成条件的表述
  （以「混合批次的四项计数勾稽 + 连带回滚明示 + 逐项安全下钻」为验收口径）。

本轮按后者采证：**除「1 成 1 败」外，R2c-I 其余断言（四项计数、安全逐项失败、
回读一致、处理中显式、页面计数与结果一致）全部闭环**。

## 3. 采证过程中发现的其他事实（如实登记，不扩权处理）

- 表单定义里 TEXT 字段声明的 `length`（如 60）在**提交/导入链路均不校验**：
  100 字符 dept 单条提交与导入均成功（物理列宽按类型建表，未按声明值限长）。
  属表单校验产品缺陷，非 P61 错误文案范围，登记移交，不在本轮擅自改动。
