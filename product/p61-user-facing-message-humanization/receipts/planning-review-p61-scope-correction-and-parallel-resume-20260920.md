## 1. 复盘结论

P61 的原始诉求并非只改两三个词：它明确要求对全系统可达提示做一致性、可行动性和安全披露治理。因此，真实存在的 SQL/堆栈/Provider 原文外露、错误键直接显示、失败态被空态替代、认证提示防枚举等问题，属于合理范围。

但后续正式方向把完整 zh-CN/en-US 平台、全局 `errorKey` 契约、事件引用诊断链、批量结果模型、全站页面与移动视觉覆盖同时设为 P61 的完成条件，范围确有扩大。验收还把 P53 类型的布局遮挡、移动视口和页面视觉覆盖纳入 P61，导致“提示语治理”被架构建设、证据工程和 UI 验收共同绑住。

## 2. 为什么连续未通过

1. 第一次阶段回执时仍有真实产品缺口：硬编码与键值外显、失败反馈不完整、敏感诊断外露等尚未收口。
2. 方向升级为 XL 后形成十八项验收，执行同时改错误契约、国际化、诊断、安全净化、批量结果和页面表现，验证面随之急剧扩大。
3. 后两次失败的主要差异已转为最终进程身份不一致、附件格式错误、截图缺元数据、全量盘点不可复算等证据问题，而不是提示语本身。
4. 规划侧至少有一项已确认的错误口径：要求同一导入批次同时成功和失败，与既有整批原子回滚冲突；验收04已撤回，该项不计为执行失败。
5. 顶栏挤压、移动画布和页面布局属于 P53；继续用这些项目阻塞 P61 属于范围混入。

所以，连续失败并不等于实现一直没有进展，也不代表所有打回都错误；它反映出前期真实问题与后期范围/证据门槛膨胀叠加。
