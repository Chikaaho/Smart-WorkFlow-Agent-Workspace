# P13 / I26：SysRole 与 V5 数据库列契约对齐

## 当前状态

**PASSED** — 执行层已完成自验收，规划层于 2026-08-17 对照六项验收方向最终验收通过。

## 功能目标

以 V5 迁移完成后的 `sys_role` 表结构为唯一数据库契约，消除 SysRole 持久化映射与测试数据库口径的旧列残留，使完整迁移环境中的角色读取及登录角色装配不再因列不存在而失败。

## 规划裁定

1. V5 在 H2、PostgreSQL 两方言中均已将 `is_builtin` 收敛为 `built_in`、将 `description` 收敛为 `remark`，且后续迁移未恢复旧列；执行结果应遵循该链尾契约。
2. 本轮采用“应用映射与测试口径对齐现有数据库契约”的方向，不通过新增兼容迁移重新创建旧列。不得反转 V5 已完成的类型和命名收敛。
3. P13 可独立完成，不与 P10（BPM/H2 V8 partial index）或 P12（sw-bootstrap 迁移测试基建）合并。P10/P12 只限制 H2 真全链迁移验证，不构成本轮修正 SysRole 契约的实现前置。

## 非目标

- 不修复 P10，不修改 BPM V8 partial index。
- 不建设 P12 所述 sw-bootstrap 永久迁移测试基建。
- 不新增、恢复或回填 `is_builtin`、`description` 旧列，不追加反向兼容迁移。
- 不改变角色业务语义、权限模型、数据权限五档规则、角色菜单/部门关联关系或对外接口字段语义。
- 不修改前端。
- 不顺带处理 P24、P25 或其他系统管理缺口。

## 影响范围

- **后端 system 角色持久化边界**：SysRole 与 MyBatis-Plus 的数据库列映射。
- **后端相关测试口径**：触达 `sys_role` 的测试建表结构、夹具及其契约说明，需与 V5 链尾结构一致。
- **功能消费路径**：角色列表、详情、按 code 查询以及登录过程中的角色装配；新增、修改路径不得继续生成旧列 SQL。
- **知识与状态同步**：完成后核销 I26/P13，并按工作区宪法 §3.3 第10项同步完整知识库、功能清单和压缩记忆所需材料。

## 验收方向

最终完成回执必须提供足够证据证明以下条件同时成立：

1. 后端对 `sys_role` 的持久化 SQL 不再引用 `is_builtin` 或 `description`，并正确使用 V5 链尾的 `built_in` 与 `remark`。
2. 所有触达 `sys_role` 的测试数据库结构不再以旧列模拟生产契约，相关注释或夹具不存在“按旧实体映射建表”的失真口径。
3. 角色列表、详情/按 code 查询、登录角色装配，以及包含相关字段的新增/修改行为均有可核验的通过证据。
4. 后端受影响模块测试与项目级回归通过，既有角色、认证及数据权限能力无回归；编译/测试遵守 2G 内存上限。

## 风险方向

- **测试先红风险**：应用映射纠正后，仍使用旧列的自建测试 DDL 会立即失配；执行角色需确保测试契约整体同步，而非只改生产映射。
- **字段类型风险**：`built_in` 的数据库类型已由 smallint 收敛为 boolean，不能仅机械改名后继续依赖旧类型假设。
- **验证边界风险**：H2 真全链目前会先受 P10 阻断。不得将“无法完成 H2 全链验证”误判为 P13 未修复，也不得据此宣称 P10/P12 已被覆盖；应在回执中如实分离本轮证据与外部阻塞。
- **范围蔓延风险**：角色授权关联表及 `data_scope` 本身没有本次列名失配，不应借机重构。
