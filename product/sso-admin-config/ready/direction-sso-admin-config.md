## 一、目标与准入规则

本系统为B端：用户须先存在于当前租户组织架构，SSO只识别并绑定已有用户，不开通新用户。默认覆盖钉钉与飞书，个人/企业身份模式都不能绕过本地用户准入。

一次登录按下列业务顺序：
1. 完成厂商授权换票，取得可信稳定外部主体和厂商服务端返回的手机号；企业成员模式同时校验允许企业标识。手机号必须来自当前已认证主体的厂商可信接口，不能信任回调自带手机号、前端输入或可编辑个人资料的自报值。
2. 在服务端确定的当前租户内，按规范化可信手机号查已有SSO绑定用户；命中唯一有效记录且Provider/应用/外部主体一致，重新装载本地用户、组织资格、租户状态和权限后登录。稳定主体与既有手机号绑定冲突时拒绝，禁止仅凭手机号覆盖外部身份。
3. 无SSO绑定时，在当前租户组织架构查相同手机号的已存在有效用户；只有唯一匹配、用户与所属组织有效且不与既有外部绑定冲突，才安全建立绑定并签发既有本地会话。
4. 无用户、重复手机号、账号/租户失效、缺可信手机号或冲突均拒绝，不自动创建用户、不跨租户搜索、不默认绑定管理员。对外统一安全提示“暂时无法使用第三方登录，请联系管理员核对账号信息”，内部审计记录必要的脱敏原因。

已有绑定也必须经过当前本地用户有效性检查；本地或厂商手机号改变、手机号回收、外部主体变化不自动迁移绑定或合并账号，应拒绝并由管理员核对。手机号格式按国家区号规范化，不能只截后11位；现有重复数据不批量合并删除。绑定并发保持唯一性与原子性。既有绑定兼容方案必须保留历史身份与审计，不用旧候选手动绑定页面绕过本规则。

手机号权限属于本次登录必要权限，可沿用Owner控制台必要配置授权核实开通。手机号字段可用性、是否具有验证语义、厂商当前权限/审批条件必须查官方契约与真实返回；拿不到可信手机号时fail closed，精确报告输入缺口，继续独立管理页面工作。前期“基础身份零权限可登录”的结论不代表手机号权限已满足。

## 二、后台配置能力

在既有后台管理体系提供租户级SSO配置列表、详情、新增/编辑、启停、应用凭据更新、配置检查、审计查询。展示平台、应用标识、身份模式、允许企业标识、启用状态、凭据是否已配置、服务端推导的只读回调地址、更新时间。现有系统视觉、表单、国际化、菜单与权限机制复用。

个人/企业成员模式显式选择；企业模式必须填允许企业标识，个人模式仍须本地手机号白名单准入。企业微信可保留已有配置记录只读标注延期，本期不提供其新增启用入口。

secret只写：响应和页面不回显原文/密文，留空保留旧值；掩码不得被当成新secret写回。新增和显式更新校验真实非占位输入。用户界面的“更新应用密钥”与系统加密主密钥轮换分开，本期不提供主密钥轮换按钮。

明确SSO加密器依赖绑定及密钥来源，避免被agent bean注册顺序隐式替代；兼容已有密文，不能更换全局密钥致其他模块不可读。需要迁移时采用可回退兼容方案并单独给出受影响数据范围，禁止盲目重加密生产数据。

配置检查只验证配置完整性、解密与必要格式/可达条件，不自动宣称真实登录通过或静默发起用户授权。错误信息与审计不泄密。

## 三、权限、生效和审计

配置查看、编辑、启停、应用secret更新、审计查询分别受服务端权限控制；租户来自认证上下文，客户端不能覆盖。普通用户不可见后台入口且构造请求被拒；具备某项权限不默认拥有其他项，秘密更新不隐式混在普通编辑权限中。

保存后对后续授权生效；停用Provider后拒绝新授权及在途回调/未兑换票据的新会话签发。修改appId、身份模式、企业标识或应用secret时，旧配置发起且未完成的授权安全失败并可重新发起，不串用新旧配置。既有已签发本地会话按现有本地撤销规则管理，配置停用不冒称已全员登出；UI明确该边界。配置检查不得修改配置或绑定。

记录保存、启停、凭据更新、校验失败、手机号准入拒绝和绑定/登录结果的最小审计；包含操作者、租户、平台、时间、脱敏原因，不含secret/token/原始手机号或完整厂商响应。敏感字段访问最小化。
