## 1. E2：子执行详情——缺陷确认、修复与两种方式截图

### 缺陷确认（审查记录的猜想成立）

`ExecutionDetail.vue` 只在 `onMounted` 加载；父行轨迹里「查看子执行」是 `router.push('/agent/executions/detail/' + id)`——同路由仅换参数，组件被复用、`onMounted` 不再触发。第 2 轮两张截图同 sha1 且画面停在父行轨迹，正是这个机制：地址栏换成子行编号，内容仍是父执行。

### 修复（Web `bb32650`）

`ExecutionDetail.vue` 增加 `watch(executionId, …)`：参数变化时复用挂载时的同一套入参校验并调 `loadDetail()`（其开头会重置 detail/nodes/humanTasks/lifecycleState/error，不会串数据）。新增用例 `113-E2: 父行跳子行（同路由仅换参数）后内容重新加载`：先渲染父执行，改路由参数后断言按新编号重新请求、画面换为子执行内容、父内容消失。测试桩方面：`vue-router` mock 的 `params` 改走 `reactive` 代理（Vue 对同一 target 缓存同一代理，既有用例只读值不受影响），API 桩按入参分派而非 `mockResolvedValueOnce` 队列——本文件用例不卸载组件，前序实例仍在 watch 共享路由，Once 队列会被旧实例抢先消费。

Web 四项门禁重跑全绿：typecheck 0 错、lint 0 错 0 警、test **2122 通过 +3 跳过**（+1 即本用例）、build 通过。
