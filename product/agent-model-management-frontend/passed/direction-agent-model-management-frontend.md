## 1. 目标（一句话）

为既有大模型配置后端能力补齐可达、可授权、可验证的前端管理闭环，使管理员能够通过页面完成模型接入、参数配置、密钥维护、多 Key 状态查看和连通性测试，并在全部五项真实满足后核销 P5。

## 2. 产品语义

- 在「智能体」管理域提供明确可达的大模型管理入口；有权用户可以从菜单进入，刷新和直接访问路由行为一致。
- 列表支持分页和名称关键字查询，并清楚展示名称、协议、模型、启停状态及多 Key 调度相关状态；不得把密文或明文 API Key 放入列表、URL、日志或前端持久化。
- 新增和编辑覆盖既有契约字段：名称、协议类型、API 地址、模型名称、API Key、`temperature`、`maxTokens`、`topP`、超时、重试、启停、备注，以及已有多 Key 分组、排序、额度冷却配置。
- 协议类型遵循既有 `openai` / `ollama` / `other` 契约。参数的必填、范围、默认值和协议差异应在界面上可理解，不能提交前端自创的枚举值或字段。
- API Key 查询只展示后端返回的脱敏值；编辑时不填写新 Key 必须保持旧密钥，填写新 Key 才表示替换。前端不得尝试还原、缓存或回显明文。
- 支持新增、查看/编辑、删除、启停配置和按单条配置发起连通性测试；测试结果至少呈现成功/失败、后端消息与耗时，不把 4xx 可达语义擅自改判为网络失败。
- `lockedUntil` 等系统运行态只读展示，不允许用户伪造写入；动态装载沿用后端“配置变更后下次调用即时生效”的既有语义，不引入虚假的加载/卸载按钮。
- Mock 模式与真实接口在列表、保存、删除、脱敏、空 Key 保留、权限和连通性结果结构上保持一致。

## 3. 非目标

- 不修改模型 CRUD、加密存储、动态 `ChatModel` 构造、多 Key 轮询、额度锁定或连通性探测的后端业务语义。
- 不新增显式加载/卸载 API；现有按请求读取配置、即时生效的动态装载语义保持不变。
- 不纳入 M07-F02 Prompt 配置、运行日志页、单步调试，亦不纳入工具管理页、Token 统计、助手配置、RAG 或 SSE 对话窗口。
- 不调整图设计器及其模型下拉契约，不重构 Agent 编排引擎，不新增模型供应商插件体系。
- 不默认扩大普通角色权限，不新增默认用户，不改变 `superadmin` 旁路语义。
- 不为本功能改业务表结构。若生产菜单可达性必须补迁移，只允许最小菜单/按钮权限 seed；不得借机修改 V19/V24 或其他既有迁移。

## 4. 影响范围（模块级）

### 前端

- Agent 模块的模型管理页面、API/类型契约、表单校验、列表与交互状态。
- 路由与菜单消费、按钮级权限展示，以及现有图设计器模型下拉的兼容回归。
- Mock handlers、fixtures 与专项测试。
- API Key 安全边界：仅提交用户当次输入，不持久化 token/key，不展示后端未返回的敏感信息。

### 后端与迁移

- 既有 `/agent/models` CRUD、分页、详情与 `/{id}/test-connection` 契约预期零业务改动。
- 若审计确认生产菜单缺失，可补 H2/PostgreSQL 双方言的最小菜单及按钮权限 seed，使 `agent:model:view`、`agent:model:manage`、`agent:model:test` 可配置；不得自动授予所有普通角色。
- 除上述可达性 seed 外，预期零实体、Service、Controller 和业务表变更。

### 规划与知识状态

- 完成后核销 P5，并更新 I45 中 M07-F01 前端缺口。

## 5. 风险方向

1. **密钥泄漏**：详情回填、表单状态、错误提示、Mock、测试快照或浏览器存储都可能意外暴露 API Key；必须以“只显示脱敏值、空值保持旧密钥、明文只存在于当次提交输入”为硬边界。
2. **后端契约漂移**：已有 DTO 在多 Key 能力加入后扩展过字段；前端若只按早期 Step1 字段建模，会造成配置丢失或运行态字段被误写。
3. **伪动态装载**：后端已是按调用动态读取配置，若前端增加无真实语义的加载/卸载控制，会制造误导和新契约债务。
4. **菜单可见但接口无权**：页面入口、按钮显隐与三类后端权限必须闭合；只做静态路由或只给 `superadmin` 可用都不算管理能力完成。
5. **连通性语义误判**：后端把 2xx～4xx 视为服务可达；前端应展示后端结论和消息，不能自行用 HTTP 状态二次覆盖。
6. **Mock 与真实接口分叉**：模型管理包含脱敏、空 Key 保留和运行态字段，简单内存 CRUD 容易掩盖真实契约问题。

## 6. 验收标准

1. 有权用户可从生产菜单进入模型管理页，刷新/直达路由可用；无权用户看不到对应入口或操作，直接调用仍由后端拒绝，`superadmin` 既有行为不变。
2. 列表分页、名称查询、加载、空态和错误态完整；展示字段能区分协议、模型、启停、多 Key 分组/优先级及额度锁定状态，且无明文或密文 Key 泄漏。
3. 新增、编辑、删除和启停形成真实接口闭环；表单覆盖既有基础参数与多 Key 配置，协议值、数值范围、必填和默认行为与后端契约一致。
4. API Key 仅显示脱敏值；编辑留空保持原密钥、输入新值才替换。自动化证据证明响应、页面、日志、URL、本地/会话存储和测试快照均不含明文或 `apiKeyCipher`。
5. 每条模型可发起连通性测试并明确展示成功/失败、消息和耗时；覆盖 OpenAI、Ollama、other、网络不可达及后端判定可达的 4xx 场景，不泄漏鉴权信息。
6. `agent:model:view`、`agent:model:manage`、`agent:model:test` 三类权限在菜单、页面按钮和真实请求链上分别生效；至少证明授权用户可操作、撤权后拒绝、未认证拒绝，且不通过默认扩权达成。
7. Mock 与真实 API 契约一致，现有 GraphDesigner 的模型下拉仍可正常读取；M07-F02 既有图定义、设计、发布和执行路径无回归。
8. 前端 `typecheck`、`lint`、`test`、`build` 在 2G 上限下全部通过，测试数量不低于当前基线 **66 files / 602 tests**，并包含列表、表单、密钥、权限、连通性和 Mock 专项证据。
9. 若补菜单/权限迁移，H2 与 PostgreSQL 脚本语义对齐、版本无冲突，并通过 H2 新库全链与上一版本升级链；后端项目级测试数量不低于当前 **582**。若确认无需后端变更，回执须给出生产可达性证据并证明后端与 Flyway 零改动。
10. 所有编译测试遵守 2G 内存上限与前后端互斥；回执提供实际互斥检查、命令、退出码、测试计数和偏差说明。
11. 完成 §3.3 第10项知识库全量同步：P5、I45、M07-F01-01～05、current-status、功能追踪、known-issues、session-handoff、需求池全文对齐，并证明无关清单行零漂移。
