# 多宿主执行监督与自动续行治理方向

> 下发角色：规划（Planner）  
> 指定实施角色：管理员（Admin）  
> 优先级：P0  
> 任务等级：XL  
> 方向状态：READY  
> 日期：2026-09-16  
> 任务性质：工作区治理实现，不计入业务功能数，不占用或核销业务 P 编号  
> 触发事实：Zcode 执行线程在仍有明确可执行工作项时多次结束回合，需要用户人工恢复

## 1. 背景与问题定义

当前工作区已经定义唯一终态机器契约、剩余工作项、实际工具观察、进展指纹、停止原因和自动回注语义，但执行门禁的实际触发仍受宿主集成能力影响。Zcode 中出现了以下真实行为：执行代理明确报告仍有十项未完成工作并表示将继续，却在同一任务中多次结束回合，需要用户手动触发后续执行。

该问题的本质是“模型回合结束”被宿主当成了“任务允许结束”。治理目标必须把这两个事件分开：模型可以结束一次回合，但任务是否终止只能由工作区机器契约和外部监督器裁决。

本任务属于核心治理与多宿主演进，涉及终态契约、角色绑定、宿主适配、自动续行、崩溃恢复和错误线程防护，按 XL 处理。

## 2. 产品目标

1. 建立独立于具体模型和宿主的执行 Supervisor，成为执行任务终止、续行和恢复的唯一裁决入口。
2. Zcode 与 Codex 通过各自 Host Adapter 接入同一 Supervisor、Validator 和 terminal contract，不形成平行终态规则。
3. 当仍有已授权、依赖满足且可执行的工作项时，任何普通回合结束都自动回注精确 next_action，不要求用户点击“继续”。
4. 缺失、过期、矛盾或与实际工具观察不一致的终态声明默认拒绝结束，并要求修复契约或继续原子动作。
5. 合法完成、真实外部阻塞、用户暂停与用户取消能够被准确区分，不制造无限循环，也不扩张授权范围。
6. Supervisor、Zcode、Codex 或操作系统进程重启后，可以恢复当前任务、剩余账本和唯一下一动作。
7. 多窗口、多线程和多工作区环境下，自动回注只能进入原执行线程，不能依赖当前键盘焦点猜测目标。

## 3. 核心治理裁决

### 3.1 唯一终态契约

- terminal-contract.json 继续作为唯一机器终态契约；不得为 Zcode、Codex 或 UI 自动化另建第二套终态 schema。
- Host Adapter 只负责采集宿主事件、绑定线程身份和发送 Supervisor 已批准的回注，不裁决任务是否结束。
- Validator 只依据角色、任务状态、work_items、remaining_actionable_count、independent_work_exhausted、next_action、next_action_type、progress_fingerprint、progress_basis、stop_reason、tool_results、browser_status 及宿主实际观察作出决定。
- 助手自然语言中的“完成”“继续”“稍后处理”或其他自述不能覆盖机器契约。

### 3.2 回合结束与任务终止分离

- 每次模型停止输出、发送最终消息或宿主进入空闲，只产生 TURN_ENDED 事件，不自动产生 TASK_TERMINATED。
- Supervisor 收到 TURN_ENDED 后必须执行终态校验：
  - 存在可执行项：拒绝终止并回注精确 next_action；
  - 契约缺失或过期：拒绝终止并要求恢复契约；
  - 声明与工具观察不一致：拒绝终止并指出差异；
  - 合法完成：只放行一次；
  - 真实阻塞：满足现有阻塞证据门槛后放行；
  - 用户暂停/取消：立即停止自动续行。
- “我继续处理”后结束回合属于普通让渡，不是异常，也不能成为用户确认节点。

### 3.3 宿主外 Supervisor

Supervisor 作为本地独立进程或服务运行，生命周期不依赖单个 Zcode/Codex 回合，至少承担：

- 活动角色、工作区、任务和线程身份绑定；
- terminal contract 原子读取、版本校验和新鲜度检查；
- 宿主实际结束事件、工具结果、浏览器状态与进展指纹核对；
- 允许结束、拒绝结束、自动续行、重新规划和合法阻塞裁决；
- 回注幂等、重复事件去重和错误线程防护；
- 会话租约、心跳、崩溃恢复和人工暂停/取消；
- 可审计事件记录，不记录秘密或完整敏感输入。

Supervisor 不替代 Executor 实施业务工作，也不得生成授权范围外的新工作项。

### 3.4 Host Adapter 契约

每个 Host Adapter 必须实现同一最小能力：

1. 返回稳定的 host、workspace、thread/session、active_role 和 turn/event identity。
2. 报告回合开始、工具活动、回合结束、窗口/线程关闭和宿主重启。
3. 向指定原线程发送一条带幂等键的 Supervisor 回注。
4. 回读已发送消息或宿主确认，证明没有发送到其他线程。
5. 支持用户暂停/取消，不在暂停状态继续输入。
6. 无法可靠识别目标线程时拒绝发送，而不是向当前焦点窗口猜测输入。

适配器可以使用宿主 API、CLI、扩展事件、进程包装或 Windows 可访问性接口；具体选择必须由管理员基于实际能力矩阵确定，并如实标注保证等级。

### 3.5 Zcode 适配

Zcode Adapter 按实际可用能力选择最强路径：

- 具备结构化 API、CLI、扩展事件或线程命令时，直接订阅回合事件并按线程 ID 回注。
- 能够由受治理入口启动时，由启动器创建会话租约并持有进程、工作区和线程身份。
- 只有可见 GUI 时，允许使用 Windows UI Automation 读取可访问性树、识别目标线程状态并提交回注；必须固定工作区和线程身份，并验证发送后的实际目标。
- GUI 模式无法取得稳定线程身份时，只允许受治理工作区存在一个活动 Zcode 执行线程；不满足这一限制时拒绝自动输入并报告真实能力缺口。
- Zcode 被关闭或崩溃后，Supervisor 保留活动任务；重新绑定同一线程或受控替代线程后，从契约 next_action 恢复。

### 3.6 Codex 适配

- Codex Stop Adapter 接入同一 Supervisor 和 Validator，保持既有宿主投影字段兼容。
- Codex 宿主事件只是一种输入来源，不拥有独立终态语义。
- Codex 与 Zcode 对相同 terminal contract、tool observations 和 work_items 必须得出相同裁决。

### 3.7 会话绑定与租约

- 受治理执行任务启动时，必须绑定 workspace root、host、thread/session、active_role、task identity 和 contract revision。
- Executor 角色绑定不能依赖模型在对话中自称角色；必须来自启动入口或宿主适配器的可信绑定。
- 租约仅解决活动会话归属，不另建终态状态机。
- 相同工作区可以支持多个线程，但每个回注必须绑定精确线程；GUI 降级模式按其身份能力限制并发。
- 契约采用原子写入和单调 revision，Supervisor 不接受倒退版本或与当前任务身份不匹配的快照。

### 3.8 自动回注与收敛

- 回注内容必须来自契约中的精确 next_action，并包含当前剩余原子工作项，不使用泛化“继续”作为唯一指令。
- 每次回注携带由 session identity、contract revision 和 turn event 组成的幂等键；同一事件最多回注一次。
- 重复 progress_fingerprint 按既有收敛纪律处理：
  1. 首次重复：要求执行一个可验证原子动作；
  2. 再次重复：要求切换工具或实现路径；
  3. 继续重复：要求 Supervisor 触发重新规划；
  4. 仍有授权内可执行项时不得借重复失败结束任务。
- 回注只允许推进已经授权的工作项；若 next_action 超出授权，Supervisor 停止自动执行并请求用户裁决。

### 3.9 人工控制与安全边界

- 用户可以随时暂停、恢复或取消受治理任务，暂停/取消立即压过自动续行。
- 真实秘密、MFA、人机验证、破坏性动作、远程发布或授权外状态变化继续使用现有确认门禁。
- dev/test 固定配置、既有测试账号和非秘密输入属于可继续动作，不产生新的用户确认。
- GUI 自动化不得操作任务线程之外的窗口、系统对话框或其他应用；目标身份不明确时 fail closed。

## 4. 功能范围

- 宿主无关 Supervisor、统一 Validator 调用和决策结果。
- Zcode Host Adapter、Codex Host Adapter 及共同 Adapter 接口。
- 受治理任务启动、角色/线程绑定、租约、心跳和恢复。
- TURN_ENDED 采集、终态验证、自动回注、幂等去重和收敛升级。
- 用户暂停/恢复/取消控制面。
- Zcode API/CLI/扩展/GUI 能力矩阵及实际采用路径。
- 多线程错误目标防护、宿主崩溃和 Supervisor 重启恢复。
- 治理事件审计、诊断工具和管理员运行说明。
- 为完成本方向所需的治理实现、工程配置、自动化验证资产及对应回执。

## 5. 非目标

- 不修改模型权重、模型服务或第三方宿主内部闭源实现。
- 不代替 Executor 完成 P61 或其他业务任务。
- 不改变业务权限、数据、流程或功能状态。
- 不把自动续行扩大为无授权自主工作；Supervisor 只推进现有授权账本。
- 不通过截获秘密、绕过 MFA、人机验证或远程发布门禁保证不停机。
- 不创建平行 terminal contract，也不按模型名称改变治理强度。
- 不在本任务中执行远程提交、推送、发布或历史改写；如后续需要，按管理员 Git 边界另行授权。

## 6. XL 阶段边界

### 阶段 A：现状能力矩阵与统一接口

核实当前 terminal contract、Validator、Supervisor 回注链、Codex Adapter 与 Zcode 可用集成面，形成可复核能力矩阵和统一 Host Adapter 契约。阶段结论必须来自实际工具和宿主行为，不以文档推测替代。

### 阶段 B：Supervisor 核心与会话治理

建立宿主外 Supervisor、任务/线程绑定、契约 revision、结束裁决、自动回注幂等、暂停/取消和崩溃恢复。使用隔离 Host Adapter 证明核心逻辑与具体宿主解耦。

### 阶段 C：Zcode 完整接入

以能力矩阵中最强可用路径接入 Zcode，完成真实线程识别、回合结束采集、自动回注、发送回读、多窗口防误投和宿主重启恢复；GUI 路径需额外证明可访问性目标稳定。

### 阶段 D：Codex 收敛与一致性

让 Codex Adapter 复用同一 Supervisor/Validator，证明相同输入跨宿主得到相同裁决；既有 Codex 工作流和宿主投影不回退。

### 阶段 E：故障注入与整体验收

完成多次中途停止、合同缺失/过期/矛盾、重复指纹、真实阻塞、用户暂停、错误线程、进程崩溃和合法完成矩阵。所有行为证据成立后才能提交治理任务完成回执。

## 7. 验收标准

1. 在真实 Zcode 执行线程中预置至少十个可执行工作项，代理连续五次结束回合；每次均由 Supervisor 自动恢复到精确 next_action，用户不点击继续，工作项不丢失、不重复执行。
2. remaining_actionable_count 大于零、契约缺失、契约过期、revision 倒退、工作项与计数不一致时，任务均不能被标记为终止。
3. 助手自然语言声称“完成”或“继续”不会改变 Validator 裁决；实际工具观察与契约冲突时以真实观察为准。
4. 合法完成时 Supervisor 只放行一次，不重复回注，不在任务完成后重新激活线程。
5. BLOCKED 仅在真实工具结果、已尝试路径、解除条件和独立工作已穷尽同时成立时放行；固定测试输入和可继续动作不能伪装成阻塞。
6. 相同 progress_fingerprint 重复时依次触发原子动作、路径切换和重新规划；仍有可执行项时不进入终态。
7. Zcode Adapter 能唯一绑定工作区和线程；两个窗口或线程同时存在时，回注零误投、零重复、零跨工作区输入。
8. Zcode 关闭、Adapter 崩溃或 Supervisor 重启后，任务从最后有效 contract revision 和 next_action 恢复；已完成动作不重复。
9. 用户暂停后不再产生自动输入；恢复后从原任务继续；取消后任务租约释放且不再复活。
10. Zcode 无结构化事件能力时，实际 GUI 适配仍能识别目标线程和结束状态；无法证明身份时安全拒绝输入并给出明确能力结果。
11. Codex 与 Zcode 对同一组合同与实际观察产生一致的 allow/reinject/replan/blocked 裁决。
12. Host Adapter、Supervisor 和 Validator 之间只存在一套终态字段及允许值；扫描和运行证据证明没有平行终态 schema。
13. 每次回注具有可复算幂等键；重复 TURN_ENDED、事件重放和网络/IPC 重试不会生成第二条相同回注。
14. 自动回注内容绑定现有授权工作项和精确 next_action；越权动作、破坏性动作和远程发布继续进入用户确认。
15. 管理员可以查看不含秘密的任务身份、最后 revision、裁决、回注次数和停止原因；普通执行输出不能篡改审计记录。
16. Zcode/Codex 实际集成、Supervisor 单元/集成测试、故障注入矩阵和受影响治理门禁全部通过，计数与原始输出一致。

## 8. 行为证据要求

- 正式证据必须包含真实 Zcode 可见线程，而非只用模拟 Adapter；模拟只证明 Supervisor 核心。
- “连续五次中途停止自动恢复”需保存每次 TURN_ENDED、contract revision、Validator 结论、回注幂等键、实际发送目标、回读结果和下一次工具动作。
- 多窗口验证至少包含目标线程和一个非目标线程，证明非目标线程内容、输入框和消息计数不变。
- 崩溃恢复需实际终止并重启 Adapter/Supervisor/Zcode 中适用的进程，不能只调用模拟异常方法。
- 合法完成和真实阻塞分别提供正向与反向案例；只有错误日志或类名不能替代实际放行/拒绝行为。
- GUI 适配证据必须来自用户可见会话，保存窗口/线程身份、可访问性目标、发送前后状态和失败时的安全拒绝。
- Codex 一致性可以使用既有 Hook 触发，但必须证明裁决来自共同 Supervisor/Validator。
- 回执逐项对照十六条验收标准，附实际命令、工具结果、退出码、进程身份、原始事件流与清理结果。

## 9. 关键风险与停止条件

- Zcode 没有可调用 API 且可访问性树无法稳定识别线程时，不得以坐标点击冒充可靠适配；完成其他独立工作后，携带真实工具结果和所需最小宿主能力进入用户裁决。
- 宿主升级改变可访问性目标或线程标识时，对应 GUI 快照失效，只重验受影响适配层。
- Supervisor 可能造成自动循环；必须以工作项、进展指纹、重规划和用户暂停共同收敛，禁止无条件重发。
- 多窗口误投属于高风险缺陷，出现一次即不得继续自动输入，直到身份绑定修复并重新通过负向验证。
- 终态契约或角色绑定若必须由模型自述才能建立，方向未满足，不得通过。
- 实现若需要降低秘密、MFA、破坏性操作或远程发布门禁，停止扩张并返回管理员/Owner裁决。

## 10. 交付与状态边界

管理员角色负责读取治理实现、核实 Zcode 能力、修改治理脚本/配置/适配器、执行故障注入验证并提交治理回执。该任务不进入业务功能状态机，不改变 P61 状态、功能数、业务清单或正式验证基线。

管理员不得在本任务中修改业务实现或代替 Executor 完成 P61。完成十六项标准后提交治理任务完成回执，由 Owner 或后续明确授权的治理审查确认；未满足时如实记录剩余差异，不得仅凭“已增加守护脚本”宣称解决。
