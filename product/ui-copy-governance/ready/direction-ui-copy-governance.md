## 说明的三档裁决

| 档位             | 判断依据                                                                       | 本轮要求                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 第一档：必要说明 | 用户正确使用功能所必需，名称本身不足以表达，如脚本函数用法、参数与关键取值约束 | 放功能右上角的小问号，鼠标移动上去悬浮展示完整内容；局部字段解释就近关联。优先复用现有 HintTip 与 Tooltip，正文不堆长说明。                                                              |
| 第二档：可选说明 | 当前操作不依赖，但学习和查阅有价值，如完整步骤、背景与扩展示例                 | 从页面抽出，整理进入现有操作手册；无现有入口时用前端 `docs/user-guide/operation-manual.md`。记录迁入章节，去重并改成用户语言，手册入口可查阅。                                           |
| 第三档：无用说明 | 按钮/标题已说明用途，或文字没有用户价值、只是开发备注和实现过程                | 直接删除重复说明，保留业务名称；不转移到问号或操作手册。例：「新增流程（支持流程节点配置、任务绑定及状态管理）」的按钮收敛为「新增流程」，括号内内容仍须按实际用途判断有无独立帮助价值。 |

说明分档不替代即时操作反馈：校验错误、必要风险确认、权限与不可用状态、实际处理结果继续当场准确显示。业务单位、范围和状态限定可保留。面向配置人员的脚本/API/协议等产品概念结合受众判断，不能仅因含技术词就删除。语义不确定的内容保留原状并列为待确认。

## 审计范围与变更边界

- 全部前端页面、静态与动态路由、菜单、公共组件、表单/流程设计器、工作台、管理与业务模块，以及桌面/H5 等当前实际提供的入口；以实际仓库和路由为准，不沿用旧模块清单或扩建新端。
- 所有标题、按钮、菜单、卡片、表单标签/占位、说明，以及弹窗、抽屉、Tooltip、Toast、通知、空/加载/异常状态和权限控制下的显示内容。
- 条件渲染、动态拼接、组件属性/配置、国际化语言资源、请求层错误映射、API 返回消息及运行配置或业务元数据进入界面的展示链；标清文字来源。中英文等当前实际使用资源保持语义一致。
- 注释、日志、测试文本、Mock、演示资产与生成文件需区分是否进入真实用户界面。只作内部用途的内容按其用途处理，不以搜索命中直接认定 UI 缺陷；生产可达的占位或开发状态需准确收口。

只优化展示文案和承载说明的最小展示结构。不得改变接口、数据结构、权限、业务规则、流程状态、交互结果或持久化字段；不做无关布局改版、组件重构、错误体系/帮助平台建设。保留既有 errorKey、机器码、鉴权结果与安全净化契约。若文字来自后端、数据库种子或租户自定义配置，记录来源及所需后续范围；不跨入后端改契约，不覆盖租户内容，不用前端猜测文本替换掩盖来源问题。

先核实真正的路由、模块、组件、语言资源和文案来源，建立覆盖清单，再结合用途与实际交互做语义判断。正则只能定位候选，不得按括号、Hint/Note 名称或技术词批量删改。确认的问题直接优化；不确定项保留并记录，继续独立可完成的工作。具体实施计划、内部分批和测试设计由 Executor 自主安排。

## 验收标准

| 编号                    | 通过条件                                                                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC01 全量范围可核实     | 有基于实际路由/模块、公共组件、语言资源与展示来源的覆盖清单；区分已语义审阅、仅静态定位及未能验证的范围。全量扫描不能用少量关键词命中或几个页面抽查替代；浏览器交互按风险选代表场景，不要求穷举截图。 |
| AC02 三档去向正确       | 确认的问题均按三档处置。第一档问号位置合理、悬浮可读；第二档有实际手册章节与查阅入口；第三档冗余说明已删除，名称简洁明确，不产生新的重复帮助。                                                        |
| AC03 必要信息与语义保留 | 即时错误、风险、状态与结果仍准确可见；同一业务术语一致，没有把处理中说成已成功、把不可用说成可用，或误删脚本/配置使用所需约束。                                                                       |
| AC04 行为与资源兼容     | 未改变业务逻辑、API、数据/权限/规则、机器码与错误键契约；已修改的动态字符串和语言资源引用有效，本次删除没有造成悬挂键或孤立展示节点。                                                                 |
| AC05 验证及限制真实     | 现有适用检查通过，有代表性页面及隐藏状态的实际结果；未确认项、不可达来源、未覆盖交互与工具限制明确列出，不以静态扫描宣称完整浏览器验证。                                                              |

6. 变更与交付摘要：规则引用、实际文件/来源范围、提交推送结果、未触及的在途修改、行为契约核实结论及剩余项。代码与完整 diff 由 Executor 核实；Planner 读取变更结论、行为结果及已有证据。原始输出、截图和日志只本地留存，不入 Git；不追加非必要哈希校验。
