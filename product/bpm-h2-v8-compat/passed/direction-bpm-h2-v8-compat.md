# P10 / I47：BPM H2 V8 迁移链兼容性修复

## 当前状态

**PASSED** — 执行层已完成自验收，规划层于 2026-08-17 对照六项验收方向最终验收通过。

## 功能目标

消除 BPM H2 迁移链在 V8 唯一约束处的方言不兼容，使 BPM 迁移能够纳入 H2 全链验证，并恢复对完整迁移链及其下游数据库契约的真实回归保障。

## 规划裁定

1. 本轮唯一主问题是 I47：BPM H2 V8 使用 PostgreSQL partial unique index 语法，导致 H2 迁移链无法执行。
2. PostgreSQL 侧现有“仅 active=true 的记录唯一”业务语义必须保留；H2 侧应获得可执行且可验证的等价约束语义。具体兼容实现由后端执行角色依据实际 H2/Flyway 能力裁定并在回执中说明。
3. 验证目标不是让单个 V8 文件孤立通过，而是把此前因 I47 排除的 BPM 迁移重新纳入真实 H2 全链验证，并证明 V8 之后的 BPM 迁移可继续执行。
4. 若永久全链验证需要补充最小测试基建，可纳入本功能；但不得借此重构整个测试框架或扩大为跨模块测试平台建设。

## 非目标

- 不改变 BPM 流程定义绑定、发布、激活/停用的业务规则。
- 不改变 PostgreSQL 生产语义，不以删除唯一性约束换取 H2 兼容。
- 不修改前端。
- 不处理 I49 菜单角色授权、I50 登录校验时序、I48 flow-graph adapter 限制或其他需求池缺口。
- 不新增与迁移兼容性无关的表、接口、页面或业务能力。

## 影响范围

- **后端 BPM 迁移边界**：BPM 模块 H2/PostgreSQL 双方言 V8 及与其约束语义直接相关的后续迁移。
- **迁移验证边界**：当前排除 BPM 的 H2 Flyway 冒烟/全链验证口径，以及为永久回归所需的最小测试基建。
- **业务回归边界**：流程定义绑定中 active 唯一性、重复绑定及启停切换相关行为。
- **知识与状态同步**：完成后核销 I47/P10，更新 Flyway 冒烟口径，并按宪法 §3.3 第10项全量同步知识库、功能清单和需求池。

## 验收方向

最终完成回执必须提供足够证据证明以下条件同时成立：

1. H2 BPM 迁移链不再因 V8 的 partial index 语法失败，且 V8 之后的 BPM 迁移可连续执行。
2. PostgreSQL 迁移仍保留既有 active 条件唯一语义；H2 等价方案有明确的约束语义证据，不能仅证明 SQL 可解析。
3. active 绑定唯一性、非 active 历史记录共存以及启停/重复绑定边界均有可核验测试证据。
4. BPM 迁移被纳入可重复的 H2 全链验证，不再依赖“排除 BPM 两条迁移”的 28 条冒烟口径；回执明确报告修复后的迁移计数和验证入口。
5. 后端受影响模块测试与项目级回归通过，基线不得低于 527 tests，编译/测试遵守 2G 内存上限。
6. 无前端改动、无无关业务行为变化；回执列明实际修改范围、命令与结果、计划偏差、遗留风险，以及 §3.3 第10项要求的知识库触碰文件和清单变更明细。

## 风险方向

- **语义弱化风险**：H2 兼容写法可能只解决语法而没有保持“active=true 才唯一”的业务约束，必须用正反例验证。
- **双方言漂移风险**：H2 与 PostgreSQL 可以采用不同实现，但最终业务语义必须一致；不得机械追求 SQL 文本一致。
- **历史迁移风险**：V8 属已发布历史迁移。执行角色必须评估校验和及已有环境影响，在回执中明确选择与兼容策略，不得静默破坏既有数据库升级路径。
- **验证假阳性风险**：只跑绕过 Flyway 的手写测试 DDL不能关闭 I47；验收证据必须包含真实 Flyway BPM 链。
- **范围蔓延风险**：最小测试基建仅服务迁移回归，不扩展为通用数据库测试重构。
