## 48 DR06 函数缺口

新增 `script-hosts`（表单字段脚本与表单事件脚本共用的补充宿主函数）：

- 组织关联查询：`获取用户信息/获取用户姓名/查询用户/获取部门信息/获取部门名称/获取上级部门/获取部门列表`。数据只来自页面在脚本执行前装载的已授权目录快照（`/system/user/options` 上限 200 + 部门树，与人员/部门选择器同一接口）；快照未装载时明确报「组织目录未装载」，不越权直查、不返回猜测值。
- 日期计算：`当前日期/当前时间/日期加减/日期差`；非法日期/天数明确报错，跨月跨年与闰日有测试。
- 明细控件选项：`获取子表字段选项(table, column)` 返回子表列选项值；列不存在/非子表报错。
- 装配：`field-scripts` 与 `form-events` 两个运行面共用；`FormRender`/`TaskDetail` 仅在存在字段或事件脚本时预载快照（失败不阻断表单，函数报未装载）；目录 `script-catalog` 增补 11 条并保持「目录 ⊆ 宿实现」一致性测试。
- 说明：当前契约没有「部门→成员」批量授权查询，本批未实现 `获取部门成员`；不以显示名或越权接口替代。人员身份仍以稳定 ID 返回（`获取用户姓名` 为阅读辅助）。

## 51 意见人员字段

- 契约：`ApprovalOpinionConfig` 字段类型加入 `USER`；服务端 `ApprovalUserTaskTranslator`/`ApprovalOpinionValidator` 双白名单加入 `USER`。
- 服务端权威校验：USER 值只接受正整数稳定 ID（单个或数组，≤50），显示名/文本一律判非法；任务动作前用 `UserQueryFacade.findActiveUserIds(ids, tenantId)` 核验同租户启用用户，任一不满足即拒绝（APPROVAL_OPINION_INVALID）。旧 TEXT 意见字段文本输入保持兼容。
- 填写与暂存：PC 意见表单 USER 用共享 `DynamicField`/UserControl 选择，提交/暂存写稳定 ID；移动端意见表单新增人员下拉（同租户启用用户，仅存 ID）。
- 只读与历史：`InstanceFlowPanel` 按意见表单定义识别 USER 字段，用授权目录解析显示名，展示「姓名（ID）」；解析不到时保留 ID，不伪造姓名。
- 测试：服务端 `ApprovalOpinionValidatorTest` 6/0（ID/数组、显示名拒绝、非正数/超长、必填、旧 TEXT 兼容）；Web `TaskDetail.spec` 43/0（新增必填拦截 + ID 提交）。

## 52 意见附件受控下载与催办接收人

意见附件：

- 新增 `GET /workflow/attachments/opinion/{actionRecordId}/download`：登录 + 记录存在 + 记录所属实例可访问（发起人/当前参与人/抄送/超管/数据管理者）+ `storageKey` 必须被该记录冻结意见数据中的附件字段实际引用（支持字符串或 `{storageKey,name}`），才经 StorageFacade 下载；文件名不能拼地址，任意 storageKey 不放行。
- 历史项新增 `actionRecordId`（旧响应缺省），供定位；Web 意见详情仅对结构化引用渲染下载按钮，纯文本旧值显示「不可查看（缺少可解析引用）」，不伪造恢复。
- 测试：`WorkflowAttachmentControllerTest` 13/0（引用命中下载、未引用/非附件字段 403、记录不存在 404）。

催办：

- 合法操作者扩展为「实例发起人 或 当前活动任务办理人/候选人」，服务端按引擎当前状态判定（不再仅发起人）。
- `UrgeReqDTO.recipientIds` 可选：必须全部属于当前实例合法待办人集合；越界/空集合明确拒绝并留痕，不向外发送；为空保持实例级旧语义（全部待办人）。冷却、留言长度、幂等/审计沿用原实现。
- Web：任务详情 `instanceId`（新增响应字段）+ 参与人可见催办入口；催办弹窗提供「催办接收人」多选（当前待办人与活动参与人，排除本人），不选=全部；旧响应无 `instanceId` 时回退发起人实例列表。
- 测试：`BpmUrgeServiceTest` 11/0（参与人可催办、外部人 403、子集只发所选、越界 REJECTED 留痕）；Web `TaskDetail.spec` 新增参与人催办 + 接收人提交断言。
