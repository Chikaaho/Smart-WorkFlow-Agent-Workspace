# 0.2.0 像素级 UI 验收标准

2026-10-22｜Planner｜Owner 明确要求的正式验收硬标准

## 1. 覆盖与基准

五项目标的页面开发都要对照 Figma 做像素级还原。验收覆盖实际可达的独立页面、弹窗、菜单、主题、控件和关键状态；设计索引的每个画框须有承接项。布局、公共组件、主要内容和交互状态均需符合设计，不能仅凭菜单和控件类型相同判为通过。

视觉权威为 Figma 文件 `mbEKPcZv9pcchmElQanR5E` 的核心页 `0:1` 与规范页 `258:2`。主基准是对应完整画框的原始尺寸导出图；桌面画框通常为 1920×1080。Owner 指定的 `332:6543` 为详情正文，完整页面对照同时使用父画框 `5:2`，不能只裁出正文忽略顶栏和容器。

执行前取得与当前任务相关的设计图和关键属性，记录文件、节点、读取时点、原始尺寸及适用状态。实施期间来源无实质变化时沿用；发生变化只处理受影响节点，不反复全量读取或计算产物哈希。已可直接读到的素材和证据直接引用。

## 2. 相同条件下比较

- 设计图与实际截图保持相同视口、原点、缩放和像素尺寸。主对照用 1920×1080、浏览器缩放 100%、device scale factor 1；其他尺寸画框用其真实尺寸。不得先缩小、模糊、拉伸、平移或裁掉失败区域降低误差。
- 使用同一主题、字体、字重、字号、行高、图标和控件状态。字体资源或图标缺失先解决资源问题；不能把未加载的回退样式算作还原通过。
- 比较时固定业务数据、语言、时间、展开/选中/焦点、滚动位置和加载完成状态。页面使用可回读的合法业务对象，不用整页设计图片、截图背景或静态摆拍页代替真实页面。
- 每组保留 reference、runtime、diff，以及必要的半透明叠图；原始图不修改。记录 URL、身份/租户、对象、视口、节点、实现基线和差异工具参数。

## 3. 量化门槛

| 项目 | 通过门槛 |
| --- | --- |
| 位置与几何 | 主容器、导航/侧栏、卡片、表格列/行、按钮、输入、弹窗与浮层的 x/y/宽高及关键间距，相对设计偏差均不超过 1 CSS px；边框、分隔线和对齐无持续累计偏移 |
| 字体与排版 | 字体、字重、字号、行高、对齐、换行、截断方式与设计一致；文字基线和关键文字框偏差不超过 1 CSS px；不得以系统字体差异掩盖字号/行高/布局错误 |
| 颜色与表面 | 主题、背景、文字、边框、图标、选中/禁用/悬浮色逐项对照；稳定色相对设计 RGB 各通道偏差不超过 3，透明度及阴影参数对应设计 |
| 整页像素差 | 在同尺寸原图上比较，单像素 RGB 任一通道差值大于 8 计为差异像素；稳定区域差异比例不超过 1%，即该口径像素一致率至少 99% |
| 内容与关键区域 | 内容区域同样达到至少 99%；导航、表单、表格、审批区、弹窗、脚本面板等每个关键区域至少 98%。分别报告，不能用大面积背景稀释内容偏差 |
| 状态与完整性 | 目标状态无缺组件、错图标、错层级、错误留白、遮挡、穿透、裁切或不可达操作。满足总比例但仍有明显结构/文字/操作偏差，仍不通过 |

像素比例由工具按实际图像计算，报告分子、分母、排除面积和结果；不得用目测评分、内部截图互比或“已接近”替代与设计的比较。工具、算法和参数由 Executor 实现并记录，以上口径固定；数值变化不能靠改阈值、改基准或扩大遮罩实现。

## 4. 动态内容与渲染差异

优先通过真实可控数据对齐设计内容。确实无法固定的时间戳、业务标识、用户自带图片等，可排除其最小内容矩形；每处写明对象、原因、矩形和面积，总排除面积不得超过该图的 1%。排除后仍核对该容器的位置、尺寸、边距和排版。

禁止遮罩整段正文、整张表、整块卡片、全部文字、导航或主要业务区域。固定标签、按钮、默认图标、表头、颜色和间距不得作为动态内容排除。不能通过模糊、缩图或边缘侵蚀吞掉真实差异。

同字体条件下仍有真实抗锯齿或渲染器差异时，保留原图、完整 diff、受影响字形/边缘和几何结果，作为具体差异交 Planner 判断；不自动忽略全部文字或自行放宽门槛。差异未获基于证据的具体裁决前，该项保持未通过，不由总分覆盖。

## 5. 代表状态与回归范围

每个独立页面、全新弹窗和关键状态都有对应视觉结果。公共组件的完全等价状态可以引用同一组证据，但须明确组件和消费者；具有不同布局、数据密度、主题、尺寸或权限显示的状态分别对照。每个设计画框都在覆盖矩阵登记承接/共用关系，不能用几张首页截图证明全局完成。

关键组至少包含全局框架、表单设计与子表、校验、数据填写/只读详情、审批区与更多操作、租户/超管筛选、新建/编辑、脚本目录/编辑/运行结果、流程监听和发布快照。加载、空、错误、校验、禁用、悬浮、菜单展开及主题变化按受影响组件覆盖。

1366×768 检查桌面响应式；375×812 检查既有移动业务入口。没有对应移动稿时验证规范、数据与操作可达性，不虚报移动端像素还原率。节点数量和截图数量分开报告，不把状态变体计成独立业务功能。

## 6. 验收与收敛

每批 UI 完成时先做本标准的设计对照并修复差异，再提交该批回执；功能可用与像素还原同时通过才算对应页面完成。受影响公共组件变化后，只重验覆盖矩阵命中的消费者；已通过且未变化的页面沿用证据。

首轮一次提交完整覆盖与失败清单，Planner 自行读取实际图像和结果；不因报告措辞或单次工具截断让执行方重复封装。两轮仍不通过按既有规则先自查口径和方法，再带真实差异交 Owner 裁量，不能降低“像素级还原”要求后宣称通过。
