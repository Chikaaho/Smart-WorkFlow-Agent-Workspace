## 3. 量化门槛

| 项目 | 通过门槛 |
| --- | --- |
| 位置与几何 | 主容器、导航/侧栏、卡片、表格列/行、按钮、输入、弹窗与浮层的 x/y/宽高及关键间距，相对设计偏差均不超过 1 CSS px；边框、分隔线和对齐无持续累计偏移 |
| 字体与排版 | 字体、字重、字号、行高、对齐、换行、截断方式与设计一致；文字基线和关键文字框偏差不超过 1 CSS px；不得以系统字体差异掩盖字号/行高/布局错误 |
| 颜色与表面 | 主题、背景、文字、边框、图标、选中/禁用/悬浮色逐项对照；稳定色相对设计 RGB 各通道偏差不超过 3，透明度及阴影参数对应设计 |
| 整页像素差 | 在同尺寸原图上比较，单像素 RGB 任一通道差值大于 8 计为差异像素；稳定区域差异比例不超过 1%，即该口径像素一致率至少 99% |
| 内容与关键区域 | 内容区域同样达到至少 99%；导航、表单、表格、审批区、弹窗、脚本面板等每个关键区域至少 98%。分别报告，不能用大面积背景稀释内容偏差 |
| 状态与完整性 | 目标状态无缺组件、错图标、错层级、错误留白、遮挡、穿透、裁切或不可达操作。满足总比例但仍有明显结构/文字/操作偏差，仍不通过 |

以上比例仅对同条件可比对象适用；比较不适用的整图不得拿作失败依据或宣称达标，按第4/7节保留固定UI实值裁决。像素比例由工具按实际图像计算，报告分子、分母、排除面积和结果；不得用目测评分、内部截图互比或“已接近”替代与设计的比较。工具、算法和参数由 Executor 实现并记录，以上口径固定；数值变化不能靠改阈值、改基准或扩大遮罩实现。

## 4. 动态内容与渲染差异

真实业务内容沿Owner2026-10-28裁决，不以对齐演示值为验收前提。对同条件可比图，时间戳、业务标识、用户图片等非文字动态内容可扣最小矩形，总面积≤1%，扣除后仍核容器/边距/排版。若真实记录数、业务图形、权限或合法字段组成使整图不具同态可比性，保留原图和原分数、明确整图比较不适用，由Planner裁决同态固定区域及共同组件；该判断不是扩大1%遮罩额度或全图免验，也不把不适用整图写成99%通过。

禁止遮罩整段正文、整张表、整块卡片、全部文字、导航或主要业务区域。固定标签、按钮、默认图标、表头、颜色和间距不得作为动态内容排除。不能通过模糊、缩图或边缘侵蚀吞掉真实差异。

同字体条件下仍有真实抗锯齿或渲染器差异时，保留原图、完整 diff、受影响字形/边缘和几何结果，作为具体差异交 Planner 判断；不自动忽略全部文字或自行放宽门槛。差异未获基于证据的具体裁决前，该项保持未通过，不由总分覆盖。

## 5. 代表状态与回归范围

关键组至少包含全局框架、表单设计与子表、校验、数据填写/只读详情、审批区与更多操作、租户/超管筛选、新建/编辑、脚本目录/编辑/运行结果、流程监听和发布快照。加载、空、错误、校验、禁用、悬浮、菜单展开及主题变化按受影响组件覆盖。

## 7. 文字项判定与真实数据（Owner 2026-10-27批准；2026-10-28补充数据口径）

文字边缘是否属于栅格化差异须有具体证据；两个页面分数接近不能证明原因相同。只有以下字体、几何、颜色条件全部满足的文字项适用本节独立判定，未满足者继续计入失败。

1. **文字项判定**：以 DOM 文字矩形为单位，同时满足才算通过：字体族、字重、字号、行高与设计一致；文字框 x/y/宽高偏差≤1 CSS px，基线偏差≤1 CSS px；文字颜色 RGB 各通道偏差≤3。
2. **计入方式**：通过的文字项，其矩形从整页分子、分母中同时扣除，只在报告里列出；失败的文字项保留在分子分母内，并逐项列出位置与实际偏差。文字矩形取实际文字外接矩形外扩不超过1 CSS px，不得扩大；非文字元素（图标、线条、背景、弧线、纹理、圆角、阴影）不适用本款，仍按第3节99%/98%判定。
3. **动态文本**：内容与宽度因真实数据不同时，只比锚点（左/右对齐边）、基线、字体字号字重颜色，不比文字内容与宽度；不得借此排除非文字元素。第4节原有“总排除面积≤1%”继续适用于非文字元素的动态矩形，文字项不计入该1%。
4. **真实数据与比较适用性**：Owner于2026-10-28在本规划会话直接确认“是，按真实数据验收”，不要求演示数据同值。4:2、6:2按真实条数/分页总量，7:2按真实30天聚合/柱高与真实权限状态，不造历史、不删行、不显示无权能力；7:2十四柱/30日分段有效。三处示例数据比较条件关闭，字体、组件样式、固定表面/轴/颜色/间距及实际数据正确性仍验。因真实条数不同的内容密度差逐元素判断，不据此遮整表/整图或把未检视UI标通过。
5. **合法数据对齐**：允许在授权 dev 测试租户中经正常业务流程，按参考图内容建立合法对象（表单、流程、收藏、有截止时间的待办等），只增不改不删历史对象，仅用于比较。不得通过数据库直写、删除真实数据或修改授权来对齐。
6. **失败归类**：几何、字体、颜色、组件缺失、文案不一致属实际缺陷，不得归为“字体/数据待规划”。只有字形栅格化差异且上述文字项条件全部满足，才不计入失败。
