## DR01：基线、定义版本与当前状态

从新核实的 develop 建本版任务分支，承接 0.1.10 已发布成果；先纠正本版依赖的当前入口。缺失的历史回执只记录来源和限制，不制造补证原文。执行方同步 knowledge 后，按授权更新受影响摘要、根版本声明和变更记录，功能计数与已过基线不因同步增加。

表单字段、校验、事件动作、默认列表解释，以及流程监听器、节点操作策略均随对应定义发布版本冻结。新版本用于新业务；已发起实例、已提交记录和引用旧版本的草稿继续使用其绑定版本。编辑定义不原地改变历史。旧定义缺少新增配置时使用本文件的兼容缺省行为；新定义保存与发布前校验引用、依赖、权限和类型。

## DR02：创建租户与首任管理员

- 新增租户按稿填写名称、管理员账号、初始密码。租户标识由服务端生成并保持稳定；账号按现有租户内唯一规则校验，密码遵守现有策略。创建租户、建立其首任管理员和必要初始化原子完成，失败零半成品；重复请求不产生多个租户或管理员。
- 首任管理员属于新租户，只取得租户内管理权限；系统 `superadmin` 继续仅属于租户 0。建立稳定的租户—首任管理员关联，列表按该关联显示，不随机取一个用户或用账号文本猜测管理员。
- 初始化使用现有可复用的租户权限/菜单模板及必需默认配置，创建一个归属本租户的根部门并关联首任管理员；复制的是模板规则，不复制其他租户的人员、业务数据或秘密。只开放该租户按现有产品授权可使用的功能。
- 创建结果提供可用的租户标识和现有认证入口信息，使首任管理员能够以该租户身份登录。沿用现有认证与租户识别机制，默认租户登录保持兼容。初始密码不在响应、列表、日志或证据回显。
- 既有租户保持原标识和数据。能由已有明确授权关系唯一确认管理员时建立关联；无法唯一确认时显示“未配置”，由超管在该租户中选择有效管理员或创建首任管理员，不能自动提升无关账号。
- 租户 0 和系统超级管理员是保留对象：租户页只读，服务端同时拒绝编辑、停用、删除和更改其归属。非零租户默认提供新增、编辑名称、启停和管理员维护，不提供删除租户、清理业务数据或迁移对象归属。

## DR03：目标租户、停用和过期

**目标租户**：超管在单一租户筛选下新增用户/部门，继承该明确目标，弹窗显示只读租户名称；“全部租户”下新增时，先用统一租户选择器确定目标，再进入新建弹窗。不得静默回落租户 0。编辑时目标取被编辑对象，禁止通过本版修改其租户归属。部门父子、角色、岗位及关联对象必须属于同一目标租户。服务端分别校验操作者和目标，不把筛选值改成操作者身份。普通租户用户始终受认证租户与权限约束。

**停用/过期**：

| 对象 | 确定行为 |
| --- | --- |
| 登录、刷新、会话、SSO、OpenAPI | 沿当前有效性机制拒绝新访问；既有会话的新请求也不得继续通过 |
| 新表单写入、流程发起、人工办理和管理操作 | 停止该租户的新业务准入；已有数据和流程记录不删除、不改写历史终态 |
| 在途实例与未开始的异步工作 | 保留对象及原状态，暂停该租户新的业务推进/认领；不批量伪造实例挂起、失败或完成状态 |
| 已经开始的一次执行或外部发送 | 有界完成已进入执行的原动作并记录真实结果，防止强中断造成未知副作用；不因此接受新业务链 |
| 定时、预约和通知队列 | 未开始的工作停止认领；已发出的工作可接收和记录结果。保留原对象，不重复创建或发送 |
| 重新启用 | 通过原准入机制恢复尚有效工作，继续绑定原对象与版本；已过期预约按既有 EXPIRED 规则收敛，不补发过点预约或重复补跑历史触发 |

停用、过期和重新启用均记录操作者/原因、租户、时间及结果。已进入执行的边界以持久认领/发送状态为准，不能按线程是否存在猜测。租户状态检查在关键准入和认领点生效，普通前端隐藏不能代替。超管仍可查询状态、查看必要诊断及重新启用，业务数据查询沿原授权。

## DR04：表单配置、长度与正则

- 字段/动作权限、默认列表、受控数据源的配置入口纳入本版，配置者必须拥有相应设计/管理权限。表单默认视图与个人显示偏好分开：个人偏好只能在已授权的列和动作内调整，不回写管理员默认配置，不扩大权限。
- 最大长度承接既有 `length` 含义，新增最小长度、正则与用户提示。存储契约可由 Executor 选择，但现有最大长度配置必须生效；同时出现两个互相冲突的最大长度来源时保存/发布拒绝，不静默选值。
- 长度按 Unicode 码点计数，中文和非 BMP 字符使用一致口径；不因校验自动 trim、截断或替换用户内容。最小长度为非负整数，最大长度为正整数，最小不得大于最大。未配置限制及旧定义的无上限标识保持原义，读取时规范化，不因新增规则将旧无上限值误判为零长度上限。
- 空值由必填规则控制；可选字段为空时不执行最小长度或正则，避免把它隐式变为必填。非空值需要满足全部已配置约束。正则按完整字段值匹配，提供一致且有界的跨端语法；无效、不支持或无法有界执行的表达式在保存/发布前拒绝并说明，不在业务提交时失控执行。
- 客户端提供即时校验，服务端对创建、更新、正式提交和导入执行同一规则，覆盖主表和现有明细层级。自定义提示按纯文本安全展示；没有提示时给出字段及约束明确的默认说明。
- 保存草稿不强制必填、最小长度或业务正则通过，允许保存未填完内容；仍遵守身份、字段权限、类型和系统资源限制。正式提交再完整校验。已有历史记录不回填或裁剪，回看不追溯报错；本次新写入/修改按绑定版本规则执行。
- 已有公式的正式结果继续由服务端重算，受控数据源继续执行服务端授权、超时、输出及敏感信息限制。UI 和脚本不能更改这些权威边界。

## DR05：表单三类事件

表单事件是可编辑表单的用户端生命周期事件，运行在隔离、有界的前端脚本环境；复用既有解释器与宿主函数能力，保持现有 CSP，不开放 `eval`、`new Function`、任意 DOM/全局对象、原始网络或存储访问。Executor 可扩展必要语法与异步宿主调用，但应明确支持范围、可诊断错误及真实资源边界，不以“支持 JavaScript”宣称任意运行环境。

| 事件 | 顺序和结果 |
| --- | --- |
| `onLoad` | 身份、绑定版本、主表/明细、控件与既有字段加载脚本完成后执行，同一次表单装载一次；普通重渲染不重复执行。失败保留已加载数据，显示可定位错误，不自动循环重跑 |
| `beforeSubmitHandler` | 提交时先提交控件编辑值并结清已有字段联动，再按配置顺序执行本事件；脚本修改及其字段联动结清后，执行最终客户端校验与服务端提交。返回 false、显式拒绝、异常、超时或取消均阻止该次提交，保留填写内容并释放提交锁 |
| `afterSubmitHandler` | 业务提交已确认成功、取得稳定记录/提交标识后，按顺序执行一次；不等待整个流程结束。若仅得未知受理结果，先按原标识查清结果，不能重新提交。失败明确提示“已提交，后续处理失败”，不回滚、不自动重发业务提交 |

同一事件的动作有稳定 ID、顺序和启用状态；旧定义没有表单事件时不新增隐式动作。脚本失败停止该事件的后续动作，已成功业务提交的事实不受影响。字段加载/值变更脚本继续沿用，联动要有循环与次数保护。

异步平台函数可等待但必须有时限和取消：单动作执行及宿主调用默认上限 5 秒，同一事件默认总上限 15 秒；已有更严格的资源预算继续有效。用户确认等待单独计时，不计入上述计算/宿主调用预算；按一次可取消交互处理，最长 60 秒，等待期间不允许重复提交，取消/超时返回明确取消结果。页面离开、请求取消或失去执行对象时清理本次执行和监听，不遗留锁或后台重复动作。具体可配置方式由 Executor 决定并在回执列实际生效值。

草稿保存和审批暂存不触发提交前/后事件。创建、编辑、发起流程，以及实际提交可编辑审批意见表单的动作，针对各自绑定表单执行事件；主业务表单只读查看不运行带写入副作用的表单事件。审批动作的必填与业务校验仍按该动作的既有契约，不把原本允许未完整填表的退回/驳回改成同意动作的全量必填。纯转办/委托/沟通等不提交表单的动作不触发。事件不能绕过服务端字段/记录/动作权限、规则或公式；必须强制的业务约束继续落在服务端支持的校验和业务契约中。

提供后处理失败的可定位结果和显式重试；重试只处理失败/未执行动作，沿原稳定提交和动作标识去重，不重放已成功副作用，也不再次提交业务。提交后对页面数据的修改不自动写回刚提交记录；页面仍可编辑时，它属于下一次显式编辑，已转只读时拒绝写入。关键业务后台处理使用受控服务端能力和流程事件，不依赖浏览器离开后仍运行脚本。

## DR06：表单函数与共用编辑体验

首期必须提供并有参数、返回、错误和示例说明的能力如下，公有命名由 Executor 统一制定并在实现回执给出目录：

- 数据模型与上下文：字段/明细定义、当前表单及版本、用户及租户、页面读写状态、当前提交结果。流程尚未存在时，实例/任务/节点等返回有类型的空值及可用性信息。
- 主表：单值及批量读写、清空、类型正确的默认值与派生值；仅操作有权查看/编辑字段。
- 明细：读取集合、稳定行标识及单元格，新增/删除/更新行、批量赋值、汇总；覆盖当前已支持层级，不在本版另建更深嵌套模型。
- 控件：按字段/明细行/列读取和调整显示、只读、必填及选项；即时反映到页面。只能进一步限制或在已授予能力内调整，不能解除服务端必填、可见或编辑限制。
- 组织与流程：有权用户/部门/角色/岗位及其关联查询，当前可用流程、节点、办理人与变量的只读查询；不暴露无权对象，不允许借脚本改变当前租户或任务归属。
- 通用与交互：受控字符串、数字、日期等常用转换和计算，消息及确认。
- 平台集成：按已登记、已授权的能力标识调用，参数/响应有类型、有界、可取消，秘密保持在服务端。加载/提交前只允许查询和无外部写副作用的能力；写副作用通过提交后或明确的服务端业务入口执行，使用稳定提交/动作标识实现幂等。

共用面板按场景装载目录，不把表单函数伪装成流程端函数。模拟运行与真实语法、参数类型和错误一致，使用明确的样例/预览对象；写操作不触碰真实业务，结果明确标为预览。支持目录搜索、参数说明、示例插入、清空确认、独立结果区、取消及应用；取消不保存，应用后由定义保存/发布链生效。

## DR07：流程监听与触发器统一

新稿「事件监听」是既有流程触发器的统一编辑视图，使用同一版本化定义和执行链，不另建一份独立运行表或重复投递体系。名称、事件、顺序、启用状态、脚本以及已有条件/结果分支均进入同一流程定义快照。旧配置缺启用字段时视为启用；旧事件、结果分支和动作语义保持，复杂配置在高级区完整可编辑，不因简化页面丢失。

主视图提供「流程发起」「流程结束」两类，分别承接实例已建立后的 PROCESS_START 与终态已提交后的 PROCESS_COMPLETED；其他已支持的节点/任务事件保留在相应节点或高级配置入口。上述简单监听器的时机用于新配置；若旧触发器使用不同事务阶段或失败策略，保留其原版本语义并在同一模型中显式区分，不静默搬移旧动作的执行时点。页面说明真实触发时机，示例脚本名称不将已发生的流程事件变成同步提交前检查；发起前表单检查使用 DR05 的提交前事件和服务端规则。

服务端事件按原实例、事件和动作标识去重，重新投递只重试未成功副作用。监听脚本失败可查询、可诊断，不回滚已成立的发起或终态，不凭浏览器重试制造第二个流程。新版本启停不追溯改变旧实例绑定快照。节点脚本、流程监听与表单事件共用编辑体验，执行对象与函数能力仍各自明确。

## DR08：加签位置和多人办理顺序

新 UI 将两个维度分开：加签位置为前加签/后加签，多人办理方式为并行/串行；默认前加签、并行，可在同一弹窗高级区设置多人办理顺序。

- 前加签：当前原办理人保留责任，追加人员先完成必要意见，原办理人再完成原任务；未满足加签条件不得提前推进节点。
- 后加签：保留原办理人的已提交意见，在同一审批责任上追加后续办理；追加人员完成前不得提前推进节点，不改写原意见。
- 多人并行均可同时办理，串行按配置顺序；本版加签要求全部追加人员完成且通过，退回/驳回按节点已有合法动作处理。每人、顺序、轮次、取消原因和原任务关系可追溯。
- 新请求明确携带两个维度。旧请求只携带并行/串行时保持原已过语义，不静默改成前/后加签；Executor 在实现记录中列出旧行为和兼容映射。新配置随定义/动作记录保存，界面回显正确。
- 补签仍是对既有责任的补充确认，不重开或重写原流程终态。加签/补签的重复、取消、失效人员、越权与并发沿统一命令和幂等保护。

## DR09：节点操作、审批草稿和缺失入口

- 节点允许操作与合法退回目标进入流程定义版本。最终可用动作是操作者权限、任务归属/状态、节点策略和目标合法性的交集；服务端执行同一交集。旧定义没有新增策略时保持既有动作语义，不默认全关或扩大授权。
- 退回只选择合法历史节点和轮次，不能仅凭画布节点存在接受目标。办理页和详情页用同一状态结果；次要动作进入「更多」而不改变接口与业务结果。
- 审批暂存复用既有节点意见草稿服务，绑定租户、实例、任务、节点轮次和当前办理人。允许未填完必填内容；身份、字段权限、类型和资源限制仍执行。恢复时仅该办理人可见，暂存不完成任务、不生成已办、不触发表单提交事件或审批通知。正式办理需完整校验；任务终态后拒绝继续改写草稿，原意见和轨迹保留。
- 定义版本挂起仅阻止该版本新发起，既有实例继续按已绑定版本正常办理；恢复同一版本后可再次新发起。与租户停用导致的业务准入暂停区分。
- 授权代理规则可查询、新增和撤销，明确授权人、受托人、时间与流程范围；沿原权限和循环/跨租户/停用检查。废弃入口只对有权主体和合法实例状态开放，复用既有废弃结果和审计；不与监控中的其他干预混淆。

## DR10：像素级还原

Owner 明确要求页面开发按 UI 做像素级还原。以 [视觉验收标准](visual-acceptance-020.md) 为正式硬门槛，设计值、实际浏览器截图和差异结果共同判定；页面结构相似、组件测试通过或实现自述不能替代此项。标准适用于五项目标的全部页面和组件状态。
