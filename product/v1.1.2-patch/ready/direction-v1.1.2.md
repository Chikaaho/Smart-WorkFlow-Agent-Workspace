## 1. 目标

修掉 1.1.0 上线后发现的取消缺陷和显示问题，让用户看到的编号、状态、运行结果都可信。

| ID | 内容 | 验收标准 |
|---|---|---|
| B1（P71，优先） | 取消执行时，如果传入的是**执行编号**，接口返回 200，但执行实际没有取消 | 用执行编号和受理号取消，结果相同：状态变为 CANCELLED，等待中的人工任务一起关闭，子执行一起取消。传入不存在或不属于当前用户的编号时，返回明确的错误，不能 200 却什么都没做。设计器的「取消执行」按钮、待办、详情页凡是能取消的入口，实际都能取消成功 |
| B2（P70） | 设计器运行中，结果区误显示「执行失败 耗时 0ms」 | 运行中显示「运行中」，结束后才显示成功或失败。开始新一次运行时清掉上次的结果 |
| B3（P70） | 状态没有中文 | 执行详情和列表的 `CANCELLED`，实例监控的 `DISCARDED`，都显示中文。顺带检查 Graph 执行和实例监控的全部状态值，凡是还显示英文原值的都补上中文 |
| B4（P70） | 失败分类列太窄 | Graph 执行列表的「失败分类」列能完整显示 `HUMAN_TIMEOUT` 这类值；如果放不下，显示中文名称，并在鼠标悬停时显示原值 |
| B5（P70） | 实例监控干预页的「当前节点」显示编码 | 显示节点名称，例如「部门审批」，不显示 `n_approve`。名称取不到时才回退到编码 |
| B6 | README 展示图两端卡片被切 | `agent-graph.png` 里所有节点卡片都完整显示，文字清晰。三仓同步 |

## 3. 影响与风险

- B1 涉及取消的级联：父执行、等待中的人工任务、子执行。修的时候必须保证**用受理号取消**这条已经能用的路不退化。
- B1 要先查清楚：设计器、待办、详情这几个入口现在分别传的是哪个编号。如果有入口传的是执行编号，那线上用户现在就取消不了，要在回执里写明。
- B3 的中文映射要和流程模块已有的状态文案保持一致，不要另起一套叫法。
