## 1. 功能范围与验收标准

### G1 设计器重做（Web 为主，Server 补参数声明和逐节点事件）

| ID | 验收标准 |
|---|---|
| G1-1 适配层 | `flow-graph` 适配层支持：自定义节点组件渲染、点击边、按命令更新节点和边（不再每次改动都销毁重挂）。流程设计器不受影响。I48 在 known-issues 里改成「1.1.0 已扩展」，写清新的导出面 |
| G1-2 节点卡片 | 9 种节点都用自定义卡片：类型图标、标题、一行关键配置摘要（如 LLM 显示模型名，条件显示分支数，知识库显示库名），按类型配色，选中有高亮，运行时有状态色。视觉风格和流程设计器一致（圆角、阴影、字号、配色体系），回执给同尺寸对照截图 |
| G1-3 添加与布局 | 左侧节点面板分组，支持拖入和点击添加。节点和边上有「+」，点了选类型就插在后面并自动连线。新节点自动落在空位，**连续添加不重叠**。有「整理布局」按钮。支持撤销/重做、缩放栏、适配画布。小地图不做 |
| G1-4 参数声明 | 开始节点可以声明输入参数（名称、类型：文本/数字/布尔/JSON，是否必填，说明）；结束节点声明输出参数，每个参数从上游变量里选。执行接口接收结构化入参，缺必填参数时拒绝并说明是哪个。**旧图照常打开和运行**：没有声明的图视为只有一个文本参数 `input`，原来的接口用法不变。图定义 JSON 加键即可，不改表结构 |
| G1-5 变量引用 | LLM 提示词、条件、工具参数、知识库查询等填值的地方都可以插入变量：选择器只列出**当前节点上游可达**的节点输出和开始节点参数，按节点分组。引用的变量被删掉或者不在上游时，发布校验报错，并指出是哪个节点、哪个字段。旧的 `{{变量名}}` 写法继续能用 |
| G1-6 配置面板 | 右侧配置面板按页签组织，风格同流程设计器。开始/结束节点不再是空面板。点条件边可以编辑分支关键词，也可以删除边 |
| G1-7 试运行面板 | 在设计器里直接试运行：填写开始节点参数后运行，画布上每个节点实时显示等待/运行中/成功/失败/跳过；点节点可以看耗时、入参、出参和错误。流式输出照常显示。后端在现有事件通道上补逐节点开始/结束事件（含耗时、入参、出参摘要，大字段截断）。执行详情页也显示异步执行的节点轨迹（现在是空的） |
| G1-8 单节点运行 | 在节点配置面板里手动填写该节点用到的变量，单独运行这个节点，显示输出和耗时。工具节点运行前要二次确认，因为会真的调用工具。单节点运行不改图、不产生正式执行记录（或者明确标为调试记录），回执说明采用哪一种 |
| G1-9 权限与空态 | 没有编辑权限的人只读打开（可以看、可以看运行记录，不能改、不能运行）。空图、图加载失败、运行失败都有明确提示 |

### G3 人工节点与子图节点（Server + Web）

| ID | 验收标准 |
|---|---|
| G3-1 人工节点配置 | 配置：给处理人看的说明（可以引用变量）、要填写的字段（文本/单选/数字）、决策按钮（如「通过」「退回」，每个按钮接一条出边）、处理人（指定用户或角色）、超时时长和超时走哪条边 |
| G3-2 等待与处理 | 运行到人工节点后，执行状态变成**等待人工**，不占用执行线程。处理人在 Graph 运行页的「待我处理」列表里看到它，填写并点按钮后执行继续，填写内容作为该节点的输出变量供下游使用。非处理人提交时服务端拒绝。同一个等待只能被处理一次，重复提交报错 |
| G3-3 超时、取消、重启 | 超时后按配置走超时边；没配超时边就以失败结束并写明原因。等待中可以取消。**服务重启后等待中的执行仍然在等**，处理后能继续，变量不丢 |
| G3-4 子图节点 | 选择一个已发布的 Graph，绑定**固定版本**，把当前变量映射到子图开始节点参数，子图结束节点的输出映射回变量。父子执行有关联：执行详情里能从父跳到子 |
| G3-5 子图约束 | 发布时检测引用环（A→B→A）并拒绝；嵌套深度上限默认 3 层，超限时发布报错。取消父执行时子执行一起取消。子图超时不能超过父执行剩余时间。子图里有人工节点时，父执行也显示等待人工，处理后父子都继续 |
| G3-6 运行可视化 | 试运行面板和执行详情里，人工节点显示「等待 XX 处理」，子图节点显示子执行状态和跳转入口 |

### G4 小尾巴

| ID | 验收标准 |
|---|---|
| G4-1 任务详情操作栏 | 任务详情页在 1440×900 下，滚动到底时明细表最后一行完整可见，不被底部操作栏遮住。操作栏改变高度时（展开意见框）也不遮挡 |
| G4-2 发起人筛选 | 流程监控的发起人筛选改成选人组件，可以按姓名搜索，并有固定选项「系统（IoT）」，选它能筛出 IoT 实例 |
| G4-3 实例监控干预页 | 发起时间、干预时间用统一格式 `yyyy-MM-dd HH:mm:ss`，不带微秒；状态显示中文（列表和干预历史的前后状态都改）；流程定义显示名称而不是内部 key（后端补名称字段） |
| G4-4 沙箱偶发 | 修 `JavaSubprocessExecutor` 的竞态：子进程正常退出后有界等待读取线程，仍然没拿到结果就返回明确失败（「子进程未返回输出」），不允许出现「成功但输出为空」。补一个能稳定复现原竞态的测试 |
