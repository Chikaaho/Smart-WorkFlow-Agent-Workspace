# product 使用说明（规则）

`product/` 是 **L/XL 跟踪型功能**的需求方向与回执仓库，按功能组织。S/M 直接执行任务默认不创建本目录下的功能文件。

## 目录结构（每个 L/XL 功能）

```
product/<feature-name>/
├── ready/     — 待执行或待复核的需求方向文档
├── receipts/  — 执行、测试、审查、补证与终态同步回执（历史追加保留，永不移动）
└── passed/    — 已由规划角色确认通过并归档的方向文档
```

## 关键规则

- 只有需要正式状态、P 编号、基线、跨会话跟踪或独立规划验收的 L/XL 功能进入本生命周期。
- `ready/` 中存放需求方向文档（目标/非目标/影响范围/风险/待确认问题），交付执行角色后由执行角色自行拆分 Step、设计执行/测试方案并自主完成。
- `receipts/` 中由执行角色写功能级 completion receipt；补证、修正与终态同步使用新文件追加，历史回执永远保留，不得移动到 `passed/`。
- `passed/` 中的需求方向文档为已通过最终验收的归档文档，不可重复下发。
- 主需求方向在功能级规划验收 `PASSED` 后由规划角色从 `ready/` 移至 `passed/`；执行角色不得移动方向文档到 `passed/`，也不得创建 `done/` 表示自行验收。

## 初始状态

本目录初始无业务功能方向；首个 L/XL 需求方向由规划角色创建 `ready/` 并下发。已有历史 `step-N-*` 文件为历史存档。
